# Deferred analysis: sub_0801A894

Window-curtain open animation (engine). Two `u8` params: `flags`, `count`.
Programs the WIN0/WIN1 hardware registers (0x04000040..0x04000046) and sweeps
WIN0V down / WIN1V up over `count+1` vblank frames toward a fully-open split,
then enables BG3 in DISPCNT (0x04000000 |= 0x800). `flags & 1` / `flags & 2`
turn on the WIN0 / WIN1 display bits (DISPCNT bits 13/14) up front.

Callees: `__divsi3` (in-ROM libgcc at 0x08033D14), `sub_080008DC` (vblank wait,
in src/system/vblank.c). Both already peeled. Step magnitude = `56 / count`.

## Drift

Best reached: **byte_diff 8, diff_count 5** (from 199/62 cold). Down to TWO
residual instruction-selection differences, both on register r4 (which holds the
`count`-derived value, the loop counter `i`):

1. **divsi3 arg-eval order** (offset +0x16/+0x18): target emits
   `movs r0,#56` THEN `adds r1,r4,#0` (const arg0 first, count-reload last);
   our build emits `adds r1,r4,#0` then `movs r0,#56`. 0-byte size delta, pure
   ordering — but counts toward the diff.
2. **`i = (u8)(count+1)`** (offset +0x5a..+0x5e): target routes via r0 —
   `adds r0,r4,#1; lsls r0,#24; lsrs r4,r0,#24`; our build does the 2-address
   in-place form `adds r4,#1; lsls r4,#24; lsrs r4,r4,#24`.

Root cause of BOTH: getting `count` into r4 (target's assignment is flags=r5,
count=r4) currently REQUIRES a hard-register pin `register u8 c asm("r4")`.
Because r4 is then a *hard* register, agbcc's combine/peephole freely emits the
2-address in-place `adds r4,#1` and schedules the divsi3 arg-reload differently.
The target uses a *regular pseudo* that the allocator happened to place in r4 —
that gives the via-r0 forms. But agbcc's natural allocation (no pin) assigns
flags→r4, count→r5 (the opposite of target): with equal QTY_CMP_PRI priority for
the two params, the tie breaks by qty-creation order and flags (param 0) is
created first, so flags wins r4. So we cannot get BOTH the correct param
assignment AND the via-r0 insn forms with the levers tried.

### Levers tried (all FAILED to close the last 8 bytes)
- Pin `c asm("r4")` (KEEP — gives byte_diff 8; this is the best base).
- Pin `f asm("r5")` for flags → REGRESSES to 195 (folds the param extraction
  `adds r5,r0,#0` via-r0 into a direct `lsrs r5,r0,#24`). Do NOT pin flags.
- `stepHi asm("sl")` second copy of step (KEEP — required: target holds step in
  BOTH r6 (subtract) and sl (add) via `mov sl,r6` + `mov r2,sl; adds r0,r7,r2`).
- `u16 full = 0xF0;` named local for the 0xF0 store constant (KEEP — fixes the
  0xF0-hoist placement so it materializes between the win0h/win0v pool loads).
- i as int / `(1+c)` / `t=c+1; i=(u8)t` / `while((i=i-1)!=0)` → all fold to the
  same in-place `adds r4,#1`.
- `asm volatile("" : "+r"(c))` barrier before the i computation → no change.
- Dividend as a variable `n=56` → constant-folded, no change.
- old_agbcc (`CC = $(OLD_AGBCC_BIN)`) → identical byte_diff 8.
- CFLAGS sweep on the natural (unpinned) base: -fno-gcse, -fno-cse-follow-jumps,
  -fno-expensive-optimizations, -fno-force-mem → all stay at byte_diff 15 (the
  param-swap base). agbcc has no -fno-schedule-insns.
- Reordering the C (i-computation before the flag tests) → REGRESSES to 214
  (forces a second stack slot, sub sp #8).
- Adding a 3rd `count` reference to break the QTY tie in count's favor → did NOT
  flip flags off r4.
- **Permuter**: imported a clean `.inst.n` scratch (base score 1290 = byte_diff 8),
  ran the full ~50s/-j4 budget, `--stop-on-zero --better-only` → never beat the
  base, no score-0, no output-*. The base is a permuter local minimum; the
  residual is below the statement-mutation granularity.

### Next lever to try (DIFFERENT from the above)
The crux is "count→r4 as a *regular pseudo*, not a hard-reg pin." Ideas a future
agent has NOT tried:
- Find a way to make the *natural* allocator prefer count→r4 without a pin:
  the QTY tie is creation-order. Read `tools/agbcc-src/gcc_arm/local-alloc.c`
  `block_alloc` / `qty_compare` more deeply — maybe make flags' lifetime
  genuinely longer (delay its last use past i) so its priority drops below count

  once more AFTER the loop in a way agbcc folds to no insn.

- A pointer/index cast trick (cf. sub_0800A1C8) to launder `c` through a pseudo

## Best-effort C (byte_diff 8 — KEEP the c-pin / stepHi / full levers)

```c
#include "macros.h"
#include "types.h"
extern int __divsi3(int num, int den);
extern void sub_080008DC(void);
void sub_0801A894(u8 flags, u8 count)
{
    register u8 c asm("r4") = count;
    register u8 stepHi asm("sl");
    vu16 *win0h, *win0v;
    u16 full;
    u8 step, top, bottom, i;
    step = (u8)__divsi3(56, c);
    stepHi = step;
    top = 0xA0; bottom = 0;
    if (flags & 1) *(vu16 *)0x04000000 |= 0x2000;
    if (flags & 2) *(vu16 *)0x04000000 |= 0x4000;
    i = (u8)(c + 1);
    if (i != 0) {
        win0h = (vu16 *)0x04000040;
        full = 0xF0;
        win0v = (vu16 *)0x04000044;
        do {
            *win0h = full;
            *win0v = (top << 8) | 0xA0;
            *(vu16 *)0x04000042 = full;
            *(vu16 *)0x04000046 = bottom;
            sub_080008DC();
            top = (u8)(top - step);
            bottom = (u8)(bottom + stepHi);
            i = (u8)(i - 1);
        } while (i != 0);
    }
    *(vu16 *)0x04000040 = 0xF0;
    *(vu16 *)0x04000044 = 0x70A0;
    *(vu16 *)0x04000042 = 0xF0;
    *(vu16 *)0x04000046 = 0x30;
    *(vu16 *)0x04000000 |= 0x800;
}
```
