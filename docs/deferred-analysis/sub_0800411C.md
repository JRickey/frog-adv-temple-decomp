# sub_0800411C — deferred analysis

Mode-X game-state dispatcher at `0x0800411c` (768 B), handler for
`GAME_MODE_SCENE_20` (20) and `GAME_MODE_ATTRACT` (24). It is the
"fuller" sibling of `sub_08002844` (mode_15.c): same 9-state
`switch (*statep)` dispatcher driven by a `mov pc, rN` jump table, but
with the case-0 setup block (`sub_08006BB4`/`sub_08007228`×2/
`sub_0800B7B0`×2) and the case-3 spawn block (`sub_08007660`/
`sub_080072E0`×2/.../`sub_08004508`) INLINED instead of factored into
`sub_0800441C` / `sub_080044A4`. Large 972-byte stack frame with seven
scratch buffers.

VERDICT (classify_unmatchable): ATTEMPT_MATCH (`mov pc, r0` is the C
switch lowering, NOT unmatchable). The dispatcher core, layout, prologue
and 8 of 9 cases match. The residual is a pure register-coloring /
arg-evaluation-order divergence — NOT NAKED material.

## Drift

- Best **byte_diff = 313** (from 631 at first compile); **diff_count 90**
  Thumb instrs, but ~60 of those 90 are `b.n` branch-target offsets that
  differ by a constant 4 — pure CASCADE from a handful of real coloring
  diffs upstream. The real distinct diffs are only:
    1. **Entry init r0/r1 swap.** Baserom: `ldr r0,=0x3b9; add r0,sp;
       movs r1,#0; strb r1,[r0]`. Built: address in r1, value in r0.
       (`u8 zero=0; STATE=zero;` flips it to address-in-r0 but adds an
       r7 push — net worse. Cosmetic, 2 bytes.)
    2. **Argument-evaluation order (the dominant root cause).** For the
       inlined calls `sub_08007228(3, buf1, 2)` (case 0, ×2) and
       `sub_080072E0(0, 3, buf1)` (case 3, ×2) and the `sub_08004508`
       args, the baserom emits the CONST arg first then the buffer
       address: `movs r0,#3; add r1,sp,#612`. agbcc emits the ADDRESS
       first: `add r1,sp,#612; movs r0,#3`.
    3. **case 4 `sub_08009C14` arg**: baserom recomputes `&state`
       (`ldr r0,=0x3b9; add r0,sp`); built reuses the cached `statep`
       pointer in r4 (`adds r0,r4,#0`). Using the recompute form
       (`sub_08009C14((u8*)&ctrl[1])`) matches that 1 instr but pushes
       r7 (5-reg prologue) because `&accept` then gets hoisted to r5 —
       so the 4-reg-prologue reuse form was kept instead. Net 1-instr
       diff either way.

- **Root cause of #2 (confirmed via agbcc source + isolated probes):**
  `calls.c:precompute_register_parameters` copies any reg-passed arg with
  `rtx_cost > 2` into a pseudo when `SMALL_REGISTER_CLASSES && reg_parm_seen`
  (always true here). `thumb.h` CONST_COSTS gives a `PLUS` with a const
  `>= 256` a cost of `COSTS_N_INSNS(2)` (offsets 0/sp are free → buf0=sp+0
  matches const-first; buf1=sp+612, buf2=sp+684 etc. are expensive →
  precomputed). Whether the precompute pseudo is REMATERIALISED inline at
  the call (→ const-first, baserom) or kept in a hard reg (→ addr-first,
  built) is a **global** local-alloc/reload decision.
    - Isolated probes PROVE const-first is reachable: a `while`-loop body
      with a `switch` + the SAME case-0 shape (5 buffers, p5/p6 held in
      r4/r5, volatile state byte, `pendingMode=13`) compiles to
      `movs r0,#3; add r1,sp,#612` (const-first) — see `/tmp/p16b.c`
      pattern. It only flips to addr-first once the FULL 9-case function's
      global register pressure is present. So it is a sharp global-coloring
      local minimum, not a structural wall.

## What DID land (keep these for the next attempt)

- Frame layout MATCHES: declare the accept/state pair as a 4-byte ARRAY
  `u8 ctrl[4]` (NOT separate scalars — scalars sort to the TOP of the
  frame at 0x3c8; only a BLKmode array lands in the array group at 0x3b8,
  giving accept=ctrl[0]@0x3b8, state=ctrl[1]@0x3b9). Buffers declared in
  order buf0[612],buf1[72],buf2[108],buf3[32],buf4[128],ctrl[4],buf5[8],
  buf6[8] land at exactly the baserom sp-offsets.
- State byte addressing: `#define STATE (*(volatile u8*)&ctrl[1])` yields
  the baserom's `ldr =0x3b9; add sp; ldrb/strb [+0]` form (a plain
  `ctrl[1]` gives `add sp,#952; [+1]` instead — 0x3b9 is not an
  add-encodable sp offset, so the baserom uses the literal). Same idiom
  mode_15.c uses for its init.
- case 3 mask handling MATCHES baserom (`movs r2,#8; adds r0,r2,#0;
  ldrh r1,[ent,#52]; ands r0,r1`) by mirroring mode_15: `register u32
  nextState asm("r3"); p3720=gEntities; nextState=8;` then `(p3720->status
  & 8)` / `(gIwram_6110.inputFlags & 8)` with the literal 8.
- Buffer-pointer hoisting into callee-saved r4/r5(/r6): introduce
  `u8 *pair11=buf5; u8 *pair16=buf6;` at the top of cases 0/3/4 so agbcc
  holds them across the intervening calls (matches baserom r4/r5/r6).
- Prologue `push {r4,r5,r6,lr}` matches once statep is reused (not
  recomputed) for the case-4 `sub_08009C14` call.
