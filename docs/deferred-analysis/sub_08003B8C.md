# Deferred Analysis: sub_08003B8C

Range: [0x08003b8c, 0x08003bfc) — 112 bytes, Thumb

## Status

1-byte-off near-match. All structural aspects match; only the branch condition
code differs (`d9` = `bls.n` vs `dd` = `ble.n`).

## Drift

**Best byte_diff: 2 bytes** (instruction-level).

The loop comparison instruction at offset 0x58 in the function is:
- Compiled: `d9 e8` (`bls.n 2c`) — unsigned ≤ (Lower or Same)
- Target:   `dd e8` (`ble.n 2c`) — signed ≤ (Less or Equal)

Both are functionally identical for counter values 0..5. The difference is
purely the ARM condition code in the branch instruction.

**Root cause:** agbcc 2.x applies a "loop reversal" optimization for any
`s32 i <= 5` loop: converts to countdown `for (i = 5; i >= 0; i--)` using
`bge.n`. To avoid this, `i` must be `u32` (unsigned), which gives `bls.n`
instead of `ble.n`.

## Levers tried

1. `u32 i`: gives `bls.n` (count-up, correct structure) — 1 byte off
2. `s32 i`: gives `bge.n` countdown — completely different structure
3. `register int i asm("r7")`: gives `ble.n` count-up — BUT r7 not
   included in prologue/epilogue push/pop (4 bytes wrong total)
4. `s8 i`, `u8 i`, `s16 i`, `u16 i`: extra narrowing sign/zero-extension
   instructions in loop body
5. `5 >= i` reversed comparison: same countdown behavior
6. `(int)i <= 5` cast: same countdown behavior
7. `const int n = 5; i <= n`: same countdown (agbcc inlines the const)
8. `old_agbcc` compiler: same result
9. Permuter (45s, ~400+ iters): found score 1190 but not 0. Best variant
   used `short new_var = i` as the condition var, which got `ble.n` but
   lost the `adds r7, #1` increment (semantically broken).

## Best-effort C

1-byte difference. The `u32 i` type is the only viable choice:

#include "iwram.h"

void sub_08003B8C(void)
{
    struct IwramAt35E0 *p35E0;
    s32 b;
    u32 i;

    sub_0800658C((void *)0x03006110, 0x80, 12, (const void *)0x082f9b2c, 1, 5);
    sub_0800CE98(12, 0);
    sub_08009CBC();

    i = 0;
    p35E0 = &gIwram_35E0;
    /* agbcc packs b = (0x5D + i) << 16; r4 = b >> 16 is the tile offset */

        sub_0800CBE8(p35E0->_field_18, p35E0->_field_19, 6, b >> 16, 13);
        sub_0800CBE8(p35E0->_field_18, p35E0->_field_19, 7, b >> 16, 14);
    }
}
