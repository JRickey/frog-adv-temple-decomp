# sub_08012664 — deferred analysis

Spawn-tile picker. Reads cached tile coords from `gIwram_35E0` (offsets 8 and
10, read as `u8`), builds two exclusion bands `[base..base+4]` / `[base..base+2]`
where `base = (u8)(coord - 3)`, collects the values in `0..7` / `0..4` NOT in
each band into two stack candidate buffers, then random-picks (via
`sub_0801185C(count)`, a VCOUNT LCG RNG returning `[0,count)`) and writes the
spawn tile X to `gEntities + 0x692` (clamped `[1,8]`) and Y to `gEntities + 0x694`
(clamped `[2,6]`). NOTE the genuine original quirk: the **Y** pick indexes the
**colCand** buffer (held in r8) with a count drawn from the Y exclusion set — the
baserom's `add r0, r8` at 0x12740 reuses r8=colCand, not the rowCand buffer.

## KEY NEW FINDINGS (these are the load-bearing escapes the prior note lacked)

### 1. The store idiom — defeat the r9-hoist with a RAW-ADDRESS base + deferred load
`*(u16*)(gEntities + 0x692)` is `base(0x03003720) + separate-offset-literal(0x692)`,
two pool words added at runtime (the established `sub_0800D9C8` / `sub_0800D070`
idiom: `offset = 0x692; asm("" : "+r"(offset)); p = base + offset;`).
TWO traps, both solved:
  (a) Using the **`gEntities` SYMBOL** for the base makes agbcc GCSE-hoist the base
      address into a callee-saved high reg (r9) ABOVE the candidate loops (since it's
      loop-invariant and referenced after the loops) → forces a wider prologue
      (`push {r6,r7}` vs `push {r7}`), shifting every branch target → byte_diff ~300.
      FIX: cast the **raw integer address `(u8 *)0x03003720`** instead. A plain
      integer constant is cheap to reload, so agbcc does NOT cache it in r9 — it
      loads it fresh at the store (matching `ldr r4,[pc]` at 0x1272c). This alone
      took byte_diff 273 → 62.
  (b) Compute the picked VALUE into a temp BEFORE materialising the dest address
      (`value = colCand[sub_0801185C(...)] + 1; ... colDst = base + off; *colDst = value;`)
      so the base load lands AFTER the `bl` (the baserom loads base post-call). Took
      62 → 43.

### 2. The two-intermediate read form (keep this)
    t8  = coords[8]  << 24;     /* both byte reads + <<24 FIRST ... */
    t10 = coords[10] << 24;
    colBase = (t8  + 0xFD000000) >> 24;   /* ... then both adds, sharing 0xfd<<24 */
    rowBase = (t10 + 0xFD000000) >> 24;
Reading BOTH coords before EITHER add makes agbcc interleave exactly like the
baserom (read q[8]→r1<<24, read q[10]→r0<<24, build constant, both adds). Without
this it computes colBase fully before reading q[10]. Took 43 → 40.

### 3. The constant DOES yield to a `register u32 k asm("r6")` pin (prior note WRONG)
The prior note claimed `k=r6` "FAILS to compile (spill error)". That was only true
on its dirtier base. On the clean base above, `register u32 k asm("r6"); k = 0xFD000000;`
compiles fine and pins the `0xfd<<24` constant to callee-saved r6 — EXACTLY matching
the baserom. Took 40 → 22 (the read region AND the constant now match byte-for-byte).

### 4. The store registers need pins (all load-bearing, verified by drop-test)
`base asm("r4")`, `offsetCol asm("r1")`, `offsetRow asm("r2")`, `colDst asm("r5")`.
`rowDst` reuses r4 (base consumed) automatically — its pin is NOT needed (drop-tested).
`t8` pin also NOT needed.

## THE IRREDUCIBLE 22 BYTES — a pure local-allocator quantity-tie, NO source control

With the k=r6 pin the residual is a COUPLED 3-instruction recolor + a 4-instruction
clamp-index recolor, NONE of which any C shape controls (the function takes NO
arguments, so there is no incoming-register lifetime to anchor the coloring — see the
prior note's corpus finding: every corpus multi-stack-base match is argument-anchored):

  A. colCand-temp / colExcl-base SWAP (≈8 bytes via branch-offset cascade):
       target:  `add r0,sp,#12; mov r8,r0; mov r6,sp`   (colCand-temp=r0, colExcl=r6 reusing dead k)
       built:   `add r6,sp,#12; mov r8,r6; mov r0,sp`   (colCand-temp=r6, colExcl=r0)
     The baserom ties the dead constant's r6 to the colExcl-base (use-then-release);
     agbcc gives colCand-temp r6 instead. This is a `combine_regs` coalescing tie-break.
  B. clamp zero-index register cycling (≈8 bytes):
       each `value = *colDst` emits `movs rN,#0; ldrsh r0,[ptr,rN]`; target cycles the
       throwaway zero-reg r6,r1,r2,r6; built cycles r1,r2,r6,r1. Uncontrollable from C.
  C. base-load position (net 0 bytes, just a scheduling slot).

### The swap (A) and the position diff are COUPLED — fixing one breaks the other
- Pinning `register u8 *ce asm("r6"); ce = colExcl;` and walking colExcl through `ce`
  FIXES the swap (colCand-temp→r0, colExcl→r6) → diff_count drops to 13 — BUT agbcc
  then schedules `mov r6,sp` early (at 0x1e instead of 0x26), cascading a branch
  offset → byte_diff 28. Assigning `ce` inside the loop (permuter's idea) fixes the
  position but the swap reappears. They are mutually exclusive with this lever.

## Best-effort C (verified byte_diff 22, diff_count 14, default OLD_AGBCC -O2)

```c
#include "iwram.h"
#include "types.h"

extern int sub_0801185C(u8 range);

void sub_08012664(void)
{
    u8 *coords;
    u8 colExcl[5];
    u8 rowExcl[3];
    u8 colCand[8];
    u8 rowCand[4];
    u32 t8;
    u32 t10;
    register u32 k asm("r6");
    u32 colBase;
    u32 rowBase;
    u8 i;
    u8 j;
    u8 colCount;
    u8 rowCount;
    u8 hit;
    register u8 *base asm("r4");
    register u32 offsetCol asm("r1");
    register u32 offsetRow asm("r2");
    register s16 *colDst asm("r5");
    s16 *rowDst;
    s16 value;

    coords = (u8 *)&gIwram_35E0;
    t8 = coords[8] << 24;
    t10 = coords[10] << 24;
    k = 0xFD000000;
    colBase = (t8 + k) >> 24;
    rowBase = (t10 + k) >> 24;

    for (i = 0; i <= 4; i++)
        colExcl[i] = i + colBase;
    for (i = 0; i <= 2; i++)
        rowExcl[i] = i + rowBase;

    hit = 0;
    colCount = 0;
    for (i = 0; i <= 7; i++) {
        for (j = 0; j <= 4; j++) {
            if (i == colExcl[j])
                hit = 1;
        }
        if (hit == 0)
            colCand[colCount++] = i;
        hit = 0;
    }

    rowCount = 0;
    for (i = 0; i <= 4; i++) {
        for (j = 0; j <= 2; j++) {
            if (i == rowExcl[j])
                hit = 1;
        }
        if (hit == 0)
            rowCand[rowCount++] = i;
        hit = 0;
    }

    value = colCand[sub_0801185C(colCount)] + 1;
    base = (u8 *)0x03003720;
    offsetCol = 0x692;
    asm("" : "+r"(offsetCol));
    colDst = (s16 *)(base + offsetCol);
    *colDst = value;

    value = colCand[sub_0801185C(rowCount)] + 2;
    offsetRow = 0x694;
    asm("" : "+r"(offsetRow));
    rowDst = (s16 *)(base + offsetRow);
    *rowDst = value;

    value = *colDst;
    if (value <= 0)
        *colDst = 1;
    value = *colDst;
    if (value > 8)
        *colDst = 8;

    value = *rowDst;
    if (value <= 1)
        *rowDst = 2;
    value = *rowDst;
    if (value > 6)
        *rowDst = 6;
}
```

### The residual 22 bytes = three COUPLED groups, all downstream of ONE coloring tie
1. **Group A — colCand-temp / colExcl-base r0↔r6 SWAP** (≈8 bytes via branch cascade,
   offsets 0x22-0x28). target: `add r0,sp,#12; mov r8,r0; mov r6,sp` (colCand-temp=r0,
   colExcl-base=r6). built: `add r6,sp,#12; mov r8,r6; mov r0,sp` (swapped).
2. **Group B — base-load (`ldr r4,[pc]` for 0x03003720) position** (net 0 bytes,
   offsets 0xc8/0xd0). target loads base the FIRST insn after the 1st `bl`; built loads
   it after `add r0,r8; ldrb; adds #1`. old_agbcc has NO instruction scheduler
   (`-fschedule-insns{,2}` are rejected; INSN_SCHEDULING undefined), so this is pure
   RTL emission order, not a scheduler slot.
3. **Group C — clamp zero-index `movs rN,#0; ldrsh r0,[ptr,rN]` cycle** (≈8 bytes,
   offsets 0xe8-0x10e). target cycles r6,r1,r2,r6; built cycles r1,r2,r6,r1. A pure
   phase-shift in the "first free reg" pick, downstream of B's liveness.

### The ROOT cause (NEW — the precise pass + reg identities)
local-alloc block 0 (the read/prologue region) holds only THREE local quantities
(pseudo regs 22/41/42 = the `<<24` read intermediates) — colCand-temp and colExcl-base
are NOT local; both are GLOBAL quantities colored by `gcc/global.c`. From the global
trace on the floor-22 build:
  - colExcl-base (fill loop) = pseudo **reg 38**, refs=4 live_len=20 → **phys=0 (r0)**.
  - the r6 it "should" get instead goes to pseudo **reg 31** (refs=6 live_len=88, the
    rowCand-collection rowExcl-base/counter region) — higher priority, colored r6 first.
  - colCand-base (held across both `bl`s, MUST be callee-saved, can't be r0) = pseudo
    **reg 172** → phys=8 (r8). colCount = reg 30 → phys=12 (ip).
`global.c find_reg` picks the LOWEST free hard reg (thumb has no REG_ALLOC_ORDER, so
ascending 0,1,2,…). colExcl-base gets **r0 because r0 is free & lowest** during its life.
The target gives colExcl-base r6 because in the target **colCand-temp occupies r0**,
displacing colExcl-base to r6. So the entire swap reduces to: *which quantity gets r0 —
colCand-temp or colExcl-base.* The colCand-temp (the low reg in `add temp,sp,#12; mov
r8,temp`, needed because thumb `add sp,#imm` can't target r8) is a RELOAD/global temp;
its register is decided by the reload↔global interaction, with NO source-level handle
for a function that takes **no arguments** (no incoming-reg lifetime to anchor coloring).

### ce-pin (`register u8 *ce asm("r6"); ce=colExcl; … ce[i]=…`) — still the best swap-fix
Fixes the COLOR (colExcl→r6, Group A gone) → diff_count 13, but FORCES `mov r6,sp` to
emit EARLY (at 0x1e, with the constant, instead of lazily at 0x26) because the explicit
`ce=` assignment is sequenced there → byte_diff 28. The non-ce floor-22 emits `mov r0,sp`
lazily (right POSITION) but wrong COLOR. **Position and color are mutually exclusive with
every lever found** — the target needs BOTH (lazy emission AND r6), which only happens
when colExcl-base is a normal global pseudo that global.c *colors* r6, which it won't do
while r0 is free and lower.
