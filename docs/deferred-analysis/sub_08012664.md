# sub_08012664 — deferred analysis

Spawn-tile picker. Reads cached tile coords from `gIwram_35E0` (offsets 8 and
10, read as `u8`), builds two exclusion bands `[base..base+4]` / `[base..base+2]`
where `base = (u8)(coord - 3)`, collects the values in `0..7` / `0..4` NOT in
each band into two stack candidate buffers, then random-picks (via
`sub_0801185C(count)`, a VCOUNT LCG RNG returning `[0,count)`) and writes
`gIwram_3720._field_692` (tile-X, clamped to `[1,8]`) and `_field_694` (tile-Y,
clamped to `[2,6]`). NOTE the genuine original quirk: the **Y** pick indexes the
**X** candidate buffer (`colCand`, held in r8) with a count drawn from the Y
exclusion set — the baserom's `add r0, r8` at 0x12740 reuses r8=colCand, not the
rowCand buffer. The best-effort C below faithfully reproduces that.

## Drift

Best reached: **byte_diff 8, diff_count 8** — pure register-coloring, identical
opcodes/operand-structure throughout. The ENTIRE residual is one constant's
register:

  target: `movs r6,#253; lsls r6,#24; adds r1,r1,r6; adds r0,r0,r6`  (0xfd<<24 in r6)
  built:  `movs r2,#253; lsls r2,#24; adds r1,r1,r2; adds r0,r0,r2`  (0xfd<<24 in r2)

This cascades to one coupled swap: the baserom puts the `colCand` base-temp in
**r0** and the `sp`/`colExcl` base in **r6** (`add r0,sp,#12; mov r8,r0; mov r6,sp`),
while agbcc puts colCand-base in r6 and sp-base in r0. It is a single
coalescing-order decision in agbcc's local allocator — it parks the short-lived
`0xfd<<24` constant in callee-saved **r6** because it is about to reuse r6 for the
sp-base, minimizing pressure; our build instead grabs the low caller-saved r2 for
the constant and leaves r6 for colCand-base.

### Cracking the byte-subtraction (already solved, keep this)

`base = (u8)(coord - 3)` naively compiles to `subs #3; lsls#24; lsrs#24` (narrow),
but the baserom uses the WIDE shift-domain form with a SHARED `0xfd<<24` constant.
The winning structure is the **two-intermediate** form (do NOT regress this):

    t8  = q[8]  << 24;            /* both byte reads + <<24 first ... */
    t10 = q[10] << 24;
    colBase = (t8  + 0xFD000000) >> 24;   /* ... then both adds share 0xfd<<24 */
    rowBase = (t10 + 0xFD000000) >> 24;

That, plus `extern int sub_0801185C(...)` (NOT `u8` — the `int` return removes the
two post-`bl` `lsls/lsrs#24` index truncations), plus pinning the struct pointer
`q asm("r0")`, plus the `hit`-reset-at-loop-bottom shape (init `hit=0` once before
loop3, reset at the bottom of each outer iteration), plus `u8 rowCand[4]` (a [5]
forces `sub sp,#28`; the baserom frame is exactly 24), takes it from diff 99 -> 8.

### Next idea to try (NOT yet attempted)

The straight `register u8 *cc asm("r0")` persistent pin regressed (r0 too hot);

#include "types.h"

extern int sub_0801185C(u8 range);

void sub_08012664(void)
{
    u8 colExcl[5];
    u8 rowExcl[3];
    u8 colCand[8];
    u8 rowCand[4];
    register u8 *q asm("r0");
    u32 t8;
    u32 t10;
    u8 colBase;
    u8 rowBase;
    u8 i;
    u8 j;
    u8 colCount;
    u8 rowCount;
    u8 hit;

    q = (u8 *)&gIwram_35E0;
    t8 = q[8] << 24;
    t10 = q[10] << 24;
    colBase = (t8 + 0xFD000000) >> 24;
    rowBase = (t10 + 0xFD000000) >> 24;

    for (i = 0; i <= 4; i++)
        colExcl[i] = i + colBase;
    for (i = 0; i <= 2; i++)
        rowExcl[i] = i + rowBase;

    hit = 0;
    colCount = 0;
    for (i = 0; i <= 7; i++) {
        for (j = 0; j <= 4; j++) {

                hit = 1;
        }
        if (hit == 0)
            colCand[colCount++] = i;
        hit = 0;

    rowCount = 0;
    for (i = 0; i <= 4; i++) {

            if (i == rowExcl[j])
                hit = 1;
        }
        if (hit == 0)
            rowCand[rowCount++] = i;
        hit = 0;
    }

    /* Y pick deliberately indexes colCand (baserom reuses r8=colCand at 0x12740). */
    gIwram_3720._field_692 = colCand[sub_0801185C(colCount)] + 1;
    gIwram_3720._field_694 = colCand[sub_0801185C(rowCount)] + 2;

    value = (s16)gIwram_3720._field_692;
    if (value <= 0)
        gIwram_3720._field_692 = 1;
    value = (s16)gIwram_3720._field_692;
    if (value > 8)
        gIwram_3720._field_692 = 8;

    value = (s16)gIwram_3720._field_694;
    if (value <= 1)
        gIwram_3720._field_694 = 2;
    value = (s16)gIwram_3720._field_694;
    if (value > 6)
        gIwram_3720._field_694 = 6;
}

## Corpus sweep (2026-06-03)

**Outcome: improved (byte_diff 8 -> 6). No transferable corpus trick found. Reverted to pristine; variant D preserved as permuter seed in nearMatchBase.**

### The exact asm idiom that diverges
The function is argument-less. After two byte reads shifted `<<24`, it builds a shared `0xfd<<24` constant and reuses it across two `adds`, then sets up three stack-array bases (one into r8). At diff-8 (documented baseline) the divergence was a coupled 3-way recolor:
- `0x12676`: baserom `movs r6,#253` (constant -> callee-saved r6) vs built `movs r2,#253` (constant -> caller-saved r2).
- `0x12686`: baserom `add r0,sp,#12` (colCand-base reuses the now-dead struct-pointer reg r0) vs built `add r6,sp,#12`.
- `0x1268a`: baserom `mov r6,sp` (colExcl-base REUSES r6 after the constant died) vs built `mov r0,sp`.
The baserom ties the short-lived constant and the colExcl-base into ONE quantity sharing r6 (use-then-release); agbcc instead ties the constant to the loop counter (both r2) and gives the bases r6/r0.

### Variant D (the improvement, 8 -> 6)
Pinning the two byte-read intermediates `register u32 t8 asm("r1"); register u32 t10 asm("r0");` (keeping the existing `q asm("r0")` pool anchor) made the stack-base coloring match EXACTLY — diffs at 0x20/0x22/0x24/0x26/0x28 (the colCand/colExcl/sp bases) all vanished. New residual at diff-6: (a) the constant still r2 vs r6 (0x12-0x1a, 4 bytes), and (b) a new ldrb scratch artifact at 0x0e/0x10 (`ldrb r6,[r0,#10]; lsls r0,r6` vs in-place `ldrb r0,[r0,#10]; lsls r0,r0`, 2 bytes) introduced because t10=r0 makes agbcc grab r6 as a transient. Diff-6 is STRUCTURALLY CLOSER than diff-8 (more hard-features correct: all three stack-base registers match), so it is the better permuter seed even though it carries the new 2-byte scratch.

### Why the trick did NOT transfer
The corpus proves multi-stack-base functions match in pure C, but in every case the callee-saved register assignment is pinned by incoming-argument lifetimes (an arg arrives in r0-r3 and is moved to a fixed callee-saved reg, anchoring everything downstream). sub_08012664 takes NO arguments, so the constant-vs-stack-base coloring is decided purely by the local allocator's quantity tie-break with no external anchor. No corpus function reproduces "a short-lived shifted constant tied into a callee-saved register that is then RELEASED and reused for a stack base" via a C-source shape.

### agbcc pass implicated (register-coloring)
`tools/agbcc-src/gcc_arm/local-alloc.c`. The constant pseudo is allocated EARLY: `QTY_CMP_PRI` (line ~1489) = `refs*log(refs)/lifetime*10000`, and the constant is short-lived + 3-referenced (high priority). `find_free_reg` (line ~1921) then either honors a `qty_phys_sugg`/`qty_phys_copy_sugg` arithmetic/copy suggestion or takes the lowest free reg (no `REG_ALLOC_ORDER` is defined for ARM, so order is 0..7). The baserom's constant carries a suggestion to r6 because `combine_regs` (line ~1163) tied it to the colExcl-base pseudo (non-overlapping lifetimes); agbcc in our build ties it to the loop counter instead. A `register ... asm("r6")` pin CANNOT model this because it reserves r6 for the constant's whole scope and blocks the use-then-release reuse (every k=r6 pin regressed to 22). This is a coalescing/tie-break decision, not an idiom.

### RECOMMENDED NEXT ANGLE
Seed decomp-permuter from variant D (nearMatchBase, diff-6) — it is 2 bytes closer AND has all three stack-base registers correct, so the search space is now two LOCAL recolorings instead of a coupled cascade. Specifically: (1) the constant r2->r6 tie, and (2) the ldrb r6->r0 scratch at 0x0e. Two concrete permuter-targetable ideas the manual sweep did not exhaust: (a) introduce a dead/dummy use of a callee-saved temp between the constant's death and the `mov rN,sp` so the allocator coalesces them (mirroring the baserom tie) — permuter's "add temp variable" mutation may stumble onto the right placement that hand-pinning cannot; (b) re-express the t10 read so it lands in r0 in-place WITHOUT a scratch (e.g. read t10 into the q register slot via `q = (u8*)((u32)q[10]<<24)` style aliasing) to kill the 0x0e/0x10 diff, then permute only the constant tie. If permuter still cannot reach the constant recolor after seeding from D (the prior 2200-iter run was seeded from the diff-8 base and could not), this function is a genuine local-allocator-tie unmatchable and the honest fallback is NAKED+NON_MATCHING with variant D embedded as the readable #ifdef NON_MATCHING body.
