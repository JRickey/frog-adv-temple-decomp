## Semantics (fully reverse-engineered — logic is SOLVED, unchanged from round 54)

Top-of-screen status-banner show/clear. `kind` selects the message:
- 0 / >4 : blank the line (16 spaces at ROM 0x081be01c)
- 1 : localized "LEVEL CLEARED" (5-string table at 0x081bdff4), index `gIwram_34B0._data`
- 2 : world-specific cleared message via table-of-tables at 0x083087b4,
      indexed by `gIwram_34B0._data` then `(pendingMode/3 - 1)`; guarded by
      `pendingMode%3==0 && pendingMode!=0`, else `pendingMode==16`
- 3 : "YOU WIN" (0x081be008), 4 : "YOU LOSE" (0x081be010)

Setup: ldmia/stmia struct-copy the 5-ptr localized table to a stack array,
call `text_0800e76c()`, save BG palette word 0x050001da into r9 (restored at
cleanup), yArg=10 held in r8. `pendingMode==15` -> early epilogue. Centering:
scan the string counting displayable chars until `|`; a `[` advances the byte
index by 4 (control code) instead of 1; `x=(30-len)/2`. Per-case wait loops
pump `sub_08017000()`/`sub_080004C4()`/`sub_08000900()` frame-counter with
timeouts (120 for cases 1-2, 179 for 3-4); cases 1-2 two-phase gated by
`gIwram_34B4._data[0]`. Shared `done:` runs `sub_08020BAC(); gStructAt3003570
|= 2;` before the cleanup blank-line draw.

## What this round CHANGED vs round 54 (READ THIS — three new structural wins)

The dispatch is a **casesi JUMP TABLE** (`lsls #2; ldr =table; adds; ldr [r0];
mov pc, r0` + an absolute `.word[5]` table at 0x1bba8: case0->cleanup,
1->0x1bbbc, 2->0x1bc90, 3->0x1bdac, 4->0x1bdf8; >4 also -> cleanup). Round 54's
C lowered the switch to a COMPARE CHAIN. **Fix: add an explicit `case 0: goto
cleanup;`** so cases 0-4 are dense and agbcc emits casesi. This alone fixed the
entire dispatch block.

The `(u8)i` index update was emitted with an extra `adds rN,r0,#0` move because
round 54 wrote it as a ternary `i = (u8)((str[i]=='[') ? i+4 : i+1)`. **Fix:
write it as an if/else** (`if (str[i]=='[') i=(u8)(i+4); else i=(u8)(i+1);`) —
now `i` narrows directly into its reg (`lsrs r1,r0,#24`), matching baserom.

The correct prologue is `push {r4,r5,r6,r7,lr}` (FOUR low callee-saved) + r8/r9.
Round 54 only ever got 3. **A 4th callee-saved (r7) IS reachable** by giving
case 2 a SECOND live pointer: declare `base = &gIwram_34B0` AND
`tables = WORLD_CLEARED_TABLES` as locals (so both stay live across the case-2
scan). That register pressure makes agbcc save r7 (verified `b5f0` prologue +
`mov r7,r9; mov r6,r8; push {r6,r7}`).

Combined floor this round: **byte_diff 615 / diff_count 222** (best-effort C
below — clean 3-save form). The 4-save variants land 642-643 (see wall).

## Drift — the REMAINING wall (two coupled register-coloring/scheduling items)

With the jump-table + if/else + str(r4)/len(r6)/pendingMode(r5) pins, the
prologue/setup, struct-copy `ldmia {r2,r3,r5}`, yArg `movs r5,#10; mov r8,r5`,
dispatch, and case 1 scan ALL match byte-for-byte up to offset 0x68. The two
remaining roots (everything else is branch-offset cascade):

1. **case-1 `base` (&gIwram_34B0) wants callee-saved r7 but agbcc picks
   scratch.** baserom: `ldr r0,[pc]` (base into scratch r0), index str via
   r0/r1, then `adds r7,r0,#0` (COPY r0->r7 to survive the scan), reread
   `ldr r0,[r7,#0]`. agbcc in case 1 has r2/r3/r5 all FREE during base's
   lifetime (the case-1 scan only needs r0,r1,r4,r6; pendingMode=r5 is dead in
   case 1), so the late-priority `base` pseudo (only 2 refs, long live range ->
   low `floor_log2(refs)*refs/live_length` priority in global.c `qty_compare`)
   takes the lowest free reg (r2 normally, or r5 once pendingMode-pinned).
   - Pinning `base asm("r7")` makes r7 a RELOADED TEMP that is NOT added to the
     thumb save mask (prologue stays 3 saves) AND forces `ldr r7,[pc]` instead
     of the load-into-r0-then-copy shape. CONFIRMED dead end (round 54 + this
     round). The `register asm("rN")` hint is honored as a constraint, not as a
     promotion, for a plain local in agbcc 2.x.
   - The base+tables pressure trick saves r7 but case-1 base then lands in r5
     (free), not r7. A SEPARATE `base1 asm("r7")` for case 1 lands it in r7 but
     with the wrong `ldr r7,[pc]` load shape (no `adds r7,r0,#0` copy).
   - Root: baserom unifies `base` as ONE global pseudo promoted to r7 across
     both cases; agbcc SPLITS the live range per-case and colors case 1's
     independently. No source shape reached makes r2/r3/r5 busy during case-1
     base's lifetime, which is what would force r7.

2. **`len` lazy (u8)-narrow.** baserom narrows len every iteration
   (`adds r0,r6,#1; lsls; lsrs r6`) so the exit uses `subs r0,r0,r6` directly.
   agbcc does in-place `adds r6,#1` (it proves len stays < 256) and re-narrows
   at the exit use (`lsls r1,r6,#24; lsrs r1`). Every `len = (u8)(len+1)` /
   `len += 1; len = (u8)len` form collapses to the in-place add. This is a
   scheduling/range-tracking decision, ~2-4 insns.
