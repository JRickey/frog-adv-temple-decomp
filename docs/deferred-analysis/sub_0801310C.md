### Confirmed-good levers THIS round (keep these in any next attempt)
1. **DROP the `bit asm("r6")` pin** — this was the round-14 mistake. Letting agbcc
   choose bit's register made the accum RMW emit the target's `adds r0,r6,#0`
   (bit-copied-into-orr-dest) shape and dropped 99 -> 92. bit still naturally
   lands in r6; pinning it FORCED the wrong (no-copy) accum shape.
2. **Entity-write base-first 2-word idiom** (defeats the `gEntities+0x1a5b` fold
   that collapses to one 0x0300517b literal, -8 bytes):
   ```c
   { u32 entOffset = 0x1a5b; u8 *entSlot = (u8 *)gEntities;
     asm volatile("" : "+r"(entOffset)); *(entSlot + entOffset) = 0; }
   ```
   Order matters: declare entOffset FIRST, entSlot SECOND, fence the offset,
   then `*(entSlot + entOffset)` -> `adds r0,r0,r1` base-first + base-pool-first.
3. Pins that ARE load-bearing (removing each -> worse): `base asm("r5")`,
   `accum asm("sl")`, `offset asm("r5")`. `i asm("r8")`/`ctrlRef asm("r9")` are
   neutral *with bit pinned* but REQUIRED once bit is unpinned (unpinning all
   three together -> 218). Keep i/ctrlRef pinned.
4. Two-locals on/off (`s32 s5v = ...sel5; s32 s6v = ...sel6;` read BOTH up front)
   is REQUIRED — it forces two r9->low ctrl copies. Any interleaved/inline form
   (`((s32)ctrlRef->selN>>i)&1` sequential, or pointer-reload) CSE-merges the two
   copies into ONE (worse, 105-108).

### THE RESIDUAL — pervasive coloring at higher pressure (3 clusters, ~81 real diffs)
All structure/calls/CSE/asrs/pool-order MATCH. The target consistently colours
scratch with NON-preferred regs (r6/r4/r2-reuse) where agbcc-from-clean-C picks
preferred ones (r0/r1/r4) and CACHES pointer copies the target RE-DERIVES:
1. **Function-top compare** `(s5&0xff)==(s6&0xff)`: target threads r6 (so r2=sv
   AND r4 were BOTH occupied); built uses r4 (only r2=sv occupied -> r4 free).

   below) instead of rematerialising like the target.
2. **Loop-top ctrl copies**: target `mov r2,r9;ldrh;mov r2,r8(i);...mov r4,r9;ldrh`
   (first ctrl-copy r2 reused for i, second re-derived r4); built hoists both to

3. **accum setup** `accum=base+0xd3`: target `adds r0,r5,#0;adds r0,#211;...;mov

   r5 in place because base is dead). agbcc won't build the high-reg value via a

(base+0xdc = 0x030036ec, the loop's `*0x36ec` write) and `accum` (base+0xd3).
