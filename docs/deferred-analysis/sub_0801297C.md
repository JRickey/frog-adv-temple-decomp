3x3 (WxH) tile-block blit from a ROM descriptor's source-row pointer into an
EWRAM staging buffer, followed by a DMA-ish dispatch to `sub_080100E4`.
Function is **fully understood** — the C below reproduces the target
**instruction-for-instruction modulo a consistent register-coloring
permutation**. The only unsolved drift is agbcc's choice of callee-saved high
registers (r8/r9) for two values; everything else matches.

## What it does

- `srcX = (u16)(gIwram_3720._field_692 * 3)`, `srcY = (u16)(gIwram_3720._field_694 * 3)`
  (both s16 sub-coords read from gIwram_3720, x3 -> tile units).
- Reads a 0x18-byte blit descriptor at `sBlitDesc_6e64` (the SECOND record of a
  pair inside the sSpriteAnimBlock blob; base 0x08306e64): `width`@0x1C,
  `height`@0x1E, `flags`@0x20, `srcRec`@0x28 (a row-pointer record; `srcRec[2]`
  i.e. `[srcRec+8]` is the u16 tile stream).
- `bank = flags >> 4`; destBase = `(bank & 1) ? 0x02010000 : 0x02000000` (EWRAM).
- `dst = (u16*)(destBase + (srcY*pitch + srcX)*2)` where `pitch = gIwram_60A0._pitch`
  (u16 @ 0x030060A0+0x1A).
- Nested loop: for each of `height` rows, copy `width` halfwords from `src` to
  `dst`, then `dst += pitch - width`. `y` counter is `(u8)(y+1)` each iteration.
- Tail: `sub_080100E4(bank&1, 0x02010000|0x02000000, 0x0600E800|0x0600E000)`
  then `gIwram_64C0._field_0A = 0`.

## Drift

- **Best: byte_diff 199, diff_count 79** (Thumb). Build is structurally
  complete — same instructions, same control flow, same pool literals.
- The residual is a **register permutation**. Target allocation:
  - B = `(u16)(srcX*3)` -> **r8** (callee-saved high)
  - A = `(u16)(srcY*3)` -> **ip**
  - `height` -> **r9** (callee-saved high)
  - `width` -> r5, `srcRec` -> r6 (reused as `mode=flags>>4` after `src` load), `flags>>4` -> r3
  - `gIwram_60A0` base held in **ip** across the loop (set ONCE via `mov ip,r4`,
    back-edge jumps PAST the reload).
  Built allocation (descriptor-reads-first ordering): everything lands in
  caller-saved low regs + ip; **no r8/r9**, so the target's
  `mov r7,r9; mov r6,r8; push {r6,r7}` prologue + matching epilogue are absent.
- Because B/A/height never cross a `bl`, agbcc prefers caller-saved low regs;
  the baserom chose callee-saved r8/r9 anyway. This is a pure local/global
  register-allocation decision (`local-alloc.c`/`global.c` preference order),
  not a structural one.

## Best-effort C (byte_diff 199 / diff_count 79, structurally complete)

Requires (already staged in this attempt, reverted on defer):
- `linker.ld`: `sBlitDesc_6e64 = 0x08306e64;` + IWRAM dot-pins

```c
#include "iwram.h"
#include "types.h"

/* Two 0x18-byte tile-blit descriptors at sBlitDesc_6e64; this function reads
 * the second record (offsets 0x18..0x2f). */
struct BlitDesc {
    u8 _pad00[28];
    u8 width;     /* +0x1C */
    u8 _pad1D;
    u8 height;    /* +0x1E */
    u8 _pad1F;
    u8 flags;     /* +0x20: bit 4 selects the EWRAM staging bank */
    u8 _pad21[7];
    const u16 *const *srcRec; /* +0x28: srcRec[2] is the tile stream */
};

extern const struct BlitDesc sBlitDesc_6e64;
extern void sub_080100E4(u8 bank, u16 *src, u16 *dst);

void sub_0801297C(void)
{
    u16 srcX;
    u16 srcY;
    u8 width;
    u8 height;
    const u16 *const *srcRec;
    u8 bank;
    u32 destBase;
    u16 *dst;
    const u16 *src;
    u8 x;
    u8 y;

    width = sBlitDesc_6e64.width;
    height = sBlitDesc_6e64.height;
    srcRec = sBlitDesc_6e64.srcRec;
    bank = sBlitDesc_6e64.flags >> 4;
    srcX = (u16)(gIwram_3720._field_692 * 3);
    srcY = (u16)(gIwram_3720._field_694 * 3);

    destBase = 0x02000000;
    if (bank & 1)
        destBase = 0x02010000;

    dst = (u16 *)(destBase + (srcY * gIwram_60A0._pitch + srcX) * 2);
    src = srcRec[2];

    y = 0;
    while (y < height) {
        for (x = 0; x < width; x++) {
            *dst++ = *src++;
        }
        dst += gIwram_60A0._pitch - width;
        y = (u8)(y + 1);
    }

    if (bank & 1)
        sub_080100E4(bank & 1, (u16 *)0x02010000, (u16 *)0x0600E800);
    else
        sub_080100E4(bank & 1, (u16 *)0x02000000, (u16 *)0x0600E000);

    gIwram_64C0._field_0A = 0;
}
```

## Opus attempt (round 24) — entry block now byte-identical; residual is pure global-allocator coloring

Re-derived from scratch (did NOT extend the prior 79-diff base). Reached
**diff_count 30** (vs the prior 79), with the **entire entry computation byte-
identical to the target** through the srcX/srcY/prologue. The loop body and the
flush tail also match structurally. The *only* residual is the global register
allocator's coloring of {srcX, srcY, height, srcRec, bank} into
{r8, r9, ip, r6, r3} — and which register holds the `state` base across the loop
(target reuses `ip`; agbcc keeps it in a separate low reg).

### What FINALLY cracked the entry (use these — they are pure C, no pins)

1. **Pool separation for srcX/srcY** — the prior base used `(u8*)0x03003720 + 0x692`,
   which agbcc constant-folds into a single pool word `0x03003db2`. The target loads
   the *base* `0x03003720` and the *offset* `0x692`/`0x694` as SEPARATE pool words and
   adds them at runtime (`adds r0,r1,r2; ldrsh r0,[r0,r7]`). Fix: extend
   `struct IwramAt3720` with `s16 _field_692;`/`s16 _field_694;` (pad 0x6e..0x691) and
   read `gIwram_3720._field_692` — agbcc keeps base+offset separate because 0x692 is
   out of the ldrsh immediate range. This alone removed many byte diffs.

2. **flagsPtr anchor → srcX lands in r8 WITH the u16 truncation intact, AND r8+r9
   both get pushed.** Add `const u8 *flagsPtr = &desc->flags;` right after `desc =`,
   and read `bank = *flagsPtr >> 4;`. agbcc then hoists `r4 = desc + 0x20` to the very
   top (exactly like the target's `adds r4,r3,#0; adds r4,#32`), which raises register
   pressure across the descriptor reads enough that srcX is promoted to r8 (callee-
   saved) — and crucially WITHOUT a `register asm("r8")` pin, so the `(u16)` cast
   `lsl#16/lsr#16` survives (a pin drops it; see prior section). This is the key new
   lever the prior attempt missed.

3. **Deferred srcX truncation = compute the *product* into an `s32` temp first.**
   Write `s32 px = field_692 * 3; srcY = (u16)(field_694 * 3); srcX = (u16)px;`
   (srcX product computed FIRST, but its `(u16)` cast emitted AFTER srcY is fully
   computed). This reproduces the target's split `lsls r2,#16 … <srcY> … lsrs r2,#16;
   mov r8,r2` byte-for-byte. With this + (1) + (2), the entry through the
   `ldrb r5,[r3,#28]` (width) is byte-identical, srcY lands in `ip`, prologue pushes
   r8+r9.

### Drift that remains (the genuine register-coloring wall)

After the entry matches, the allocator permutes the rest:
- **srcX → r2 (built) vs r8 (target)** in the deferred-product variant, OR
  **bank → r8 (built) vs r3 (target)** — they fight over r8.
- **height → r6 (built) vs r9 (target)**; **srcRec → r1/r2 (caller-saved) vs r6 (target)**.
- **state base across the loop**: target reuses `ip` (`mov ip,r4` once in the loop
  preheader, back-edge jumps past it, reloads pitch via `mov r3,ip; ldrh [r3,#26]`);
  agbcc keeps state in a low reg (r7) and reloads `[r7,#26]` directly.

Root cause (read `tools/agbcc-src/gcc_arm/global.c::allocno_compare`): hard regs are
handed out in priority order `log2(refs)*refs/live_length * size`. The target gives
srcX (short live range, high priority) r8 and preserves `bank` (long range crossing
the loop) low-then-r6 by SPLITTING it (`adds r6,r3,#0` reuses srcRec's dead r6).
agbcc instead keeps `bank` as ONE allocno in a high reg and never splits it, so the
coloring permutes. None of caller/callee-save tie-break levers reach this.

### Levers tried THIS round that did NOT close it (try something ELSE next)

- `register asm("r8"/"r9"/"ip"/"r6")` pins (any subset): each pin DROPS the srcX/srcY
  `(u16)` store-time truncation (pin is word-mode) and/or over-spills (`push {sl}`,
  `sub sp,#4`). Confirms prior finding — do NOT pin the u16 coords.
- Splitting `bank` into `bank` + `u32 flushBank = bank;` (to mimic the r3/r6 split):
  reshuffles worse (srcRec→ip, flushBank→r8). 212.
- Hoisting `u32 isBank1 = bank & 1;` as a single survivor: changes semantics (target
  computes `bank&1` TWICE from the preserved full bank). 213.
- Per-TU `CFLAGS`: `-ffixed-r1/-r2/-r7`, `-fno-strength-reduce`, `-fno-gcse`,
  `-fcaller-saves`, `-fno-cse-follow-jumps`, `-fno-rerun-cse-after-loop` — all no-op
  (still 216). agbcc rejects `-fschedule-insns(2)` (no scheduler in this build, so the
  truncation deferral is NOT a scheduling artifact — it's RTL-gen + reload).
- `OLD_AGBCC_BIN`: identical (prior finding holds).
- Anchoring `state`/`srcRec` early: shuffles which value gets the high reg, never the
  exact target permutation.
- **Permuter** (45s, -j4, --stop-on-zero): base score 4580, best 3600, NOT trending to

## Corpus sweep (2026-06-03)

### The exact asm idiom that diverges
The baserom computes two in-function scalar coordinates and parks them in **callee-saved high registers without either crossing a function call**:
- `srcX = (u16)(field_692 * 3)` → after `ldrsh; lsls#1; adds; lsls#16; lsrs#16` the value is moved to **r8** (`0c12 lsrs r2,r2,#16; 4690 mov r8,r2`). srcX is then used exactly ONCE (`4440 add r0,r8` at the dst computation) — a 2-ref, short-live-range value in a callee-saved reg.
- `srcY = (u16)(field_694 * 3)` → **ip**.
- `height` (descriptor +0x1E) → **r9**, used as the outer-loop bound at two `cmp r0,r9` sites (`129e0`, `12a0e`).
- `width`→r5, `srcRec`→r6 (then reused for `bank` via `1c1e adds r6,r3,#0`), `bank=flags>>4`→r3.

The whole blit (nested halfword copy loop) contains **no internal `bl`**, so none of srcX/srcY/height cross a call. The promotion to r8/r9 is pure register pressure: ~9 simultaneously-live values across the loop exceed the 8 low regs, and the baserom's allocator spilled srcX→r8 and height→r9. agbcc, given the same C, spills a DIFFERENT pair.

### Why the trick did NOT transfer
In EVERY corpus instance where an in-function scalar lands in a callee-saved high register, it is because **the value is live across a `bl`** (agbcc is forced to pick a callee-saved reg) OR it is **multiply-referenced across the whole function** (high allocno priority crowds it out of low regs that are taken by even-higher-priority allocnos). My target's srcX has neither property: it is used once and crosses no call. There is no C idiom that makes agbcc voluntarily place a once-used, call-free value in r8 — `find_reg` iterates registers in **ascending regno order** (no `REG_ALLOC_ORDER` defined for agbcc ARM, confirmed at gcc_arm/global.c:1389), so a call-free value always prefers the lowest free low reg. The baserom's r8 choice is a pressure-spill artifact of the original compiler's *allocation order*, not reproducible from C structure.
