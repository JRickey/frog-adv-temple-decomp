# sub_0801297C — deferred analysis

3x3 (WxH) tile-block blit from a ROM descriptor's source-row pointer into an
EWRAM staging buffer, followed by a DMA-ish dispatch to `sub_080100E4`.
Function is **fully understood** — the C below reproduces the target
**instruction-for-instruction modulo a consistent register-coloring
permutation**. The only unsolved drift is agbcc's choice of callee-saved high
registers (r8/r9) for two values; everything else matches.

## What it does

- `srcX = (u16)(gIwram_3720._field_692 * 3)`, `srcY = (u16)(gIwram_3720._field_694 * 3)`
  (both s16 sub-coords read from gIwram_3720, x3 -> tile units).
- Reads a 0x18-byte blit descriptor at `sBlitDesc_6e64` (the SECOND record of a
  pair inside the sSpriteAnimBlock blob; base 0x08306e64): `width`@0x1C,
  `height`@0x1E, `flags`@0x20, `srcRec`@0x28 (a row-pointer record; `srcRec[2]`
  i.e. `[srcRec+8]` is the u16 tile stream).
- `bank = flags >> 4`; destBase = `(bank & 1) ? 0x02010000 : 0x02000000` (EWRAM).
- `dst = (u16*)(destBase + (srcY*pitch + srcX)*2)` where `pitch = gIwram_60A0._pitch`
  (u16 @ 0x030060A0+0x1A).
- Nested loop: for each of `height` rows, copy `width` halfwords from `src` to
  `dst`, then `dst += pitch - width`. `y` counter is `(u8)(y+1)` each iteration.
- Tail: `sub_080100E4(bank&1, 0x02010000|0x02000000, 0x0600E800|0x0600E000)`
  then `gIwram_64C0._field_0A = 0`.

## Drift

- **Best: byte_diff 199, diff_count 79** (Thumb). Build is structurally
  complete — same instructions, same control flow, same pool literals.
- The residual is a **register permutation**. Target allocation:
  - B = `(u16)(srcX*3)` -> **r8** (callee-saved high)
  - A = `(u16)(srcY*3)` -> **ip**
  - `height` -> **r9** (callee-saved high)
  - `width` -> r5, `srcRec` -> r6 (reused as `mode=flags>>4` after `src` load), `flags>>4` -> r3
  - `gIwram_60A0` base held in **ip** across the loop (set ONCE via `mov ip,r4`,
    back-edge jumps PAST the reload).
  Built allocation (descriptor-reads-first ordering): everything lands in
  caller-saved low regs + ip; **no r8/r9**, so the target's
  `mov r7,r9; mov r6,r8; push {r6,r7}` prologue + matching epilogue are absent.
- Because B/A/height never cross a `bl`, agbcc prefers caller-saved low regs;
  the baserom chose callee-saved r8/r9 anyway. This is a pure local/global
  register-allocation decision (`local-alloc.c`/`global.c` preference order),
  not a structural one.

## Levers already tried (pick a DIFFERENT one next)

- **`register u16 srcX asm("r8")` + `register u8 height asm("r9")` pins**:
  gets the EXACT prologue (`push {r6,r7}`, size 240) BUT a hard-reg pin is
  word-mode, so the `(u16)` narrowing of `srcX*3` is dropped at the store
  (`mov r8,r0` with no `lsls#16;lsrs#16`); the value is then re-truncated at
  every use -> diff worsens to 112-163. Hard-reg pins CANNOT carry the
  store-time u16 truncation the target has. **Do not re-pin srcX.**
- **Statement ordering**: descriptor-reads-BEFORE-srcX/srcY gives the best 79
  (width lands in r5 like target); srcX/srcY-first gives 92-125. 
- **Local pointer anchors** (`const struct BlitDesc *desc`, `struct IwramAt60A0 *vp`):
  all made it WORSE (96-127). The vp-held-across-loop idea (to force a single
  `mov ip` like target) backfires every way it was placed.
- **OLD_AGBCC** (`CC = $(OLD_AGBCC_BIN)`): identical 79.
- **`-ffixed-r7`**: forces r8/r9 usage in a standalone compile, but through the
  Makefile preproc pipeline it did not converge (other regs shifted); still 79.
- **Permuter**: scratch imported & ran ~60 iters; base score 6885, stuck ~6500
  (no progress toward 0). The high base score suggests the residual is not a
  statement-reorder/scope mutation the permuter explores — it's the allocator's
  caller-vs-callee-saved preference. Likely need a `default_weights.toml` tweak
  or a structure that raises live-register pressure across the descriptor reads.

## Next ideas (untried)

- Raise simultaneous live-register pressure across the descriptor reads so the
  allocator is FORCED onto r8/r9 with the natural u16 truncation intact (a pin
  drops the truncation; pressure would not). E.g. introduce a genuinely-live
  extra value spanning srcX..dst, or compute srcX/srcY interleaved with the
  descriptor reads so both B and A are live across more instructions.
- Try `-fno-schedule-insns` / `-fno-schedule-insns2` / `-fcaller-saves` toggles
  per-TU; read `tools/agbcc-src/gcc_arm/{local-alloc,global,regclass}.c` for the
  caller-vs-callee-saved tie-break (`SREG`/`CALLER_SAVE`) and craft C that flips it.
- Fix the permuter scratch: the `.inst.n` target.s has a baked BL offset to
  sub_080100E4 that may mis-normalize; rebuild target.s so the BL is a proper
  relocation, then re-run with more iters.

## Best-effort C (byte_diff 199 / diff_count 79, structurally complete)

Requires (already staged in this attempt, reverted on defer):
- `linker.ld`: `sBlitDesc_6e64 = 0x08306e64;` + IWRAM dot-pins
  `gIwram_60A0 = 0x030060A0` (before 6110) and `gIwram_64C0 = 0x030064C0` (after 6150).
- `include/iwram.h`: `IwramAt3720` extended with `s16 _field_692; s16 _field_694;`
  (pad 0x6e..0x691); new `IwramAt60A0` (`u16 _pitch` @0x1A) and `IwramAt64C0`
  (`u8 _field_0A` @0x0A) + their externs.

```c
#include "iwram.h"
#include "types.h"

/* Two 0x18-byte tile-blit descriptors at sBlitDesc_6e64; this function reads
 * the second record (offsets 0x18..0x2f). */
struct BlitDesc {
    u8 _pad00[28];
    u8 width;     /* +0x1C */
    u8 _pad1D;
    u8 height;    /* +0x1E */
    u8 _pad1F;
    u8 flags;     /* +0x20: bit 4 selects the EWRAM staging bank */
    u8 _pad21[7];
    const u16 *const *srcRec; /* +0x28: srcRec[2] is the tile stream */
};

extern const struct BlitDesc sBlitDesc_6e64;
extern void sub_080100E4(u8 bank, u16 *src, u16 *dst);

void sub_0801297C(void)
{
    u16 srcX;
    u16 srcY;
    u8 width;
    u8 height;
    const u16 *const *srcRec;
    u8 bank;
    u32 destBase;
    u16 *dst;
    const u16 *src;
    u8 x;
    u8 y;

    width = sBlitDesc_6e64.width;
    height = sBlitDesc_6e64.height;
    srcRec = sBlitDesc_6e64.srcRec;
    bank = sBlitDesc_6e64.flags >> 4;
    srcX = (u16)(gIwram_3720._field_692 * 3);
    srcY = (u16)(gIwram_3720._field_694 * 3);

    destBase = 0x02000000;
    if (bank & 1)
        destBase = 0x02010000;

    dst = (u16 *)(destBase + (srcY * gIwram_60A0._pitch + srcX) * 2);
    src = srcRec[2];

    y = 0;
    while (y < height) {
        for (x = 0; x < width; x++) {
            *dst++ = *src++;
        }
        dst += gIwram_60A0._pitch - width;
        y = (u8)(y + 1);
    }

    if (bank & 1)
        sub_080100E4(bank & 1, (u16 *)0x02010000, (u16 *)0x0600E800);
    else
        sub_080100E4(bank & 1, (u16 *)0x02000000, (u16 *)0x0600E000);

    gIwram_64C0._field_0A = 0;
}
```

## Opus attempt (round 24) — entry block now byte-identical; residual is pure global-allocator coloring

Re-derived from scratch (did NOT extend the prior 79-diff base). Reached
**diff_count 30** (vs the prior 79), with the **entire entry computation byte-
identical to the target** through the srcX/srcY/prologue. The loop body and the
flush tail also match structurally. The *only* residual is the global register
allocator's coloring of {srcX, srcY, height, srcRec, bank} into
{r8, r9, ip, r6, r3} — and which register holds the `state` base across the loop
(target reuses `ip`; agbcc keeps it in a separate low reg).

### What FINALLY cracked the entry (use these — they are pure C, no pins)

1. **Pool separation for srcX/srcY** — the prior base used `(u8*)0x03003720 + 0x692`,
   which agbcc constant-folds into a single pool word `0x03003db2`. The target loads
   the *base* `0x03003720` and the *offset* `0x692`/`0x694` as SEPARATE pool words and
   adds them at runtime (`adds r0,r1,r2; ldrsh r0,[r0,r7]`). Fix: extend
   `struct IwramAt3720` with `s16 _field_692;`/`s16 _field_694;` (pad 0x6e..0x691) and
   read `gIwram_3720._field_692` — agbcc keeps base+offset separate because 0x692 is
   out of the ldrsh immediate range. This alone removed many byte diffs.

2. **flagsPtr anchor → srcX lands in r8 WITH the u16 truncation intact, AND r8+r9
   both get pushed.** Add `const u8 *flagsPtr = &desc->flags;` right after `desc =`,
   and read `bank = *flagsPtr >> 4;`. agbcc then hoists `r4 = desc + 0x20` to the very
   top (exactly like the target's `adds r4,r3,#0; adds r4,#32`), which raises register
   pressure across the descriptor reads enough that srcX is promoted to r8 (callee-
   saved) — and crucially WITHOUT a `register asm("r8")` pin, so the `(u16)` cast
   `lsl#16/lsr#16` survives (a pin drops it; see prior section). This is the key new
   lever the prior attempt missed.

3. **Deferred srcX truncation = compute the *product* into an `s32` temp first.**
   Write `s32 px = field_692 * 3; srcY = (u16)(field_694 * 3); srcX = (u16)px;`
   (srcX product computed FIRST, but its `(u16)` cast emitted AFTER srcY is fully
   computed). This reproduces the target's split `lsls r2,#16 … <srcY> … lsrs r2,#16;
   mov r8,r2` byte-for-byte. With this + (1) + (2), the entry through the
   `ldrb r5,[r3,#28]` (width) is byte-identical, srcY lands in `ip`, prologue pushes
   r8+r9.

### Drift that remains (the genuine register-coloring wall)

After the entry matches, the allocator permutes the rest:
- **srcX → r2 (built) vs r8 (target)** in the deferred-product variant, OR
  **bank → r8 (built) vs r3 (target)** — they fight over r8.
- **height → r6 (built) vs r9 (target)**; **srcRec → r1/r2 (caller-saved) vs r6 (target)**.
- **state base across the loop**: target reuses `ip` (`mov ip,r4` once in the loop
  preheader, back-edge jumps past it, reloads pitch via `mov r3,ip; ldrh [r3,#26]`);
  agbcc keeps state in a low reg (r7) and reloads `[r7,#26]` directly.

Root cause (read `tools/agbcc-src/gcc_arm/global.c::allocno_compare`): hard regs are
handed out in priority order `log2(refs)*refs/live_length * size`. The target gives
srcX (short live range, high priority) r8 and preserves `bank` (long range crossing
the loop) low-then-r6 by SPLITTING it (`adds r6,r3,#0` reuses srcRec's dead r6).
agbcc instead keeps `bank` as ONE allocno in a high reg and never splits it, so the
coloring permutes. None of caller/callee-save tie-break levers reach this.

### Levers tried THIS round that did NOT close it (try something ELSE next)

- `register asm("r8"/"r9"/"ip"/"r6")` pins (any subset): each pin DROPS the srcX/srcY
  `(u16)` store-time truncation (pin is word-mode) and/or over-spills (`push {sl}`,
  `sub sp,#4`). Confirms prior finding — do NOT pin the u16 coords.
- Splitting `bank` into `bank` + `u32 flushBank = bank;` (to mimic the r3/r6 split):
  reshuffles worse (srcRec→ip, flushBank→r8). 212.
- Hoisting `u32 isBank1 = bank & 1;` as a single survivor: changes semantics (target
  computes `bank&1` TWICE from the preserved full bank). 213.
- Per-TU `CFLAGS`: `-ffixed-r1/-r2/-r7`, `-fno-strength-reduce`, `-fno-gcse`,
  `-fcaller-saves`, `-fno-cse-follow-jumps`, `-fno-rerun-cse-after-loop` — all no-op
  (still 216). agbcc rejects `-fschedule-insns(2)` (no scheduler in this build, so the
  truncation deferral is NOT a scheduling artifact — it's RTL-gen + reload).
- `OLD_AGBCC_BIN`: identical (prior finding holds).
- Anchoring `state`/`srcRec` early: shuffles which value gets the high reg, never the
  exact target permutation.
- **Permuter** (45s, -j4, --stop-on-zero): base score 4580, best 3600, NOT trending to
  0 — the residual is global-allocator coloring, which the permuter's statement/scope
  mutations cannot reach (matches prior 6885→6500 observation). Note: the permuter
  scratch's score is inflated by the cross-region `bl 0x100e4` + pool normalization, so
  it's not a reliable oracle here even setting aside the coloring wall.

### Next ideas (genuinely untried)

- Force `bank` to SPLIT into two allocnos (low r3 + reuse-r6) the way the target does.
  The target's `adds r6,r3,#0` is a copy that the prior+this attempt could not induce
  from C. Maybe an explicit `register u32 bankLoop asm("r6") = bank;` placed AFTER
  `src = srcRec[2];` (so r6 is free) — but srcRec must NOT be pinned to r6 (it must die
  there naturally first). The sibling `sub_08012BC4` uses exactly this `register u32
  loopState asm("ip")` block-scoped-after-the-kill trick for its loop-invariant; mirror
  that pattern for `bank`→r6 here.
- Mirror `sub_08012BC4` (the proven-matching SAME blit+flush in the same file) even
  more closely: it block-scopes the loop-invariant `register … asm("ip") = (u32)state;`
  INSIDE the `if (row < rows)` guard, and recomputes the flush bank inside nested
  `{ register u32 one asm("r1"); … }` blocks. Porting that exact block structure
  (rather than a flat while-loop) may align the coloring.

void sub_0801297C(void)
{

    const u8 *flagsPtr;
    s32 px;
    u16 srcX;
    u16 srcY;

    u8 height;
    const u16 *const *srcRec;
    u32 bank;
    u16 *dst;
    const u16 *src;

    u8 y;

    desc = (const struct BlitDesc *)0x08306e64;

### UPDATE — sibling-structure port (best byte_diff this round = 188)

Ported `sub_08012BC4`'s EXACT do-while block structure (the proven-matching SAME
blit+flush in this file) — keeping the flagsPtr-anchor + deferred-product entry, but
replacing the flat `while/for` loop with the sibling's
`if (y < height) { register u32 loopState asm("ip") = (u32)state; do { … inner do-while
… } while (y < height); }`. This reproduces the target's **loop-invariant-in-ip**
pattern (`mov ip,r1` in the preheader, back-edge reloads pitch via `mov rX,ip;
ldrh [rX,#26]`) — a piece the flat-loop version got wrong. byte_diff dropped to **188**,
diff_count still 30, entry still byte-identical through 0x2e.

Residual is UNCHANGED and is the wall: `bank` still grabs r8 (target: r3, split to r6),
`srcX` stays in r2 (target: moved to r8), `height` → r6 (target: r9). Pinning srcX/srcY
to r8/ip drops their `(u16)` truncation (the sibling's pins survive only because ITS
coords arrive as u32 *parameters*; ours are `s16*3` computed in-function). So the
sibling pattern matched the loop but not the entry coloring.

The single unbroken nut: induce agbcc to (a) keep `bank` in a low reg early and SPLIT a
loop-surviving copy into r6 (reusing srcRec's dead reg, as the target's `adds r6,r3,#0`
does), freeing r8 for srcX, and (b) promote `height` to r9. Neither pins (drop trunc)
nor statement-order nor per-TU flags nor the permuter reached it. This is a genuine
global-allocator (`global.c` priority/Chaitin-coloring) divergence — the same class the
prior attempt named. Recommend a future pass try the explicit
`register u32 bankLoop asm("r6") = bank;` placed AFTER `src = srcRec[2];` (so srcRec has
died and freed r6) to mimic the split, WITHOUT pinning srcRec.

### UPDATE 2 — bankLoop=r6 split DOES free r8 for srcX (but breaks srcRec/height)

Tried the recommended `register u32 bankLoop asm("r6") = bank;` block placed after
`src = srcRec[2];` (sibling-loop base). Result: `bank` lands DIRECTLY in r6 and `srcX`
gets r8 — the two values that were fighting are now both correct. BUT the r6 pin pushes
`srcRec` to `ip` and `height` to r7, a NEW wrong permutation. byte_diff 218, diff_count
still 30.

CONCLUSION after 8+ distinct structures (flat while/for, srcX-first, descriptor-first,
full/partial pins, flagsPtr+deferred-product, sibling do-while+loopState=ip, bank-split,
isBank1 hoist) + ~8 per-TU `-fXXX` flags + a 45s permuter run: EVERY variant converges
to **diff_count 30** but a DIFFERENT register permutation of {srcX, srcY, height,
srcRec, bank} over {r8, r9, ip, r6, r3} — the exact target permutation
(srcX=r8, srcY=ip, height=r9, srcRec=r6, bank=r3-then-r6) is never reached together.
Each lever fixes 1-2 of the five and breaks 1-2 others; pins additionally drop the u16
truncation on the coords. This is a genuine global-allocator (Chaitin coloring,
`global.c`) divergence, NOT a structural/idiom gap — confirmed by the permuter being
unable to trend toward 0 (statement mutations can't repaint the interference graph).

The entry block (through the width read) IS byte-identical, so the C *structure* is
correct. A future pass needs either (a) a coloring lever not yet found that lands all
five simultaneously, or (b) this is the rare game-logic register-coloring NAKED. Given
the corpus says game logic is ~100% matchable, (a) is more likely — recommend codex/
deeper allocator analysis rather than NAKED.
