# Deferred: sub_0801D33C (0x0801D33C, 252 bytes)

DMA3 streamer. Tail call of sub_0801D4CC(u8 arg). Pushes the per-arg frog
tile/palette blocks to OBJ-VRAM / OBJ palette RAM via REG_DMA3 (0x040000D4):
11 transfers, each `str src; str dst; str cnt; (void)cnt` (read-back flush).
Two fixed ROM tilemap blocks (0x081BE054 → r3=srcA, 0x081BE074 → r5=srcB) are
pushed in 8-byte chunks (+8/+16/+24 runtime adds off an anchored base), and two
ROM source-pointer tables (0x083087C8, 0x083087E8) are indexed by `arg + 1`.
Sibling sub_0801D268 (same file, MATCHED) is the closest template.

## Drift

- **Best: byte_diff 7, diff_count 3.** A single residual divergence at +0x4e..+0x56:
  - target:  `ldr r2,[pc] (0x083087C8); lsrs r0,#22; adds r0,#4; adds r2, r0, r2`
  - built:   `lsrs r0,#22; adds r0,#4; ldr r3,[pc] (0x083087C8); adds r2, r0, r3`
  The ONLY difference is which dead register holds the tableA base: target reuses
  **r2** (the just-freed cnt-readback reg, coalesced into the address→value chain
  `r2=idx+base; r2=*r2; str r2`), built uses **r3** (the just-freed srcA reg).
  Everything else — prologue, srcA/srcB regs (r3/r5), idx math (`lsrs#22; adds#4`),
  tableB access (`adds r0,r0,r2`, MATCHES) — is byte-identical.

- **Root cause (read from agbcc source):** `config/arm/arm.h` REG_ALLOC_ORDER is
  `{3, 2, 1, 0, 12, 14, 4, 5, ...}` — agbcc's `find_free_reg` tries **r3 before r2**,
  so the late-materialized tableA-base pseudo naturally lands in r3. The baserom
  compiler instead **coalesced** the base into the result register r2 (via
  local-alloc.c `combine_regs`/`may_save_copy`, the must_match tie). That tie does
  NOT fire here because Thumb `adds rd,rs,rn` has no rd==rs constraint, so agbcc
  leaves base (r3) separate from result (r2). This is a pure register-coloring
  artifact at ONE instruction; it is NOT a structural-impossibility (classifier =
  ATTEMPT_MATCH), so NAKED is not warranted.

  Why the sibling sub_0801D268 matches but this doesn't: d268 uses its indexed
  table at the FUNCTION START, so the `tableBase` input-barrier anchors the base
  early into r2 and the whole chain coalesces. Here the table is used in the
  MIDDLE (after 5 DMA blocks), so the barrier instead forces the base load — and
  the `arg<<24`/index math — to the top, regressing to byte_diff 214 (prologue
  gains `push {r4,lr}; sub sp,#4`, idx becomes `adds#1; lsls#2`).

## Levers tried (all FAILED to move the r2/r3 tie-break)

- Word-index `tbl[arg+1]` (diff 7, BEST) vs byte-offset `*(void**)(CONST+idx)` with
  idx=arg*4+4 (diff 87, separates the `+4`, shuffles pool order).
- Shared `idx` local vs inline `arg+1` per table (shared is required: inline →
  diff 87 with pool-offset cascade).
- `idx` computed at top vs at use-site (at-top → diff 74: `lsrs#22` hoists early).
- Pointer accumulation `tableA += idx; *tableA` — no change (diff 7).
- `const void *const *tableA` declared at top, used late — no change (diff 7).
- `register const void *const* tableA asm("r2")` + barrier — diff 215 (breaks prologue).
- `register u32 idx asm("r0")` — diff 215 (collides with arg reg, DMA base → r2).
- `tableA=0x083087C8; asm volatile("" ::"r"(tableA))` input barrier (the d268 idiom)
  — diff 214 (forces base + index math to the top, adds stack frame).
- `-ffixed-r3` per-TU — diff 227 (cascades into r4/r5/r8 + `push {r6}`).
- `CC = OLD_AGBCC_BIN` per-TU — IDENTICAL diff 7 (not a toolchain-version issue).
- **decomp-permuter: 2231 iterations, j4, `--stop-on-zero --better-only` —
  ZERO `new best`, ZERO score-0.** Statement/scope/temp mutation cannot reach a
  hard-register alloc-order tie-break; base score never improved from 5405.

## Next lever to try (NOT yet attempted)

The tie is `combine_regs` coalescing base→result into r2. Ideas a future pass
could try that this one did not:
- Force the base load to be the SOURCE of a move whose dest is the result reg
  (give the base pseudo an r2 *preference* without an early-materializing barrier)
  — e.g. an `asm("")` output-only barrier on the loaded value, not the base.
- A per-TU `-fcaller-saves` / `-foptimize-register-move` / `-fregmove` toggle
  (regmove is the pass that does exactly this kind of tie; it may be off/on
  differently than the baserom default).
- Re-derive the index as a `(arg<<24>>22)` expression (matching the asm's literal
  `lsls#24 … lsrs#22`) so the value flow into the address mirrors the baserom's
  and the coalescer sees the same RTL shape.
