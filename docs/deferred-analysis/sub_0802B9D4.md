# Deferred analysis: sub_0802B9D4

**Range:** 0x0802b9d4..0x0802ba64 (144 bytes, Thumb)
**Dest file:** src/game/sub_0802b9d4.c

## Summary

sub_0802B9D4 iterates over 20 entities starting at gEntities[3], divides their
X/Y coordinates by 24 to get tile positions, checks if each tile position is
valid via sub_0800D270, and sets entity.status |= 0x0C for entities not in
a valid position. Then calls sub_08021510 with a count descriptor to spawn
entities at valid positions.

## Drift

**Best byte_diff:** 31 bytes (diff_count: 16 instructions)
**Compiler:** old_agbcc -O2

**Root cause:** The initialization of the stack descriptor d[0] uses a
read-modify-write pattern in the expected asm that agbcc folds at -O2:

Expected (baserom):
```
ldr r2, [pc, #120]     ; r2 = 0xffff0000 (pool entry)
ldr r0, [sp, #4]       ; load d[0] from stack
ands r0, r2            ; clear low 16 bits
movs r1, #20           ; r1 = 20
orrs r0, r1            ; set low bits = 20
ldr r1, [pc, #116]     ; r1 = 0x0000ffff (second pool entry!)
ands r0, r1            ; clear high 16 bits -> r0 = 20
str r0, [sp, #4]       ; store 20 to d[0]
```

At -O2, agbcc recognizes (any_val & 0xffff0000) | 20 & 0x0000ffff = 20 and
simplifies the entire chain to just `movs r0, #20; str r0, [sp, #4]`.

**Approaches tried:**
- `u32 d[2]; d[0] = (d[0] & m2) | 20; d[0] &= m1;` with m2=0xffff0000, m1=0x0000ffff
  → Folds to 20 at -O2.
- Various formulations with volatile, pointer aliasing, asm() barriers
  → Still folds.
- `u32 m = (u16)-1; d[0] &= ~m; d[0] |= 20; d[0] &= m;`
  → Prevents fold! Generates load+mask dance for d[0] BUT uses MVN instruction
  for ~m (pool stores 0x0000ffff, computes 0xffff0000 via mvn). Expected uses
  two SEPARATE pool entries (0xffff0000 and 0x0000ffff directly). Results in
  140-byte function vs expected 144 bytes. diff_count=16, byte_diff=31.
- `u32 m = (u32)~(u16)-1; d[0] &= m; d[0] |= 20; d[0] &= ~m;`
  → Also prevents fold but uses BIC instruction for ~m. diff_count=17, byte_diff=114.
- Per-TU -O1 flag: gives mask dance but TWO intermediate stores and different
  register layout (more differences, not closer).

**Pool needed:** 0xffff0000, 0x0000ffff, gEntities, gIwram_6110 (4 entries).
**Pool generated (best attempt):** 0x0000ffff, gEntities, gIwram_6110 (3 entries) + MVN.

The expected asm seems to come from a compiler pass configuration where the
algebraic fold (x & C1) | K & C2 = K is NOT applied when both C1, C2 are pool
constants. Our agbcc applies this fold at -O2, earlier agbcc versions may not.

**Levers tried:**
- -O1: too many structural differences
- -O2 -fno-gcse: no help (it's local CSE, not GCSE)
- -fno-peephole: no help
- volatile d[0]: prevents fold but emits extra load/store around each mask separately
- asm("" : "+m"(d[0])): no help
- Base pointer change: no help

1. Load 0x0000ffff (m) from pool into r2
2. Compute 0xffff0000 (~m) via `mvns r3, r2` (extra instruction)
3. Use r3 for the mask_hi AND operations
Expected: load 0xffff0000 directly into r2 from pool; load 0x0000ffff into r1
for the second AND; no MVN instruction.
