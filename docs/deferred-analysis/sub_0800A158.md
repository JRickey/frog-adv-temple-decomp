# Deferred: sub_0800A158 (0x0800a158, 112 bytes)

Builds two packed-u32 args (coord, size) on the stack via halfword RMW masking,
then tail-calls `sub_0800CED0(base, coord, size, 0, 0)` (5 args; 5th spilled to
sp[0]). Semantics:

```
y = (u16)(entity[4] + entity[38] - entity[41])          ; entity[41] = h (u8)
x = (u16)(entity[2] + entity[36] - (entity[40] >> 1))   ; entity[40] = w (u8)
coord = (x << 16) | y      ; low half = y, high half = x
size  = (h << 16) | w      ; low half = w, high half = h
return (u8)sub_0800CED0(base, coord, size, 0, 0);
```

`sub_0800CED0` takes (r0=base, r1=coord, r2=size, r3=0, sp[0]=0) and treats r1/r2
as packed coordinate pairs (it sign/zero-extends the halfwords). Confirmed by
disassembling 0xced0: `ldr r0,[sp,#28]` (5th arg), halfword extracts of r1/r2.

## Round-4 (Opus) finding — the structural KEY the round-3 attempt missed

The round-3 note got stuck at byte_diff 53 because its C used **register-packed**
arg construction (`coord = y | (x<<16)` computed in registers, `sub sp, #4`). The
target instead does genuine **32-bit read-modify-write masking on memory-resident
args** (`sub sp, #12`, args at sp[4]/sp[8]):

```
ldr  r4, =0xffff0000        ; mask_hi, held in r4 across the whole function (CSE)
adds r3, r4, #0             ; scratch copy of mask_hi
ldr  r5, [sp, #4]           ; load OLD coord
ands r3, r5                 ; coord & mask_hi
orrs r3, r2                 ; | y
str  r3, [sp, #4]           ; store coord  (r3 ALSO kept live as the cache)
... x computation ...
ands r3, r2(mask_lo)        ; reuses r3 = cached coord, NOT a reload
orrs r3, r5(x<<16)
str  r3, [sp, #4]
```

**The ONLY C form that reproduces this 32-bit RMW masking is a `volatile u32 *`
alias:**

```c
u32 coord, size;
volatile u32 *pc = &coord, *ps = &size;
*pc = (*pc & 0xffff0000) | y;          /* -> ldr/and/orr/str, NOT folded */
```

Every NON-volatile form FOLDS the mask away (agbcc proves the uninitialized upper
bits are dead → `coord = y | (x<<16)` in registers, `sub sp, #4`). Tested and
folded under BOTH `agbcc` and `old_agbcc`:
- struct-of-two-u16 by value          → register pack (sub sp,#4)
- `u16 *` alias into u32              → `strh` halfword stores (not 32-bit RMW)
- two 16-bit bitfields                → folds to register pack
- explicit `coord = (coord & m)|v`    → folds (uninit read elided)
- `*(volatile u32*)&coord` only at the call read → folds the assignments

## Drift on the best (volatile) structure

**Best byte_diff: 54, diff_count 28** — same byte count as round-3 but with the
CORRECT structure (volatile RMW backend). The front-end (first 16 bytes through
`subs r2,r2,r6`) matches PERFECTLY with these pins:

```c
register u16 f4 asm("r3"); register u16 f26 asm("r4");
register u32 y_sum asm("r2"); register u32 h asm("r6"); register u16 x asm("r5");
register u16 e2 asm("r7");   /* entity[2] */
```

Residual differences are ALL register coloring, rooted in ONE decision:

1. **Target allocates a 4th callee-saved register (r7); my C only ever uses
   r4-r6 (`push {r4,r5,r6,lr}`).** The target holds e2 then w in r7 (short-lived
   temps) AND pushes r7 — because at the x-computation point r0-r3 are all
   occupied (entity, coord-cache r3, mask, scratch), forcing callee-saved r7.
   My versions free a caller-saved reg there, so agbcc never needs r7.

2. **Target keeps `coord` register-cached in r3 across the x-block** (memory home
   at sp[4] + live register copy), so the 2nd mask uses the cached r3, not a
   reload. The `volatile` qualifier I need for the RMW *forces every access to
   memory*, so my version RELOADS `ldr [sp,#4]` each time instead of caching.
   This is the irreducible conflict: volatile gives the RMW masking but kills the
   register cache; non-volatile gives the cache but folds the masking away.

3. mask_hi (r4) and mask_lo (r2) are CSE'd and held the whole function in the
   target (loaded once, reused for both coord and size). My pins for these
   disturbed the front-end allocation.

## Levers tried (round 4) — what did NOT work

- `volatile u32 *` alias (the RMW key) — gets structure right, 54 bytes.
- front-end pins f4=r3/f26=r4/y_sum=r2/h=r6 — front 16 bytes perfect.
- pin e2=r7 + SPLIT `x_base = e2 + entity[36]` statement → agbcc MISCOMPILES:
  `add r5, r5, sp; add r5, r5, #4` (confuses the pinned r7 value with the
  `&coord` stack address, because of the volatile pointer). Only the SINGLE-
  expression `x = (u16)(e2 + entity[36] - (entity[40]>>1))` is safe.
- pin w=r7 / e2w=r7 (reuse e2's reg for w) — broke front-end scheduling, r7
  still not pushed.
- pin mask_hi=r4 + mask_lo=r2 — masks still reloaded from pool, front-end broke.
- `asm("" : "=m"(coord))` barrier to force memory — did NOT force RMW (one-shot
  clobber, then normal folding).
- `old_agbcc` on explicit-mask form — also folds.
- **Permuter (50s, ~2000 iters, base score 855): ZERO improvement over base.**
  The residual is an allocator register-CHOICE the permuter's statement-reorder /
  scope mutations cannot reach — not a scheduling drift.

## What a future agent should try (DIFFERENT directions)

The blocker is reproducing "memory-home + register-cache + RMW-mask that reads the
OLD value" simultaneously. `volatile` gives RMW but no cache; non-volatile gives
cache but folds. Promising unexplored directions:

1. Find a NON-volatile escape that defeats the dead-upper-bits fold WITHOUT
   killing the register cache: take `&coord` and let it escape through a path
   agbcc can't prove (e.g. store the pointer into a file-scope `u32 *gScratch`
   that another TU reads), so agbcc must assume coord's initial value is live →
   keeps the RMW masks AND register-caches. Risk: extra str of the pointer.
2. Read `tools/agbcc-src/gcc_arm/local-alloc.c` / `global.c` to find the exact
   condition under which agbcc promotes a short-lived temp to a callee-saved
   (r7) register vs a caller-saved one, then engineer the simultaneous-liveness
   (5+ live pseudos at the x-block: entity, coord-cache, mask, e2, w) that forces
   it without `volatile`'s side effects.
3. The args may NOT be C-level masks at all: try a `union { u32 w; struct { u16
   lo, hi; } h; }` that is **address-taken and escaped** so SRA does not fire,
   accessed via the `.h.lo/.h.hi` members (which agbcc may lower to 32-bit RMW on
   the memory home rather than `strh`).

## Best-effort C (volatile structure, byte_diff 54 — front 16 bytes match)

```c
extern u8 sub_0800CED0(void *base, u32 p1, u32 p2, int z3, int z5);

u8 sub_0800A158(void *base, u8 *entity)
{
    u32 coord;
    u32 size;
    volatile u32 *pc = &coord;
    volatile u32 *ps = &size;
    register u16 f4 asm("r3");
    register u16 f26 asm("r4");
    register u32 y_sum asm("r2");
    register u32 h asm("r6");
    register u16 x asm("r5");
    register u16 e2 asm("r7");
    u32 mask_hi, mask_lo;
    u16 y;

    f4 = *(u16 *)(entity + 4);
    f26 = *(u16 *)(entity + 38);
    y_sum = (u32)f4 + f26;
    h = entity[41];
    y = (u16)(y_sum - h);
    mask_hi = 0xffff0000;
    *pc = (*pc & mask_hi) | y;
    e2 = *(u16 *)(entity + 2);
    x = (u16)(e2 + *(u16 *)(entity + 36) - (entity[40] >> 1));  /* MUST be one expr */
    entity += 40;
    mask_lo = 0x0000ffff;
    *pc = (*pc & mask_lo) | ((u32)x << 16);
    *ps = (*ps & mask_hi) | *entity;
    *ps = (*ps & mask_lo) | (h << 16);
    return sub_0800CED0(base, coord, size, 0, 0);
}
```
