### The blocking pattern
The target has:
1. `lsrs r2, r2, #16` (y truncation to u16) at offset 0x14
2. `ldr r4, [pc, #80]` (mask_hi = 0xffff0000) at offset 0x16  
3. `adds r3, r4, #0` (mask_hi copy to r3)
4. `ldr r5, [sp, #4]` (load UNINITIALIZED arg1 from stack sp[4])
5. `ands r3, r5`; `orrs r3, r2`; `str r3, [sp, #4]` (arg1 intermediate)
6. `ldrh r7, [r1, #2]` (entity[2] → r7) **uses r7 = callee-saved!**
7. `ldrh r2, [r1, #36]` (entity[36] → r2)
8. `adds r5, r7, r2` (x_base)
...more masking for arg2

My code skips to x computation at offset 0x14 without the mask/stack-spill block.

### Root cause: circular dependency
For arg1/arg2 to be stack-allocated (at sp[4]/sp[8]):
- All of r4-r7 must be SIMULTANEOUSLY occupied when arg1/arg2 need allocation
- But r7 is only needed for entity[2] during x computation
- Entity[2] uses r7 BECAUSE r0-r6 are all occupied (including r3=arg1 intermediate)
- r3=arg1 requires the stack-spill pattern to exist

The stack spill is self-referential: it exists because of the register pressure that it creates. agbcc's local allocator makes this decision at function entry based on live-range analysis.

### Levers already tried (exhaustively)

### What a future agent should try
The remaining difference is the deferred `lsrs r2, r2, #16` at offset 0x14 and the entire mask block for arg1. The most promising direction:

1. **Force y to be used EARLY and in r2**: the y variable (r2) must be consumed by the arg1 mask operation BEFORE x computation. Currently agbcc defers the lsrs until after x_base computation.

2. **Address-of arg1 trick**: if you can somehow force agbcc to take the address of arg1 before using it, arg1 would be forced to a stack location. Example: a separate function that accepts `u32 *` and writes the masked value via pointer. But this adds an extra BL.

3. **Modify `y = (u16)(y_raw - h)` to ensure the mask_hi pool load happens right after**: maybe use `mask_hi = 0xffff0000u; y = (u16)(y_raw - h); arg1 = (arg1 & mask_hi) | y;` where `arg1` has a KNOWN initial value that requires masking (not zero/uninit).

4. **Register pressure via 6+ simultaneous live variables at arg1 allocation**: f4(r3), f26(r4), y_sum(r2), x_base(r5), h(r6), entity(r1), base(r0). All 7 non-callee-saved registers taken. arg1 must go to stack.

5. The x_base `ldrh r5, [r1, #36]` at offset 0x0e: in target, this is at offset 0x22 (later). Getting x_base computation DEFERRED (after the arg1 mask block) is key.
