# sub_0803080C — deferred analysis

Sound stream opcode handler in `src/system/sub_0803079c.c` (the same TU as its
matched sibling `sub_0803079C`). Range [0x0803080c, 0x080308b0), 164 bytes,
ATTEMPT_MATCH (no structural-impossibility signature). Default compiler
(`old_agbcc`) is correct for this TU (the sibling matches with it).

Semantics (fully understood — see the C below):
- `(channel, state_ptr)` opcode handler. `stream = (u8*)*state_ptr`.
- `channel <= 2`: target `ic = (u8*)gpSoundSystem + channel*36`.
  `stream[1] & 1` ? `*(u16*)(ic+0x22) = stream[2]` (set) :
  `*(u16*)(ic+0x22) += stream[2]` (accumulate). Then
  `gpSoundSystem->chFlags[channel] |= SOUND_FLAG_ENV_DIRTY`.
- `channel > 3`: `slot = (channel*64 - 0x100) + (u8*)gpSoundSystem->swSlots`.
  Same set-vs-accumulate on `*(u16*)(slot+2)`, then
  `*(u32*)(slot+0x38) |= SOUND_FLAG_ENV_DIRTY`.
- `channel == 3`: no-op. Always `*state_ptr += 4; return 1;`.

## Drift

The C below is **STRUCTURALLY PERFECT** — correct 164-byte size, exact control
flow, correct per-arm `gpSoundSystem` literal reloads (two pool entries 0x30834
+ 0x30860, not a hoisted single load), correct tail-merge of the store across
the inner if/else. The ONLY residual is **register coloring**, and it is a
single root cause that cascades:

- **`channel` lands in r2; target wants r3.** Everything else follows: with
  channel in r2, r3 is free so the accumulate temp (`ic[0x22]` read) takes r3
  (target: r6), and the `gpSoundSystem` pool literal takes r0 (target: r2,
  reused across the merged chFlags load `ldr r1,[r2,#0]` at 0x3084c).

Best results from the first pass (default old_agbcc, `compile_and_view_assembly.py`):

- pin stream=r4:                            byte_diff 46

- + pin accumulate temp acc=r6:             byte_diff 40  (prologue `push {r4,r5,r6,lr}` now MATCHES)

```c
s32 sub_0803080C(s32 channel, u32 *state_ptrArg)
{
    u32 *state_ptr;
    u8 *stream;

    state_ptr = state_ptrArg;
    stream = (u8 *)*state_ptr;

    if (channel <= 2) {
        SoundSystem *ss;

        if (stream[1] & 1) {
            *(u16 *)((u8 *)gpSoundSystem + channel * SOUND_INLINE_CHANNEL_STRIDE + 0x22) = *(u16 *)(stream + 2);
            ss = gpSoundSystem;
        } else {
            ss = gpSoundSystem;
            *(u16 *)((u8 *)ss + channel * SOUND_INLINE_CHANNEL_STRIDE + 0x22) += *(u16 *)(stream + 2);
        }
        ss->chFlags[channel] |= SOUND_FLAG_ENV_DIRTY;
    } else if (channel > 3) {
        u8 *slot;

        slot = (channel * SOUND_SW_SLOT_STRIDE - 0x100) + (u8 *)gpSoundSystem->swSlots;
        if (stream[1] & 1) {
            *(u16 *)(slot + 2) = *(u16 *)(stream + 2);
        } else {
            *(u16 *)(slot + 2) += *(u16 *)(stream + 2);
        }
        *(u32 *)(slot + SOUND_SLOT_FLAGS_OFFSET) |= SOUND_FLAG_ENV_DIRTY;
    }

    *state_ptr += 4;
    return 1;
}
```

### Why `channel` will not take r3 (root cause, verified)

agbcc local-alloc orders quantities by reference DENSITY
`log2(refs)*refs*size/(death-birth)` (gcc_arm/local-alloc.c QTY_CMP_PRI,
~line 1488) and allocates highest-density first into REG_ALLOC_ORDER
(`3,2,1,0,12,14,4,5,6,...` — r3 first). `channel` has a LONG lifetime (entry →
mid-function), which DIVIDES its priority below the short-lived accumulate temp.
So the temp grabs r3, channel falls to r2.

**Every attempt to pin `channel`/`ch` to r3 DESTROYS the tail-merge** (size
jumps 164 → 176, the two arms each get their own `strh` instead of branching to
a shared store). Verified with: `register s32 channel asm("r3")` at decl;
3-pin (channel+state_ptr+stream); ch/sp local-copy idiom pinned; pointer-`p`
per-arm restructure. This is a hard agbcc coupling: channel in a low call-used
reg (r2) ⇒ agbcc keeps `ic` live across the branch and merges; channel in a
callee-saved reg (r3) ⇒ enough free low regs to store-in-place per arm.

Pinning the `gpSoundSystem` literal to r2 (per-arm `register SoundSystem **gp
asm("r2")`) pushed channel to r6 and broke structure (172 bytes). Pinning the
acc temp to r6 fixed the prologue save but did NOT relocate the actual temp
(still r3) — channel stayed r2.

Per-TU flags tested (none move channel off r2): `-fno-strength-reduce`,
`-fno-gcse`, `-fcaller-saves`, `-fno-force-mem`, `-fno-cse-follow-jumps`.
`-ffixed-r2` would force it but the sibling `sub_0803079C` in the SAME TU uses
r2, so it would break the sibling.

## Best-effort C

byte_diff 40, structurally perfect, only `channel` register wrong (r2 vs r3):

```c
s32 sub_0803080C(s32 channel, u32 *state_ptrArg)
{
    register u32 *state_ptr asm("r5") = state_ptrArg;
    register u8 *stream asm("r4");

    stream = (u8 *)*state_ptr;

    if (channel <= 2) {
        if (stream[1] & 1) {
            *(u16 *)((u8 *)gpSoundSystem + channel * SOUND_INLINE_CHANNEL_STRIDE + 0x22) = *(u16 *)(stream + 2);
        } else {
            register u16 acc asm("r6");
            acc = *(u16 *)((u8 *)gpSoundSystem + channel * SOUND_INLINE_CHANNEL_STRIDE + 0x22);
            *(u16 *)((u8 *)gpSoundSystem + channel * SOUND_INLINE_CHANNEL_STRIDE + 0x22) = acc + *(u16 *)(stream + 2);
        }
        gpSoundSystem->chFlags[channel] |= SOUND_FLAG_ENV_DIRTY;
    } else if (channel > 3) {
        u8 *slot;

        slot = (channel * SOUND_SW_SLOT_STRIDE - 0x100) + (u8 *)gpSoundSystem->swSlots;
        if (stream[1] & 1) {
            *(u16 *)(slot + 2) = *(u16 *)(stream + 2);
        } else {
            register u16 acc asm("r6");
            acc = *(u16 *)(slot + 2);
            *(u16 *)(slot + 2) = acc + *(u16 *)(stream + 2);
        }
        *(u32 *)(slot + SOUND_SLOT_FLAGS_OFFSET) |= SOUND_FLAG_ENV_DIRTY;
    }

    *state_ptr += 4;
    return 1;
}
```
