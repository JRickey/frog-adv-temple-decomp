## Semantics (fully understood)
Waypoint-advance for entity[idx] over a level-layout record array `base`
(8-byte records: u16 x @0, u16 y @2, u8 selector @4 — modelled as `Entry`,
the same struct sub_08021838 uses). `base[0]`/`base[4]` are header bytes
(count / selector) passed straight to sub_08021838. field_33 = current record
index, field_1A = axis selector (1..4). For the dictated axis the entity must
have reached the record coord (eq on one axis via ldrh/ldrh, gt/lt on the
other via ldrsh/ldrsh — see the cast pattern in the C); if so, sub_08021838
commits the next hop. Tail re-arms status: `(status|2)&0x7fff` when bit 0x8000
set. Caller: sub_0802ab64 `sub_080219BC(sLevelLayoutPtrs_317ED4[i], i+2)` — so
the public extern's `s32 slot` is actually consumed as **u8** (entry masks it).

## Drift (what does NOT work — pick a DIFFERENT lever next time)
Best clean result: **byte_diff 9, diff_count 9, ZERO register pins, size 268
(exact).** Levers that got there (all SOURCE-shape, no pins needed in the end):
- param `idx` typed `u8` (gives the `lsls #24; lsrs #24` entry mask)
- `Entry *rec` declared **block-scoped inside each case `{ }`** (function-scope
  rec → callee-saved r4; block-scope → caller-saved r0, matching target). Big win.
- `rec = (Entry *)(recIdx * 8 + (u32)src)` — the `(u32)` cast (NOT `&src[..]`,
  NOT `(u8*)src`) flips the record `adds` operand order to `offset+src`. -8 bytes.
- equality compares cast `(u16)e->x`/`(u16)e->y` (→ ldrh/ldrh); inequality cast
  `(s16)...`/`(s16)rec->b` (→ ldrsh/ldrsh).
- `status` cached in a local (single ldrh) + staged tail `u16 t=2; t|=status;
  status & ... ` — fixed the tail status double-read.
- `ents = gEntities; e = ents + idx;` (held-base form) for the ENTITY init
  multiply — matches target exactly (`ldr r1,[pc]; lsls r0,r6,#3; ...;
  adds r2,r0,r1`).

The IRREDUCIBLE residual = two INDEPENDENT agbcc tail-block coloring choices:
1. **Tail entity-multiply (5 bytes, 0xd6..0xde):** target uniquely uses
   `ldr r0,[pc]; lsls r1,r6,#3; ...; adds r2,r1,r0` (pool→r0, offset→r1) so the
   following `ldrh r1,[r2,#52]` (status) reuses the offset's r1. agbcc keeps the
   init-consistent `pool→r1, offset→r0`. Tried: `ents+idx`, `gEntities+idx`,
   `&gEntities[idx]`, `(u32)` casts, explicit offset local, decl reorder — all
   stay pool→r1 (or regress to bd 11/13/21). NOT flippable via source shape.
2. **Tail OR accumulator (4 bytes, 0xee..0xf4):** target `movs r0,#2; orrs r0,r1`
   (constant `2` is accumulator, result r0). agbcc reuses live `status`(r1) as
   accumulator → `orrs r1,r0`. Tried `t=2;t|=status`, `t=2|status`,
   `status|=2`, `result=2|status` at function scope, u16/u32/int status — all
   keep status as accumulator. NOT flippable via source shape.
