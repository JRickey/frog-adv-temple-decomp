calls sub_080059C4(e). Range [0x0802c910, 0x0802ca20), 272 bytes (the

## Drift

best byte_diff = 2, diff_count = 2 -- a single `ldrsh` index-register
choice in case 4 ONLY:

```
+0x00c0  target: movs r2, #2            built: movs r1, #2
+0x00c2  target: ldrsh r0, [r5, r2]     built: ldrsh r0, [r5, r1]
```

Both baserom and agbcc emit `ldrsh r0,[r5,idx]` for e->x (s16 @ off 2;
Thumb-1 has no immediate-offset ldrsh). Case 3 matches (index = r2). Case 4
diverges: agbcc colours the index scratch to r1 (case 4 falls through into the
shared set_state where newState=3 lives in r1, so the dying index reg is
reused); baserom keeps it in r2 (which it later reuses for the 0x6aa shadow
offset). This is a local-alloc free-register SELECTION-ORDER choice for a
short-lived scratch pseudo -- not C-reachable in this fall-through context.

The rest of the function is a clean byte match. The hard-won shape that got
here (do NOT re-derive -- these are load-bearing):
- struct Entity *e = &gEntities[22] (matches sub_0802bc24 convention).
- case 0 status test MUST read the field directly: if ((e->status & 0x8000)==0)
  -- NOT a cached `u16 status` local -- else the mask materialises before the
  status load (field-first vs const-first ordering, codegen-notes).
- case 0 OR: e->status |= 2 (field RMW) -> const-first `movs r0,#2; orrs r0,r1`.
- cases 3/4 status MUST be TWO separate field RMW statements:
      if (e->status & 0x8000) { e->status |= 2; e->status &= 0x7fff; }
  A fused `(e->status|2)&0x7fff` or a staged temp both mis-colour the OR/AND
  chain (byte_diff 135 / 10 respectively). Two RMW = byte_diff 2.
- Switch case BODIES lay out in SOURCE order (confirmed: reordering source to
  0,4,3 reorders the bodies and breaks layout) -> keep 0,3,4.
