## What the function does (verified from asm)
Takes (s16 x, s16 y). Calls `mode = (u8)sub_0800D270(x, y)`.
- mode==1: scan entity records `gIwram_3720 + (i+3)*56` for i in 0..19.
- mode==2: scan records `gIwram_3720 + (i+23)*56` for i in 0..9.
For each record whose `_h34 & 8 == 0`, compute `col=(s16)(_h2/24)`,
`row=(s16)(_h4/24)`; if `(u16)col==(u16)x && (u16)row==(u16)y`, set
`_h34 |= 8|4` (built as `t=8; t|=flags; t|=4;` two orrs — matches), then a
col/row range gate identical to `sub_0800D270`'s body, and on success write
`gIwram_53A0[(u8)((row-5)*8 + (col-3))] = 0` (clamped to 0xFF). Then `return`.
The two branches share the final write block but keep separate range-check tails
(asymmetric branch encoding: ret==1 ends `bgt;b 0xd41c`, ret==2 ends `ble 0xd41c`).

The 56-byte record loop index `(i+3)*56` is the same `(N+K)*56` stride idiom as
the matched sibling `src/engine/sub_0800d0f8.c`. Struct fields: `_h2`(+2),
`_h4`(+4), `_h34`(+0x34) flags (bit 8 = active/skip; sets 8|4 on match).

## Drift (best-effort PURE C reached)
best byte_diff: **287**, diff_count 147 (size 364 vs target 400; ~36 bytes short).
Structure is CORRECT (goto-restructured loops match the bottom-tested `do/while`
with the `i++; if((s8)i<=N)` increment — this fixed an earlier double-add at the
loop-back). Remaining drift is all register-coloring + one compare idiom:

1. **flags/saved-i register swap (r6<->r7).** Target: flags in r7, spilled loop
   counter in r6. agbcc naturally assigns flags=r6, saved-i=r7. Pinning
   `register u16 flags asm("r7")` BREAKS the prologue: agbcc then maps the 3
   high-reg saves (sl,r9,r8) to r4,r5,r6 and treats r7 as a free (UNSAVED) reg →
   prologue drops to `push {r4,r5,r6}` instead of the target's `push
   {r4,r5,r6,r7}`. So the r7 pin is a dead end; the swap must come from natural
   allocation pressure, not a pin.
2. **The compare emits 1 fewer insn than target.** Target stores `col=(u16)(div)`
   (lsrs r4) and the equality compare materializes `col<<16` and `ux<<16` and
   compares the `<<16` forms (`cmp r0,r1`), reusing `col<<16`'s `asrs r3` as the
   `(s16)col` for `dcol`. My `col=(s16)div; (u16)col==ux` compares directly
   against r9 (no `<<16`), 1 insn shorter per compare × 4 compares ≈ the 36-byte
   gap. Tried: `col=(u16)div` + `(s16)col==(s16)ux` + `dcol=(s16)col-3` → size
   climbs toward 376/372 but byte_diff/diff_count get WORSE (the row range tests
   then re-derive `(s16)row` each time instead of reusing the compare's side
   product; target computes `(s16)row` ONCE in the 2nd compare (`asrs r4`) and
   reuses it for every row test). Couldn't get agbcc to reuse that signed form.
3. **arg-setup scheduling.** Target interleaves `lsls r0,#16; lsls r1,#16` then
   extracts, using r3 as the `(u16)y` temp (`lsrs r3,r1,#16; mov r8,r3`). Mine
   computes ux fully then uy, reusing r2. Minor (≈3 insns).
4. **index multiply uses r0 (target) vs r1 (mine)** — falls out of (1)/(3).
