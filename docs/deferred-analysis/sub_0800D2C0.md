# sub_0800D2C0 — deferred analysis

Destination: own TU `src/engine/sub_0800d2c0.c`, linker entry before
`asm/disasm_0x0800d2c0.o(.text)`. Both callees are peeled:
`sub_0800D270` and in-ROM libgcc `__divsi3` at `0x08033D14`.
Classifier verdict: `ATTEMPT_MATCH`, not `STRONG_UNMATCHABLE`; do not ship
NAKED for this target.

## Drift

Best result remains the clean pinned-C plateau:

- `byte_diff 251`, `diff_count 86`, generated size `376` bytes vs target
  `400` bytes.
- Required source shape for this plateau:
  - preserve unsigned input halves in `r9`/`r8` and mode in `sl`;
  - split `flags1`/`flags2` so the loop counter wins `r6` and flags land in
    `r7`;
  - compute entity addresses through `(u8 *)gEntities + (slot + base) * 56`.
    The readable `&gEntities[slot + base]` form folds to `gEntities+constant`
    and worsens the diff.
- Remaining wall: target emits copy-spread around `scol`/`srow`, especially
  `adds r2,r3,#0; subs r3,r2,#3`, then row/map check copies through `r1`/`r0`.
  agbcc coalesces the column copy into `subs r3,#3`, leaving the function about
  24 bytes short. This is regmove/CSE liveness behavior, not a relocation issue.

Newly ruled out in this pass:

- Clean no-pin readable implementation: `byte_diff 329`; high-register
  allocation and status/counter coloring diverge immediately.
- Helper function for map-index readability: emitted before the target and
  shifted `sub_0800D2C0` by `0x24`.
- Alternate compiler probe with newer `AGBCC_BIN`: worse prologue; drops `sl`
  from the high-register save set.
- Parameter conversion reorder (`ux; uy; sx; sy`): worsened plateau from 251
  to 255.
- Scratch-register declarations for the spread copies:
  - `rowA asm("r1")` and reusing `t asm("r0")` partially produce `r4 -> r1`
    and `r1 -> r0`;
  - `scolCopy asm("r2")`, unpinned `scolCopy`, and an inner initialized
    `register s32 colCopy asm("r2") = scol` are all coalesced away, still
    emitting `subs r3,#3`;
  - this shape grows to `392` bytes but worsens to `byte_diff 263`.
- Flag probes on that scratch shape:
  - `-fno-rerun-cse-after-loop`: `byte_diff 270`;
  - `-fno-peephole`: unchanged at `byte_diff 263`.
- Corpus check:
  - current-tree C grep for an analogous row-range temp found no useful hit;
  - register-pin grep only surfaced generic hard-reg examples;
  - history asm search could not run because `tools/agent/corpus-mirrors/` is
    not populated in this worktree.

Likely next useful angle: instrument `regmove.c` and `cse.c` together in a
private agbcc copy and find the exact pass interaction that removes the
`REG_DEAD`-sensitive column copy. Prior instrumentation showed
`copy_src_to_dest` never fires for the plateau C; this pass confirms hard-reg
scratch declarations do not change that liveness.
