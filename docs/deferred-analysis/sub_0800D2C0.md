## MAJOR PROGRESS THIS ROUND: the register-swap blocker is SOLVED (287/273 → 271)
The prior two rounds (287, then 273 byte_diff) plateaued on ONE documented blocker:
baserom puts `flags` in r7 and the saved loop counter (`i<<24`) in r6; agbcc swapped
them (flags→r6, counter→r7). The prior agent declared this "unreachable by source,
permute it." That was WRONG — it IS reachable. Two source-shape changes flip it:

1. **Pin the OR-result temp to r0** (`register u16 t asm("r0")`). Baserom builds the
   `status |= 8|4` value in r0 (caller-saved); my earlier C let `t` COALESCE with the
   `flags` pseudo into the callee-saved r6, inflating flags' ref-count to 8 (it spanned
   both loops AND absorbed `t`). Pinning `t` to r0 drops flags to 6 refs.
2. **Use DISTINCT per-loop flags variables** (`flags1` in loop1, `flags2` in loop2)
   instead of one shared `flags`. Each then has 3 refs (< the counter's 4), so the
   counter WINS r6 and flags lands in r7 — exactly baserom.
   Verified via an instrumented `global.c` (`AGBCC-DBG`/`AGBCC-GBL` probes): the
   physical-reg pick (r4,r5,r6,r7 per `REG_ALLOC_ORDER {3,2,1,0,12,14,4,5,6,7,...}`) goes
   to the higher-`QTY_CMP_PRI` allocno; priority is dominated by `qty_n_refs`. Make the
   competitor (flags) LIGHTER than the counter and the counter grabs the earlier reg (r6).
   NB: the SHARED symlinked `tools/agbcc-src` builds a compiler that DIVERGES from the
   installed `tools/agbcc/bin/old_agbcc` (the matching one) on fine CSE/scheduling — use
   the instrumented build ONLY for ref-count/alloc *introspection*, validate every byte
   claim against the REAL `old_agbcc` / full `make` + compile_and_view_assembly.

3. **Index chain register**: materialize `si = (s8)i;` and index
   `(struct Entity *)((u8 *)gEntities + (si + 3) * 56)` (the matched-sibling
   `sub_0800d0f8.c` idiom). Inline `(s8)i + 3` put `(s8)i` in r0 + temp in r1; the named
   `si` puts `(s8)i` in r1 + temp in r0 + pool in r1 — matching baserom (`asrs r1,r2,#24;
   adds r1,#3; lsls r0,r1,#3; subs r0,r0,r1; lsls r0,r0,#3; ldr r1,[pool]; adds r5,r0,r1`).
   This requires the BYTE-OFFSET cast idiom, NOT `&gEntities[si+3]` (the latter folds the
   `+3*56` into the pool literal, dropping the `adds r1,#3`).

4. **The s16==s16 compare trick** (from the prior round, KEPT): `(s16)col == (s16)ux`
   on un-pinned `u16 col`/`row` reproduces the baserom `lsls;lsls;asrs;cmp` reuse form
   (the `asrs` side-product feeds dcol + row range tests). Do NOT truncate before the
   compare (`(u16)col == ux` or `srow == (s16)uy` both LOSE the reuse).

5. `dcol asm("r3")` recovers baserom's `(u16)dcol` RECOMPUTE for the second range test
   (vs my CSE'ing it once): 256→271 byte_diff but 92→83 diff_count (structurally closer).
