### SOLVED this round (all PURE C — keep these, they are the new base below)
1. **prologue arg-setup (round-12 drift #3)** — was 6 diff bytes, now 1. FIX: declare
   `sx=(s16)x; sy=(s16)y;` locals and assign in the order `ux; sx; uy; sy;` then call
   `sub_0800D270(sx, sy)`. This groups `lsr ux`+`asr sx` per-x (matching baserom) instead
   of batching both `asr` at the call. ORDER MATTERS: `ux` first → r9, `uy` later → r8
   (the high-reg pins still needed; any other order flips r8/r9 → byte_diff 348+).
   RESIDUAL: 1 insn — baserom hoists `lsl r1` (y<<16) to slot 2 (right after `lsl r0`);
   agbcc emits it after `asr sx`. Pure emission-DAG order; not reached by reorder (sy-first
   breaks the high regs). LOW PRIORITY (1 insn).
2. **(s16)row → r4 (round-12 drift #1, the DECLARED-UNREACHABLE wall)** — SOLVED.
   Round 12 said `srow asm("r4")` "is ignored — the anonymous compare asrs ignores the
   pin." That was because they kept the compare as `(s16)row == (s16)uy` (anonymous asr).
   THE FIX: MATERIALIZE the compare value into a NAMED pinned var and compare THAT:
   `register s32 scol asm("r3"); register s32 srow asm("r4"); scol=(s16)col; if (scol != (s16)ux) ...;
   srow=(s16)row; if (srow != (s16)uy) ...;` and use srow/scol in ALL the tail tests.
   Now `asr r4` (srow) and `asr r3` (scol) byte-match the baserom. Root cause (proven by
   instrumenting global.c `find_reg`): gcc/global.c does NOT use REG_ALLOC_ORDER in the
   scan — it picks the LOWEST-numbered free reg. `(s16)row` (pseudo, nrefs≈12,
   priority≈1.24 by allocno_compare = floor_log2(nref)*nref/livelen) is allocated EARLY
   (high priority) when r2,r3,r4 are all free → grabs r2. Probe showed conflicts=[r0,r1]
   only, no r2 conflict, no someprefers → lowest = r2. Pinning the MATERIALIZED srow to r4
   makes the asr write r4 directly. (Round-12's pin failed only because their asr was the
   anonymous compare side-product, which the pin can't reach.)

1. **dcol-copy (~2 insns ×2 loops).** baserom: `adds r2, r3, #0; subs r3, r2, #3`
   (copy scol r3→r2, then 3-operand subs). ours: `subs r3, #3` (2-operand in-place).
   The in-place is shorter so our agbcc prefers it; the baserom keeps the regmove
   `copy_src_to_dest` fallback (gcc/regmove.c ~line 2951). regmove inserts the copy only
   when the in-place two-address fixup FAILS — i.e. when scol (the subs src) does NOT die
   at the subs. In the baserom scol IS dead after the subs (confirmed: r2 copy never read
   later), yet it still copies → a liveness/REG_N_REFS quirk we could not reproduce.
   Tried & FAILED: `tmp asm("r2")` intermediate (coalesced away → in-place); split
   `dcol=scol; dcol-=3;` (coalesced); keep scol live via `(u16)(scol-3)` recompute in the
   2nd check (added wrong insns, 270); `idx = (srow-5)*8 + scol - 3` (folds to dcol).
   Compare sibling sub_0800D270 (MATCHED): it has scol→r2, dcol→r3 → DIRECT `subs r3,r2,#3`
   (no copy) because scol/dcol are in DIFFERENT regs there. Here both want r3 → copy.
2. **row-spread (~4 insns ×2 loops).** baserom keeps srow in r4 and COPIES it down a chain
   for the range tests: `adds r1, r4, #0; cmp r1,#4; cmp r1,#12` then `adds r0, r1, #0;
   cmp r0,#4; cmp r0,#13` and the final compute uses the r0 copy (`subs r0,#5`). ours
   compares r4 directly (`cmp r4,#4`...). The srow→r4 PIN forces it to STAY in r4, killing
   the spread; without the pin it goes to r2 (drift #1 returns). This is the
   "highreg-spread" idiom — value in a callee-saved reg copied to caller-saved scratch per
   block. Needs srow in r4 (for the asr match) AND then spread via copies — contradictory
   with a single pin. THE one to crack next.
3. **field-offset reg + divsi block schedule (~6 insns).** `movs r2,#2 / movs r3,#4`
   (target) vs `movs r1,#2 / movs r2,#4` (ours), plus the two divsi blocks shift by a few
   slots. Downstream of (1)/(2)'s register pressure — likely cascades when (2) is cracked.
