# sub_0800D0F8 — deferred analysis

Engine function at 0x0800D0F8 (256 bytes). **Fully understood semantically**;
the residual is an agbcc loop-representation drift in the two tail blocks
(Block A/B). Callees are already peeled (sub_0800DB04, sub_0802BAF8,
sub_0802BB5C) on the main line — resume from the C below.

## Semantics

Scans the 64-byte cell array at `gIwram_53A0` (indices 0..63). For each cell:
- cell == 1 and the running `x` counter <= 19: call `sub_0800DB04(&v, i)`
  (packs a u32 = two s16 coords), then `sub_0802BAF8((s8)x, (s16)v, (s16)(v>>16))`,
  then `x++`.
- cell == 2 and the running `y` counter <= 9: same with `sub_0800DB04`,
  `sub_0802BB5C`, `y++`.

After the scan, two tail blocks set flag bit 0x08 in `_field_34` of one entity
record each:
- Block A: if `(s8)x <= 19`, `p = &gEntities_03003720[(s8)x + 3]`; loop counter
  runs from x..19 (the entry pointer is computed ONCE from x, NOT the counter —
  a single entry is modified), `p->_field_34 |= 8`.
- Block B: if `(s8)y <= 9`, `p = &gEntities_03003720[(s8)y + 23]`, loop y..9.

`gEntities_03003720` stride = 56 bytes (0x38). `_field_34` is the flag halfword
shared with sub_080031D4 / sub_0800D8A0 (bit 4 = inactive; this sets bit 3 = 0x08).

The OR in the loop body is emitted as **two** `orrs` (`| 8 | 0`): the baserom
`movs r6,#8; movs r5,#0; ... orrs r2,r6; orrs r2,r5`. Reproduced with two
non-const locals `mask=8; extra=0;` (a literal `| 8 | 0` constant-folds away).

## Drift  (best: byte_diff 107, diff_count 50, size-exact 256 bytes)

The MAIN scan loop matches to **1 instruction** (a scheduling swap at 0x1a/0x1c:
baserom does `adds r5,r1,#0` (save i<<24) BEFORE `ldrb r0,[r0]`, the build does
it after). Everything 0x1e..0x86 is byte-identical.

The two TAIL blocks are the residual. The baserom compiles them as a **do-while
(body-first, no entry `b.n`) over a PROMOTED-char biv** — the loop counter lives
as `x<<24` in a register and is incremented by literal `+0x01000000`
(`movs r0,#0x80; lsls #17; adds r3,r3,r0`), with `(s8)(counter>>24)` for the
compare. The accumulator is a callee-saved/working register pair
(`adds r2,r4,#0; orrs; orrs; adds r4,r2,#0`).

agbcc gives me EITHER the promoted-char biv `<<24` form (only via a `for (j=x;
j<=19; j++)` with `s8 j`) — but then adds a test-first `b.n` to the loop
condition + a pool island, OR a clean do-while body-first (only via `s32 j` /
`do{}while(++j<=19)`) — but then a plain-int counter (no `<<24`, 20 bytes too
short). I could not get BOTH (do-while body-first AND promoted-char biv) out of
agbcc 2.x from any C structure tried.
