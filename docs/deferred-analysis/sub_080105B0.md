## What this function is (confirmed)

Tilemap-blit driver, pure leaf (no callees):

    sub_080105B0(struct BlitEntry *entries, u8 index, u8 srcIndex)

- `BlitEntry` 24-byte stride: dstX@0, dstY@2, cols@4, rows@6, flags@8,
  srcTable@0x10. (`*24` strength-reduces to `((i*2)+i)<<3`.)
- `gBlitState` @ 0x03006500: src@0xc, dst@0x14. dst/src live IN IWRAM and are
  read/incremented/written-back inside the inner copy loop (the `#define
  gBlitState (*(...)0x03006500)` macro form is correct — each access
  re-materializes the 0x03006500 literal, matching the baserom which reloads
  `ldr r3,=0x03006500` inside the loop).
- `gSceneScroll` @ 0x030060A0: stride@0x1a.
- flags bit 4 selects EWRAM bank: set -> 0x02010000 (HI), clear -> 0x02000000 (LO).
- `gBlitState.dst += stride*dstY + dstX` then `dst += stride - cols` per row.

## Drift — the SHARP register-coloring minimum (the whole problem)

Best clean result: **byte_diff 136, diff_count 55, size 224 vs 228** with
`src/engine/sub_080105b0.s: CFLAGS += -fno-expensive-optimizations` and NO pins.
EVERY one of the 55 diffs is an `ARGUMENT_MISMATCH` (register number) — the
instruction *sequence/opcodes* are identical. The structure is right.

KEY FINDING (the lever the prior 7-pin attempt missed):
**`-fno-expensive-optimizations` ALONE flips agbcc from 2 high regs (byte_diff
215, size 208) to all 3 high regs (sl/r9/r8, byte_diff 136, size 224)** — the
correct prologue, no pins needed. The expensive-opt gate is cse.c:2829
(REG+const address-merge) which over-CSEs the entry address. Disabling it is the
right call and produces a much cleaner base than the prior pinned 117.

The IRREDUCIBLE residual is a single allocation decision that cascades through
every downstream register:

- **baserom**: keeps `(u8)index` in **ip** (`mov ip, r1` right after the byte
  extraction, per REG_ALLOC_ORDER ip is the 5th preference after r0-r3), keeps
  `(u8)srcIndex` in **r6**, computes `i2 = index*2` once (kept in r5->sl), and
  recomputes `(i2 + index) << 3` for the entry pointer at every use. 228 bytes.
- **ours (-fno-expensive)**: keeps `index` in **r3**, `srcIndex` in **r2**,
  caches the COARSER `index*3` (= i2+i) in r4->sl, recomputes only `(i3) << 3`.
  This saves the 2 instructions (`mov r0,ip; lsls r5,r0,#1`) that re-derive i2,
  hence size 224 (4 bytes short). Because index sits in r3 not ip, every later
  register number shifts -> 136 byte_diff of pure ARGUMENT_MISMATCH.

It is circular: baserom keeps `index` live because it caches the finer `i*2`;
ours folds `index` into `i*3` so it never needs `index` separately, so it never
promotes `index` to a high reg. The decision is made in cse.c / local-alloc.c
qty-priority (local-alloc.c:1300 `qty_order` / qty_compare) — `index`'s quantity
out-ranks the entry pointer for r3 in our IR, the opposite of baserom.

## Levers TRIED that do NOT work (don't repeat)

1. `register u32 i asm("ip")` — old_agbcc handles a long-lived ip pin badly:
   it DROPS the r8/r9/sl saves and spills, size jumps to 252-256, byte_diff 239+.
   (Local `asm("ip")` IS accepted by old_agbcc — the prior note's "param asm
   rejected" is only for *parameters*; but the pin regresses regardless.)
2. `register u32 j asm("r6")` — regresses (146 with flag, 215 without).
3. Any EXPLICIT `entry` pointer local (`entry = &entries[i]`, macro `ENTRY(...)`,
   `(u8*)entries + ((i2+i)<<3)`, explicit `i2`/`i3` var, 8-byte-stride view
   indexed by `index*3`) — agbcc CSEs the whole pointer back into ONE cached
   value -> size 188-208, byte_diff 214-221. The PLAIN `entries[i]` subscript
   (recomputed each use) is the ONLY shape that reproduces baserom's recompute.
4. `struct BlitState *st = &gBlitState;` anchor — wrong: baserom reloads the
   0x03006500 literal fresh each loop; anchoring caches it -> 192/200, regress.
5. Flag sweep (all with -fno-expensive, all stuck at 136/140): -fno-gcse,
   -fno-strength-reduce, -freduce-all-givs, -fmove-all-movables (183, worse),
   -foptimize-register-move / -fno-regmove, -fno-cse-follow-jumps,
   -fno-cse-skip-blocks, -frerun-loop-opt, -frerun-cse-after-loop, -funroll-loops,
   -fno-thread-jumps, -fpcc-struct-return, -O1/-O3, -ffixed-r3 (149, worse),
   -ffixed-r2-r3 (221, worse).
6. Newer `AGBCC_BIN` (vs old_agbcc): worse (189 with flag, 215 without).
7. Permuter: scratch is mis-scored here (target.o base score ~2530 vs expected
   ~5*55=275 — the known $t/$d target bug; make_permuter_target also sized the
   target at 224 from our .o, not the 228 baserom). base is also far above the
   <=40 threshold and the residual is a single coloring decision a statement
   reorder is unlikely to flip. Not productive as configured.

## Best-effort C (CLEAN — zero pins, byte_diff 136, structurally identical)

`src/engine/sub_080105b0.s: CFLAGS += -fno-expensive-optimizations`

```c
#include "types.h"

struct BlitEntry {
    u16 dstX;
    u16 dstY;
    u16 cols;
    u16 rows;
    u8 flags;
    u8 _pad09[7];
    const u16 *const *srcTable;
    u8 _pad14[4];
};

struct BlitState {
    u8 _pad00[12];
    const u16 *src;
    u8 _pad10[4];
    u16 *dst;
};

struct SceneScroll {
    u8 _pad00[26];
    u16 stride;
};

#define gBlitState (*(struct BlitState *)0x03006500)
#define gSceneScroll (*(struct SceneScroll *)0x030060A0)

void sub_080105B0(struct BlitEntry *entries, u8 index, u8 srcIndex)
{
    u32 i;
    u32 j;
    u32 row;
    u32 col;

    i = index;
    j = srcIndex;

    if ((entries[i].flags >> 4) & 1) {
        gBlitState.dst = (u16 *)0x02010000;
    } else {
        gBlitState.dst = (u16 *)0x02000000;
    }

    gBlitState.dst += gSceneScroll.stride * entries[i].dstY + entries[i].dstX;
    gBlitState.src = entries[i].srcTable[j];

    row = 0;
    if (row < entries[i].rows) {
        do {
            col = 0;
            if (col < entries[i].cols) {
                do {
                    *gBlitState.dst++ = *gBlitState.src++;
                    col = (u8)(col + 1);
                } while (col < entries[i].cols);
            }

            gBlitState.dst += gSceneScroll.stride - entries[i].cols;
            row = (u8)(row + 1);
        } while (row < entries[i].rows);
    }
}
```
