# sub_08005D10 — deferred analysis

Entity-pool animation-advance loop at 0x08005d10..0x08005ed8 (456 bytes,
asm slice asm/disasm_0x08005d10.s, dest src/game/sub_08005d10.c).

THREE independent passes (Sonnet, Opus, Opus-round-3) reach the SAME plateau
(byte_diff 261 / diff_count 48 under old_agbcc + `-fno-gcse`). Round 3 found
the ROOT CAUSE in the agbcc SOURCE: the residual is a single, **unconditional**
`SYMBOL_REF + CONST_INT` constant-fold in `plus_constant_wide`
(tools/agbcc-src/gcc/explow.c) — a true instruction-selection gap between our
bundled agbcc and whatever compiled the baserom. No clean-C shape, flag, or
register pin escapes it under EITHER bundled agbcc. The logic, control flow,
and struct layout are FULLY CORRECT and verified (three passes agree).

## What it does (confirmed)

`void sub_08005D10(s32 slot, s32 endSlot)` — iterates `gEntities[slot..endSlot]`
(stride 0x38) advancing each entity's animation frame. Cousin (MATCHES):
`sub_08020FE4` (src/engine/sub_08020f3c.c) — same subsystem, same stamp-store
idiom, but its `off` lives in a LOW register (r3), so its `(off+const)+base`
sidesteps the fold below. THIS function's `off` lives in r8 (high), forcing the
const onto the symbol register — exactly the path our agbcc cannot reproduce.

- Gate: `s64 ret = sub_08006830(&gIwram_6110, slot, endSlot); if (ret==0) return;`
  Declare callee `extern s32 sub_08006830(...)` (NOT long long); the s32->s64
  widen-on-assign emits the baserom `asr r1,r0,#0x1f; orr r0,r0,r1`.
- `now = gGameStuff._unk00;` (held in sl naturally).
- 3 pointer givs + index: r8=offset(+=0x38), r5=e(+=0x38), [sp,#20]=field28(+=0x38),
  r9=i(+=1). The stamp address is NOT a giv — it is recomputed each branch as
  `gEntities(bare) + 0x20 + offset(r8)`. Three branches: status-bit-2 set /
  (now-stamp)<delay / else-advance. The best-effort C below is byte-accurate
  except for the fold.

## ROOT CAUSE — the ONLY residual (NEW this pass, confirmed from agbcc source)

Baserom stamp store (3 sites): `ldr r0,=gEntities` (BARE, reloc addend 0)
`; adds r0,#0x20 ; add r0,r8 ; str sl,[r0]`. Our agbcc instead emits
`ldr r0,=gEntities+0x20` (reloc addend 0x20, the +0x20 FOLDED into the literal)
`; add r0,r8` — one insn SHORTER per site. That deletes 3×`adds #0x20`, changes
3 pool addends, and cascades every downstream BL/branch target → byte_diff 261.

**Why it is unconditional** (read tools/agbcc-src/gcc/explow.c
`plus_constant_wide`, ~line 107): for `x = SYMBOL_REF`, `c = 0x20` it sets
`all_constant = 1`, falls to `x = gen_rtx_PLUS(symbol, GEN_INT(0x20))`, and
returns `gen_rtx_CONST(PLUS(symbol, 0x20))` — a single CONST rtx that
`force_const_mem` pools WHOLE. Every C form that yields `plus_constant(symbol,
0x20)` (i.e. any `gEntities + 0x20`, `(u8*)gEntities + 0x20`,
`&gEntities[i].field@0x20`, `sb = gEntities+0x20`, `(off+0x20)+(u32)gEntities`,
`(u32)gEntities + 0x20 + off`) hits this and folds. The address legitimization
(thumb.h `CONSTANT_ADDRESS_P` / `LEGITIMATE_CONSTANT_P`) only un-constants a
BARE pooled SYMBOL_REF, never the symbol+addend CONST — so once folded it stays
folded. To get the baserom shape the symbol must be in a REGISTER (opaque, not
a SYMBOL_REF rtx) BEFORE the +0x20 is applied; no pure-C expression forces that
under this agbcc (and `register`-pinning the symbol does not change the rtl).

This is the SAME root behind all three "issues" the prior note enumerated:
1. stamp-store fold (above) — the only SIZE-affecting diff (456 vs our 460/436).
2. preheader e-vs-offset ordering — field28's add_val `base+0x28` folds, so
   agbcc derives e first; same fold, same-count, not match-breaking alone.
3. AnimDesc table-ptr coloring (`ldr r4,[r1]` vs `ldr r1,[r1]`) — downstream
   register pressure from #2; same-count.

## Verdict
This is a confirmed agbcc-revision instruction-selection gap on
`ldr=sym(bare); adds#const; add highreg`, NOT a source-shape problem (proven in
explow.c). NAKED is NOT appropriate: classify_unmatchable returns ATTEMPT_MATCH
(no class3-libgcc signature), and the corpus has NO C-pairing for the bare-
symbol+runtime-adds idiom (history search over metroidret/pret surfaced only
already-C `adds #0x20` in unrelated code). Shipping NAKED would be a premature,
permanent regression. DEFERRED honestly.

## The only avenue that could land this
Make the bundled agbcc NOT fold `SYMBOL_REF + small CONST_INT` into a pooled
CONST when the symbol is also being added to a register — i.e. obtain/build an
agbcc revision whose `plus_constant`/legitimization splits `symbol + const`
into `ldr=symbol; add const`. That is a toolchain change, out of scope for a
pure-C decomp. Absent that, this function stays an honest asm slice. (Repairing
the permuter venv would NOT help: #1 is a fold, not a coloring/ordering issue.)

#include "game.h"
#include "iwram.h"
#include "macros.h"
#include "types.h"

extern s32 sub_08006830(struct IwramAt6110 *p, s32 lo, s32 hi);
extern u8 sub_08005ED8(u8 state, u8 dir);
extern u8 sub_08005F50(u8 state, u8 dir);

typedef struct SpriteAssetEntry2 {
    u32 id;
    const u8 *ptr;
} SpriteAssetEntry2;
extern const SpriteAssetEntry2 sSpriteAssetTable[];

typedef struct AnimDesc {
    const u8 *frames;
    u32 _unk04;
    u8 frameCount;
    u8 state;
    u8 dir;
} AnimDesc;

typedef struct AnimFrame {
    s8 dx;
    s8 dy;
    u8 _pad02[6];
    u8 delay;
    u8 field_09;
    u16 field_0A;
    u16 field_0C;
    u8 field_0E;
    u8 field_0F;
} AnimFrame;

void sub_08005D10(s32 slot, s32 endSlot)
{
    struct Entity *e;
    u8 *field28;
    u8 *base;
    u32 offset;
    u32 now;
    s32 i;
    AnimFrame frame;

    {
        s64 ret = sub_08006830(&gIwram_6110, slot, endSlot);
        if (ret == 0)
            return;
    }

    now = gGameStuff._unk00;
    i = slot;
    if (i > endSlot)
        return;

    offset = i * 0x38;
    base = (u8 *)gEntities;
    field28 = base + offset + 0x28;
    e = (struct Entity *)(base + offset);
    do {
        if ((e->status & 2) != 0) {
            const AnimDesc *desc = (const AnimDesc *)(sSpriteAssetTable[e->field_00].ptr + e->field_1A * 12);

            frame = *(const AnimFrame *)desc->frames;
            e->field_1C[0] = desc->frameCount;
            e->field_18[1] = sub_08005ED8(desc->state, desc->dir);
            e->field_18[0] = sub_08005F50(desc->state, desc->dir);
            e->field_1B = 0;

            e->field_01 = frame.field_09;
            e->x += frame.dx;
            e->y += frame.dy;
            e->field_24 = frame.field_0A;
            e->field_26 = frame.field_0C;
            field28[0] = frame.field_0E;
            field28[1] = frame.field_0F;
            e->field_1C[1] = frame.delay;
            *(u32 *)((offset + 0x20) + (u32)gEntities) = now;
            e->status = (e->status | 0x100) & 0xFFFD;
        } else if (now - *(u32 *)((offset + 0x20) + (u32)gEntities) < e->field_1C[1]) {
            e->status &= 0xFEFF;
        } else {
            u8 nextFrame = e->field_1B + 1;

            if (nextFrame == e->field_1C[0]) {
                e->status |= 0x8000;
            } else {
                const AnimDesc *desc;

                e->field_1B = e->field_1B + 1;
                desc = (const AnimDesc *)(sSpriteAssetTable[e->field_00].ptr + e->field_1A * 12);
                frame = ((const AnimFrame *)desc->frames)[nextFrame];

                e->field_01 = frame.field_09;
                e->x += frame.dx;
                e->y += frame.dy;
                e->field_24 = frame.field_0A;
                e->field_26 = frame.field_0C;
                field28[0] = frame.field_0E;
                field28[1] = frame.field_0F;
                e->field_1C[1] = frame.delay;
                e->status |= 0x100;
            }
            *(u32 *)((offset + 0x20) + (u32)gEntities) = now;
        }

        offset += 0x38;
        field28 += 0x38;
        e = (struct Entity *)((u8 *)e + 0x38);
        i++;
    } while (i <= endSlot);
}
