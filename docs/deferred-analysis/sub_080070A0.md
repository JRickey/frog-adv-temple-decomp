## What the function does (confirmed)

the first entry being "ripe" (`gGameStuff._unk00 - entry->stamp >= ageMax`,

theory was WRONG:

- There are **ZERO copy-preferences** on any allocno (`copypref=[]` for all).
  Base→r4 in the 34/15 shape is **purely conflict + allocation-ORDER driven**,
  decided in `global.c`, not a copy-suggestion in `local-alloc.c`.

## THE THREE LEVERS THAT FIXED base/entry/active/mask (all pure C)

1. **base=r2, entry=r5, `mov r8,r2`:** compute `active` with a LITERAL `& 2`
   (NOT `& mask`) AND assign `mask = 2` AFTER `active`. Any use of the `mask`
   VARIABLE in the active expression, OR assigning `mask=2` before `active`,
   makes `mask` live during the guard and shoves base back to r4. The literal
   keeps base block-local -> r2 (verified by the debug-agbcc ASSIGN trace).
2. **active=ip, mask=r9 (defeat the active<->mask swap):** with base=r2 fixed,
   `active` (assigned first) otherwise grabs r9 and `mask` gets ip — the reverse
   of the baserom. Reorder/decl tricks do NOT flip it (the first-materialised
   loop-invariant always takes r9). PIN them: `register GameStuff *game asm("r8")`
   and `register s32 mask asm("r9")`. Pins are PURE C (status stays "matched").
   Pinning ONLY mask backfires (pushes game off r8); pin BOTH game and mask.
3. With (1)+(2) the entire guard + setup + loop REGISTER allocation matches the
   baserom (entry=r3 in loop, i=r4, &gEntities=r5, last=r6, game=r8, mask=r9,
   active=ip). Confirmed by objdump: the loop register file is byte-for-byte the
   baserom's.

## THE TWO REMAINING TAILS (both agbcc instruction-selection, NOT register coloring)

These are the entire residual `43/15`. Both resist every C shape tried:

A. **deltaY load form (4 diffs @0x40,0x42,0x4e,0x50).** Baserom loads BOTH
   deltas register-indexed: `movs r0,#17; ldrsb r0,[r3,r0]` (dy) and
   `movs r2,#16; ldrsb r2,[r3,r2]` (dx). agbcc gives dx (offset 0x10) the indexed
   `ldrsb` but emits dy (offset 0x11, the SECOND consecutive s8 read) as
   `ldrb r0,[r3,#17]; lsls#24; asrs#24` (immediate ldrb + late sign-extend). This
   is consistent regardless of read/use/statement order, `s8 *`/`((s8*)e)[0x11]`
   index-cast, or up-front reads. Making dy `s32` DOES force `ldrsb` BUT widens
   it to a callee-saved reg (entry shifts r3->r1, dy->r4) and the loop regs break
   (148 bytes, much worse). Same for `s8 dx; s32 dy`. So: s8 => right regs/wrong
   load; s32 => right load/wrong regs. No middle ground found.
   Corpus (`corpus_asm_search.py --asm 'ldrsb r[0-7],\[r[0-7], r[0-7]\]'`)
   confirms a SINGLE s8 field read DOES lower to indexed ldrsb (pokeemerald
   berry_crush `s8 unk5`); the problem is specifically the SECOND of two adjacent
   s8 reads where agbcc reuses the immediate form. Not yet cracked.

B. **mask `mov r0,r9` before the AND (loop-misalignment, ~3 diffs).** If you also
   SHARE the `#2` constant — `mask = 2;` THEN
   `active = gIwram_35E0._field_10 & mask;` (field FIRST, NO `(u16)` cast, so the
   u16 zero-extension `lsls#16;lsrs#16` is kept) — agbcc DOES emit the baserom's
   shared single `#2` in r9 with the extension (verified: real old_agbcc setup
   becomes `mov r2,#2; mov r9,r2; ldr r0; ldrh r0,[r0,#16]; and r0,r0,r2; lsl;lsr;
   mov ip,r0`). BUT the baserom does `mov r0,r9; ands r0,r1` (re-reads mask from
   r9 -> a high-reg copy, +2 bytes) whereas agbcc keeps `#2` alive in low r2 and
   does `and r0,r0,r2` (no copy). That missing 2-byte `mov r0,r9` shifts the loop
   START 2 bytes early, so EVERY loop branch target mismatches and byte_diff
   balloons to ~101 even though the instructions are otherwise more correct. To
   match you must force mask to be r9-ONLY at the AND (drop the low copy) so the
   `mov r0,r9` reappears AND the loop re-aligns — not achieved.
   NOTE: the SHARED form (lever B) and the SPLIT-constant form (the
   `## Best-effort C` below, two `#2`) are both 152 bytes; the split-constant
   keeps the loop ALIGNED (43/15), the shared form misaligns it (101/20). Ship
   nothing with the shared form until the `mov r0,r9` is also forced.

## Levers RULED OUT this round (do not repeat)

- `s32`/mixed delta types: fix ldrsb, break loop registers (148 bytes, 110/38).
- `active = field & mask` (mask VAR in active): base -> r4 always.
- `mask = 2` before `active`: base -> r4 always.
- `active = mask & field` or `(u16)(... & mask)`: drops the u16 extension
  (agbcc proves result < 0x100) -> 2 bytes short -> branch cascade.
- pin ONLY mask=r9: pushes game off r8 to ip. Pin game=r8 AND mask=r9 together.

- `u32 tick` cache of `_unk00`: no help (42/16), baserom re-reads via r8 in loop.
- Permuter: UNAVAILABLE (the vendor/decomp-permuter symlink is a broken self-loop
  even on main, ".venv missing"); prior note also says its score is inflated ~30x

struct ScrollStepEntry {
    u16 subX;  /* +0x00 */
    u16 subY;  /* +0x02 */
    u8 _pad04[8];
    u32 stamp; /* +0x0C */
    s8 deltaX; /* +0x10 */
    s8 deltaY; /* +0x11 */
    u8 ageMax; /* +0x12 */
    u8 _pad13[7];
    u8 flags;  /* +0x1A */
    u8 _pad1B[9];
};

void sub_080070A0(struct ScrollStepEntry *entries, s32 first, s32 last)
{
    register GameStuff *game asm("r8");
    struct ScrollStepEntry *entry;
    u16 active;
    s32 i;
    register s32 mask asm("r9");

    if (gGameStuff._unk00 - entries[first].stamp < entries[first].ageMax)
        return;

    game = &gGameStuff;

    i = first;
    if (i > last)
        return;

    active = (u16)(gIwram_35E0._field_10 & 2); /* literal &2 keeps base in r2 */
    mask = 2;                                  /* assigned AFTER active, pinned r9 */

    entry = &entries[first];
    do {
        s8 dy = entry->deltaY; /* TAIL A: this lowers to ldrb+sext, not indexed ldrsb */
        s8 dx = entry->deltaX;

        entry->subX += dx;
        entry->subY += dy;

        if (active != 0 && (entry->flags & mask) != 0) {
            gEntities[0].x += dx;
            gEntities[0].y += dy;
        }

        entry->stamp = game->_unk00;
        entry++;
        i++;
    } while (i <= last);
}
