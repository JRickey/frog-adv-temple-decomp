# Deferred analysis: sub_080070A0

**Range:** 0x080070a0 – 0x08007138 (152 bytes, Thumb, OLD_AGBCC TU)
**TU:** src/game/sub_08006b88.c (OLD_AGBCC)
**Struct stride:** 36-byte (0x24) entries, accessed at offsets 0,2,12,16,17,18,26

## Drift

Best byte_diff achieved: ~120/152 bytes (all attempts).
diff_count: ~49 instruction-level mismatches.

The function is a LEAF (no calls) that uses TWO high registers (r8, r9)
simultaneously in the loop body — unusual for a leaf, but forced by
register pressure from 8 simultaneously live values.

### What the target needs

The target's loop has 8 simultaneously live values:
- r3: current entry ptr (changes each iteration, `+= 36`)
- r4: loop counter i (changes each iteration, `+= 1`)
- r5: &gIwram_3720 (stable)
- r6: last (stable)
- r8: &gGameStuff (stable, reloaded each iter via `mov r7, r8; ldr r0, [r7]`)
- r9: constant 2 (stable, used for `e->flags & 2` check)
- ip: cached gIwram_35E0._field_10 & 2 (stable)
- r7: temporary (ldrh targets)

With all 8 stable registers occupied, old_agbcc is FORCED to use
`movs rN, #17; ldrsb rN, [r3, rN]` (register-indexed form, 4 bytes)
instead of `ldrb rN, [r3, #17]` (immediate form, 2 bytes) for the
s8 deltaY load — because no free register is available for the offset.
This is what makes the target 8 bytes LONGER than the best-effort C.

### Register assignment in target prologue

```
adds r3, r1, #0   <- first → r3 (temporary!)
adds r6, r2, #0   <- last  → r6
ldr r2, [pc, #124]  <- r2 = &gGameStuff (0x03005330)
...
adds r5, r1, r0   <- entry0 → r5 (not r3!)
ldr r0, [r2]      <- tick = gGameStuff._unk00
...
mov r8, r2        <- LATE PIN: r8 = &gGameStuff (after tick loaded)
...
adds r4, r3, #0   <- first COPIED from r3 to r4 (r3 freed for entry ptr)
...
movs r2, #2; mov r9, r2  <- r9 = 2 (constant mask, pinned)
mov r0, r9; ... ands r0, r1  <- r0 = field_10 & 2
mov ip, r0        <- ip = field_10 & 2 (cached)
adds r3, r5, #0   <- entry0 COPIED to r3 (from r5, r5 freed for gIwram_3720)
ldr r5, [pc, #84] <- r5 = &gIwram_3720
```

Key: `first` uses r3 TEMPORARILY (before entry0 computation), then is
COPIED to r4. Entry0 uses r5 temporarily, then COPIED to r3. These extra
copies (4 extra instructions = 8 bytes) are artifacts of old_agbcc's
register allocator resolving the tight constraint.

### What I tried (14 variants)

1. **Pure gGameStuff macro + no mask var**: r4=first, r6=last, no r8/r9 saves,
   gGameStuff reloaded from pool each loop. 144 bytes, byte_diff=130.

2. **pGS = (GameStuff*)0x3005330 local ptr**: r4=first, r9=last, ip=&gGameStuff,
   r8=ip_val. Saves r8+r9 but wrong assignments. 144 bytes.

3. **extern u32 gIwram_5330 + mask=2 after checks**: r4=first, r9=last,
   r8=&gIwram_5330, ip=2, r6=field_10&2. Saves r8+r9 but r9=last (wrong).
   144 bytes.

4. **gGameStuff macro + pGS pointer + mask=2**: r4=first, r9=last, r8=&gGameStuff.
   Still r9=last (wrong) because pGS allocated to r8 EARLY, pushing last to r9.

5. **register pin r6=last + extern gIwram_5330 + mask**: r6=last CORRECT, but
   ip/r9 assignments still wrong, and extra duplicate-check branch generated.

6. **Pure gGameStuff macro + mask=2 (early init)**: r4=first, r8=last,
   ip=2, r6=field_10&2. r8=last is wrong.

And many other variations. None reproduces: r8=&gGameStuff, r9=2, r6=last
simultaneously.

### Root cause

With any approach that pins &gGameStuff in a register (forcing r8 save):
- Old_agbcc allocates r8 EARLY for the gGameStuff address
- This pushes `last` from r6 to r9 (r6 is now taken by other values)

With the pure macro approach (no pin for gGameStuff):
- r4=first, r6=last (correct)
- But gGameStuff address is reloaded from pool literal each iteration
- No r8/r9 saves at all

The target achieves r8=&gGameStuff + r6=last by LATE-BINDING r8:
- first → r3 (using arg register as temp)
- last → r6 (using callee-saved register)
- gGameStuff pool loaded to r2, then late-pinned via `mov r8, r2`

This late-binding pattern from the gGameStuff MACRO (not a local pointer)
only happens when old_agbcc's liveness analysis sees the pool-loaded address
as needing survival through the loop AND there's a specific ordering of
register saves. I couldn't reproduce this combination.

## Best-effort C

```c
/* Struct for 36-byte entries with movement deltas */
struct MoveEntry {
    s16 subX;  /* +0 */
    s16 subY;  /* +2 */
    u8 _pad04[8];
    u32 stamp;   /* +12 */
    s8 deltaX;   /* +16 */
    s8 deltaY;   /* +17 */
    u8 ageMax;   /* +18 */
    u8 _pad13[7];
    u8 flags;  /* +26 */
    u8 _pad1b[9];
};

/* Sweeps [first, last] entries, applying deltaX/deltaY to sub-pixel coords
 * (+0/+2), and when gIwram_35E0._field_10 & 2 != 0 and entry->flags & 2 != 0,
 * also updating gIwram_3720._field_2/4. Refreshes entry->stamp each iteration.
 * Gate: skips entirely if first entry's age (tick - stamp) < ageMax. */
void sub_080070A0(struct MoveEntry *entries, s32 first, s32 last)
{
    struct MoveEntry *entry0 = entries + first;
    u32 tick = gGameStuff._unk00;
    u32 mask;
    u32 ip;
    struct MoveEntry *e;
    s32 i;

    if (tick - entry0->stamp < (u32)entry0->ageMax)
        return;
    if (first > last)
        return;

    mask = 2;
    ip = gIwram_35E0._field_10 & mask;
    e = entry0;

    for (i = first; i <= last; i++, e++) {
        s8 dx = e->deltaX;
        s8 dy = e->deltaY;

        e->subX += dx;
        e->subY += dy;

        if (ip != 0 && (e->flags & mask) != 0) {
            gIwram_3720._field_2 += dx;
            gIwram_3720._field_4 += dy;
        }

        e->stamp = gGameStuff._unk00;
    }
}
```
