## Drift

The function advances 0x24-byte scroll-step entries over inclusive `[first, last]`.
For each ripe entry (`gGameStuff._unk00 - stamp >= ageMax`) it adds signed
deltaX/deltaY to the entry sub-coordinates, optionally mirrors the same raw
delta onto `gEntities[0].x/y` when both `gIwram_35E0._field_10 & 2` and
`entry->flags & 2` are set, then refreshes the entry stamp.

The clean C reaches exact size but stays in a coupled allocator minimum:

- Target initial block: `first` in `r3`, `last` in `r6`, entry base in `r5`,
  game base loaded in `r2`, then `mov r8, r2` only after the first tick read.
- old_agbcc clean C: coalesces `first/i` through `local-alloc.c:combine_regs`,
  materializes the game pointer into `r8` before entry arithmetic, uses `entry`
  in `r3`, puts `mask` in `ip`, and puts `active` in `r9`.
- Target loop wants `mask = 2` in `r9`, `active` in `ip`, `entry` in `r3`,
  and `gEntities` in `r5`.

Newly ruled out in this GPT-5.5 round:

- Newer `agbcc` per-TU override: worse, `byte_diff 72` / `diff_count 44`.
- Split `start = first` and `end = last` source shapes: no improvement or worse
  (`60/33`, `63/34`, `71/44` depending on the local).
- `tick = gGameStuff._unk00` source shape: regresses to 144 bytes (`126/52`).
- Pins for `start=r3`, `end=r6`, `i=r4`, `mask=r9`, `active=ip`: regresses to
  148 bytes or worse; `active=ip` drops the required zero-extension sequence.
- `mask=r9` alone with the entity-base experiment: `120/43`.
- `game=r8`: `55/30`, confirms the known wrong early `mov r8` materialization.
- `(active & mask) != 0` condition shape: `87/44`.
- `register struct Entity *entity asm("r5")` alone reaches `53/27`, but the
  generated code overlaps the pinned `r5` with the live entry pointer and is not
  a correct readable C base. A scoped `entryBase r5 -> entry` / `entity r5`
  reuse attempt is safer but worse (`56/28`).
- Per-TU `CFLAGS += -fno-gcse`: shifts earlier functions in the TU and moves
  this symbol to `0x080070b0` (`LAYOUT DRIFT +0x10`).
- Per-TU `CFLAGS += -fno-schedule-insns`: rejected by `old_agbcc`.
- Corpus current-tree grep for flag/delta patterns found only broad unrelated
  patterns. History searches for `mov (r8|r9|ip), rN` and indexed `ldrsb`
  with `--require-c` returned zero hits.

Compiler source read:

- `tools/agbcc-src/gcc_arm/local-alloc.c`: copy combining favors tying
  `i = first` when it can save a move.
- `tools/agbcc-src/gcc_arm/global.c`: `allocno_compare` orders pseudos by
  `floor_log2(refs) * refs / live_length`, explaining the stubborn
  `mask`/`active` priority swap.
- `tools/agent/agbcc_oracle.py --pass greg` on the clean C shows the key
  dispositions: mask in `ip`, active in `r9`, entry in `r3`, game in `r8`.

Next useful move is private instrumentation of `old_agbcc` around
`local-alloc.c:combine_regs` and the global allocation decision for the
mask/active pseudos, to find a source shape that prevents the `first/i`
coalescing and flips mask/active without explicit pins.

#define SCROLL_ENTRY_MIRROR_FLAG 2

struct ScrollStepEntry {
    u16 subX;
    u16 subY;
    u8 _pad04[8];
    u32 stamp;
    s8 deltaX;
    s8 deltaY;
    u8 ageMax;
    u8 _pad13[7];
    u8 flags;
    u8 _pad1B[9];
};

void sub_080070A0(struct ScrollStepEntry *entries, s32 first, s32 last)
{
    GameStuff *game = &gGameStuff;
    struct ScrollStepEntry *entry = &entries[first];
    s32 mask = SCROLL_ENTRY_MIRROR_FLAG;
    s32 i;
    u16 active;

    if (game->_unk00 - entry->stamp < entry->ageMax)
        return;

    if (first > last)
        return;

    active = (u16)(gIwram_35E0._field_10 & mask);

    i = first;
    do {
        s8 deltaY = entry->deltaY;
        s8 deltaX = entry->deltaX;

        entry->subX += deltaX;
        entry->subY += deltaY;

        if (active != 0 && (entry->flags & mask) != 0) {
            gEntities[0].x += deltaX;
            gEntities[0].y += deltaY;
        }

        entry->stamp = game->_unk00;
        entry++;
        i++;
    } while (i <= last);
}
