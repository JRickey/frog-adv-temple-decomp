## Drift

The clean C shape matches the instruction count and loop structure but not register coloring.
The remaining differences are register-allocation couplings, not control-flow differences:

- Target keeps `&gGameStuff` in scratch `r2` for the initial tick read, then copies it late into `r8`; agbcc colors the same loop-live pointer pseudo into `ip` and puts `active = gIwram_35E0._field_10 & 2` in `r8`.
- Target keeps `first` in `r3`, then copies it to loop counter `r4`; agbcc merges `first` and `i` into `r4`, cascading `entry`/`gEntities` into `r3`/`r4` instead of target `r3`/`r5`.
- Target uses register-offset `ldrsb` for both signed deltas; agbcc emits `ldrb` plus shift sign-extension for the +17 delta.

Compiler pass read: `tools/agbcc-src/gcc_arm/global.c`.
`allocno_compare()` sorts pseudos by `floor_log2(refs) * refs / live_length`, and `find_reg()` can use call-clobbered regs in this call-free leaf. `REG_ALLOC_ORDER` in `config/arm/arm.h` puts `ip` before `r8`, so the higher-priority loop-live `gGameStuff` pointer grabs `ip` before the lower-priority active flag can. This explains the stable `pointer -> ip`, `active -> r8` coloring.
