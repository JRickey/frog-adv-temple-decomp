# sub_080076A4 — deferred (register-coloring local minimum, byte_diff 71)

## Summary

`sub_080076A4(ctx, rect)` null-checks both args, then transforms a
centre+extent rectangle into two packed `{s16 lo; s16 hi;}` points and
tail-calls `sub_0800CED0(ctx, pos, ext, 0, 0)`. The structure is fully
understood and the C below is semantically exact; the residual is a pure
agbcc register-coloring / SUBREG-insertion divergence.

NOTE on the slice: the original `asm/disasm_0x080076a4.s` peel (0x108 bytes,
0x076a4–0x077ac) actually contained TWO functions — `sub_080076A4`
(0x076a4–0x07712) and an unnamed second function at 0x07714
(0x07714–0x077ac, structurally near-identical: same rect→packed-point
transform but with two extra signed s16 args sign-extended and a 5-reg+hi
prologue). A clean decomp of just sub_080076A4 must first re-peel the second
function into its own slice `asm/disasm_0x08007714.s` (name `sub_08007714`)
and split the linker.ld entry. (This attempt did that, then reverted; redo it
on the next attempt.)

## Function semantics (target, exact)

```
ip   = ctx                 (survives whole body, reloaded into r0 before bl)
r3   = rect
if (ctx == 0 || rect == 0) return 0;

pos.x (lo) = (u16)(rect->_h2 - (rect->_h6 >> 1))
pos.y (hi) =        rect->_h0 - (rect->_h4 >> 1) - 1
ext.x (lo) =        rect->_h4
ext.y (hi) =        rect->_h6        ; reuses r5 = _h6<<16 from the pos.x calc

return sub_0800CED0(ctx, pos /*r1*/, ext /*r2*/, 0 /*r3*/, 0 /*sp[0]*/);
```

`sub_0800CED0` signature (inferred): `(void *ctx, struct {s16 x; s16 y;} a,
struct {s16 x; s16 y;} b, s16 c, s16 d)` — two packed points by value (r1, r2),
then two s16 (r3, stack), with d pushed to sp[0] before the call.

## Drift

- Best: **byte_diff 71, diff_count 37**, with the ip-pin + OLD_AGBCC base below.
- OLD_AGBCC is REQUIRED: it fixes the `pos.y` arithmetic from the new-agbcc
  `mvns r0,r0; adds r0,r0,r3` (`-x-1 → +~x` combine fold) to the target's
  `subs r0,r3,r0; subs r0,#1`. (Makefile per-TU `... .s: CC = $(OLD_AGBCC_BIN)`,
  same as the sibling `sub_080077ac.s`.)
- `register void *c asm("ip") = ctx;` is REQUIRED to get ctx into `ip` (without
  it OLD_AGBCC parks ctx in a callee-saved reg r4/r5 → byte_diff 76). But the
  pin then emits `adds rect,r1,#0` BEFORE `mov ip,r0`; target order is
  `mov ip,r0` first. ~2 bytes of the residual.

The dominant, unreached drift is the **packing method for `pos`**:
  - target builds BOTH pos and ext with the 6-instr MASK form
    `ldr =0xffff0000; mov rT,=const; ands pos, rT(garbage); orrs pos, lo;
     ands pos, =0x0000ffff; orrs pos, hi<<16` — reusing the two mask constants
    across both packs (CSE), which also raises register pressure enough that
    ctx naturally spills to `ip`.
  - agbcc here builds `ext` with the mask form but `pos` with a SHIFT form
    (`lsls hival,#16` then `lsrs pos,loval,#16; orrs pos, hival`) because
    `pos.x` is a COMPUTED value (`_h2 - _h6/2`) whereas `ext.x` is a clean
    field copy (`_h4`). The SUBREG-insertion path for a register-allocated
    packed struct picks shift for the computed field and mask for the copy.
  - This also flips the pos↔ext register colouring (target pos→r6/ext→r7;
    we get pos→r7/ext→r6).

## Best-effort C (byte_diff 71 / 37; REQUIRES per-TU OLD_AGBCC)

```c
#include "iwram.h"
#include "macros.h"
#include "types.h"

struct PackedPoint {
    s16 x;
    s16 y;
};

struct CenterRect {
    u16 _h0;
    u16 _h2;
    u16 _h4;
    u16 _h6;
};

extern s32 sub_0800CED0(void *ctx, struct PackedPoint a, struct PackedPoint b, s16 c, s16 d);

s32 sub_080076A4(void *ctx, struct CenterRect *rect)
{
    register void *c asm("ip") = ctx;
    struct PackedPoint pos;
    struct PackedPoint ext;

    if (c == NULL || rect == NULL)
        return 0;

    pos.x = rect->_h2 - (rect->_h6 >> 1);
    pos.y = rect->_h0 - (rect->_h4 >> 1) - 1;
    ext.x = rect->_h4;
    ext.y = rect->_h6;

    return sub_0800CED0(c, pos, ext, 0, 0);
}
```
