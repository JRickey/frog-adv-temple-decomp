Animated tile-blit tick handler. Reads sentinel `gIwram_3610` (0x03003610); if `== 1`,
throttles on the per-descriptor `timeStep` vs `gGameStuff._unk00`, blits one frame via
`sub_0801025C(rows,cols,x,y,bank,frame,dst)`, then ALWAYS calls `sub_0800E7D4()`.
Descriptor = 24-byte record at `0x08306E64` (field map in the C below). State record at
`0x030064C0` (`lastTick` +4, `frameIndex` +10). Coords x/y are signed halfwords at
`0x03003720 + 0x692/0x694`, each `*3` then `(u16)`. `dst` is 0x0600E000 / 0x0600E800 per
`(bankNibble>>4) & 1`. Control flow: `*flag != 1` -> jump to the sub_0800E7D4 tail
(0x12afe); timeStep-not-elapsed -> plain return WITHOUT calling sub_0800E7D4 (0x12b02).

## Progress this session (Opus round 5): 86/41 -> **79/31**, with the CORE allocation cracked

The prior session's 86/41 plateaued with state/desc swapped AND flag=sl/dst=r9/bank=ip.
This session got **flag=r9, bank=SPILLED to [sp,#12], frame=`sub sp,#16`, AND the coords
indexed-load `ldrsh r3,[r2,r4]` all CORRECT** — the entire left two-thirds of the function
now matches. Two findings did it:

### Finding 1 — `state asm("r6")` pin fixes the state/desc swap (cheap, load-bearing)
The natural alloc puts `state` (0x030064C0; refs=6, ll~106, high priority) in **r8** and
`desc` in r7, forcing extra `mov r3,r8; ldrb` copies and a y-coord spill. The target wants
state in **r6** (low reg, direct `ldrb [r6,#10]`). Pinning `register ScaleBlitState *state
asm("r6")` makes desc->r7, frames->r8 fall out NATURALLY (no frames pin needed) and removes
the swap. This alone: 130->... and combined with the rows/cols hoist + `one asm("r1")`
(below) -> 83/33.

### Finding 2 — the **subtraction trick** creates the pressure that SPILLS `bank` (the big one)
The target SPILLS `bank` (the `>>4` nibble, arg4) to `[sp,#12]` and reloads it for the arg
(`ldr r4,[sp,#12]; str r4,[sp,#0]`), giving a 16-byte frame and leaving the dead-`sl` the
prior session chased. Clean C keeps bank in a callee-saved reg (sl/ip) — NO spill, 12-byte
frame. The prior session's `volatile bank` forced the spill but reloaded at every use (bad).

The spill is a REGISTER-PRESSURE artifact: it only happens when one more callee-saved value
is live across the coords block than there are free callee-saved regs. Writing the frame
index increment as:

```c
    state->frameIndex++;
    frameIndex = state->frameIndex - 1;   /* recover the pre-increment value */
```

instead of `frameIndex = state->frameIndex; state->frameIndex = frameIndex + 1;` adds exactly
one short-lived pseudo (the `state->frameIndex` re-read + subtract) whose live range overlaps
bank's. That tips the allocator into **spilling bank** — and the spill CASCADES: flag moves
sl->**r9** (correct), the frame grows to 16 (correct), and the coords x-load stops folding so
it becomes the target's `ldrsh r3,[r2,r4]` indexed form (correct). This is the single most
valuable lever found. (It IS a semantic no-op but reads as a hack — see "remaining" for why
the target's NATURAL pressure source is the `<<24>>22` idiom, not this subtraction.)

The 79/31 base (in "Best-effort C") = state=r6 + `one asm("r1")` (for the `movs r1,#1`
mask) + rows/cols hoist + the subtraction trick + a `useAlt` temp.

### Wall A — frames<->dst swap (THE blocker)
Both `frames` (desc->frames) and `dst` (e000/e800) are computed before coords and die before
the `bl`. The target gives the LONGER-lived `dst` the caller-saved **ip** and the shorter
`frames` the callee-saved **r8** — backwards from the usual "longer-lived gets callee-saved".
The 79/31 build does the natural thing (frames=ip via higher priority, dst=r8). Root cause
(greg `-dg`): priority `floor_log2(refs)*refs/live_length` makes `frames` (ll~35) outrank
`dst` (ll~74), so frames grabs `ip` (first in REG_ALLOC_ORDER for a non-call-crossing value),
dst falls to r8. The target's dst-in-ip must come from a **copy-preference** (`mov ip,rN`
builds dst directly into ip) the clean C doesn't trigger.

Levers RULED OUT for the swap this session:
- `register const u32 *frames asm("r8")`: TRIGGERS AN AGBCC MISCOMPILE on this
  pressure base — agbcc silently DROPS THE WHOLE BODY (output calls sub_0801025C 0 times,
  ~4 insns, just the `*flag!=1` early-exit). Reproduced with/without the state=r6 pin. DO
  NOT pin frames=r8 on the subtraction base; verify `grep -c sub_0801025C` on the .s.
- `register u32 dst asm("ip")`: gets dst=ip + frames=r8 BUT RELIEVES the pressure, so bank
  goes back into sl (no spill), frame back to 12, coords re-fold. 154/50. The pin defeats
  Finding 2.
- moving dst-select AFTER coords (to shorten dst's range): 163/88 (target computes dst
  BEFORE coords — do not move it).
- loading frames early to lengthen its range: 157/54.
- `useAlt` temp / split selector: cosmetic only (33->31 diff_count), no swap.
- decomp-permuter from the 910-score base (base79), -j4, ~4 min: 910->780, NO match.
  The swap needs a coordinated copy-preference change the permuter's local mutations miss
  (same conclusion as the prior session).

### Wall B — `<<24>>22` frame-index idiom
Target: `ldrb r4,[r6,#10]; adds r5,r4,#1; strb r5,[r6,#10]; lsls r4,#24; lsrs r4,#22; add
r4,r8`. The `<<24>>22` is `((u8)oldIdx) << 2` — agbcc RE-narrows a freshly-`ldrb`'d u8. Clean
C emits `lsls r4,#2` directly (agbcc tracks the ldrb result as clean-u8). Tried (none emit
`<<24>>22`): `(u8)frameIndex` cast in subscript, `int frameIndex`+`&0xFF` (gives `mov
#0xff;and`), `state->frameIndex++` postfix, `*(u8*)&state->frameIndex`, index-before-store.
HYPOTHESIS for the next agent: the target's `<<24>>22` is likely the NATURAL pressure source
that spills bank (replacing my artificial subtraction). Find the C that emits `<<24>>22`
(probably `frameIndex` being a wider/signed type re-narrowed for the `u32*` subscript, or the
index being a multi-step expression) and the subtraction hack should become unnecessary AND
the swap may resolve simultaneously.

## Best-effort C (79/31 — state=r6 + one=r1 + subtraction trick; bank spills, flag=r9, coords OK)

```c
#include "game.h"
#include "types.h"

struct ScaleBlitDescriptor {
    u16 field_00;
    u16 field_02;
    u8 cols;       /* +4  -> arg1 */
    u8 pad_05;
    u8 rows;       /* +6  -> arg0 */
    u8 pad_07;
    u8 bankNibble; /* +8  -> bank = (>>4); (&1) selects dst */
    u8 pad_09;
    u16 frameCount;/* +10 (halfword) */
    u8 timeStep;   /* +12 */
    u8 pad_0D[3];
    const u32 *frames; /* +16 */
    u32 pad_14;
};

struct ScaleBlitState {
    u8 pad_00[4];
    u32 lastTick;   /* +4 */
    u8 pad_08[2];
    u8 frameIndex;  /* +10 */
};

extern u8 gIwram_3610;
#define sScaleBlitDesc_6E64 (*(const struct ScaleBlitDescriptor *)0x08306E64)

extern void sub_0801025C(u8 rows, u8 cols, u16 x, u16 y, u32 bank, u32 frame, u32 dst);
extern void sub_0800E7D4(void);

void sub_08012A6C(void)
{
    u8 *flag;
    GameStuff *gs;
    register struct ScaleBlitState *state asm("r6"); /* else state->r8, forcing copies + y-spill */
    const struct ScaleBlitDescriptor *desc;
    u32 tick;
    u32 bank;
    u32 dst;
    const u32 *frames;
    u8 *coords;
    u16 x;
    u16 y;
    u8 rows;
    u8 cols;
    u8 frameIndex;

    flag = &gIwram_3610;
    if (*flag != 1)
        goto done;

    gs = &gGameStuff;
    state = (struct ScaleBlitState *)0x030064C0;
    tick = gs->_unk00;
    desc = &sScaleBlitDesc_6E64;
    if (tick - state->lastTick < desc->timeStep)
        return;

    state->lastTick = tick;

    bank = desc->bankNibble >> 4;
    {
        register u32 one asm("r1"); /* fresh `movs r1,#1` mask for `bank & 1` */
        u32 useAlt;

        one = 1;
        useAlt = bank & one;
        dst = 0x0600E000;
        if (useAlt)
            dst = 0x0600E800;
    }

    frames = desc->frames; /* WANT r8; currently ip (Wall A) */
    rows = desc->rows;
    cols = desc->cols;
    coords = (u8 *)0x03003720;
    x = *(s16 *)(coords + 0x692) * 3;
    y = *(s16 *)(coords + 0x694) * 3;

    /* The subtraction recovers the pre-increment index; the extra pseudo's live range
       overlaps `bank`, tipping the allocator into SPILLING bank to [sp,#12] (-> flag=r9,
       16-byte frame, indexed coords load). The target gets the same pressure from its
       `<<24>>22` index idiom (Wall B) — replace this hack once that idiom is reproduced. */
    state->frameIndex++;
    frameIndex = state->frameIndex - 1;
    sub_0801025C(rows, cols, x, y, bank, frames[frameIndex], dst);

    if (state->frameIndex >= desc->frameCount)
        *flag = 0;

done:
    sub_0800E7D4();
}
```
