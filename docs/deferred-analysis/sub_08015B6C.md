# sub_08015B6C deferred analysis

## Drift

Target is a leaf 2D rectangular `u16` tile copy, range `0x08015B6C..0x08015C24`
(184 bytes). Signature model:

```c
void sub_08015B6C(u8 mode, s16 dstX, s16 dstY, u8 widthArg, u8 heightArg,
                  struct TilemapBlitSource *src);
```

`mode` selects the EWRAM destination bank: 0 -> `0x02000000`, 1 ->
`0x02010000`, 2 -> `0x02020000`. Destination offset is
`dstY * (*(u16 *)(0x030060A0 + 0x1A)) + dstX`, with signed `s16` casts for
`dstX`/`dstY`. Source tiles are at `src + 0x0C`; source row stride is `u16` at
`src + 0x30`.

Classifier verdict: `ATTEMPT_MATCH`. No callees.

Best current pure-C floor is still `byte_diff 41`, `diff_count 19`, exact size
184. The loop body matches; remaining drift is:

1. Prologue parameter setup: target loads both stack args first
   (`ldr r4,[sp,#28]`, `ldr r5,[sp,#32]`, `mov r8,r5`) before width/height
   shifts and before `mov ip,r2`. agbcc emits the `src` high-reg assignment as
   a body statement after the `r3`/`r4` pre-shifts.
2. Offset block: target casts `dstX` through `r0` into `r2`, lowers `ip` through
   `r7`, and loads `0x030060A0` late. The best C emits an in-place `r2` cast,
   lowers `ip` through `r3`, and materializes the scroll-state base earlier.
3. `srcp` high-reg lowering: target uses `mov r7,r8; ldr r3,[r7,#12]` and
   later `mov r7,r8; ldrh r7,[r7,#48]`. Best C lowers through `r0`, because
   `r0` is free at both reload sites.

Newly ruled out in this run:

- Clean readable loop with no pins: builds but gives `byte_diff 97`,
  `diff_count 72`.
- Unsigned-argument/source-level loop reshaping modelled after
  `sub_08012BC4`: worsens size to 176 and `byte_diff 149`.
- Register initializers (`register ... asm("r8") = src`, etc.) do not move
  the prologue load early; they worsen to `43/23`.
- Typed or integer two-step `r7` source-pointer loads can produce `mov r7,r8`,
  but spill the field load through `[sp,#12]` or add extra copies, regressing
  to `41/18` or `66/21`.
- Inlining `(s16)dstX` in the offset expression gets a different shape but
  stores `dstX` in `r9`, shifts the pool, and regresses to size 188 /
  `byte_diff 170`.
- A per-TU `-ffixed-r0` probe is invalid for this clustered C file: it changes
  earlier functions and shifts `sub_08015B6C` by +4 bytes.
- Prototype parameter `asm("r8")` is rejected by agbcc. Old-style parameter
  declarations compile but produce the same `41/19` code.
- Diagnostic empty `asm` barriers after `srcp = src` and `dy = ...` do not move
  the prologue high-reg setup; they only emit `.code 16` markers in the `.s`.
- Corpus current-tree search has many `mov r7,r8` asm hits, but no history
  `--require-c` pairing was found for the exact prologue/high-reg lowering
  searched in this worktree.

Relevant agbcc pass notes: `function.c::assign_parms` emits only the stack
height parameter early; the `srcp = src` hard-register assignment is emitted
after `NOTE_INSN_FUNCTION_BEG`. `reload1.c` then chooses `r0` as the cheapest
low scratch when lowering `r8` because the offset result in `r0` is dead.
Further progress likely needs a source form that makes the stack `src` copy an
early parameter home without changing earlier functions in the TU, or a deeper
private-compiler trace around the high-register copy emission/reload scratch
choice.
