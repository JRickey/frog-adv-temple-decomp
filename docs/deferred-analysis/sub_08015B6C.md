# sub_08015B6C — deferred analysis

2D rectangular tilemap copy (a `sub_08012BC4` cousin). Copies a
`width x height` rectangle of u16 tiles from `src->tiles` (struct field 12,
row stride at field 48) into one of three EWRAM buffers selected by `mode`
(0 -> 0x02000000, 1 -> 0x02010000, 2 -> 0x02020000), at sub-rect origin
(dstX, dstY), using the global scene stride at `*(u16*)(0x030060A0+26)`.

Range 0x08015B6C..0x08015C24 (184 bytes). Leaf (no calls).
Classifier: ATTEMPT_MATCH (no `mov pc`, no high-reg-across-bl, not class3).
Dest: `src/engine/sub_08015a00.c` (append after `sub_08015B20`).

## Status

The C below is **structurally byte-perfect** — every Thumb instruction is
present in the right order. It is stuck at **byte_diff 104 / diff_count 72**
purely on (A) a loop-invariant base-load *scheduling* difference and (B) a
consistent callee-saved-register *renaming*. Many fundamentally different
attempts (below) all bottom out; no pure-C shape with the project's default
`old_agbcc` escapes the local minimum.

## Drift

Two independent clusters, both present in EVERY attempt:

### Cluster A — loop-invariant base load placement (the real blocker)
The base `0x030060A0` is read for `stride` pre-loop AND reloaded inside the
loop (`state[13] - width`), so it is loop-invariant and gets cached in a
callee-saved reg (r9). 
- **Target**: casts dstX/dstY FIRST (`lsls/asrs` into r2 and r0), THEN
  `ldr r1,[pc,#92]` (base into LOW r1), `ldrh r3,[r1,#26]`, `muls`, and emits
  `mov r9,r1` as the VERY LAST preheader insn (right before the loop top).
- **old_agbcc (every attempt)**: hoists the whole base-load+cache to the TOP
  of the post-switch block — `ldr r7,[pc]; mov r9,r7; mov r0,r9; ldrh r2,[r0,#26]`
  — BEFORE the dstX/dstY casts.
This is `loop.c` `move_movables` preheader emit-position + the scheduler. It
is NOT controllable by source shape (confirmed: idx-temp split, separate
`loopState` ptr, inline `((u16*)0x030060A0)[13]`, reordering srcData vs dst
all leave it). `-fno-gcse` does NOT defeat it (it is loop-invariant motion,
not gcse). `-fno-schedule-insns`/`-insns2` are rejected by old_agbcc.

### Cluster B — callee-saved register renaming
Consistent permutation of a perfect structure:
| var      | target | old_agbcc (clean) |
|----------|--------|-------------------|
| height   | r4     | r6                |
| width    | r5     | r3 (caller-saved) |
| dst      | r6     | r5                |
| srcData  | r3     | r2                |
| col      | r2     | r1                |
| nextRow  | r1     | r4                |
Root cause: `qty_compare` priority (`floor_log2(n_refs)*n_refs*size/(life)`)
puts `width` highest in old_agbcc → it grabs r3 (first in `REG_ALLOC_ORDER`
`{3,2,1,0,12,14,4,5,6,...}`); the target keeps width in callee-saved r5.

## Levers tried (all fail)
- Clean (no pins), several local-decl orders: **byte_diff 104**, perfect struct.
- `register u8 height asm("r4") = heightArg`: **diff_count 44** (BEST) — PERFECT
  prologue, cascades width->r5, dst->r6. But adds (a) Cluster A and (b) an r4
  re-truncation in the loop (`adds r0,r4,#0; lsls r4,#24; cmp; lsrs r4,#24`,
  +8 bytes, size 192). The u8-init form is the ONLY one that cascades.
- `register u32 height asm("r4"); height=(u8)heightArg`: no re-trunc, size 184,
  but LOSES the cascade -> 105.
- `register int height asm("r4")`: signed `bge` instead of `bcs` -> 105.
- Full pins (width=r5,height=r4,src=r8,dst=r6 via init): prologue grows to
  size 200 (extra `mov rN` per pinned param) -> 145.
- Pins via plain assignment, body pins (row=r0,col=r2,srcData=r3): size 192 -> 114.
- `-ffixed-r1/-r2/-r3`: 148-188 (forces spills). `-fno-gcse`/`-fforce-addr`/
  `-fno-strength-reduce`/`-fno-expensive-optimizations`/`-fno-cse-follow-jumps`/
  `-fno-rerun-cse-after-loop`: all 104-113, no help.
- Compiler swap to newer AGBCC_BIN: size 176, byte_diff 153 (wrong model).
- Permuter ~1830 iters (`-j4 --better-only`): base score 1165 -> best 875, but
  the 875 variant (`int new_var=0; col=new_var`) compiles to byte_diff 178 under
  old_agbcc — the permuter's compile path diverges from the project's, so its
  score is not predictive here. NOT productive.

## Next attempt — start from the height-pin diff-44 base
The `register u8 height asm("r4") = heightArg` version is the structural floor
(diff_count 44). To finish it you must independently kill (A) the base-load
hoist position and (B) the r4 re-truncation. (A) likely needs an agbcc cut whose
`move_movables` emits the invariant copy last (instrument `loop.c` to confirm),
or a backend tweak — no source lever found. If (A) is truly fixed only by a
different toolchain, this function may be a genuine old_agbcc miss and stays
deferred. Do NOT ship NAKED (it is ATTEMPT_MATCH, not STRONG_UNMATCHABLE).

## Best-effort C

```c
struct BlitSource {
    u8 _pad00[12];
    const u16 *tiles;
    u8 _pad10[32];
    u16 srcStride;
};

void sub_08015B6C(u8 mode, s16 dstX, s16 dstY, u8 width, u8 height, struct BlitSource *src)
{
    u16 *dst;
    u16 *state;
    const u16 *srcData;
    u16 stride;
    u8 row;
    u8 col;

    switch (mode) {
    case 0:
        dst = (u16 *)(0x80 << 18);
        break;
    case 1:
        dst = (u16 *)0x02010000;
        break;
    case 2:
        dst = (u16 *)0x02020000;
        break;
    }

    state = (u16 *)0x030060A0;
    stride = state[13];
    dst += dstX + dstY * stride;

    srcData = src->tiles;
    row = 0;
    while (row < height) {
        col = 0;
        if (col < width) {
            do {
                *dst++ = *srcData++;
                col = (u8)(col + 1);
            } while (col < width);
        }
        dst += state[13] - width;
        srcData += src->srcStride - width;
        row = (u8)(row + 1);
    }
}
```
