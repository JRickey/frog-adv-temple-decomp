`sub_080185C0` @ 0x080185c0, 0x88 (136) bytes. Range **[0x080185c0, 0x08018648)**.
Lives as the first `thumb_func_start` of `asm/disasm_0x080185c0.s` (the slice already

## What the function does (logic fully recovered, verified correct)

Time-gated cyclic DMA + alpha-blend setup. Takes the 16-byte `sOamDmaCfg_08100`
config record. The existing callers (`sub_08019834.c`, `sub_0801f418.c`,
`sub_0801fd0c.c`) declare it as **`(u32 a, u32 b, u32 c, u32 d)`** and pass
`sOamDmaCfg_08100[0..3]` — but agbcc keeps four plain u32 params in callee-saved
registers and reads the narrow members via bit-shifts (`lsls/lsrs`), which does NOT
match. The matching ABI is a **16-byte struct passed by value**: agbcc spills r0-r3
to a 16-byte stack home (`sub sp,#16; str r0..r3,[sp,#0/4/8/12]`) and reads the
narrow members straight from the spill (`ldrh [sp,#0]`, `ldrb [sp,#2]`,
`ldr [sp,#4]`, `ldr [sp,#8]`, `ldrh [sp,#12]`). Passing 4 separate u32 args in
r0-r3 is byte-identical to passing a 16-byte struct by value, so when this lands the
three caller decls should switch to `sub_080185C0(*(DmaCycleCfg*)sOamDmaCfg_08100)`.

Struct layout (exact, from the member loads):
  - +0  u16  limit          (cycle wrap count; sOamDmaCfg_08100 → 0x0008)
  - +2  u8   delay          (frames between advances; → 0x08)
  - +4  const u32* srcTable (DMA source pointer list; → 0x0830809c)
  - +8  void* dst           (DMA dest; → 0x06007b80 VRAM)
  - +12 u16  dmaHalfwords   (byte count; → 0x0480 → cnt = DMA_ENABLE | (0x480>>1))

State struct at IWRAM 0x03006480: `[+4] u32` timestamp, `[+0xa] u8` cycle index.
`sub_08000900()` returns the global frame counter (gGameStuff._unk00).

Every `delay` frames (since `state[+4]`), advance `state[0xa]` (reset to 0 when it
reaches `limit`), DMA `srcTable[state[0xa]] → REG_DMA3` (`dmaHalfwords>>1` halfwords,
DMA_ENABLE), bump `state[0xa]`, restamp `state[+4]`. Then unconditionally write
REG_BLDCNT(0x04000050)=0x1142, REG_BLDALPHA(0x04000052)=0x0909.

## Drift — REVISED (this Opus pass; supersedes the old -O1 path)

**Best result: byte_diff 8, diff_count 6 at the DEFAULT build (-O2 / old_agbcc, NO
per-TU flag).** This is a cleaner, better-characterised plateau than the prior note's
`-O1 byte_diff 4` path: at default -O2 the limit-comparison REGISTERS are already
correct (state→r1, limit→r0, `cmp r1,r0; bcc`) — the only comparison residual is a
2-instruction *schedule swap*, not the full register mirror that -O1 produced.

The three findings that get to byte_diff 8 (apply ALL — re-derived from scratch):
  1. **16-byte struct-by-value param** (forces the r0-r3 spill + narrow `ldrh/ldrb`
     member reads). 4 plain u32 params → `lsls/lsrs` extraction (byte_diff 77, wrong).
  2. **BLD as two ABSOLUTE stores**, NOT a `bld++` pointer:
     `*(vu16*)0x04000050 = 0x1142; *(vu16*)0x04000052 = 0x0909;`
     agbcc's CSE recognises 0x...52 = 0x...50+2 and emits the exact target idiom
     (base in r1, value funnels through r0 via `adds r0,rN,#0`, `adds r1,#2`). This
     is the *matched* idiom — verify against `sub_08012588` (byte_diff 0), which
     compiles two absolute BLD stores to byte-identical code. The `bld++` pointer
     form folds the 2nd store into `strh [r0,#2]` and does NOT match.
  3. **`src = cfg.srcTable;` local cache** (sequences the srcTable load before the
     subscript index, fixing one reorder) **AND declare `u8 *state;` AFTER
     `u32 now = sub_08000900();`** then assign `state = (u8*)0x03006480;` (defers the
     state-base `ldr r4` to AFTER the call, matching the target `bl; ldr r4` order).

### The byte_diff-8 residual: three ISOLATED register-coloring diffs (all want r3)
```
(A) compare schedule  target: mov r0,sp ; ldrb r1,[r4,#10]    built: ldrb r1,[r4,#10] ; mov r0,sp
                       (registers identical; just the 2-instr emit order swapped)
(B) subscript index   target: ldrb r3,[r4,#10] ; lsls r0,r3,#2  built: ldrb r0,[r4,#10] ; lsls r0,r0,#2
                       (target keeps index in r3; agbcc fuses index→result in r0)
(C) BLDALPHA value    target: ldr r3,=0x0909 ; adds r0,r3,#0    built: ldr r2,=0x0909 ; adds r0,r2,#0
                       (target uses r3 for the 2nd BLD value; agbcc reuses r2)
```
All three are the SAME phenomenon: the baserom's allocator parks short-lived
transients in r3 (the 4th arg reg, free after the struct spill) while agbcc-O2 reuses
r0/r2. Root: local-alloc quantity ordering + regmove `optimize_reg_copy` coalescing
(`gcc_arm/regmove.c` `fixup_match_2`/`optimize_reg_copy_2`). The fusion that produces
`lsls r0,r0,#2` (B) and the r2 reuse (C) is what differs.

## Best-effort C (default -O2, NO per-TU flag — byte_diff 8, the three r3 coloring diffs only)

```c
#include "macros.h"
#include "types.h"
#include "gba/dma.h"
#include "iwram.h"

extern u32 sub_08000900(void);

typedef struct {
    u16 limit;
    u8 delay;
    u8 _pad3;
    const u32 *srcTable;
    void *dst;
    u16 dmaHalfwords;
    u16 _pad14;
} DmaCycleCfg;

/* Time-gated cyclic DMA + alpha-blend setup. The 16-byte config record
 * (sOamDmaCfg_08100) is passed by value. */
void sub_080185C0(DmaCycleCfg cfg)
{
    vu32 *dma;
    const u32 *src;
    u8 *state;
    u32 now = sub_08000900();

    state = (u8 *)0x03006480;

    if (now - *(u32 *)(state + 4) >= cfg.delay) {
        if (state[0xa] >= cfg.limit)
            state[0xa] = 0;

        dma = (vu32 *)0x040000D4;
        src = cfg.srcTable;
        dma[0] = src[state[0xa]];
        dma[1] = (u32)cfg.dst;
        dma[2] = DMA_ENABLE | (cfg.dmaHalfwords >> 1);
        dma[2];

        state[0xa]++;
        *(u32 *)(state + 4) = sub_08000900();
    }

    *(vu16 *)0x04000050 = 0x1142;
    *(vu16 *)0x04000052 = 0x0909;
}
```

## Instrumentation findings — REVISED (Round-25 Opus pass; the mechanism is now PROVEN)

Built a private debug `old_agbcc` (copied `tools/agbcc-src/gcc` → `/tmp`, added
`fprintf` to `combine_regs` and the qty→hardreg loop in `local-alloc.c:block_alloc`;
**never touched the shared symlink**). Compiled the byte_diff-8 C and dumped both the
`combine_regs` tie decisions and the final qty/pseudo→hardreg map (`-dl` lreg dump
cross-checked). This PINS DOWN diff (B) — the `lsls r0, r3, #2` vs `lsls r0, r0, #2`
index residual — to an exact, deterministic allocator decision:

The DMA-block subscript `dma[0] = src[state[0xa]]` lowers to (lreg dump):
```
(set (reg:SI 41) (zero_extend (mem state[0xa])))     ; index load
(set (reg:SI 43) (ashift (reg 41) 2))  REG_DEAD 41   ; index<<2  — index DIES here
(set (reg:SI 44) (plus (reg 43) (reg 24=srcTable)))   ; + base
(set (reg:SI 45) (mem (reg 44)))                      ; load src[idx]
(set (mem dma[0]) (reg 45))
```
`combine_regs(usedreg=41, setreg=43, may_save_copy=0, already_dead=0)` SUCCEEDS the tie
at the ashift because reg 41 has a `REG_DEAD` note there (local-alloc.c line ~1666:
`if ((already_dead || find_regno_note(insn, REG_DEAD, ureg)) && reg_meets_class_p(...))`).
So 41 and 43 (and 44) all land in **one quantity → hardreg 0** → `ldrb r0; lsls r0,r0`.
Confirmed in the dump: `pseudo 41 → qty2 → r0`, `pseudo 43 → qty2 → r0`, `pseudo 44 → qty2 → r0`.

The target keeps the index in **r3, a SEPARATE qty from the r0 address chain** — i.e. in
the baserom compile the SAME tie did NOT fire. The tie can only fail one of two ways
(combine_regs source): (a) `reg_qty[setreg=43] >= -1` already (the shift-result pseudo
was born/given a qty *before* the ashift insn is processed for combining — line ~1654
`if (reg_qty[sreg] >= -1 ...) return 0;`), or (b) `reg_meets_class_p` fails. Neither is
reachable by reshaping the C subscript: **every subscript form tried fuses identically.**

### Subscript source forms PROVEN to still fuse to `ldrb r0; lsls r0,r0` (do NOT retry these):
- `src[state[0xa]]`, `cfg.srcTable[state[0xa]]`, `*(src + state[0xa])`
- `*(const u32*)((const u8*)src + (state[0xa] << 2))`  (explicit byte offset)
- `*(volatile u8*)(state+0xa)` index read
- typed state struct `st->cycleIdx` instead of `state[0xa]`
- `u32 i = state[0xa]; dma[0]=src[i];` (the temp is optimized away → identical RTL)
- `register u32 idx asm("r3") = state[0xa];` in an inner scope (pin IGNORED — value dies
  at the ashift, local-alloc reallocates the dead transient to r0 regardless of the pin)

### The ONE source change that broke the tie (but is net-WORSE) — the lead for next time:
Caching the index AND **reusing it for the increment** —
`idx = state[0xa]; if (idx>=limit){state[0xa]=0; idx=0;} dma[0]=src[idx]; … state[0xa]=idx+1;`
— makes reg 41 live past the ashift, so the tie fails and the subscript becomes
`ldrb r3 … lsls r0, r3` (✓ diff B closed!). BUT the target RE-READS state[0xa] at both the
reset and the increment (`ldrb` at 0x2e/0x4e independent of the subscript), so reusing the
cached `idx` there rewrites those into `movs r3,#0` / `adds r0,r3,#1` and shifts the whole
tail → **byte_diff 58 (much worse)**. The needle to thread: extend the subscript index's
live range *just* past the ashift WITHOUT it feeding the reset or the increment (both of
which must stay fresh `ldrb [r4,#10]` reads). No pure-C expression found that does this —
the optimizer either folds the extra use away (no live-range extension) or wires it into
the increment/reset (byte-changing). This is the crux for diffs B (and by knock-on, C):
the r3 coloring of the index frees r2 for the BLDALPHA value so it can land in r3 too.
