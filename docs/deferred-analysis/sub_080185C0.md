# sub_080185C0 — deferred analysis

`sub_080185C0` @ 0x080185c0, 0x88 (136) bytes. Range **[0x080185c0, 0x08018648)**.

## IMPORTANT: asm-slice boundary correction

The auto-peel that produced `asm/disasm_0x080185c0.s` labelled `sub_080185C0`
with `.incbin 0x185c0, 0x2d8` (728 B → [0x185c0, 0x18898)). That range actually
contains **TWO** functions:
  - `sub_080185C0` : [0x185c0, 0x18648)  — 0x88 B (this target; `push {r4,lr}`, ends `bx r0` @ 0x18630)
  - a second fn    : [0x18648, 0x18898)  — 0x250 B (`push {r4-r7,lr}` + r8/r9 save, ends `bx r0` @ 0x18888)

To decomp this target, the slice must be split: replace the single
`sub_080185C0` incbin block with `sub_080185C0` removed (decompiled to C) +
a new `sub_08018648` incbin block for the [0x18648, 0x18898) leftover, and
update linker.ld's comment accordingly. (detect-fn-boundary over-extends here;
trust the existing `thumb_func_start` labels / the `bx r0` at 0x18630.)

## What the function does (fully recovered, logic is correct)

Time-gated cyclic DMA + alpha-blend setup. Takes a 16-byte config **struct by
value** (the matching ABI shape — agbcc spills r0-r3 to a 16-byte stack frame
and reads the narrow members `ldrb [sp,#2]` / `ldrh [sp,#0]` / `ldrh [sp,#12]`;
the original prototype is NOT 4 separate u32s even though the existing caller
`sub_08019834.c` declares it that way — that caller decl should be updated to
pass `*(DmaCycleCfg*)sOamDmaCfg_08100` when this lands).

Struct layout (from the member loads):
  - +0  u16  limit          (cycle wrap count; sOamDmaCfg_08100 → 0x0008)
  - +2  u8   delay          (frames between advances; → 0x08)
  - +4  u32* srcTable       (DMA source pointer list; → 0x0830809c)
  - +8  void* dst           (DMA dest; → 0x06007b80 VRAM)
  - +12 u16  dmaHalfwords   (byte count; → 0x0480 → cnt = DMA_ENABLE | (0x480>>1))

State struct at IWRAM 0x03006480: `_field_4` (u32 timestamp), `_field_a` (u8 cycle index).
`sub_08000900()` returns the global frame counter (gGameStuff._unk00).

Every `delay` frames (since `_field_4`), advance `_field_a` (wrapping at `limit`),
DMA `srcTable[_field_a]` → `dst` (`dmaHalfwords>>1` halfwords), then unconditionally
arm REG_BLDCNT(0x04000050)=0x1142, REG_BLDALPHA(0x04000052)=0x0909.

## Drift

Best result: **byte_diff 4, diff_count 4** with `CFLAGS += -O1` (per-TU override),
the struct-by-value param, a `register vu16 *bld asm("r1")` pin (fixes the BLD
base/value reg flip — sanctioned per codegen-notes "register T *p asm(rN)"), and
a `src = cfg.srcTable` local cache (fixes subscript operand-eval order).

The SOLE residual is a **register mirror-swap in the `state[0xa] >= cfg.limit`
comparison**:
```
target:  mov r0, sp ; ldrb r1,[r4,#10](state) ; ldrh r0,[r0,#0](limit) ; cmp r1, r0 ; bcc
built :  mov r1, sp ; ldrb r0,[r4,#10](state) ; ldrh r1,[r1,#0](limit) ; cmp r0, r1 ; bcc
```
i.e. target colours state→r1 / limit→r0; agbcc(-O1) colours state→r0 / limit→r1.
Both branch `bcc` and are semantically identical — pure coloring.

### Root cause (characterised via the -da lreg/greg RTL dumps + opt-level bisect)

In the RTL the limit is a MEM operand of the `cmpsi` (`(compare (reg state) (mem
limit))`); the reload pass picks the mem-load scratch reg AFTER colouring the
state pseudo. The state→r1 colouring the baserom uses is produced ONLY by the
**`-fexpensive-optimizations`** pass set (which enables regmove's global
coalescing). Confirmed by opt-level bisect:
  - `-O1`                          → comparison MIRROR (wrong), subscript+BLD RIGHT  → byte_diff 4
  - `-O2`  ==  `-O1 -fexpensive-optimizations`
                                   → comparison REGISTERS RIGHT (only ldrb/mov-sp
                                     ORDER off), but regmove now coalesces the
                                     subscript index (r3→r0) and BLD 2nd const
                                     (r3→r2) WRONG → byte_diff 8
  - `-O1 -foptimize-register-move`/`-fregmove` alone → still mirror (byte_diff 4)

So the target needs the comparison colouring from `-fexpensive-optimizations`
AND the subscript/BLD colouring from NOT having it — a conflict no single
opt level + source shape I tried reconciles.

### Levers tried (all fail to close it)
- Comparison operand swap `cfg.limit <= state[0xa]` → flips branch to `bhi` (wrong encoding).
- `register u16 limit asm("r0")` and/or `register u8 cycle asm("r1")` pins on the
  compare operands → get the REGISTERS right but force an EAGER fused addr+value
  load, losing the target's deferred `ldrh` schedule (byte_diff 4, diff_count 2).
  The deferred load only survives with the operand read INLINE, which mirror-swaps.
- `u16 lim = cfg.limit` local (makes limit the pseudo, state the mem operand) →
  flips to limit→r1/state→r0 (still wrong, + `mov r0,sp` now correct: byte_diff 5).
- Caching `cyc = state[0xa]` for subscript+increment to keep idx live (defeat
  regmove coalesce under -O2) → restructures the increment, much worse.
- Pinning subscript idx to r3 under -O2 → extra eager read, worse.
- Flag sweeps (`-fno-{gcse,rerun-cse-after-loop,expensive-optimizations,
  cse-follow-jumps,rerun-loop-opt,strength-reduce,force-mem,peephole,
  caller-saves,function-cse}` under both -O1 and -O2) → none flip the comparison
  colouring without the subscript/BLD regression.
- pointer-to-cfg member access, local reorder, ternary/else forms → all regress.

## Best-effort C (-O1, byte_diff 4 — only the limit-comparison register mirror)

```c
#include "types.h"
#include "gba/dma.h"

extern u32 sub_08000900(void);

typedef struct {
    u16 limit;
    u8 delay;
    u8 _pad3;
    const u32 *srcTable;
    void *dst;
    u16 dmaHalfwords;
    u16 _pad14;
} DmaCycleCfg;

void sub_080185C0(DmaCycleCfg cfg)
{
    vu32 *dma;
    register vu16 *bld asm("r1"); /* base->r1 / value->r0 for the BLDCNT/BLDALPHA pair */
    const u32 *src;
    u32 now = sub_08000900();
    u8 *state = (u8 *)0x03006480;

    if (now - *(u32 *)(state + 4) >= cfg.delay) {
        if (state[0xa] >= cfg.limit) /* DRIFT: agbcc colours state->r0/limit->r1; baserom wants the swap */
            state[0xa] = 0;

        dma = (vu32 *)0x040000D4;
        src = cfg.srcTable; /* local cache sequences src load before the index */
        dma[0] = src[state[0xa]];
        dma[1] = (u32)cfg.dst;
        dma[2] = DMA_ENABLE | (cfg.dmaHalfwords >> 1);
        (void)dma[2];

        state[0xa]++;
        *(u32 *)(state + 4) = sub_08000900();
    }

    bld = (vu16 *)0x04000050;
    *bld = 0x1142; /* REG_BLDCNT */
    bld++;
    *bld = 0x0909; /* REG_BLDALPHA */
}
```

Build with a per-TU `src/engine/sub_080185c0.s: CFLAGS += -O1` override in the
Makefile (default -O2 regresses subscript+BLD as noted above).
