# Deferred: sub_08007138

Entity-engage / AABB-overlap scan. Caller `sub_080072E0`
(src/game/sub_08007228.c) declares it as:

```c
extern s32 sub_08007138(s32 c, s8 count);
```

`c` is the base of a run of 36-byte (0x24-stride) entity records; `count`
is the signed record count. Returns 1 if any engaged record overlapped.

## What it does

```
if (gIwram_3720._field_34 & 4) return 0;
for (i = 0; i < count; i++) {
    e = (Entity*)(i*0x24 + c);
    if ((e->state[+26] & 5) != 4) continue;
    if (gIwram_3720._field_6 != e->matchKey[+8]) continue;
    arg5 = 0;
    if (&gIwram_3720 == 0) continue;     /* agbcc keeps this null-check */
    if (e == 0) continue;                /* and this one */
    /* pack two corner points (each two s16 halves) */
    p1.a = e->x[+2] - (e->h[+6] >> 1);
    p1.b = e->w[+0] - (e->y[+4] >> 1) - 1;
    p2.a = e->y[+4];
    p2.b = e->h[+6];
    if (sub_0800CED0(&gIwram_3720, p1, p2, 0, arg5)) hit = 1;
}
return hit;
```

`sub_0800CED0(base, u32 packedP1, u32 packedP2, 0, 0)` — each packed u32 is
two s16 halves laid into one word; the callee is the AABB-overlap test.

## Drift

Best: **byte_diff 159, diff_count 76** (size 236 vs 240).

This is the docs/codegen-notes.md "High registers" (Class-1) unmatchable
pattern, same as the sibling `sub_08007228` (identical wide prologue, same
cluster/author, shipped NAKED+NON_MATCHING). The baserom holds, as
**loop-carried state across both the loop back-edge AND the `bl 0x0800CED0`**:

- `sl` = 0xFFFF0000  (high-half mask, from the struct-field merges)
- `r9` = 0x0000FFFF  (low-half mask)
- `r8` = `i << 24`   (strength-reduced signed-byte loop counter)
- `ip` = 0           (the 5th/stack arg to sub_0800CED0)

and spills `count << 24` to `[sp,#12]` as the strength-reduced loop bound
(hence `sub sp,#16`, not `#12`), with `hit` on `[sp,#8]` and the loop-entry
guard reading `hit`(=0) vs `(s8)count`.

agbcc 2.x will not hold this much loop state in r8-r10/ip across a call; it
recomputes the masks/index from low registers. The tension is **mutually
exclusive in pure C**:

- Pin `i asm("r8")` → masks land in sl/r9 correctly, but pinning blocks the
  strength reduction, so `count<<24` is never spilled to `[sp,#12]`
  (`sub sp,#12`, wrong) and the entry guard differs.  → best 159/76.
- Leave `i` unpinned → strength-reduction can run, but the masks then steal
  r8/r9 (not sl/r9) and one mask collapses into the `mvns` `-1` fold. → 178+.

### The wall (isolated precisely, re-confirmed)

The ENTIRE residual now cascades from ONE fact: **the baserom's loop IV is
the strength-reduced `i<<24` carried in r8** (`mov r8, r2` at 0x718e saves
it; the increment adds `1<<24` to r8 and `lsrs #24` recovers raw `i`), with
the loop bound `count<<24` spilled to `[sp,#12]` (hence `sub sp,#16`).

- To get masks→sl/r9, hit→stack, arg5→ip (the correct high-reg allocation)
  you MUST pin `i asm("r8")`. But a *pinned* counter cannot be
  strength-reduced — agbcc keeps raw `i` in r8, increments by 1, and the
  bound `count<<24` then lives in a register (r7), so `sub sp,#12` and the
  whole loop-tail + entry-guard diverge.
- To get the strength-reduced `i<<24` IV you must leave `i` UNPINNED — but
  then agbcc allocates that derived IV to a *low* callee-saved reg (r7) and
  leaves sl free, so `hit` stays in sl, the masks land in r8/r9 (not sl/r9),
  and the high-reg allocation is wrong.

These two requirements are mutually exclusive under every pure-C lever:
pins, `-ffixed-r7`, `-fno-strength-reduce`, `-fno-gcse`, do-while vs for,
explicit hand-rolled `iv=i<<24` carried as a local, OLD_AGBCC. Confirmed by
reading `gcc_arm/loop.c` (strength_reduce only rewrites pseudo IVs, never a
register-pinned one) — the pin defeats the reduction by construction.

## Corpus sweep (2026-06-03)

Ran the FULL-MIRROR corpus methodology (`corpus_asm_search.py` over all 23 mirrors — pokeemerald/firered/ruby, metroid mzm/mf, FE6/7/8, tmc, katam, csm3, mother3, cvaos, etc.; ~70k commits), a genuinely wider surface than the prior two rounds' 7-repo `corpus.py` cache. This is a corpus-confirmed Class-1 hand-asm idiom; **defer**.

### The exact asm idiom that diverges
Baserom `sub_08007138` [0x08007138,0x08007228) iterates `for (s8 i=0; i<count; i++)` over 0x24-stride records and calls `sub_0800CED0(base, p1, p2, 0, 0)` with two s16-pairs packed by value. The baserom holds, ACROSS BOTH the loop back-edge AND the inner `bl 0xced0`:
- `r8` = the **strength-reduced signed-byte IV `i<<24`** (`mov r8,r2` at 0x718e; loop tail adds `1<<24` via `movs#128;lsls#17;add r0,r8`, recovers raw `i` via `lsrs r2,r0,#24`).
- the loop **bound `count<<24` spilled to `[sp,#12]`** (`str r0,[sp,#12]` at 0x716a), compared shifted-vs-shifted (`ldr r6,[sp,#12]; cmp r0,r6; blt`) → hence `sub sp,#16`.
- `hit` spilled to `[sp,#8]`; the entry guard `ldr r6,[sp,#8]; cmp r6,r1; bge` coalesces hit(=0) with the loop seed i=0.
- masks `sl`=0xffff0000, `r9`=0x0000ffff loaded INSIDE the loop and held across the bl (used in the explicit OR-word-build packing: `mov r1,sl; ands r1,r4` etc).
- `ip`=arg5=0 held across the bl.

Concretely: baserom WRITES four programmer-controlled values (IV, two masks, arg5) into r8/sl/r9/ip and keeps them live across a `bl`, spilling hit+bound to stack to make room. agbcc never reproduces this combination from pure C.

### Whether/why the trick transferred
It did not, because the trick does not exist: no agbcc decomp in the corpus matches "write a value (mask/IV/arg) into a callee-saved high reg and hold it across a bl" in C. The only decomp that produces this asm shape (cvaos, same publisher) leaves it hand-written. The prior agent's narrower grep reached the same conclusion; this wider sweep makes it decisive.

### agbcc pass implicated (register-coloring residual)
`tools/agbcc-src/gcc_arm/loop.c` strength_reduce/record_biv: it only rewrites PSEUDO induction variables into the `<<24` reduced form — a `register T i asm("r8")` pin makes `i` a hard reg, so the reduced biv is never created (pin defeats reduction by construction). `local-alloc.c`/`global.c`: allocate callee-saved regs by lifetime-start order, so `hit` (live whole-function) claims `sl` before the in-loop masks, and the loop bound takes the last free callee reg (sl) instead of spilling — preventing maskHi-in-sl. The two requirements (reduced IV in r8 needs i UNPINNED; correct mask/arg high-reg placement needs them PINNED) are mutually exclusive under every pure-C lever.

### New oracle finding this round (finer isolation than prior rounds)
Variant A (unpinned `s8 i`, clean `struct Point{s16 a,b}` by-value packing, NO pins) compiles to byte_diff 172 but is STRUCTURALLY the closest: agbcc independently places IV→r8, maskLo→r9, arg5→ip (THREE of four high-reg slots match baserom), and the loop tail is identical except the bound lives in `sl` (`cmp r0,sl`) where baserom spills it to `[sp,#12]` (`ldr r6,[sp,#12]; cmp r0,r6`), giving `sub sp,#12` vs baserom `sub sp,#16`. So the ENTIRE residual collapses to one decision: shifted bound → sl vs → stack (equivalently maskHi-in-sl vs pool-loaded). Forcing maskHi into sl requires the explicit OR-word-build packing (which needs both masks live) — but that packing diverges in instruction order (Variant F: 186). struct-by-value packing only needs maskLo, so sl stays free for the bound. The choice is binary and not separately controllable in C.
