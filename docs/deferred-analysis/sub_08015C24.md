# Deferred analysis: sub_08015C24

Range: [0x08015c24, 0x08015cbc) — 152 bytes, Thumb. Pure leaf, 0 callees.

Verdict: `ATTEMPT_MATCH` (NOT `STRONG_UNMATCHABLE`). It is a pure tile-buffer blit:
`sub_08015C24(u8 bank, s16 dstX, s16 dstY, u8 cols, u8 rows, const u16 *src)` — copies a
`cols x rows` rectangle of u16 tiles from `src` into one of three EWRAM banks
(0x02000000 / 0x02010000 / 0x02020000) at offset `dstX + dstY * tileWidth`, advancing
`dst` by `tileWidth - cols` between rows. `tileWidth` is the u16 at offset 26 of the scene
state struct at IWRAM 0x030060A0. The single pool literals are 0x02010000, 0x02020000,
0x030060A0 — case 0's 0x02000000 is materialized as `0x80 << 18` (movs #128; lsls #18).

## ROOT CAUSE (new this pass — read the CORRECT compiler source)

The shipped compiler is `tools/agbcc/bin/old_agbcc`, built from `tools/agbcc-src/gcc/`
(NOT `gcc_arm/`). The prior note read `gcc_arm/{thumb.md,local-alloc.c}`, which is the
WRONG file and led to a wrong `must_match_0`/copy-suggestion story for the subtract.
Correct source facts (verified by reading `gcc/thumb.md` + `gcc/local-alloc.c`):

- **+0x50 add** — `gcc/thumb.md` addsi3 alt-2 is `add %0,%1,%2` with operand 1 carrying
  the `%0` (commutative-tie-to-output) constraint. agbcc ALWAYS ties the output to
  operand 1 by default, only swapping to operand 2 when operand 1 is unavailable. From C:
  `y *= tw; y += x` -> `(plus product x)`, product is op1 -> tied -> `adds r0,r0,r1`.
  Any x-first form (`x + product`, `p = x + p`, `y = x + y*tw`) -> x is op1 -> the result
  coalesces into x's register r1 -> `adds r1,r1,r0`. The target `adds r0,r1,r0` is op1=x
  but output tied to op2(product). REACHABILITY TESTED AND REFUTED: even forcing x
  live-after the add (post-loop volatile sink) did NOT flip it to `adds r0,r1,r0` — it
  produced `adds r0,r0,r1`. There is no C expression that makes agbcc tie the addsi3
  output to op2 while op1 is the syntactically-first operand here.
- **+0x78 sub** — `gcc/thumb.md` subsi3 is `(set =l (minus l l))` with NO `%0` tie on
  either operand (a pure 3-register `sub %0,%1,%2`). So the result and the tileWidth load
  are SEPARATE quantities; whichever is allocated to r0 first wins and the other falls to
  reg_alloc_order. tw (load) is born before the result (subtract), and tw inherits the
  r0 arithmetic-suggestion from the downstream `lsls r0; adds r5,r5,r0` chain via
  `combine_regs(tw,result,may_save_copy=0)` -> both want r0 -> tw takes r0, result shares
  r0 (disjoint lifetimes). Target instead has tw in r2 (col's just-freed reg) and result
  r0. `register u32 tw asm("r2")` + `register s32 advance asm("r0")` pins are IGNORED —
  the two quantities merge before find_free_reg. Only `dst -= cols - tw` produced a
  genuine 3-reg subtract, but as `subs r0,r3,r0` (wrong operand assignment), byte_diff 8.

```c
#include "types.h"

struct SceneTileState_15C24 {
    u8 _pad00[26];
    u16 tileWidth;
};

#define SCENE_TILE_STATE ((struct SceneTileState_15C24 *)0x030060A0)

void sub_08015C24(u8 bank, u16 dstX, u16 dstY, u8 cols, u8 rows, const u16 *src)
{
    u16 *dst;
    struct SceneTileState_15C24 *state;
    register s32 x asm("r1");
    register s32 y asm("r0");
    register s32 xScratch asm("r0");
    register u32 row asm("r0");

    switch (bank) {
    case 0:
        dst = (u16 *)0x02000000;
        break;
    case 1:
        dst = (u16 *)0x02010000;
        break;
    case 2:
        dst = (u16 *)0x02020000;
        break;
    }

    xScratch = dstX << 16;
    x = xScratch >> 16;
    y = (s16)dstY;
    {
        register struct SceneTileState_15C24 *st asm("r2") = SCENE_TILE_STATE;
        y *= st->tileWidth;
        y += x;
        dst += y;
        state = st;
    }

    row = 0;
    if (row < rows) {
        struct SceneTileState_15C24 *loopState = state;
        do {
            register u8 nextRow asm("r1");
            u8 col = 0;
            nextRow = row + 1;
            if (col < cols) {
                do {
                    *dst++ = *src++;
                    col++;
                } while (col < cols);
            }
            dst += loopState->tileWidth - cols;
            row = (u8)nextRow;
        } while (row < rows);
    }
}
```
