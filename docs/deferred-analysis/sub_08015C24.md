# Deferred analysis: sub_08015C24

Range: [0x08015c24, 0x08015cbc) — 152 bytes, Thumb.

## Summary

EWRAM tilemap blit — copies a rows×cols block of u16 tiles from a caller-supplied
src pointer into one of three EWRAM buffers (0x02000000/0x02010000/0x02020000)
at (dstX, dstY) scaled by the scene stride from IWRAM 0x030060A0+26.
Pure leaf function (no callees), no high registers, classify: ATTEMPT_MATCH.

## Drift

**Best byte_diff:** 19 (diff_count 19)
**Permuter best score:** 490 (vs base 292) — u8→u16 nextRow was the only improvement found after >15 min.

### Root cause

agbcc's local-alloc assigns registers in the mirror image of the baserom throughout
the pointer computation:

  Baserom register plan:
    (s16)dstX sign-ext   -> r1   (via r0 scratch: lsls r0,r1,#16; asrs r1,r0,#16)
    (s16)dstY sign-ext   -> r0   (from r2, consuming it: lsls r0,r2,#16; asrs r0,r0,#16)
    state ptr 0x030060a0 -> r2   (r2 freed by dstY sign-ext; NOT r7)
    stride               -> r7   (ldrh r7,[r2,#26])
    product              -> r0   (muls r0,r7)
    final add            -> r0   (adds r0,r1,r0)
    state ptr still in r2; loop top does adds r7,r2,#0 (moves state to r7)

  My agbcc assignment:
    (s16)dstX sign-ext   -> r0   (lsls r0,r1,#16; asrs r0,r0,#16 -- in-place to r0)
    (s16)dstY sign-ext   -> r1   (lsls r1,r2,#16; asrs r1,r1,#16)
    state ptr 0x030060a0 -> r7   (r7 was free after switch, agbcc prefers it!)
    stride               -> r2   (ldrh r2,[r7,#26] -- self-referential, overwrites state!)
    product              -> r1   (muls r1,r2)
    final add            -> r0   (adds r0,r0,r1)
    state ptr GONE; loop freshly loads from pool (ldr r7,[pc,...])

The cascade: wrong state ptr register -> wrong col/nextRow registers in loop (r1/r2 swapped).

### Levers tried

- Expression ordering: (s16)dstX + (s16)dstY * stride (19 diff), plus permutations
- goto outer removed: state ptr lands in r2 but encoding differs, 63 diff
- u16 nextRow: reduces from 26 to 19 diff -- best single change
- asm("":::"r7") fence: same 19 diff
- register s16 sdstX asm("r1") + r7 fence: 20 diff (dstY sign-ext correct, but

- register pins for state(r2), sdstY(r0), strd(r7) + various combinations:
  all cause mov sp / extra mov ip / sp-as-intermediate (agbcc conflicts)
- Function-scope state ptr: causes ip save (agbcc saves dstY to ip at entry)
- Permuter: >15min of runtime, best score 490 (u16 nextRow change only)

### Key insight for next attempt

The baserom's out-of-place sign-ext of dstX (lsls r0,r1,#16; asrs r1,r0,#16)
uses r0 as a shared scratch for BOTH sign-extensions. After the dstX sign-ext
writes r0 (intermediate), the dstY sign-ext overwrites r0 (destination). This
"shared scratch" pattern is what triggers agbcc to put the ENTIRE product result
in r0 and dstX in r1 for the final add.

The blocker: agbcc's local allocator does a whole-function register assignment
upfront. It sees that r2 (dstY) will be needed for state ptr "later" and saves
it to ip at entry. It never realizes that dstY and state ptr have NON-OVERLAPPING
lifetimes (dstY consumed by sign-ext just before state ptr is loaded).

A C expression that forces evaluation of BOTH sign-exts BEFORE the state ptr
load, with the FIRST sign-ext using r0 as scratch (non-destructive, result to r1),
would produce the correct baserom pattern without any ip save. This requires
agbcc to see the two sign-exts as a "plan ahead" unit using r0 as shared scratch.
Unknown if achievable in pure C with OLD_AGBCC.
