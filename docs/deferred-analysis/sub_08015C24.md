# Deferred analysis: sub_08015C24

Range: [0x08015c24, 0x08015cbc) — 152 bytes, Thumb.

## Summary

EWRAM tilemap blit — copies a rows×cols block of u16 tiles from a caller-supplied
src pointer into one of three EWRAM buffers (0x02000000/0x02010000/0x02020000)
at (dstX, dstY) scaled by the scene tile stride. The stride is
`SceneScrollState.tileWidth` at IWRAM 0x030060A0 offset 26 (SAME struct as
`SceneScrollState_F2F8` / `SceneScrollState_A6D4` — offset 26 = `tileWidth`).
Signature: `sub_08015C24(u8 bank, u16 dstX, u16 dstY, u8 cols, u8 rows, const u16 *src)`
  bank=r0, dstX=r1, dstY=r2, cols=r3, rows=[sp+0]→r4, src=[sp+4]→r6.
Pure leaf function (no callees), classify: ATTEMPT_MATCH (NOT STRONG_UNMATCHABLE,
so NAKED is not appropriate — this is a coloring local minimum, defer for a fresh idea).

## Drift

**Best byte_diff: 19 (diff_count 19)** — reproduced Round 4. The "19-version" C below is
still the documented best. All 19 are ONE coupled register-coloring cascade; no structural diffs.

The baserom multiply+loop wants this exact coloring (confirmed from the bytes):
  - multiply: dstX→r1 (out-of-place: `lsls r0,r1; asrs r1,r0`), dstY→r0 (in-place), state→r2,
    stride→**r7**, `muls r0,r7`, `adds r0,r1,r0`.
  - preheader: `adds r7,r2,#0` — SPLIT copy state r2→r7 (executed ONCE).
  - loop: nextRow=r1, col=**r2**, cols=**r3**, rows=r4, dst=r5, src=r6, state=**r7**. Packs r1-r7.
The whole function fits in r0-r7 (baserom prologue `push {r4,r5,r6,r7,lr}`, NO r8/ip use).

### Root cause — CONFIRMED via instrumented agbcc (NEW, Round 4 — supersedes Round 3)

Round 3's analysis was WRONG about the mechanism: it assumed ARM's
REG_ALLOC_ORDER `{3,2,1,0,12,14,4,5,6,7}` and `-flive-range`. Neither applies to the
THUMB compiler (`tools/agbcc-src/gcc/`, built `-DOLD_COMPILER`) we actually use:

1. **thumb.h defines NO `REG_ALLOC_ORDER`** → gcc uses the DEFAULT ascending order
   r0,r1,r2,...  (NOT the ARM r3-first order). Verified: `grep REG_ALLOC_ORDER thumb.h` = none.
2. **`-flive-range` is NOT a valid option for `old_agbcc`/`agbcc` (thumb)** — only
   `agbcc_arm` (arm-elf) accepts it. So the Round-3 "live-range-split flag" hypothesis is
   a DEAD END: the LRS pass is compiled out of our thumb compiler. The `adds r7,r2,#0`
   split must come from ordinary global+local-alloc, NOT LRS.
3. `flow.c` weights `REG_N_REFS (regno) += loop_depth` — inner-loop refs are weighted, so
   cols/counters get high priority (this is correct, matches baserom's desire for them in
   low regs).

I built a PRIVATE debug `old_agbcc` (instrumented `find_reg` in global.c to print
pseudo n_refs/live_length/hardreg; sandbox in /tmp, deleted after — NEVER touched the
shared symlink) and traced the allocation. Ground truth for the 19-version:
  - dst(r5), src(r6), cols→**r7** (n_refs 8, but conflict-pushed off r3/r4 by the loop
    values nextRow/col/loopState/rows which are simultaneously live), rows(r4),
    state-loop→r3 (the reload), bank→ip, col→r1, nextRow→r2.
  The baserom wants cols=r3 (kept in its param reg through the multiply) and stride→r7;
  agbcc instead extracts cols OUT of r3 at entry (`lsl r3; lsr r7`), freeing r3, and then
  the short stride temp grabs the freed r3 (lowest free) while cols is pushed to r7. This
  is a PRIORITY INVERSION vs baserom: baserom gives the long-lived loop value (cols) the
  low reg and the short temp (stride) the high reg; agbcc gives the temp the low reg.

### KEY NEW PROGRESS (Round 4) — a no-spill base that gets state=r2 + col=r2 + the copy

The following C reaches the CORRECT state=r2 / col=r2 / `adds r3,r2,#0` copy structure
with **NO r8/ip spill** (prologue stays `push {r4,r5,r6,r7,lr}`), at byte_diff 26 /
diff_count 16. The two moves that unlocked it:
  (a) pre-extract `s32 sx=(s16)dstX; s32 sy=(s16)dstY;` BEFORE loading state — this
      vacates the dstY param (r2) so the state-r2 pin no longer collides → no spill.
  (b) pin `state asm("r2")` (multiply) + `col asm("r2")` (loop) → forces the r2 conflict
      that yields the preheader copy.
The ONLY remaining drift is a 3-way swap: stride=r3 (want r7), loopState=r3 (want r7),
cols=r7 (want r3). i.e. cols and {stride,loopState} need to trade r3↔r7. Pinning cols=r3
on top spills (cols-r3 across the switch dispatch fights the param/scratch use of r3) →
byte_diff 153. `-ffixed-r7` also spills. So the last swap resists every lever tried.

```c
/* byte_diff 26, no-spill, correct state=r2/col=r2/copy — the Round-4 base to build on */
void sub_08015C24(u8 bank, u16 dstX, u16 dstY, u8 cols, u8 rows, const u16 *src) {
    u16 *dst; struct SceneScrollState_15C24 *loopState; s32 sx, sy; u8 row;
    switch (bank) { case 0: dst=(u16*)0x02000000; break; case 1: dst=(u16*)0x02010000; break;
                    case 2: dst=(u16*)0x02020000; break; }
    sx=(s16)dstX; sy=(s16)dstY;
    { register struct SceneScrollState_15C24 *state asm("r2")=(void*)0x030060A0;
      dst += sx + sy*state->tileWidth; loopState=state; }
    row=0;
    if (row<rows) do { u16 nextRow; register u8 col asm("r2"); col=0; nextRow=row+1;
        if (col<cols) do { *dst++=*src++; col++; } while(col<cols);
        dst += loopState->tileWidth - cols; row=(u8)nextRow; } while(row<rows);
}
```

### Levers tried (Round 4 — all FAILED, do NOT repeat)
- Single state var (multiply+loop): → state in **ip** (long live range, hoisted) or **r7**
  (no split, size 148). No copy.
- Two vars (`loopState=state`): state-mul→r3, coalesces with loop → no copy.
- Fall-through default (no `goto outer`, default→multiply, fixes the 2 `b` diffs):
  byte_diff 63 (state→r7, copy lost). The `goto outer` is what makes the multiply a
  separate BB and lets state=r2; removing it regresses coloring more than it fixes.
- Product temp `s32 product=(s16)dstY*stride;`: spills dstX (115/63).
- Reorder `dstY*stride + dstX`: 114.
- col=r2 pin alone on 19-version: 20 (changes col increment encoding, net neutral).
- state-r2 pin alone: spills dstY→r8 (153).
- pre-extract sx/sy + state-r2 + col-r2: **26, NO SPILL** (the Round-4 base above).
- + cols-r3 pin: 153 (cols-r3 across switch spills). + `-ffixed-r7`: spills.
- Compiler swap old_agbcc → agbcc (newer): byte_diff 19 (no change).
- `-flive-range`: INVALID OPTION on thumb old_agbcc/agbcc (only agbcc_arm has it).
- Permuter (correct target.o via make_permuter_target.py, base score 290, 2740 iters,
  -j4 --stop-on-zero): best stayed 290, ZERO improvements — every mutation worse.
  Confirms a sharp coloring minimum the permuter cannot escape by reordering.

## Best-effort C (byte_diff 19 — the documented best, clean / no pins)

```c
#include "iwram.h"
#include "types.h"

struct SceneScrollState_15C24 {
    u8 _pad00[26];
    u16 tileWidth;
};

void sub_08015C24(u8 bank, u16 dstX, u16 dstY, u8 cols, u8 rows, const u16 *src)
{
    u16 *dst;

    switch (bank) {
    case 0:
        dst = (u16 *)0x02000000;
        break;
    case 1:
        dst = (u16 *)0x02010000;
        break;
    case 2:
        dst = (u16 *)0x02020000;
        break;
    default:
        goto outer;
    }

    dst += (s16)dstX + (s16)dstY * ((struct SceneScrollState_15C24 *)0x030060A0)->tileWidth;

outer: {
    u8 row = 0;

    if (row < rows) {
        struct SceneScrollState_15C24 *loopState = (struct SceneScrollState_15C24 *)0x030060A0;

        do {
            u16 nextRow;
            u8 col;

            col = 0;
            nextRow = row + 1;

            if (col < cols) {
                do {
                    *dst++ = *src++;
                    col++;
                } while (col < cols);
            }
            dst += loopState->tileWidth - cols;
            row = (u8)nextRow;
        } while (row < rows);
    }
}
}
```
