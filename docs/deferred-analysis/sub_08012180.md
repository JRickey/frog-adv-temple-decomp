## What it does (fully understood — model is operation-exact)

Two-slot animation tick + scroll fold. Reads the position word at
`gGameStuff._unk00` (== `0x03005330`). For each of two animation slots —
`gIwram_6150` (`struct IwramAt6150`) and `gIwram_5360` (`struct IwramAt5360`) —
if `pos - slot->_field_08 >= slot->_maxFrames` (UNSIGNED `bcc`), steps
`slot->_field_04` by ±2 based on `slot->_field_00` (a balanced `switch`:
slot0 cases {1:-2, 2:+2, 0:decay-toward-0-by-2}; slot1 cases
{3:-2, 4:+2, 0:decay}), then caches `slot->_field_08 = pos`. Finally folds both
slots' `_field_04` into the scroll struct at `gIwram_60A0`
(`struct ScrollState_60A0`): `scrollX(0x0c) += slot1->_field_04`,
`scrollY(0x10) += slot0->_field_04`, then mirror to `scrollX2(0x2c)`,
`scrollY2(0x30)`. Returns void. The switch trees + the entire tail
(0x1221c–0x12236) are byte-identical in the best base; only the base-pointer
register allocation differs.

## ROOT CAUSE (pinned this round)

The baserom holds ALL THREE base pointers in CALLEE-SAVED regs and materialises
each via a **scratch-load-then-copy spread**:
```
ldr r2, =0x5330 ; ldr r3, =0x6150
ldr r1,[r2]     ; ldr r0,[r3,#8] ; subs r1,r1,r0
adds r6, r2, #0 ; adds r5, r3, #0     <-- spread: pool-load(scratch) -> callee-saved copy
ldrb r0,[r5,#12]; ...
```
plus `adds r4, r0, #0` for slot1 in block B. So baserom uses {r4=slot1,
r5=slot0, r6=pos}, push {r4,r5,r6,lr}.

The installed agbcc (BOTH old_agbcc and agbcc) instead keeps the `pos` base in
**caller-saved r2**, loaded once at the top and **never spread**, kept live
across the whole function. This is the CORRECT cheaper choice and is forced by
`gcc_arm/global.c` `find_reg` (lines ~370–396): for a LEAF function with no
calls, all `call_used_regs` (r0–r3) are pre-marked "free / no cost", so the
global allocator prefers a caller-saved scratch for a live-across-function
pseudo (r2 needs no push, no copy). The baserom's choice (callee-saved r6 +
push of r6 + 3 `adds` spread copies) is STRICTLY MORE EXPENSIVE — agbcc will
not pick it from any equivalent leaf-function C. The matched neighbor
`sub_08012098` in the same TU confirms the preference: it keeps both its
base pointers in scratch (r0/r2) because they die quickly.

Note the asymmetry that proves it's allocation, not structure: MY build DOES
emit a spread in block B — but of the *value* (`add r3, r0, #0` copying
`*pos`), not the base. agbcc spreads where IT decides, just not where baserom
did. The diff is 3 missing base-spreads + the branch-offset cascade they cause;
diff_count 47 (absolute-cast form) / 48 (linker-symbol form). All operations
match; only the {caller r2} vs {callee r6 + spread} allocation of `pos` (which
then forces slot0->r5, slot1->r4 + their spreads) differs.

## Why this is a genuine local minimum (not solver-laziness)

The baserom made the strictly-more-expensive allocation choice that a leaf
function's cost model in the installed agbcc never selects. There is no flag in
the installed binary that flips the leaf caller-saved preference for a
persistent pointer, no pin that produces the scratch-then-copy (a pin forces a
direct load), and permuter cannot synthesise the copies. The most likely true
source either (a) was NOT a leaf at original compile time (a since-inlined call
that consumed caller-saved regs across the body, forcing the bases callee-saved)
or (b) used a TU-wide flag this 3-function shared TU cannot carry without
breaking the two matched neighbors. Next attempt should probe (a): try adding a
throwaway call/clobber that consumes r0–r3 across the base live ranges and see
if it flips the allocation, then find the C that does so WITHOUT the call.

## Round-8 Opus retry — DECOUPLED the two sub-problems (still defer)

Independently re-derived from scratch; reproduced the diff-48 clean baseline,
then ran a clobber-isolation experiment that SPLITS the divergence into two
orthogonal phenomena and proves which one is the real wall.

**The clean-C divergence is exactly 3 things, all flowing from one root:**
1. `pos` base in caller-saved r2 (built) vs callee-saved r6 (baserom).
2. The 3 base-spreads (`adds r6,r2,#0; adds r5,r3,#0; adds r4,r0,#0`):
   baserom loads each base address into a SCRATCH reg, derefs through it,
   THEN copies the base into its callee-saved home. Built loads each address
   DIRECTLY into the home reg and derefs through it (no copy).
3. The branch-offset cascade caused by the 3 missing spread instructions
   (6 bytes), which shifts every subsequent `b/beq/bcc` target.

**Experiment (decoupling):** inserting `asm volatile("" ::: "r0","r1","r2","r3")`
clobbers spanning `pos`'s live range (one before the slot0 `if`, one before the
slot1 block) FLIPS all three bases into the correct callee-saved homes — built
becomes `ldr r6,[pc]; ldr r5,[pc]` with `slot0->r5, slot1->r4, pos->r6` and
`push {r4,r5,r6,lr}` — diff drops 48 -> 44. So **sub-problem (1) (callee-saved
allocation) is fully achievable under caller-saved pressure**, confirming the
prior `global.c` leaf-cost-model diagnosis: no caller-saved pressure -> agbcc
keeps `pos` in r2; add pressure -> it correctly uses r6/r5/r4.

**The irreducible wall is sub-problem (2), the SPREAD, ALONE.** With the clobbers
in place (registers already correct) the ONLY remaining diff is the 3 missing
`adds rN, scratch, #0` copies + their offset cascade (diff floor 44). Every
attempt to induce the scratch-load-then-copy failed:
- `-fforce-addr` (CONFIRMED applied — "force-addr" present in the compile line):
  NO spread, loads directly into the home reg. diff stays 44.
- comparison via the `gGameStuff` MACRO + body via the `gs` pointer: CSE re-merges
  in block 0; block 1 re-materialises the address mid-body (a fresh `ldr [pc]`).
  diff 33 but structurally WRONG (rematerialisation, not the spread).
- comparison via anonymous casts `((T*)0xADDR)->field` + named-pointer body:
  same CSE re-merge / wrong-place rematerialisation. diff 33/38.
- comparison via DIRECT extern-struct access `gIwram_6150._field_08` + pointer
  body + clobbers: CSE merges struct-access and address-of into ONE pseudo ->
  NO spread, diff 44 (identical to clobber-only).
- newer `agbcc` on this TU: diff 48 AND breaks neighbor sub_08012100 (diff 7).
- with clobbers, flag sweep `-fno-cse-follow-jumps / -fno-cse-skip-blocks /
  -fno-rerun-cse-after-loop / -fno-thread-jumps / -fno-expensive-optimizations /
  -fcaller-saves / -fno-defer-pop / -fno-omit-frame-pointer`: ALL diff 57
  (worse — they perturb the clobber-induced allocation; NONE emit the spread).

**Why the spread is unreproducible:** it requires the address constant to be a
SEPARATE pseudo from the long-lived base pointer (constant-pseudo loaded into
scratch, used for the deref, then COPIED to the callee-saved base-pseudo). agbcc's
CSE collapses every clean-C way of writing the address into ONE pseudo, so the
base-load targets the home reg directly and no copy is ever emitted. The
baserom's two-pseudo form is the strictly-more-expensive choice the installed
compiler's CSE + reload never produce from leaf-equivalent C.

**Next attempt should target ONLY the spread** (registers are already solved by
pressure). Find clean C whose RTL keeps the address constant as a distinct
short-lived pseudo from the base pointer WITHOUT rematerialising it. The clobbers
used here are inline asm and only a DIAGNOSTIC — they cannot ship (they would make
the function non-"matched"); they exist solely to prove the register class is
solvable so the search can focus exclusively on the spread.
