## What it does (fully understood)

Two-slot animation tick + scroll fold. Reads the position word at
`gIwram_5330` (== `gGameStuff._unk00`, 0x03005330). For each of two animation
slots — `gIwram_6150` (`struct IwramAt6150`) and `gIwram_5360`
(`struct IwramAt5360`) — if `pos - slot->_field_08 >= slot->_maxFrames`,
steps `slot->_field_04` by ±2 based on `slot->_field_00` (a balanced switch
tree: slot0 cases {1:-2, 2:+2, 0:decay-toward-0-by-2}; slot1 cases
{3:-2, 4:+2, 0:decay}), then caches `slot->_field_08 = pos`. Finally folds both
slots' `_field_04` into the scroll struct at `gIwram_60A0`
(`struct ScrollState_60A0`): `scrollX(0x0c) += slot1->_field_04`,
`scrollY(0x10) += slot0->_field_04`, then mirror to `scrollX2(0x2c)`,
`scrollY2(0x30)`. Returns void.

Reference siblings: `sub_0801190C` (same 0x60A0 fold tail, matched with
`register asm("r8")`), `sub_08011884`/`sub_08012604` (same two-slot structs).

## Drift

Best **byte_diff cascade from a single allocation decision**; structural
`diff_count: 48` (clean) / **45** (block-B pos read via `*(&gIwram_5330)`).
EVERY remaining mismatch is the same root cause — do not be misled by the
branch-target ARGUMENT_MISMATCHes, they are pure offset-shift from the missing
spread instructions. The operations all match.

ROOT CAUSE: the baserom keeps `gs`/`pos` (0x5330 base) in **callee-saved r6**
via a **register spread**:
```
ldr r2, =0x5330 ; ldr r3, =0x6150
ldr r1,[r2,#0]  ; ldr r0,[r3,#8] ; subs r1,r1,r0
adds r6, r2, #0 ; adds r5, r3, #0     <-- spread: pool-load -> callee-saved copy
ldrb r0,[r5,#12]; ...
```
plus `adds r4, r0, #0` for slot1 in block B. My build allocates `gs` to
**caller-saved r2** (kept live across both blocks, no copy), so the three
`adds rCallee,rScratch,#0` copies are absent and every subsequent branch offset
shifts by 2-4 bytes. slot0->r5 and slot1->r4 ALREADY match; the entire tail
(0x180-0x19a) is byte-identical; the switch trees are byte-identical after
reordering the source case labels (2-before-1 in slot0, 4-before-3 in slot1 —
"case-number ≠ source-block-order"). Only `gs`'s register differs.

Responsible pass: `gcc_arm/global.c` find_reg / `local-alloc.c`. With
`allocno_calls_crossed==0` (no calls), agbcc's global allocator is free to use
any reg; it picks caller-saved r2 for `gs` (smaller push set {r4,r5}) where the
original picked callee-saved r6 (push set {r4,r5,r6} + 3 spread copies — the
MORE expensive choice). The spread is the signature of the pool-load landing in
a scratch reg while global-alloc assigns the pseudo a callee-saved home.

## Levers tried (all fail to induce the spread)

- `register u32 *pos asm("r6")` pin: gets the right FINAL reg (r6) but loads
  **directly** (`ldr r6,=...`), NO spread → diff 38, cannot reach 0. Pinning
  slot0/slot1 too (r5/r4): same, diff 45. The pin short-circuits the
  scratch-then-copy that produces the spread.
- `-fforce-addr` (alone; + gs-pin; + best base): does NOT create the spread;
  gs stays r2. Neighbors (sub_08012098, sub_08012100) stay matched with it.
- `-ffixed-r2`, `-ffixed-r2 -ffixed-r3`: agbcc ignores / picks other scratch;
  gs still not callee-saved. No spread.
- Flag sweep (`-fno-gcse`, `-fno-schedule-insns`, `-fno-schedule-insns2`,
  `-fno-strength-reduce`, `-fcaller-saves`, `-fno-defer-pop`,
  `-fno-cse-follow-jumps`, `-fno-omit-frame-pointer`): none help (raise diff).
- Explicit `delta` local for the subtraction: worse (50→58).
- if/else-if chain instead of switch: worse (71) — switch lowers to the correct
  balanced tree; if-chain does not.
- Compiler swap: TU is shared with two already-matched neighbors under
  OLD_AGBCC, so a per-TU `CC = AGBCC_BIN` swap is NOT available (would break
  them); not tried for that reason.
- decomp-permuter: base obj-score ~980; 2500 iters `--better-only -j4` reached
  575 but never 0. It only mutates statement/scope/temp ordering — it cannot
  ADD the 3 spread copy instructions. Best variant reads pos via
  `*(&gIwram_5330)` (→ diff 45) but no match.
