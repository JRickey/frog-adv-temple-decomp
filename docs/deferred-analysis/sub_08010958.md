# Deferred analysis: sub_08010958

Two-pass "channel apply" iterator. Walks two bitmasks in the work struct at
0x03006110 and, for each set bit, calls `sub_080105B0(list, index, flag)` with
a pointer pulled from one of three parallel 20-byte-strided ROM tables indexed
by `gGameStuff.pendingMode - 1`:
  - 0x08307EB4 (`gModeListA`) — first-pass list  (mask `*(u16*)0x03006136`)
  - 0x08307EB8 (`gModePairs`) — `{start,count}` byte pairs
  - 0x08307EBC (`gModeListB`) — second-pass list (mask `*(u8*)0x0300613A`)

Callee `sub_080105B0` was peeled in this round (commit before this note);
range [0x080105b0, 0x08010694), boundary forced because detect-fn-boundary
over-walked across the already-decompiled sub_08010694/sub_080106B8.

## Drift

Best result (PURE C, structurally correct): **byte_diff 194, diff_count 46**.
The structure is right — same number of loops, same callee args, same masks,
same `(pendingMode-1)*20` indexing. The residual is entirely agbcc
register-allocation / reload drift that no C lever or the permuter closed:

1. **base→r6 hoist (root cascade).** Target loads `base` (0x03006110) into r0,
   reads the 0x26 mask, then `mov r6, r0` to preserve base in a callee-saved
   reg for the second loop — and *reloads* base from the pool inside the first
   loop. agbcc on every C variant I tried either keeps base in r6 across the
   whole first loop (no reload, +diff) or reloads everywhere (CSE collapse,
   diff 121). Pinning `register u8 *base asm("r6")` → 54 (keeps it live, wrong).
   Inlining the cast only in the first-loop body → 121 (CSE'd back).

2. **`mov sl,r0; mov r9,r1` ordering + placement.** Target establishes the two
   high-reg pins (pairs=sl, p2a=r9) *after* the outer `cmp r4,r8; bcs` bound
   check, reusing the r1 value left over from the `*(base+0x2a)==0` test. My
   build (pins are `register asm` decls) materializes them *before* the bound
   check and recomputes. Reordering the C assignments doesn't move it (reload
   pass reorders back). Dropping the p2a pin → agbcc stops using r9 entirely
   (diff 68); both pins are required to get r9+sl used at all.

3. **r6/r7 coloring swap.** Target keeps tableA in r7 and saves the outer
   next-index `i+1` in r7 (because r4 is reused for the inner `count`); my build
   uses r6 for `i+1`. Tied to the inner-loop reusing r4 for `count`, which my
   distinct `i`/`count` locals don't induce.

4. **pair-pointer load vs `i*2` schedule swap** (`ldr r1,[r0]; lsls r0,r4,#1` vs
   `lsls r1,r4,#1; ldr r0,[r0]`) — instruction-scheduling drift.

## Levers tried (all failed to reach 0)
- `register u8 *p2a asm("r9")` + `register ModeList *pairs asm("sl")` pins → 46 (best).
  NOTE: a `register asm()` pin on the *parameter* `b asm("r8")` makes agbcc 2.x
  throw "syntax error before `asm'" when a second local `register asm()` pin and
  a struct-member-indexed body are both present — drop the param pin, keep the
  two local pins (b lands in r8 naturally anyway).
- Three separate base macros (gModeListA/Pairs/ListB at EB4/EB8/EBC) so each
  field reads as its own pool constant (matches target) → got from 55 to 46.
- `u32 idx = gGameStuff.pendingMode - 1` materialized per use → defeats the
  strength-reduction fold (`subs r0,#20` → `subs r1,#1` before the *20 scale);
  worth ~6 diff. KEEP this.
- `register u8 *base asm("r6")` → 54 (keeps base live across loop 1, wrong).
- Inline `(u8*)0x03006110` cast in loop-1 body only → 121 (CSE collapse).
- Caching the mask `!= 0` test in a local → no change (folded back).
- Reordering the two pin assignments → no change (reload reorders).
- Deref `*(base+0x2a)` as an expression (not the pinned var) before pinning
  p2a → 52→46 improvement. KEEP.

## Best-effort C (byte_diff 194, diff_count 46, PURE C)
```c
#include "game.h"
#include "macros.h"
#include "types.h"

extern void sub_080105B0(void *list, u8 index, u8 flag);

typedef struct ModeList {
    void *list;
    u8 _pad04[16];
} ModeList;

#define gModeListA ((ModeList *)0x08307EB4)
#define gModePairs ((ModeList *)0x08307EB8)
#define gModeListB ((ModeList *)0x08307EBC)

void sub_08010958(u8 a, u8 b)
{
    u8 *base = (u8 *)0x03006110;
    register u8 *p2a asm("r9");
    register ModeList *pairs asm("sl");
    ModeList *listA;
    u8 *pair;
    u8 i;
    u8 j;
    u8 count;

    if (*(u16 *)(base + 0x26) != 0) {
        listA = gModeListA;
        for (i = 0; i < a; i++) {
            if ((*(u16 *)(base + 0x26) >> i) & 1) {
                u32 idx = gGameStuff.pendingMode - 1;
                sub_080105B0(listA[idx].list, i, 1);
            }
        }
    }

    if (*(base + 0x2a) == 0) {
        return;
    }

    p2a = base + 0x2a;
    pairs = gModePairs;
    for (i = 0; i < b; i++) {
        if ((*p2a >> i) & 1) {
            u32 idx = gGameStuff.pendingMode - 1;
            pair = (u8 *)pairs[idx].list + i * 2;
            j = pair[0];
            count = pair[1];
            while (count != 0) {
                u32 idx2 = gGameStuff.pendingMode - 1;
                sub_080105B0(gModeListB[idx2].list, j, 0);
                j++;
                count--;
            }
        }
    }
}
```

## Opus attempt (round 22)

Re-derived from scratch through ~17 structurally-distinct C variants (NOT
tweaks of the prior near-match). Confirmed the prior agent's wall independently
and advanced the analysis on one of the two residual drifts.

### Results
- **Best diff_count: 40** (improves on prior 46), byte_diff 197 — variable-base
  `u8 *base` + the two-step `idx` trick below. This is the cleanest structure.
- **Best byte_diff: 162**, diff_count 48 — struct-pointer model with `work`
  pinned to r6 (see below). Lower byte_diff but the r6 pin corrupts loop2.

### KEY NEW FINDING #1 — the two-step idx defeats BOTH index drifts at once
The prior note hit a dilemma: `idx = pendingMode - 1` (one statement) defeats the
`(pm-1)*20 → pm*20-20` strength-reduce fold but reads pendingMode into r0 then
`subs r1,r0,#1` (3-op, wrong reg); inline `gGameStuff.pendingMode - 1` reads into
r1 (right reg) but re-folds to `subs r0,#20`. **The two-step form**
```c
idx = gGameStuff.pendingMode;
idx -= 1;
```
(with `int idx`, materialized at every call site) produces the EXACT target
index codegen: `ldrb r1,[r0,#10]; subs r1,#1; lsls r0,r1,#2; adds r0,r0,r1;
lsls r0,r0,#2; adds r0,r0,table; ldr r0,[r0]`. The index computation is a
byte-match in all three sites. KEEP THIS — it fully resolves the indexing drift
that the prior note left as two competing partial fixes.

### KEY NEW FINDING #2 — struct-pointer model fixes the in-loop base reload
The prior note's drift #1 (base kept in r6 across loop1 vs target reloading from
the pool inside the loop) is FIXED by modelling 0x03006110 as a struct pointer:
```c
struct WorkArea { u8 _pad00[0x26]; u16 maskA; u8 _pad28[2]; u8 maskB; };
#define gWork ((struct WorkArea *)0x03006110)
...
if (gWork->maskA >> i) & 1   /* inline gWork in the loop body */
```
With the loop body reading `gWork->maskA` (inline, not a cached `base` var),
agbcc REMATERIALIZES the constant base inside loop1 (`ldr r0,=base; ldrh
r0,[r0,#38]`), matching the target's reload. A plain `u8 *base` variable keeps
base in r6 and reuses it (no reload). So: top read via a live `work`/`base`
value, in-loop read via the inline struct constant.

### The TWO residual drifts (both agbcc reload/LICM, NOT permuter-reachable)
1. **Top base-load shape.** Target: `ldr r0,=base; ldrh r1,[r0,#0x26]; adds
   r6,r0,#0` — load base→r0, mask→r1, COPY base to r6. Every C variant either
   (a) loads base directly into r6 and reads mask into r0 (no copy, 1 insn
   shorter), or (b) with the inline/literal split, loads base TWICE (r7 for the
   mask read + r6 for the post-loop preserve) instead of load-once+copy.
   Pinning `register WorkArea *work asm("r6")` forces base into r6 (byte_diff
   162) but then r6 stays locked to work — the target FREES r6 after loop1 and
   reuses it for tableB in loop2's inner loop (`ldr r6,=tableB`), so the pin
   corrupts loop2 (`adds r6,#42` advances the pinned work in-place for the p2a
   compute). The copy-to-r6 is a reload.c decision about preserving a constant
   across a loop vs rematerializing — not inducible from C here.
2. **Loop-invariant register loads placed in the PREHEADER (after the entry
   `cmp i,bound; bcs` guard).** Target loads tableA (r7), pairs (sl), p2a (r9)
   AFTER the `movs r4,#0; cmp; bcs` bound check. Every straight-line C
   assignment before the `for` lands BEFORE the guard. Putting the assignments
   inside the loop body for LICM to hoist → LICM either recomputes per-iter
   (diff up) or doesn't hoist to the preheader cleanly. This is agbcc loop-header
   generation placement, tied to drift #1 (the base/work live-range shape).

#include "types.h"

    void *list;
    u8 _pad[16];

#define gModePairs ((struct ModeEntry *)0x08307EB8)
#define gModeListB ((struct ModeEntry *)0x08307EBC)

void sub_08010958(u8 a, u8 b)
{

    register u8 *p2a asm("r9");
    register struct ModeEntry *pairs asm("sl");
    struct ModeEntry *listA;
    u8 *pair;
    u8 i;
    u8 j;
    u8 count;
    int idx;

        listA = gModeListA;
        for (i = 0; i < a; i++) {
            if ((*(u16 *)(base + 0x26) >> i) & 1) {
                idx = gGameStuff.pendingMode;
                idx -= 1;
                sub_080105B0(listA[idx].list, i, 1);
            }
        }
    }

        return;
    }

    pairs = gModePairs;
    p2a = base + 0x2a;

            idx = gGameStuff.pendingMode;
            idx -= 1;
            pair = (u8 *)pairs[idx].list + i * 2;
            j = pair[0];
            count = pair[1];
            while (count != 0) {
                idx = gGameStuff.pendingMode;
                idx -= 1;
                sub_080105B0(gModeListB[idx].list, j++, 0);
                count--;
            }
        }
    }
}
