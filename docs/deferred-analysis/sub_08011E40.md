## Drift

### sub_08011E40 — best byte_diff 193, diff_count 42 (CLEAN, no pins/flags)
Round-33 Opus improved the prior 58 (pinned) to **42 with ZERO levers** —
cleaner C, and pins/flags only make it WORSE (every per-TU CFLAGS variant and
the AGBCC swap stay at 42 or regress to 44-94; full register pins 49-54). The
clean 42 shape is the right base; do NOT re-add pins.

ROOT CAUSE (newly isolated — this is the actionable finding):
The residual 42 instructions all cascade from ONE decision: agbcc keeps the
**address `&gIwram_6110.byteFlags8` (= base+0x2a) alive in a callee-saved reg
(r9)** across the loop, via `mov r9,r1` right after the pre-loop compare. That
displaces the loop-invariant constant `0` (which baserom keeps in r9 and reuses
for the `strh` that fills the DMA source halfword) and the constant `1` (r8).

WHY: the pre-loop compare (`ctrl->byteFlags8 != ctrl->gateByte`) computes
`&base[0x2a]` into r1, and the loop ALSO reads `ctrl->byteFlags8`. The main
`cse.c` pass recognises the loop's `&base[0x2a]` as a common subexpression with
the pre-loop's, so it keeps r1 alive (→ r9) instead of letting the compare's
`ldrb` consume it in-place.
  - baserom:  `ldrb r1,[r1]` (IN-PLACE — address dies, value overwrites it),
              then the loop re-derives `&base[0x2a]` fresh each iteration
              (`adds r0,r7,#0; adds r0,#0x2a`), and r9 holds the constant 0.
  - our 42:   `ldrb r2,[r1]` (NOT in-place — r1/`&base[0x2a]` survives) →
              `mov r9,r1` → loop reads via r9. r9 = address, not 0.

This is the `reg_single_usage` "large-loop single-use re-derive" path in
`loop.c` (~line 905): baserom's loop address is single-use so it's re-derived;
ours is CSE-merged with the pre-loop so it's multi-use and gets hoisted.

Levers that do NOT break the cross-block CSE (all tried, all stay 42 or worse):
- per-TU `-fno-gcse` (52), `-fforce-addr` (48), `-fno-move-all-movables` (48),
  `-fno-schedule-insns` (42), `-fno-strength-reduce` (42),
  `-fno-rerun-cse-after-loop` (42), `-fno-cse-follow-jumps` (59 alone; still
  keeps `mov r9,r1` when combined with a loop temp), `-fno-regmove` (44),
  `-fmove-all-movables`/`-freduce-all-givs` (94), `-ffixed-r9` (54 — just moves
  the address cache to sl + adds a stack slot).
- AGBCC (newer) per-TU swap: 202 (much worse — OLD_AGBCC is correct).
- compare via absolute `gIwram_6110` + loop via `ctrl` (or vice-versa): 44 and
  the body shrinks (base no longer held callee-saved).
- byte-pointer `flags=(u8*)&gIwram_6110` for the compare: 219/45.
- reading both flag bytes into u8 temps up front: 75 (loses the short-circuit
  gateByte read).
- loop temp `b=(byteFlags8>>i)&1`: no change (42).
- full pins (ctrl=r7, one=r8, zerov/zc=r9, result=sl): 49-54.

NEXT LEVER (for the permuter pass): from the clean-42 base, the permuter needs

for the constant 0. This is exactly statement-reordering / var-scope mutation
(permuter's wheelhouse), NOT a flag and NOT a pin.

## Best-effort C

```c
#include "game.h"
#include "gba/dma.h"
#include "gba/io.h"
#include "iwram.h"
#include "types.h"

/* gIwram_6110 is struct IwramAt6110 (include/iwram.h): byteFlags8 @0x2a,
 * gateByte @0x2b. gIwram_6480 @0x03006480 field_02 is the active sub-channel
 * index. sBlitRecords_6d40 = 0x08306d40 (ROM blit-record table). */
struct IwramAt6480_11e40 {
    u8 _pad00[2];
    u8 field_02;
};

extern struct IwramAt6480_11e40 gIwram_6480;
extern const u8 sBlitRecords_6d40[];

extern void sub_08011984(const u8 *records, u8 idx);
extern void sub_0800EE94(u8 layer);
extern u8 sub_08011AA4(const u8 *records);

u8 sub_08011E40(void)
{
    struct IwramAt6110 *ctrl;
    volatile DmaChannel *dma;
    u16 zero;
    s32 i;
    u8 result;

    result = 0;
    ctrl = &gIwram_6110;

    if (ctrl->byteFlags8 != ctrl->gateByte) {
        i = 0;
        dma = &REG_DMA3;
        do {
            if (((ctrl->byteFlags8 >> i) & 1) != 0 &&
                ((ctrl->byteFlags8 >> i) & 1) != ((ctrl->gateByte >> i) & 1)) {
                zero = 0;
                dma->src = &zero;
                dma->dst = (void *)0x0600f000;
                dma->cnt = DMA_ENABLE | DMA_SRC_FIXED | 0x400;
                (void)dma->cnt;

                dma->src = &zero;
                dma->dst = (void *)0x02020000;
                dma->cnt = DMA_ENABLE | DMA_SRC_FIXED | 0x8000;
                (void)dma->cnt;

                sub_08011984(sBlitRecords_6d40, (u8)(i * 3));
                sub_0800EE94(2);

                *(vu16 *)0x04000050 = 0x1744;
                *(vu16 *)0x04000052 = 0x020e;

                ctrl->gateByte |= (u8)(1 << i);
                gIwram_6480.field_02 = (u8)i;
            }
            i = (u16)(i + 1);
        } while (i <= 1);
    }

    if ((s8)sub_08011AA4(sBlitRecords_6d40) != 0)
        result = 1;

    return result;
}
```
