## Drift (best byte_diff 21, diff_count 8)

Two clusters, both agbcc cross-jump / block-ordering canonicalization (jump.c
`cross_jump`/`find_cross_jump`), NOT a structural C error:

1. **Bit-search guard branch sense** (offset 0x62/0x64, 2 instrs).
   - target: `bls 0x1abb4` (continue → the case-4 *bit-search* check) + `b 0x1ab70` (fail, backward).
   - built : `bhi 0x1ab70` (fail, backward) + `b 0x1abe2` (continue → dispatch).
   - Root: baserom checks `mode==5` and `mode==4` as **two sequential `if`s** (case-5
     success flows INTO the `cmp r4,#4` of case-4's guard, then bne→dispatch). My `else if`
     skips straight to dispatch. Changing to two separate `if`s DOES reproduce the flow
     (`bhi fail` then fall-through to `cmp r4,#4`) **but** is then 4 bytes short — agbcc
     merges the two `highest = i+1` found-handlers (a spurious `adds r0,r1,#1; b` at ~0x34)
     when the guards are separate ifs, shrinking the function and cascading every later
     offset → byte_diff 241. Need separate-if guards WITHOUT the found-handler merge.

2. **case-4 epilogue: pointer-vs-value caching + unshared store** (offsets 0xf6,0xf8,0xfa,0x104,0x106,0x108).
   - target: case-4 reads `roomState[2]` into **r1** (dead after the `cmp`), keeps the
     *pointer* in **r2** (`adds r2,r0,#0`), then `b 0x1ac72` to the **shared** `strh r0,[r1,#2]`
     and **re-reads** `ldr r0,[r2,#8]` at the common return. So case-4's store + return are
     cross-jump-merged with case-5's.
   - built : case-4 caches the *value* `rs[2]` in r2 (early `return rs[2]` keeps it live in a
     callee-saved reg across the store), emits its **own** `strh` + `adds r0,r2,#0; b epilogue`.
     No merge.
   - Root: the early `return rs[2]` lets agbcc keep the value (not the pointer) in r2; the
     `strh` to gIwram_35E0 (different address, no alias) does not invalidate the cached load,
     so it is never re-read.
