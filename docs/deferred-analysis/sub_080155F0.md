## Semantics (confirmed)

- Dispatch byte = `gIwram_6110.gateByte` (0x03006110 + 0x2b), values 0..3 select
  one of four (low, high) BG-tilemap variant pairs; default returns.
- Per case (inlined 4x): read selector `sel = *(s16 *)((u8*)gEntities + 0xb70)`
  (gEntities = 0x03003720; +0xb70 = gEntities[52].field_10; read **signed**,
  `ldrsh`). Compare against cached byte `*(u8*)0x0300361b` (0x03003610 + 0xb).
  If changed: DMA the chosen variant (`sel ? high : low`) into EWRAM scratch
  0x02010000 (REG_DMA3 cnt = DMA_ENABLE|0x8000), readback cnt, then RE-READ the
  selector as **unsigned** (`ldrh`, *(u16*)) and store its low byte to the cache,
  then `sub_080100E4(1, 0x02010000, 0x0600e800)` streams to BG screenblock 29.
- Shared tail: r4 = the case's palette pointer table
  (`(const u16 *const *)(0x08307e8c + caseIdx*8)`). `now = gGameStuff._unk00`
  (0x03005330); `lastTick = *(u32*)(gEntities + 0x1a60)`. If `now - *lastTick < 8`
  return; else `*lastTick = now`; a 0..1 rolling counter at `*(u8*)(gEntities +
  0x1a5b)` (reset to 0 when >1, then post-increment) indexes the palette table
  (idx*4 via `lsls#24;lsrs#22`) and DMAs the palette into 0x05000140 (cnt =
  DMA_ENABLE|0x20).
- Variant anchors: `sScenerVariantModeN{Low,High}_*` (globals in
  `asm/data/scenery_1b62aa.s`). Palette table at 0x08307e8c = 8 ROM u16-ptrs
  (0x0819de4a, 0x0819de8a, ...); it sits 0x14 past `gPaletteSrcTable_08307E78`

## Drift — THE CORE BLOCKER (new, decisive analysis this round)

This round REACHED a structurally-correct shape (correct `push {r4,r5,lr}`,
correct entity-address RECOMPUTE for the cache write, 34 instrs/case == target's
34). Best byte_diff this round: **527** (explicit if/else + 2 pins; the high
value is mostly a length-cascade artifact — see below). But the match is blocked
by ONE irreducible agbcc register-allocation conflict, proven across ~21 source
variants:

**The ternary-copy vs entity-recompute MUTUAL EXCLUSION.** The target needs BOTH
of these simultaneously, but agbcc emits them from MUTUALLY EXCLUSIVE source
shapes:

1. **Entity-address RECOMPUTE for the cache write.** The target builds
   `gEntities + 0xb70` (via `ldr =0x03003720; movs #0xb7; lsls #4; adds`) TWICE —
   once for the signed `sel` read, again for the unsigned cache-write read — i.e.
   it does NOT keep the pointer in a register. agbcc only recomputes when the
   entity-ptr pseudo is NOT assigned a callee-saved register, which requires
   register PRESSURE (the explicit `if (sel) src=high; else src=low;` keeps BOTH
   low and high live across the branch, consuming callee-saved regs, so the
   entity ptr stays in caller-saved r0 and is clobbered by the DMA stores ->
   recompute). CONFIRMED: explicit if/else + `register T low asm("r4")`,
   `high asm("r3")` pins -> `push {r4,r5,lr}`, cache RECOMPUTES. This is the
   right half.

2. **The ternary sel-copy.** The target's select is `REG_DMA3.src = sel ? high :
   low;`, which lowers to `adds r0,r1,#0; cmp r0,#0; bne high; (low path)` — a
   COPY of sel before the != 0 test, and stores low on fall-through. The explicit
   `if (sel != 0)` instead emits `cmp r1,#0; beq` (no copy). So the target's
   select shape requires the TERNARY.

THE CONFLICT: the ternary frees register pressure (low/high are lazy, loaded
only inside the conditional), so agbcc ALWAYS assigns the entity-ptr pseudo a
callee-saved register (r6, or `ip`/r12 under -ffixed-r6,r7) and CSE-REUSES it for
the cache write (NO recompute, `push {r4,r5,r6,lr}`). Proven across 8 ternary
variants: 3 pins (r4/r3/r5), named base local for read1, two scoped base locals,
volatile reads, -ffixed-r6/-ffixed-r7 (agbcc just grabs r7 or ip), -O1,
-fno-caller-saves/-fcaller-saves/-fno-function-cse/-fno-gcse/-fno-cse-follow-jumps,
and the newer AGBCC compiler — EVERY ternary variant holds the entity ptr.
So: ternary -> right select shape, WRONG (CSE) cache; explicit -> right (recompute)
cache, WRONG select shape. No single source shape gives both.

### What this means for the next agent
- This IS the classic sharp register-coloring local minimum. The designated
  escape tool is `vendor/decomp-permuter` (statement-reorder / var-scope
  mutation) — but its `.venv` is MISSING in this worktree AND in main
  (vendor/decomp-permuter is a self-referential symlink; no .venv anywhere).
  **Install the permuter venv first**, then permute from the v17 base below
  (byte_diff is misleading; the structure is 1 idiom away).
- DO NOT re-walk the levers already exhausted (full list above). The remaining
  gap is PURELY: make the ternary `sel ? high : low` NOT cause agbcc to preserve
  the entity-ptr in a callee-saved reg. Read `tools/agbcc-src/gcc_arm/local-alloc.c`
  `update_equiv_regs` / `combine_regs` + `qty_n_refs` — the entity-ptr pseudo is
  used twice (sel read + cache read); under the ternary, local-alloc ranks it
  high enough to win a callee-saved reg. The lever is to make that pseudo's
  live-range cross a clobber (e.g. force the sel-read pointer into the SAME
  caller-saved reg the DMA `.src` store writes), OR raise pressure under the
  ternary so no callee-saved reg is free WITHOUT agbcc falling back to `ip`.
- A `mov pc` / casesi switch is NOT involved here — the dispatch is a plain
  `cmp; beq` ladder over gateByte and already matches.

(both give identical case-0 code). The two `register ... asm("rN")` pins set
