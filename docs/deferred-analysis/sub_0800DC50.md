# sub_0800DC50 — deferred analysis

Entity-spawn driver at 0x0800DC50 (304 B, Thumb). Indexes the 8-byte
`sEntityInitTable` records (base 0x080C0E20) by `gGameStuff.pendingMode`, runs an
initial settle loop while the per-record `settleLimit` (record+1) is not exceeded
and `gEntities[0].field_1A <= 3`, then iterates spawn-point coordinate pairs and
calls `sub_0800A458(x, y)` until each point reports done. `classify_unmatchable.py`
returns `ATTEMPT_MATCH` (only a 2-high-reg advisory). Not class3-libgcc.

## Key advance this round (vs the prior byte_diff-30 PINNED plateau)

**The `sub_0800A458` parameter type is the size-load-bearing fix.** Declaring it
`extern u32 sub_0800A458(s16 x, s16 y)` (NOT `u16`) makes the points reads emit
register-offset `ldrsh` (`movs r3,#0; ldrsh r0,[r1,r3]` + `movs r2,#2; ldrsh
r1,[r1,r2]`) exactly like the baserom, instead of immediate-offset `ldrh`
(`ldrh [r1,#0]; ldrh [r1,#2]`). The `ldrsh` form is 2 instructions LONGER (Thumb-1
has no `ldrsh Rd,[Rn,#imm]`), which restores the function to the correct **304-byte
size**. With the wrong `u16` decl the function is 300 B (4 short), which cascades a
4-byte shift into every back-edge branch target and forks the constant-pool layout
(the prior round's 30 was masking this with pins; the true clean structure was never
the right size until the `s16` decl).

With the `s16` decl + a plain readable `for`/`while` structure and NO pins:
**byte_diff 29 / diff_count 29, all ARGUMENT_MISMATCH** — the function is now the
right size, prologue/epilogue exact, ALL high registers correct *naturally*
(r6=origin, r9=gs `mov r9,r2`, sl=table, r8=pointOffset=i*4, r7=i<<24), loop layout
exact, pool count (6 words) exact. This is strictly better than the prior round's
byte_diff-30 *with* r6/r9/sl/r8 pins — the pins are now confirmed unnecessary and
HARMFUL (re-adding them + the do/while restructure regresses to 148-222).

## Drift — the irreducible residual (byte_diff 29)

Every one of the 29 diffs is a low-register SCRATCH coloring choice at the
table-index sites: baserom reads the index into a fresh non-r0 scratch then shifts
into r0 —
```
ldrb r3, [r1, #10]      @ pendingMode -> scratch (r3 / r2 / r1 / r4, varies per site)
lsls r0, r3, #3         @ *8 -> r0
```
agbcc instead reads the index directly into r0 and shifts in place —
```
ldrb r0, [r1, #10]
lsls r0, r0, #3
```
5 such index sites, plus the same "prefer non-r0 scratch" choice on:
- the inner-loop `table`->`sl` handoff (`ldr r4; mov sl, r4` vs `ldr r0; mov sl, r0`),
- the `pointOffset` derive (`asrs r0, r7, #22; mov r8, r0` vs `asrs r1,...; mov r8, r1`),
- the flag-OR constants (`movs r3, #2; orrs r5, r3` vs `movs r0, #2; ...`),
- the points-base `ldr r2 =0x080C0E24; adds r0, r0, r2` (vs `ldr r3; adds r0, r0, r3`).

Root cause (CONFIRMED by instrumenting a private debug `old_agbcc`,
`gcc/local-alloc.c`):
`combine_regs` TIES the zero_extend (ldrb index) result pseudo to the ashift (`<<3`)
result pseudo into one quantity → both get r0. The tie fires because the index
pseudo is **local-to-block and dies once** (`reg_qty[ureg] >= 0`). For the baserom
shape the index must instead be a **cross-block pseudo** (`reg_qty < 0`), so the tie
is skipped and the index lands on the next free non-r0 scratch while the longer-lived
shift-result chain keeps r0. A fresh per-site `gGameStuff.pendingMode` memory read
(the calls clobber memory, so it cannot be cached/hoisted) is single-block by
construction — so plain C never makes the index cross-block.

Compiler passes implicated: `gcc/local-alloc.c` `combine_regs` (the tie) +
`find_free_reg` (the leftover-scratch pick). The instrumented `AGBCC_DBG2` trace
shows the phase-1 chain quantity {157,159,160,...} (nrefs=6) taking phys=r0; the
index 157 is inside that tied quantity.

## Best-effort C (byte_diff 29 — clean pure C, NO pins/asm/NON_MATCHING)

```c
#include "game.h"
#include "iwram.h"
#include "macros.h"
#include "types.h"

#define SPAWN_FLAG_DONE 1
#define SPAWN_FLAG_WAITING 2

typedef struct EntityInitDesc {
    s8 spawnCount;
    u8 settleLimit;
    u8 waitLimit;
    u8 _pad3;
    const s16 *points;
} EntityInitDesc;

extern const EntityInitDesc sEntityInitTable[];
extern void sub_0800A520(void);
extern void sub_0800A2D8(void);
extern void sub_080008DC(void);
extern void sub_0800A328(void);
/* s16 (NOT u16) params -> register-offset ldrsh at the call site -> correct 304 B size */
extern u32 sub_0800A458(s16 x, s16 y);

void sub_0800DC50(void)
{
    u8 flags;
    u32 origin;
    s8 i;
    u8 result;

    flags = 0;
    origin = gGameStuff._unk00;

    while ((gGameStuff._unk00 - origin) < sEntityInitTable[gGameStuff.pendingMode].settleLimit &&
           gEntities[0].field_1A <= 3) {
        sub_0800A520();
        sub_0800A2D8();
        sub_080008DC();
        sub_0800A328();
    }

    if (sEntityInitTable[gGameStuff.pendingMode].spawnCount == 0) {
        return;
    }

    for (i = 0; i < sEntityInitTable[gGameStuff.pendingMode].spawnCount; i++) {
        flags &= ~SPAWN_FLAG_DONE;
        while ((flags & SPAWN_FLAG_DONE) == 0) {
            if (flags & SPAWN_FLAG_WAITING) {
                if ((gGameStuff._unk00 - origin) > sEntityInitTable[gGameStuff.pendingMode].waitLimit) {
                    flags &= ~SPAWN_FLAG_WAITING;
                }
            } else {
                const s16 *points = sEntityInitTable[gGameStuff.pendingMode].points + i * 2;
                result = (u8)sub_0800A458(points[0], points[1]);
                if (result == 0xff) {
                    origin = gGameStuff._unk00;
                    flags |= SPAWN_FLAG_WAITING;
                }
                if (result == 1) {
                    flags |= SPAWN_FLAG_DONE;
                }
            }
            sub_0800A2D8();
            sub_080008DC();
            sub_0800A328();
        }
    }
}
```
