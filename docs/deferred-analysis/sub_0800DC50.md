# sub_0800DC50 — deferred analysis

Entity-spawn driver at 0x0800DC50 (304 B, Thumb). Indexes the 8-byte
`sEntityInitTable` records (base 0x080C0E20) by `gGameStuff.pendingMode`, runs an
initial settle loop while the per-record `settleLimit` (record+1) is not exceeded
and `gEntities[0].field_1A <= 3`, then iterates `spawnCount` (record+0, s8) times,
each time spinning on coordinate pairs (record+4, `points`) and calling
`sub_0800A458(x, y)` until each point reports done (1) or waiting (0xff).
`classify_unmatchable.py` returns `ATTEMPT_MATCH`. Not class3-libgcc.

## Plateau: byte_diff 29 / diff_count 29, ALL one root cause

The clean readable C below (NO pins/asm/NON_MATCHING/flags) compiles to the
correct **304-byte** size with prologue/epilogue exact, ALL high registers
correct *naturally* (r6=origin, r7=i<<24, r8=pointOffset=i*4, r9=gs base,
sl=table base, r5=flags), loop layout exact, and the 6-word pool exact. The
`extern u32 sub_0800A458(s16 x, s16 y)` decl (s16, NOT u16) is size-load-bearing:
it forces the register-offset `ldrsh` form (`movs r3,#0; ldrsh r0,[r1,r3]`) the
baserom uses, restoring the 304-byte size (u16 gives 300 B and cascades).

Every one of the 29 diffs is the SAME register-coloring choice at the 6
table-index sites: baserom reads the `pendingMode` byte into a fresh non-r0
scratch then shifts into r0 —
```
ldrb r3, [r1, #10]      @ pendingMode -> scratch (r3/r2/r1/r4, varies per site)
lsls r0, r3, #3         @ *8 -> r0
```
agbcc instead reads the index directly into r0 and shifts in place —
```
ldrb r0, [r1, #10]
lsls r0, r0, #3
```
Same "prefer non-r0 scratch" choice also affects the table->sl handoff, the
pointOffset derive (`asrs r0,r7,#22; mov r8,r0`), the flag-OR/AND scratch
constants, the ldrsh offset-reg pair, and the points-base `ldr r2 =0x080C0E24`.

## CORRECTED root cause (prior note misattributed the pass)

The prior note blamed `optimize_reg_copy_3` in `gcc/regmove.c`. **That function
is NEVER CALLED by old_agbcc** — confirmed by building a private instrumented
old_agbcc with an `fprintf` at its entry: 0 calls for both the clean base and
every variant. The merge is actually **`combine_regs` in `gcc/local-alloc.c`**
(line ~1666, the `reg_qty[sreg] = reg_qty[ureg]` tie). Instrumented trace on the
clean base shows the tie chain `ureg157(index) -> sreg159(shift) -> sreg160(add)`
folded into ONE quantity that takes r0. The tie fires because the index pseudo
DIES at the shift (`find_regno_note(insn, REG_DEAD, ureg)`, line 1666) and its
quantity's min-class admits the shift result. To SKIP the tie you need either
line 1629 (`reg_qty[ureg] < 0`, index cross-block) or line 1654
(`reg_qty[sreg] >= -1`, shift-result already-assigned/cross-block) — both require
a value that crosses a basic-block boundary, which a fresh per-site dead-once
`gGameStuff.pendingMode` read never is.

Corpus CONFIRMS this is *correct* agbcc output for this source: pokeruby
`shop.c@cf73b880e1` shows `lsl r0, r0, #0x3` (merged-to-r0) for a dead-once byte
load `ldrb r0,[r3,#9]`, and `lsl r0, r5, #0x3` (scratch) only when the index is a
HELD loop counter (r5, cross-block). Our 6 indexes are all dead-once memory reads
(calls clobber pendingMode so they cannot be cached/hoisted), so plain C cannot
make them cross-block.

## Why the obvious escapes all fail (measured this round)

- **`-fno-expensive-optimizations`** DOES flip all 6 index sites to scratch
  (regclass runs 1 pass not 2; `combine_regs` then keeps the index separate). BUT
  it STRUCTURALLY changes the function: size 296 (not 304), an extra `mov r8,r1`,
  a `movs r6,#2` hoist, and it PERMUTES every high register (gs r9->sl, i<<24
  r7->r1, pointOffset r8->r9, origin r6<->r7). Full byte_diff 187 with 5
  non-rename structural diffs that pins cannot repair. Both old_agbcc and the new
  agbcc merge the index identically with default flags (so a CC swap is no help —
  new agbcc was already 78 globally per the prior note).
- **A reused `mode` local** (`u32 mode;` reassigned at each site, so
  `REG_N_SETS(mode) > 1` breaks the tie) DOES fix the index (variants D/G/H:
  scratch=6, r0=0), but `mode` then needs a register and the baserom already
  occupies r5/r6/r7/r8/r9/sl — so `flags` is displaced r5->r4 and the loads
  reorder. Full byte_diff 187-195. There is NO free callee-saved register for a
  mode local; this escape is structurally impossible to make register-clean.
- **Comma/statement-expr index** `[(mode=X, mode)]` is copy-propagated back to a
  direct load->subscript chain → tie still fires (scratch=0, r0=6).
- **Held table base / held gs base** (`const EntityInitDesc *t = sEntityInitTable;`
  or `GameStuff *g = &gGameStuff;`) shave 1 site each (r0=5/6) but also consume a
  register and don't generalize.
- **Hard-reg pin on the index** (`register u32 m asm("r3")`) only takes at the
  non-comma sites; copy-prop defeats it elsewhere (scratch=2, r0=5).
- **Permuter** (now WORKING — set up a fresh checkout + venv in-worktree; the
  main `vendor/decomp-permuter` symlink is a self-referential loop, copy a
  populated checkout from a `.codex-worktrees/*/vendor/decomp-permuter` and make a
  venv with `pycparser`+`toml`): 4917 iterations, best score 140 vs base 150 —
  the only mutation it found was a `do{}while(0)` wrapper. This is a pure
  register-coloring minimum the permuter cannot escape (it reorders statements /
  scopes; it cannot make a dead-once memory read cross-block).

## Best-effort C (byte_diff 29 — clean pure C, NO pins/asm/NON_MATCHING/flags)

```c
#include "game.h"
#include "iwram.h"
#include "macros.h"
#include "types.h"

#define SPAWN_FLAG_DONE 1
#define SPAWN_FLAG_WAITING 2

typedef struct EntityInitDesc {
    s8 spawnCount;
    u8 settleLimit;
    u8 waitLimit;
    u8 _pad3;
    const s16 *points;
} EntityInitDesc;

extern const EntityInitDesc sEntityInitTable[];

extern void sub_0800A520(void);
extern void sub_0800A2D8(void);
extern void sub_080008DC(void);
extern void sub_0800A328(void);
/* s16 (NOT u16) params -> register-offset ldrsh at the call site -> correct 304 B size */
extern u32 sub_0800A458(s16 x, s16 y);

void sub_0800DC50(void)
{
    u8 flags;
    u32 origin;
    s8 i;
    u8 result;

    flags = 0;
    origin = gGameStuff._unk00;

    while ((gGameStuff._unk00 - origin) < sEntityInitTable[gGameStuff.pendingMode].settleLimit &&
           gEntities[0].field_1A <= 3) {
        sub_0800A520();
        sub_0800A2D8();
        sub_080008DC();
        sub_0800A328();
    }

    if (sEntityInitTable[gGameStuff.pendingMode].spawnCount == 0) {
        return;
    }

    for (i = 0; i < sEntityInitTable[gGameStuff.pendingMode].spawnCount; i++) {
        flags &= ~SPAWN_FLAG_DONE;
        while ((flags & SPAWN_FLAG_DONE) == 0) {
            if (flags & SPAWN_FLAG_WAITING) {
                if ((gGameStuff._unk00 - origin) > sEntityInitTable[gGameStuff.pendingMode].waitLimit) {
                    flags &= ~SPAWN_FLAG_WAITING;
                }
            } else {
                const s16 *points = sEntityInitTable[gGameStuff.pendingMode].points + i * 2;
                result = (u8)sub_0800A458(points[0], points[1]);
                if (result == 0xff) {
                    origin = gGameStuff._unk00;
                    flags |= SPAWN_FLAG_WAITING;
                }
                if (result == 1) {
                    flags |= SPAWN_FLAG_DONE;
                }
            }
            sub_0800A2D8();
            sub_080008DC();
            sub_0800A328();
        }
    }
}
```
