# sub_0800DC50 — deferred analysis

Entity-spawn driver at 0x0800DC50 (304 B, thumb). Indexes `sEntityInitTable`
(0x080c0e20, 8-byte records) by `gGameStuff.pendingMode` and runs two phases:
a settle loop (4 callees while `gIwram_3720._field_1A <= 3` and the entity
hasn't advanced past `record.limit`), then a per-spawn-point loop that calls
`sub_0800A458(x, y)` on each `{s16 x, s16 y}` from `record.points`, OR-ing
result-dependent bits into a `flags` byte.

VERDICT: classify_unmatchable = ATTEMPT_MATCH (NOT a NAKED candidate). The
whole structure is correct. The residual is PURE register-coloring.

## Status

Best clean readable C reaches **byte_diff 32 / diff_count 31** (the
"Best-effort C" block below). The entire structure matches — prologue/epilogue
(incl. r8/r9/sl save), the two-phase loop shape, the `s8 i` counter in `<<24`
form, the `ldrsh` coord reads, the dead `while`-entry guard, and the
high-register roles all reproduce.

The residual 32 is ONE systematic phenomenon: at ~8 sites agbcc puts a
short-lived temporary in **r0** (the lowest free caller-saved reg) where the
baserom's original compiler used a **higher scratch reg (r1/r2/r3/r4)**. Two
sub-patterns:
1. **index-tie** (~12 bytes, 6 sites): `ldrb r3,[base,#10]; lsls r0,r3,#3`
   (baserom, separate regs) vs `ldrb r0; lsls r0,r0,#3` (agbcc, coalesced).
2. **constant/move spreading** (~8 bytes): `movs r3,#0`/`movs r4,#1` and the
   `mov sl,r4`/`asrs r0`/`mov r8,r0` setup land in r0/r1 under agbcc.

## ROOT CAUSE (proven by isolated probes — this is the NEW finding)

The index-tie is agbcc's `local-alloc.c combine_regs` tying the `ldrb`-dest
pseudo to the `lsls`-dest pseudo because the `ldrb` value (pendingMode) **dies
at the shift** (used exactly once). Probes confirmed:
- Both the struct-subscript form `tbl[id].limit` AND the explicit-offset form
  `(EntityInitDesc*)((id<<3)+(u32)tbl)->limit` coalesce identically in
  isolation — the dispatch_helpers.c idiom does NOT inherently separate them;
  its `ldrb r2` there was incidental register pressure, not the idiom.
- The tie BREAKS only when the index value is **live past the shift** (e.g.
  `lim = tbl[id].limit; return lim + id;` → `ldrb r0; lsl r1,r0` separate).
  The function semantics read pendingMode exactly once per access, so no clean
  C provides a live-past use.

## THE LEVER THAT WORKS (also new — use this as the starting point)

Pinning BOTH the index AND the shift-result forces the baserom layout:
```c
register u8 id asm("r3");
register u32 boff asm("r0");
id = base->pendingMode;
boff = (u32)id << 3;            /* -> ldrb r3,...; lsls r0,r3,#3  (SEPARATE!) */
... ((const EntityInitDesc*)(boff + (u32)tbl))->limit
```
With `base` pinned r1 and `tbl` pinned r2 (and copied to r7 inside the settle
loop via a `register ... t7 asm("r7") = t;` mirroring the baserom's
`adds r7,r2,#0`), the **entire settle loop becomes BYTE-PERFECT**:
```
ldr r1,[gs]; ldr r2,[tbl]; ldr r6,[r1,#0]; ldrb r3,[r1,#10]; lsls r0,r3,#3;
adds r0,r0,r2; ldrb r0,[r0,#1]; ... adds r4,r1,#0; adds r7,r2,#0; bl x4;
ldrb r2,[r4,#10]; lsls r0,r2,#3; ldr r1,[r4,#0]; subs r1,r1,r6; adds r0,r0,r7 ...
```
This was verified — the settle loop reached 0 diff. The spawnCount/i-init
block also matches when `spawnCount` is an **unpinned `s8` local** (agbcc CSEs
the one read into r0 and does `cmp r0,#0; beq` + `movs r1,#0; cmp r1,r0; bge`).

## WHY IT STILL DOESN'T FULLY MATCH (the wall the next attempt must beat)

The fix is a LOCAL-MINIMUM TRADE-OFF: pinning to fix the index perturbs the
global allocation, and agbcc re-spreads the *constants* (the `movs #0/#2/#1`
for the ldrsh offset + flag bits, and the `mov sl`/`asrs`/`mov r8` setup
scratch) to compensate. Concretely:
- Full per-site pin version reached **byte_diff 38** (settle loop + points
  branch perfect, but constant spreading + a table-reg shift in the points
  branch net out WORSE than the clean 32).
- Settle-pins + clean phase-2 = 40 (the r1/r2 settle pins collide with
  phase-2's natural register choices).
- The points branch needs `table+4` (pool 0x080c0e24) as the base read at
  offset 0 — use `*(const s16*const*)(boff + (u32)((const u8*)sEntityInitTable+4))`
  — that part DID match; the residual there is the first `ldrsh` offset
  constant `movs r3,#0` landing in r2.

So: the index-tie and the constant-spread are coupled through the allocator.
No single global pin assignment found drives all ~8 sites to the baserom regs
simultaneously. The NEXT attempt should try to pin the **constant-materialization
scratch** regs too (the `movs #0/#2/#1` and the `mov sl` source) IN COMBINATION
with the settle/index pins, OR instrument `local-alloc.c` to watch the
allocation order at the `mov sl, rN` and `movs rN, #imm` sites and find the
flag/shape that pushes them off r0. A private debug agbcc build
(codegen-notes "Instrumenting agbcc itself") is the recommended next move —
this is now a pure "which-hard-reg" question with a known mechanism.

```c
typedef struct EntityInitDesc {
    s8 spawnCount; /* +0 */
    u8 limit;      /* +1 */
    u8 limit2;     /* +2 */
    u8 _pad3;      /* +3 */
    const s16 *points;
} EntityInitDesc;

extern const EntityInitDesc sEntityInitTable[]; /* 0x080c0e20 */

extern void sub_0800A520(void);
extern void sub_0800A2D8(void);
extern void sub_080008DC(void);
extern void sub_0800A328(void);
extern u32 sub_0800A458(s16 x, s16 y);

void sub_0800DC50(void) {
    u8 flags;
    register u32 origin asm("r6");
    s8 i;
    u8 result;
    register GameStuff *gs asm("r9");
    register const EntityInitDesc *tbl asm("sl");
    register s32 off asm("r8");

    flags = 0;
    origin = gGameStuff._unk00;

    if ((u32)flags < sEntityInitTable[gGameStuff.pendingMode].limit && gIwram_3720._field_1A <= 3) {
        do {
            sub_0800A520();
            sub_0800A2D8();
            sub_080008DC();
            sub_0800A328();
        } while ((gGameStuff._unk00 - origin) < sEntityInitTable[gGameStuff.pendingMode].limit &&
                 gIwram_3720._field_1A <= 3);
    }

    if (sEntityInitTable[gGameStuff.pendingMode].spawnCount == 0) {
        return;
    }

    i = 0;
    if (i >= sEntityInitTable[gGameStuff.pendingMode].spawnCount) {
        return;
    }

    gs = &gGameStuff;
    do {
        flags &= 0xfe;
        while ((flags & 1) == 0) {
            tbl = sEntityInitTable;
            off = i * 4;
            if (flags & 2) {
                if ((gs->_unk00 - origin) > tbl[gs->pendingMode].limit2) {
                    flags &= 0xfd;
                }
            } else {
                const s16 *points = sEntityInitTable[gGameStuff.pendingMode].points;
                points = (const s16 *)((const u8 *)points + off);
                result = (u8)sub_0800A458(points[0], points[1]);
                if (result == 0xff) {
                    origin = gGameStuff._unk00;
                    flags |= 2;
                }
                if (result == 1) {
                    flags |= 1;
                }
            }
            sub_0800A2D8();
            sub_080008DC();
            sub_0800A328();
        }
        i++;
    } while (i < sEntityInitTable[gGameStuff.pendingMode].spawnCount);
}
```

## Corpus sweep (2026-06-03)

**Outcome: improved, 32 -> 31 byte_diff.** One structural diff resolved; residual is a pure register-coloring local minimum the corpus proves is structurally unreachable from any C shape for this function. Reverted to pristine; near-match C captured as a permuter seed in `nearMatchBase`.

### The exact asm idiom that diverges
sub_0800DC50 indexes `sEntityInitTable` (8-byte records at 0x080c0e20) by the `u8` field `gGameStuff.pendingMode`. At every index site the baserom reads the field into a **separate scratch low register** and shifts into r0:
- `ldrb r3,[r1,#10]; lsls r0,r3,#3` (×4 sites: 0x12, 0x3e, 0x56, 0x90 — scratch = r3/r2/r3/r3)
- `ldrb r1,[r4,#10]; lsls r0,r1,#3` (0xb2), `mov r4,r9; ldrb r4,[r4,#10]; lsls r0,r4,#3` (0x102 back-edge)
agbcc instead **funnels both pseudos to r0**: `ldrb r0,[r1,#10]; lsls r0,r0,#3`. Same phenomenon drives the small-constant diffs: baserom puts the ldrsh offset (`movs r3,#0`/`movs r3,#2`), the flag-OR constants (`movs r3,#2; orrs r5,r3`; `movs r4,#1`), and the `0x01000000` mask (`movs r3,#128; lsls r3,#17`) in scratch r3/r4; agbcc emits r0/r1/r2. Every one of the 29 residual diffs is a same-opcode ARGUMENT_MISMATCH (pure coloring) — zero structural/REPLACEMENT diffs remain after the fix below.

### Root cause (agbcc pass implicated)
`tools/agbcc-src/gcc_arm/local-alloc.c`, allocation-priority macro `QTY_CMP_PRI = floor_log2(n_refs)*n_refs*size / (qty_death - qty_birth)`. The index pseudo (ldrb dest) has lifespan 1 (dies at the lsls); the product pseudo (lsls dest) has lifespan ~3 (lsls->adds->ldrb). Equal n_refs(2)/size(1), so the **shorter-lived index wins the tiebreak and is allocated r0 FIRST** by `find_free_reg` (lowest free hard reg). The baserom is the reverse (product gets r0, index spilled to r3). NOT `combine_regs` — a `lsls`(ASHIFT) is not a copy insn so combine_regs never fires here; this is pure first-pick ordering. Confirmed INVARIANT: byte_diff stays 32 under `CC=OLD_AGBCC_BIN`, `-fno-local-alloc` (defers entirely to global reload), `-fregmove/-fno-regmove`, and a 14-flag sweep — the coloring is fixed by the C expression shape, not by any optimization pass.

Every corpus instance of the scratch-spread `lsls r0,rN,#3` has the index gaining liveness from **context our function structurally lacks**: a loop counter, a function parameter, or a call return. sub_0800DC50's index is a *pure dying struct-field `ldrb`* read fresh at each site (the baserom re-reads `pendingMode` every time — caching it in a `u32 id` local makes it WORSE, doc-confirmed and re-confirmed). ### NEW, more precise root cause (supersedes the QTY_CMP_PRI tiebreak theory)
The index-tie is `tools/agbcc-src/gcc_arm/local-alloc.c` **`combine_regs`** (not the
qty-priority tiebreak). At `lsls r0, rIDX, #3` the shift's input pseudo (the `ldrb`
index, lifespan 1, dies AT the shift) and the shift's dest pseudo get tied into one
quantity by `combine_regs` (called from the operand-equivalence loop ~line 1170; a
Thumb `lsl Rd,Rm,#imm` has no must-match-0 constraint so `may_save_copy=0`, and with the
index dying and `no_conflict` true the combine fires). Tied quantity ⇒ one hard reg ⇒
`ldrb r0; lsls r0,r0,#3`. The baserom keeps them disjoint (`ldrb r3; lsls r0,r3,#3`),
reserving r0 for the address accumulator. Same mechanism drives the low-reg constant
spreads (`movs r0,#2` vs baserom `movs r3,#2`).

### Proven escape-resistant (probes this round, all on the real TU)
- **Isolated probe**: `tbl[id].b` (and held-ptr `(&tbl[id])->b`, and ptr-arith) ALL
  coalesce `ldrb r0; lsl r0,r0`. The ONLY shape that separates them is making `id`
  **live past the shift** (`return tbl[id].b + (u8)id;` → `ldrb r0; lsl r1,r0`), but
  (a) it puts the index in r0 and product in r1 — the OPPOSITE of the baserom's
  index-in-scratch/product-in-r0, and (b) the function's semantics read pendingMode
  exactly once per access, so any live-past use is an ARTIFICIAL extra instruction that
  changes the bytes. There is no clean-C live-past use.
- **Compiler swap**: newer `agbcc` coalesces identically (and is globally worse, ~80).
- **CFLAGS sweep** (this round, measured at the TU): `-fno-regmove`, `-fcaller-saves`,
  `-fno-cse-follow-jumps`, `-fno-defer-pop`, `-fno-function-cse`, `-frerun-cse-after-loop`,
  `-fno-thread-jumps`, `-fno-peephole`, `-fno-strength-reduce` → all stay 31.
  `-fno-gcse` → 297 (breaks structure). `-ffixed-r0`/`-ffixed-r1`/`-ffixed-r2` just
  RELOCATE the tie (index+product both move to r1/r2 together) → 309. `-O1` separates
  one site but drops the high-reg structure → 142.
- **Register pressure**: reserving r0–r2 never separates the tie — combine_regs ties the

- **decomp-permuter** (re-seeded from THIS 31-base, `-j4 --stop-on-zero --better-only`,

### Verdict (refined)
NOT a combine_regs tie wall (the tie fires in the matched twin too). The real obstacle: the
baserom splits the base/table live ranges PER PHASE (low r4/r7 in the settle loop via
load-then-copy; high r9/sl in the points loop) and re-loads the index fresh through a held
base each site (which separates it from the product). agbcc, from any single C shape, either
(a) uses the macro base → ties index to product at each dying field-read (the 30 coloring
diffs), or (b) uses a held `&gIwram_5330` base → separates the index but coalesces the held
local into ONE register across both phases, omitting the baserom's per-phase copies and
reshaping the allocation (237+). The two requirements are mutually exclusive in pure C with
this allocator. classify_unmatchable = ATTEMPT_MATCH (NOT class3-libgcc) ⇒ NAKED is a
permanent regression ⇒ kept as an honest asm slice.
