# sub_0800DC50 — deferred analysis

Entity-spawn driver at 0x0800DC50 (304 B, thumb). Indexes `sEntityInitTable`
(0x080c0e20, 8-byte records) by `gGameStuff.pendingMode` and runs two phases:
a settle loop (4 callees while `gIwram_3720._field_1A <= 3` and the entity
hasn't advanced past `record.limit`), then a per-spawn-point loop that calls
`sub_0800A458(x, y)` on each `{s16 x, s16 y}` from `record.points`, OR-ing
result-dependent bits into a `flags` byte.

## Drift

Best reached: **byte_diff 32, diff_count 31** (linked diff_bytes 32).
The whole control-flow structure MATCHES: prologue/epilogue (incl. r8/r9/sl
save), the two-phase loop shape, the `s8 i` counter kept in `<<24` form, the
`ldrsh` coord reads, the dead `while`-entry guard (`movs r0,#0; cmp; bne`)
that agbcc emits because `flags &= 0xfe` provably clears bit 0, and the
high-register roles (origin=r6, gs=r9, table=sl, i*4=r8) all reproduce.

Residual is PURE low-register coloring, two systematic patterns:

1. **`ldrb idReg; lsls r0, idReg, #3` (≈12 byte diffs).** At every
   `sEntityInitTable[gGameStuff.pendingMode]` index the baserom reads
   `pendingMode` into a *separate* scratch reg (r3/r2/r4 — whichever is free)
   then shifts into r0. agbcc instead coalesces the `ldrb` dest into r0
   (`ldrb r0; lsls r0, r0, #3`). This is a `combine_regs`/local-alloc
   quantity-coalescing decision in
   `tools/agbcc-src/gcc_arm/local-alloc.c` — the ldrb-result pseudo and the
   lsls-result pseudo land in the same quantity under our register pressure.

2. **Small constants in high scratch regs (≈8 byte diffs).** Baserom uses
   `movs r3,#0`/`movs r3,#2`/`movs r4,#1` for the ldrsh offsets and the
   `flags |= 2` / `flags |= 1` constants; agbcc emits them into r0/r1/r2.
   Same allocation-freedom root cause as (1) — the baserom had r3/r4 free as
   scratch at those points and ours doesn't.

## Best-effort C (byte_diff 32, structure correct)

```c
typedef struct EntityInitDesc {
    s8 spawnCount; /* +0 */
    u8 limit;      /* +1 */
    u8 limit2;     /* +2 */
    u8 _pad3;      /* +3 */
    const s16 *points;
} EntityInitDesc;

extern const EntityInitDesc sEntityInitTable[]; /* 0x080c0e20 */

extern void sub_0800A520(void);
extern void sub_0800A2D8(void);
extern void sub_080008DC(void);
extern void sub_0800A328(void);
extern u32 sub_0800A458(s16 x, s16 y);

void sub_0800DC50(void) {
    u8 flags;
    register u32 origin asm("r6");
    s8 i;
    u8 result;
    register GameStuff *gs asm("r9");
    register const EntityInitDesc *tbl asm("sl");
    register s32 off asm("r8");

    flags = 0;
    origin = gGameStuff._unk00;

    if ((u32)flags < sEntityInitTable[gGameStuff.pendingMode].limit && gIwram_3720._field_1A <= 3) {
        do {
            sub_0800A520();
            sub_0800A2D8();
            sub_080008DC();
            sub_0800A328();
        } while ((gGameStuff._unk00 - origin) < sEntityInitTable[gGameStuff.pendingMode].limit &&
                 gIwram_3720._field_1A <= 3);
    }

    if (sEntityInitTable[gGameStuff.pendingMode].spawnCount == 0) {
        return;
    }

    i = 0;
    if (i >= sEntityInitTable[gGameStuff.pendingMode].spawnCount) {
        return;
    }

    gs = &gGameStuff;
    do {
        flags &= 0xfe;
        while ((flags & 1) == 0) {
            tbl = sEntityInitTable;
            off = i * 4;
            if (flags & 2) {
                if ((gs->_unk00 - origin) > tbl[gs->pendingMode].limit2) {
                    flags &= 0xfd;
                }
            } else {
                const s16 *points = sEntityInitTable[gGameStuff.pendingMode].points;
                points = (const s16 *)((const u8 *)points + off);
                result = (u8)sub_0800A458(points[0], points[1]);
                if (result == 0xff) {
                    origin = gGameStuff._unk00;
                    flags |= 2;
                }
                if (result == 1) {
                    flags |= 1;
                }
            }
            sub_0800A2D8();
            sub_080008DC();
            sub_0800A328();
        }
        i++;
    } while (i < sEntityInitTable[gGameStuff.pendingMode].spawnCount);
}
```

## Corpus sweep (2026-06-03)

**Outcome: improved, 32 -> 31 byte_diff.** One structural diff resolved; residual is a pure register-coloring local minimum the corpus proves is structurally unreachable from any C shape for this function. Reverted to pristine; near-match C captured as a permuter seed in `nearMatchBase`.

### The exact asm idiom that diverges
sub_0800DC50 indexes `sEntityInitTable` (8-byte records at 0x080c0e20) by the `u8` field `gGameStuff.pendingMode`. At every index site the baserom reads the field into a **separate scratch low register** and shifts into r0:
- `ldrb r3,[r1,#10]; lsls r0,r3,#3` (×4 sites: 0x12, 0x3e, 0x56, 0x90 — scratch = r3/r2/r3/r3)
- `ldrb r1,[r4,#10]; lsls r0,r1,#3` (0xb2), `mov r4,r9; ldrb r4,[r4,#10]; lsls r0,r4,#3` (0x102 back-edge)
agbcc instead **funnels both pseudos to r0**: `ldrb r0,[r1,#10]; lsls r0,r0,#3`. Same phenomenon drives the small-constant diffs: baserom puts the ldrsh offset (`movs r3,#0`/`movs r3,#2`), the flag-OR constants (`movs r3,#2; orrs r5,r3`; `movs r4,#1`), and the `0x01000000` mask (`movs r3,#128; lsls r3,#17`) in scratch r3/r4; agbcc emits r0/r1/r2. Every one of the 29 residual diffs is a same-opcode ARGUMENT_MISMATCH (pure coloring) — zero structural/REPLACEMENT diffs remain after the fix below.

### Root cause (agbcc pass implicated)
`tools/agbcc-src/gcc_arm/local-alloc.c`, allocation-priority macro `QTY_CMP_PRI = floor_log2(n_refs)*n_refs*size / (qty_death - qty_birth)`. The index pseudo (ldrb dest) has lifespan 1 (dies at the lsls); the product pseudo (lsls dest) has lifespan ~3 (lsls->adds->ldrb). Equal n_refs(2)/size(1), so the **shorter-lived index wins the tiebreak and is allocated r0 FIRST** by `find_free_reg` (lowest free hard reg). The baserom is the reverse (product gets r0, index spilled to r3). NOT `combine_regs` — a `lsls`(ASHIFT) is not a copy insn so combine_regs never fires here; this is pure first-pick ordering. Confirmed INVARIANT: byte_diff stays 32 under `CC=OLD_AGBCC_BIN`, `-fno-local-alloc` (defers entirely to global reload), `-fregmove/-fno-regmove`, and a 14-flag sweep — the coloring is fixed by the C expression shape, not by any optimization pass.

### Why the trick did NOT transfer
Every corpus instance of the scratch-spread `lsls r0,rN,#3` has the index gaining liveness from **context our function structurally lacks**: a loop counter, a function parameter, or a call return. sub_0800DC50's index is a *pure dying struct-field `ldrb`* read fresh at each site (the baserom re-reads `pendingMode` every time — caching it in a `u32 id` local makes it WORSE, doc-confirmed and re-confirmed). With a dying field-read, `QTY_CMP_PRI` deterministically hands r0 to the index. I verified this is not C-shape-escapable: held-pointer locals -> 265; `register u32 idx asm("r3")` -> 224; inline `((const u8*)tbl)[id*8+1]` flat extraction -> 182; all worse because they restructure the prologue/address-arithmetic. No source shape reproduces "product in r0, index in scratch" for a value with lifespan 1.

### byte_diff progression
asm-only -> 32 (doc baseline, reproduced exactly) -> **31** (the win) via routing the points-loop back-edge index through the already-r9-cached `gs` pointer: `while (i < sEntityInitTable[gs->pendingMode].spawnCount)` instead of `gGameStuff.pendingMode`. This eliminated the function's ONLY non-coloring diff (the `mov r4,r9` vs fresh-pool-`ldr` REPLACEMENT at 0x102) — it is now an ARGUMENT_MISMATCH (mov r0,r9 vs mov r4,r9), i.e. the structure matches and only the coloring differs. All 29 remaining diffs are pure coloring.
