# sub_0800F24C — deferred analysis

Leaf function, 172 bytes, range [0x0800f24c, 0x0800f2f8). asm slice
`asm/disasm_0x0800f24c.s`, dest `src/engine/sub_0800f24c.c`. Classifier
verdict: ATTEMPT_MATCH (advisory: r8 pinned across the loop).

Camera/scroll clamp. For each of the first `count` (u8 arg) scroll objects in
the 0x20-byte-stride array at IWRAM 0x030060A0, derive its scroll offset from
the player sub-coords in `gIwram_3720` (`_field_2` = X, `_field_4` = Y),
recentering on a 240x160 screen and clamping against the object's world bounds
(object +0x18 = boundY, +0x1a = boundX, both in tiles, x8 to pixels). Entire
body is skipped while `gGameStuff.pendingMode == 6` (offset 10). Semantics fully
understood — see the Best-effort C.

## Progress this round (opus): 135 -> 50

The prior attempt was stuck at **byte_diff 135, dc 81**, blocked on the
addressing-mode of the x/y stores (baserom address-folds `(objs+12)+(i<<5)`
with `str [r,#0]`; agbcc emitted `objs+(i<<5)` with displacement `str [r,#12]`).

This round RE-DERIVED the structure from scratch and got to **byte_diff 50,
dc 31, size 172 (exact)** with the px/py default-stores, the clamp-to-zero
stores, the prologue, the epilogue, the loop guards and the `pendingMode==6`
early-return ALL byte-matching. The four levers that cracked the addressing
mode + ordering (each verified against a clean rebuild — note agbcc is
SENSITIVE to stale .s artifacts AND to local-decl LAYOUT, so always
`rm src/engine/sub_0800f24c.{o,s}` before measuring):

1. **`-fno-strength-reduce` per-TU** (`Makefile: src/engine/sub_0800f24c.s:
   CFLAGS += -fno-strength-reduce`). Without it the byte-offset address form
   hoists the loop-invariant constants 12/16 into `sl` + a stack slot
   (size 192). With it, agbcc recomputes `objs+N` inline per iteration (the
   baserom shape).
2. **Integer-base, named, to defeat fold-const reassociation.** The blocker
   is `fold-const.c` `associate:` (line ~5119/5163): for `(objs+12)+(i<<5)` it
   splits `(VAR+CON)` and rebuilds `VAR+(ARG1+CON)`, i.e. it GLUES the constant
   12 onto the *index* (`(i<<5)+12`), not onto objs — giving `adds r0,r1,#0;
   adds r0,#12` (constant on a copy of the index) instead of the baserom's
   `mov r0,ip; adds r0,#12` (constant on a copy of objs). A *named* integer
   base `u32 baseX = (u32)objs + 12;` then `px = (s32*)(idx + baseX);` hides
   the +12 from the outer add so fold can't reassociate it onto the index, AND
   `idx + baseX` (int + int) keeps the source operand order `adds Rd, idx,
   base` (the baserom's `adds r4,r2,r0`). Pointer arithmetic (`(u8*)objs+...`)
   does NOT work here: C `pointer_int_sum` forces pointer-first operand order
   (`adds r4,r0,r2`) which is the wrong encoding.
3. **`do { } while (i < count)` with an explicit `i=0; if (i>=count) return;`
   guard BEFORE the invariant setup.** This sinks the `ldr ip / ldr r6 /
   mov r9` base loads to AFTER the count guard (`cmp r7,r8; bcs`), matching the
   baserom (a plain `for` emits them before the guard).
4. **`register s32 idx asm("r2")`** pins the shared `i<<5` to r2 (the baserom's
   index reg), fixing several operand-order / `movs rN,#2` ldrsh-offset regs.

## Remaining drift (byte_diff 50): the bounds-clamp register allocation

The ONLY remaining divergence is the two bounds-clamp blocks (+0x5c..+0x8a) and
a 1-block `lsls r2,r7,#5` schedule slot. The clamp is a pure agbcc
register-ALLOCATION-quality difference, NOT a source difference:

baserom (for the boundX clamp):
```
movs r0,#2; ldrsh r1,[r6,r0]   @ _field_2 -> r1, loaded BEFORE obj base
mov r0,ip; adds r3,r2,r0        @ obj base -> r3
ldrh r0,[r3,#26]; lsls r2,r0,#3 @ boundX*8 -> r2  (reuses idx's r2; idx now dead)
adds r0,r2,#0; subs r0,#120     @ r0 = boundX*8 - 120  (the COMPARE value)
cmp r1,r0; ble.n
subs r0,#120                    @ r0 = boundX*8 - 240  (REUSE: subtract 120 AGAIN)
str r0,[r4,#0]
```
my best (`*px = bound*8 - 240`, the natural source):
```
mov r1,ip; adds r3,r1,r2        @ obj base FIRST (objs->r1, wrong reg+order)
movs r1,#2; ldrsh r0,[r6,r1]    @ _field_2 -> r0 (loaded AFTER obj base)
ldrh r1,[r3,#26]; lsls r2,r1,#3 @ boundX*8 -> r2
adds r1,r2,#0; subs r1,#120     @ r1 = boundX*8-120 (compare in r1, swapped)
cmp r0,r1; ble.n
adds r0,r2,#0; subs r0,#240     @ re-copy boundX*8, single -240 store
str r0,[r4,#0]
```
The source `*px = (s32)(obj->boundX*8) - 240` is the SAME expression the
baserom compiled; the baserom's allocator simply REUSED the compare's
intermediate `boundX*8-120` (then `-120` again) and kept `boundX*8` in r2
(idx's dead reg). My agbcc instead re-copies `boundX*8` and does a single
`-240`. Forcing the reuse in C requires `s32 v = bound*8-120; if (_f2 > v)
*px = v - 120;` — but `v` must survive the `cmp; ble` branch, and with the 5
required register pins (count r8, zero r9, objs ip, src r6, idx r2) there is
no caller-saved low reg free for it, so agbcc SPILLS the loop counter `i`
into `sl` (prologue grows `mov r7,sl; push {...}`) — byte_diff jumps to 158,
size 176. Every `v`-reuse variant (function-scope local, block-scope local,
`v -= 120; *px = v`) spills identically. Caching `s32 b = bound*8` and storing
`b - 240` removes the double-subtract entirely -> size 168 (4 SHORT), dc 24 but
byte_diff 58 (the size delta cascades). So the target is the LESS-optimal,
4-byte-LONGER double-subtract form that pure C can only reach via a spill.

This is genuine register-allocation drift (the baserom allocator made a better
caller-saved-reuse choice than our agbcc), not a missing idiom.

## Best-effort C (byte_diff 50, size 172 exact, structurally matching shape)

Requires `Makefile: src/engine/sub_0800f24c.s: CFLAGS += -fno-strength-reduce`.

```c
#include "game.h"
#include "iwram.h"
#include "macros.h"
#include "types.h"

struct ScrollObj {
    u8 _pad00[12];
    s32 x;       /* +0x0c */
    s32 y;       /* +0x10 */
    u8 _pad14[4];
    u16 boundY;  /* +0x18 */
    u16 boundX;  /* +0x1a */
    u8 _pad1c[4];
};

void sub_0800F24C(u8 countArg)
{
    register u32 count asm("r8") = (u8)countArg;
    register u32 zero asm("r9");
    register struct ScrollObj *objs asm("ip");
    register struct IwramAt3720 *src asm("r6");
    register s32 idx asm("r2");
    s32 *px;
    s32 *py;
    struct ScrollObj *obj;
    u32 i;

    if (gGameStuff.pendingMode == 6) {
        return;
    }
    i = 0;
    if (i >= count) {
        return;
    }
    objs = (struct ScrollObj *)0x030060A0;
    src = &gIwram_3720;
    zero = 0;
    do {
        u32 baseX = (u32)objs + 12;
        u32 baseY;
        idx = i << 5;
        px = (s32 *)(idx + baseX);
        *px = src->_field_2 - 120;
        baseY = (u32)objs + 16;
        py = (s32 *)(idx + baseY);
        *py = src->_field_4 - 80;
        if (src->_field_2 <= 119) {
            *px = zero;
        }
        if (src->_field_4 <= 79) {
            *py = zero;
        }
        obj = (struct ScrollObj *)((u32)objs + idx);
        if (src->_field_2 > (s32)(obj->boundX * 8) - 120) {
            *px = (s32)(obj->boundX * 8) - 240;
        }
        if (src->_field_4 > (s32)(obj->boundY * 8) - 80) {
            *py = (s32)(obj->boundY * 8) - 160;
        }
        i++;
    } while (i < count);
}
```
