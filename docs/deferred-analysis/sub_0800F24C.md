# sub_0800F24C — deferred analysis

Leaf function, 172 bytes, range [0x0800f24c, 0x0800f2f8). asm slice
`asm/disasm_0x0800f24c.s`, dest `src/engine/sub_0800f24c.c`. Classifier
verdict: ATTEMPT_MATCH (advisory: r8 pinned across the loop).

## What it does (fully understood)

Camera/scroll clamp. For each of the first `count` (u8 arg) scroll objects
in the 0x20-byte-stride array at IWRAM 0x030060A0, derive its scroll offset
from the player sub-coords in `gIwram_3720` (`_field_2` = X, `_field_4` = Y),
recentering on a 240x160 screen and clamping against the object's world
bounds (object +0x18 = boundY, +0x1a = boundX, both in tiles, x8 to pixels).
Entire body is skipped while `gGameStuff.pendingMode == 6` (offset 10).

Per-object (i in [0,count)):
```
objs[i].x = src->_field_2 - 120;          // +0x0c, s32 store
objs[i].y = src->_field_4 - 80;           // +0x10, s32 store
if (src->_field_2 <= 119) objs[i].x = 0;
if (src->_field_4 <=  79) objs[i].y = 0;
if (src->_field_2 > objs[i].boundX*8 - 120) objs[i].x = objs[i].boundX*8 - 240;
if (src->_field_4 > objs[i].boundY*8 -  80) objs[i].y = objs[i].boundY*8 - 160;
```
The struct at 0x030060A0 (stride 0x20) is corroborated by sub_08012B5C
(writes +0xc/+0x10 of elem0 and elem1 at +0x2c/+0x30) and struct_xref
(readers at +0x8, +0xc, +0x10, +0x18, +0x1a). gIwram_3720 is the existing
`struct IwramAt3720` extern (fields _field_2 / _field_4 already typed).

## Drift

Best result: **byte_diff 135, diff_count 81, size 168 (target 172)** with the
structurally-correct version (Best-effort C below). The prologue
(`push {r4,r5,r6,r7,lr}; mov r7,r9; mov r6,r8; push {r6,r7}`), the high-reg
pins (count=r8, zero=r9, objs=ip, src=r6), the `pendingMode==6` early return,
the loop guard (`movs r7,#0; cmp r7,r8; bcs END`), the base loads after the
guard, the entire bounds-clamp block, the loop-counter wrap, AND the full
epilogue all reproduce the baserom **byte-for-byte**.

THE SOLE DIVERGENCE is the addressing mode for the x/y stores:

- baserom folds the struct member offset into the *address*:
  `mov r0,ip; adds r0,#12; adds r4,r2,r0   ; r4 = (ip+12)+(i<<5)`
  then `str r0,[r4,#0]`. (and `#16` for y → r5). Three independent pointers
  r4 (&objs[i].x), r5 (&objs[i].y), r3 (&objs[i]) recomputed per iter; only
  `i<<5` (r2) is the shared CSE.
- agbcc (from `s32 *px = &objs[i].x;`) instead keeps the *object base*
  `r4 = ip + (i<<5)` and folds +12 into the *store displacement*:
  `str r0,[r4,#12]`. This is 1 instruction shorter per address → the built
  fn is 4 bytes short, and that length delta cascades all the pool-load
  offsets, inflating byte_diff far beyond the true ~6-instruction difference.

Root cause (from agbcc source `config/arm/thumb.h` GO_IF_LEGITIMATE_ADDRESS):
REG+REG addressing is disabled pre-reload ("only 3 guaranteed reload regs,
need 4"), so `(ip) + (i<<5) + 12` must be reduced. agbcc's `expand_expr` of
`COMPONENT_REF(ARRAY_REF(objs,i), x)` computes the ARRAY_REF address
`objs + i*0x20` first (one reg), then adds the field offset as the memory
displacement `[r,#12]`. The baserom compiler attached the field offset to the
*base* (`(ip+12)`) before the index → the address-fold form.

## Levers tried (all FAILED to flip the fold without regressing)

- `register asm("rN")` pins for count/zero/objs/src — REQUIRED, got the
  prologue + epilogue to byte-match. (This is the 168/135 base.)
- Defer the `objs=`, `src=`, `zero=` assignments past the early returns —
  REQUIRED to match the base-load ordering. (Without it, ip/r6/r9 load before
  the `pendingMode` check.)
- Byte-offset address `(u8*)objs + 12 + (i<<5)` (left-assoc, so the tree is
  `(objs+12)+(i<<5)`) → DID produce `str [r4,#0]` (address-fold!) BUT agbcc
  materialized the constants 12/16 into `sl` and a stack slot (too many
  high-reg pins leave too few low regs for the immediates) → size 192,
  byte_diff 185. WORSE.
- `s32 *off = i<<5` as an explicit local → forces off into a persistent reg,
  same 192 spill.
- `((s32*)objs)[i*8+3]` word-array indexing → 164, still displacement fold.
- separate `pos` pointer at 0x030060AC (x at struct offset 0) → adds a 4th
  pool word (target has 3) → 141.
- `&objs->x + i*8` (s32* stride-8) → 192 (emits a different scale).
- single `obj=&objs[i]` for all 4 stores (collapse px/py) → 160, diff_count
  61 but structurally WRONG (one ptr, all displacement) — not the target's
  three-pointer shape.
- OLD_AGBCC_BIN per-TU → identical 135 (not a compiler-version issue).
- CFLAGS += -fno-gcse → no change. -fno-strength-reduce → no change.
- Permuter: NOT run. (a) byte_diff 135 is far above the documented ≤40
  effective range; (b) the difference is a systematic addressing-mode
  selection, not random register-coloring/scheduling that the permuter's
  statement-reorder mutations flip; (c) the literal pool loads make a clean
  hand-built target.s scratch fragile. A future agent with the permuter
  populated could still try it on the Best-effort C below.

## Next lever to try (DIFFERENT from above)

The fold is `(ip+const)+(i<<5)` vs `(ip+(i<<5))+const`. The byte-offset form
gets the right ADDRESS shape but spills the constants because of register
pressure from 4 high-reg pins (r8/r9/ip/r6). Try FREEING a register so the
constant 12/16 can live as an `adds #imm` immediate instead of spilling:
e.g. drop the `zero asm("r9")` pin (let agbcc pick a low reg for the literal
0 — the baserom uses r9 but maybe a low-reg zero + the byte-offset address
form nets fewer total bytes), or `-ffixed-rN` to reshape allocation, or write
the y-store before computing px so the two field-base adds don't co-live.
Alternatively investigate whether `expand_expr` can be coaxed via a
`volatile`-qualified objs pointer (forces fresh address recompute each store,
which is what the baserom does) — none of the non-volatile forms recompute.

## Best-effort C (byte_diff 135, structurally matching shape)

```c
#include "game.h"
#include "iwram.h"
#include "macros.h"
#include "types.h"

struct ScrollObj {
    u8 _pad00[12];
    s32 x;       /* +0x0c */
    s32 y;       /* +0x10 */
    u8 _pad14[4];
    u16 boundY;  /* +0x18 */
    u16 boundX;  /* +0x1a */
    u8 _pad1c[4];
};

void sub_0800F24C(u8 countArg)
{
    register u32 count asm("r8") = (u8)countArg;
    register u32 zero asm("r9");
    register struct ScrollObj *objs asm("ip");
    register struct IwramAt3720 *src asm("r6");
    s32 *px;
    s32 *py;
    struct ScrollObj *obj;
    u32 i;

    if (gGameStuff.pendingMode == 6) {
        return;
    }

    objs = (struct ScrollObj *)0x030060A0;
    src = &gIwram_3720;
    zero = 0;
    for (i = 0; i < count; i++) {
        px = &objs[i].x;
        *px = src->_field_2 - 120;
        py = &objs[i].y;
        *py = src->_field_4 - 80;

        if (src->_field_2 <= 119) {
            *px = zero;
        }
        if (src->_field_4 <= 79) {
            *py = zero;
        }

        obj = &objs[i];
        if (src->_field_2 > (s32)(obj->boundX * 8) - 120) {
            *px = (s32)(obj->boundX * 8) - 240;
        }
        if (src->_field_4 > (s32)(obj->boundY * 8) - 80) {
            *py = (s32)(obj->boundY * 8) - 160;
        }
    }
}
```
