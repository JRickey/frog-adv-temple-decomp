Verdict: `ATTEMPT_MATCH`, not `STRONG_UNMATCHABLE`. **Do not ship NAKED.** The
function is a `sub_0800E85C(u8 count)` character-sprite-layer uploader (full
semantics in the "What it does" section below). It is blocked on a single

## What it does (unchanged, fully understood)

DMA-clears 0x02000000/0x06000000/0x05000000 with a stack `u16 zero` (src-fixed),
then `for (pose=0; pose<count; pose++)` indexes
`sCharacterSpriteFrames[gGameStuff.pendingMode*3 + pose]` (16-B records
`{tilesA,tilesB,tilesC,u16 width,u16 height}`), writes width/height into the
per-pose layer-control slot at `0x030060A0 + pose*0x20` (+0x18/+0x1A), and a
`switch(pose)` dispatches pose-specific LZ77 (`sub_0802D568` = svc-17
LZ77UnCompVRAM) + DMA loads, ending each case with a BGxCNT write
(0x1C03/0x1D02/0x1E0D). Tail: DMAs `frames[pendingMode*3].tilesB` to palette,
`REG_DISPCNT = OBJ_ON|OBJ_1D`, a `switch(count)` toggling BG layers via
`sub_0800EE94`/`sub_0800EE34`, clears HBlank IRQ, writes
`gIwram_3608._pad4=1; gIwram_3608._field_5=0`.

Callee `sub_0802D568` (svc-17 LZ77 wrapper, +0x10 into the NAKED libagbsyscall
block `sub_0802D558`) is exposed via, inside `src/game/sub_0802d558.c`'s NAKED
asm right after `asm(".syntax unified\n"`:
```c
"    .global sub_0802D568\n"
"    .thumb_set sub_0802D568, sub_0802D558 + 0x11\n"
```
Verified: a C `bl sub_0802D568` links with NO ld veneer. KEEP this.

## NEW root-cause this round (instrumented private debug agbcc, gcc/global.c)

Built a private debug `old_agbcc` (copy of the SHARED-symlinked `tools/agbcc-src`
to a private prefix — never touched the shared tree), with an `fprintf` at the
`reg_renumber[allocno_reg[allocno]] = best_reg` site in `gcc/global.c` and at the
`SET_REGBIT(hard_reg_copy_preferences,...)` site in `set_preference`. Compiled
ONLY this TU with it (`AGBCC_DUMP_ALLOC=1` / `AGBCC_DUMP_PREF=1`). Findings:

**1. The 498 base is NOT pure naming — there is a real const-CSE SHAPE gap.**
The constant `0x02000000` (the LZ77 EWRAM scratch) is used 3× in `case 0` —
LZ77#1 dst arg, `dma->src`, LZ77#2 dst arg — spanning the two `bl` calls. agbcc
CSE-merges all three into ONE pseudo (p116, refs=8) and the allocator gives it a
CALLEE-SAVED reg (r5 in the base) so it survives the calls. The **baserom
recomputes it fresh** (`movs #128; lsls #18` three times, into caller-saved
r1/r2/r1 — see e916/e920/e95e). So the base materializes the const once + 3 uses
(5 insns) where the baserom emits 3 fresh materializations (6 insns): a 1-insn
shape diff inside case 0, plus the r5 theft that cascades the whole coloring.

Cause: in `gcc/local-alloc.c update_equiv_regs`, a const pseudo is rematerialized
(REG_EQUIV) only if single-basic-block (`REG_BASIC_BLOCK >= 0`). The case-0 const
is multi-block (the two calls + the `if(pendingMode==13)` branch split it), so it
gets a hard reg instead of being rematerialized. No `-fXXX` defeats this
(`-fno-gcse`, `-fno-cse-skip-blocks`, `-fno-rerun-cse-after-loop`,
`-fno-expensive-optimizations` all leave it callee-saved or just move it to a
different callee-saved reg). Cast tricks (`(u8*)`, `0x06000000-0x04000000`) fold.

**2. The coloring divergence is a missing COPY PREFERENCE, proven.**
The `set_preference` probe shows the C path generates **ZERO** copy preferences
for the loop-carried values (only `tilesA→r0` and `const→r1`, both caller-saved
and pruned). Priorities (`floor_log2(refs)*refs/live_len`, gcc/global.c
`allocno_compare`): dma 0.875 > pose 0.306 (22 refs) > game 0.241 (17 refs) >
frames 0.214 > count > tilesA. So the natural dense order is dma=r4, pose=r5,
game=r6, frames=r7, count=r8, tilesA=r9.

The **baserom** is dma=r4, game=r5, **pose=r7 (r6 PUSHED-BUT-UNUSED)**, frames=r8,
count=r9, tilesA=sl. r6 is in the prologue `push {r4,r5,r6,r7,lr}` but never read
in the body (verified). For r6 to be saved yet skipped, pose must carry a copy
preference toward r7 (REG_ALLOC_ORDER is `4,5,6,7,8,10(sl),9,...`). game outranks
pose to r5 **despite fewer refs** in the baserom too (8 pendingMode reads vs ~15
pose uses) — so game=r5 is ALSO preference-driven, not priority-driven. The C
path produces no such preference, and a preference can only arise from a
`(set pseudo hardreg)`/`(set hardreg pseudo)` copy — r7/r5 are never fixed hard
regs here (only r0-r3 are), so no source shape I found injects it.

## Lever map (what each lever does — measured this round)

| lever | effect | byte_diff (real tool) |
|-------|--------|-----------------------|
| clean base (zero levers) | const→r5, pose→r6, game→r7 | **498** (best) |
| `scratch=(void*)0x02000000;` reassigned before each case-0 use | RECOMPUTES const (shape now matches baserom!) but collapses to DENSE r4-r9 (no r6 gap, no sl) | 606 |
| `-ffixed-r6` (on the scratch version) | creates the r6 GAP + uses sl + count→r9 (right structure!) but **pose=r5/game=r7 still swapped**, and `-ffixed-r6` WRONGLY drops r6 from the prologue `push` | 556 |
| scratch + `-ffixed-r6` + `register u8 pose asm("r7")` | coloring becomes EXACTLY right (dma=r4,game=r5,pose=r7,frames=r8,count=r9,tilesA=sl) BUT the pin perturbs the record-index strength-reduction AND the push still lacks r6 | 556 |
| scratch + both pins game=r5/pose=r7 (no -ffixed) | game=r5 works but frames spills (27 refs → r6 with spill) | 626 |
| no `dma` local (all `REG_DMA3` macro) | agbcc CSEs the DMA base into a 33-ref pointer at r4 (wrong — base must be `dma` used only in cases 1/2; case 0 must reload) | 570 |

The closest *structural* match is scratch + `-ffixed-r6` + `pose asm("r7")`: it
reproduces game=r5/pose=r7/frames=r8/count=r9/tilesA=sl/r6-gap. Two residual
regressions block it: (a) `-ffixed-r6` excludes r6 from the prologue push (baserom
PUSHES r6, just never uses it) — need "r6 saved but unallocated", which only the
natural preference gives, not `-ffixed-r6`/`-fcall-used-r6`; (b) the pin shifts
the `(pendingMode*3+pose)*16` index strength-reduction.

## Next useful attempt (in order)

1. **PERMUTER once it works.** This is the textbook permuter case: shape ~right,
   a sharp register-coloring local minimum. THIS ENVIRONMENT'S PERMUTER IS BROKEN
   — `vendor/decomp-permuter` is a CIRCULAR symlink (`permuter.py` errno-62 "too
   many levels of symbolic links"), no `.venv`, in worktree AND main. Fix the
   submodule/venv first, then start from the clean 498 base below. Permuter
   mutates statement order/var scope → perturbs allocno numbering + the
   copy-preference machinery (`gcc/global.c set_preference`/`expand_preferences`)
   that must bias pose→r7.
2. **Hand-inject the pose→r7 preference.** The instrumentation pinpointed the
   mechanism: `set_preference` needs a copy between `pose` and a pseudo that
   local-alloc placed at r7. Try source shapes that create a `pose`↔r7-tied
   pseudo copy (e.g. routing the loop counter through a temp that the case-0/slot
   path forces to r7). The clean fix is the preference, NOT `-ffixed-r6` (which
   breaks the push) and NOT pins (which spill/perturb).
3. **Const recompute + push-preserving r6 gap.** Combine the `scratch`
   recompute (correct shape) with a non-`-ffixed` way to leave r6 saved-but-empty.
   `-ffixed-r6`/`-fcall-used-r6` both drop r6 from the push; only the preference
   keeps it.

## Best-effort C (clean, byte_diff 498, ZERO levers — resume from here)

```c
#include "gba/dma.h"
#include "gba/intr.h"
#include "gba/io.h"
#include "game.h"
#include "iwram.h"
#include "types.h"

#define CHARACTER_BG0CNT 0x1C03
#define CHARACTER_BG1CNT 0x1D02
#define CHARACTER_BG2CNT 0x1E0D

struct CharacterSpriteFrame {
    const void *tilesA;
    const void *tilesB;
    const void *tilesC;
    u16 width;
    u16 height;
};

struct CharacterLayerCtrl {
    u8 _pad00[0x18];
    u16 width;
    u16 height;
    u8 _pad1C[4];
};

extern const struct CharacterSpriteFrame sCharacterSpriteFrames[];

/* svc 17 (LZ77UnCompVRAM) wrapper — expose via .thumb_set in
   src/game/sub_0802d558.c's NAKED asm (see top of this note). */
extern void sub_0802D568(const void *src, void *dst);
extern void sub_0800EE34(u8 layer);
extern void sub_0800EE94(u8 layer);

void sub_0800E85C(u8 count)
{
    volatile DmaChannel *dma;
    struct CharacterLayerCtrl *layer;
    const struct CharacterSpriteFrame *frames;
    GameStuff *game;
    const void *tilesA;
    u16 zero;
    u8 pose;

    zero = 0;
    REG_DMA3.src = &zero;
    REG_DMA3.dst = (void *)0x02000000;
    REG_DMA3.cnt = DMA_ENABLE | DMA_SRC_FIXED | 2;
    (void)REG_DMA3.cnt;

    zero = 0;
    REG_DMA3.src = &zero;
    REG_DMA3.dst = (void *)0x06000000;
    REG_DMA3.cnt = DMA_ENABLE | DMA_SRC_FIXED | 2;
    (void)REG_DMA3.cnt;

    zero = 0;
    REG_DMA3.src = &zero;
    REG_DMA3.dst = (void *)0x05000000;
    REG_DMA3.cnt = DMA_ENABLE | DMA_SRC_FIXED | 2;
    (void)REG_DMA3.cnt;

    for (pose = 0; pose < count; pose++) {
        frames = sCharacterSpriteFrames;
        game = &gGameStuff;
        dma = &REG_DMA3;
        layer = (struct CharacterLayerCtrl *)0x030060A0;

        layer[pose].width = frames[game->pendingMode * 3 + pose].width;
        layer[pose].height = frames[game->pendingMode * 3 + pose].height;

        switch (pose) {
        case 0:
            if (frames[game->pendingMode * 3].tilesA != NULL) {
                tilesA = frames[game->pendingMode * 3].tilesA;
            }
            sub_0802D568(tilesA, (void *)0x02000000);

            dma->src = (const void *)0x02000000;
            dma->dst = (void *)0x06000000;
            dma->cnt = DMA_ENABLE | 0x4000;
            (void)dma->cnt;

            if (game->pendingMode == 13) {
                dma->src = frames[game->pendingMode * 3].tilesA;
                dma->dst = (void *)0x06000000;
                dma->cnt = DMA_ENABLE | 0x4000;
                (void)dma->cnt;
            }

            sub_0802D568(frames[game->pendingMode * 3].tilesC, (void *)0x02000000);
            REG_BG0CNT = CHARACTER_BG0CNT;
            break;
        case 1:
            if (frames[game->pendingMode * 3 + 1].tilesA != NULL) {
                dma->src = frames[game->pendingMode * 3 + 1].tilesA;
                dma->dst = (void *)0x02010000;
                dma->cnt = DMA_ENABLE | 0x2000;
                (void)dma->cnt;
            }
            sub_0802D568(frames[game->pendingMode * 3 + 1].tilesC, (void *)0x02010000);
            REG_BG1CNT = CHARACTER_BG1CNT;
            break;
        case 2:
            if (frames[game->pendingMode * 3 + 2].tilesA != NULL) {
                dma->src = frames[game->pendingMode * 3 + 2].tilesA;
                dma->dst = (void *)0x0600C000;
                dma->cnt = DMA_ENABLE | 0x1000;
                (void)dma->cnt;
            }
            if (frames[game->pendingMode * 3 + 2].tilesC != NULL) {
                dma->src = frames[game->pendingMode * 3 + 2].tilesC;
                dma->dst = (void *)0x02020000;
                dma->cnt = DMA_ENABLE | 0x8000;
                (void)dma->cnt;
            } else {
                zero = 0;
                dma->src = &zero;
                dma->dst = (void *)0x02020000;
                dma->cnt = DMA_ENABLE | DMA_SRC_FIXED | 0x8000;
                (void)dma->cnt;
            }
            REG_BG2CNT = CHARACTER_BG2CNT;
            break;
        }
    }

    REG_DMA3.src = sCharacterSpriteFrames[gGameStuff.pendingMode * 3].tilesB;
    REG_DMA3.dst = (void *)0x05000000;
    REG_DMA3.cnt = DMA_ENABLE | 0x100;
    (void)REG_DMA3.cnt;

    REG_DISPCNT = DISPCNT_OBJ_ON | DISPCNT_OBJ_1D;

    switch (count) {
    case 1:
        sub_0800EE94(0);
        sub_0800EE34(1);
        sub_0800EE34(2);
        sub_0800EE94(3);
        break;
    case 2:
        sub_0800EE94(0);
        sub_0800EE94(1);
        sub_0800EE34(2);
        sub_0800EE94(3);
        break;
    case 3:
        sub_0800EE94(0);
        sub_0800EE94(1);
        sub_0800EE94(2);
        sub_0800EE94(3);
        break;
    }

    REG_IE &= ~IRQ_HBLANK;
    REG_DISPSTAT &= ~DISPSTAT_HBLANK_IRQ;
    gIwram_3608._pad4 = 1;
    gIwram_3608._field_5 = 0;
}
```

### Const-recompute variant (matches baserom shape; use WITH the preference fix)

Replacing the three `case 0` uses of `(void *)0x02000000` with a reassigned
local makes agbcc rematerialize the constant (caller-saved) exactly like the
baserom — eliminating the r5 theft. It alone collapses to a DENSE r4-r9
coloring, so it MUST be combined with the pose→r7 preference fix (step 2/3):
```c
    void *scratch;
    ...
    scratch = (void *)0x02000000; sub_0802D568(tilesA, scratch);
    scratch = (void *)0x02000000; dma->src = scratch;
    ...
    scratch = (void *)0x02000000; sub_0802D568(frames[game->pendingMode * 3].tilesC, scratch);
```
