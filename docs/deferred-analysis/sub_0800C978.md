# sub_0800C978 — deferred (LEFT/RIGHT multiply global-register-allocation tie)

Neighbour-cell tile-class sampler on the per-room packed-halfword grid at EWRAM
0x02030000. `switch(dir)` over a direction mask (1=up, 2=down, 4=left, 8=right,
16=auto). The four directional cases each compute a `(u16 *)cell` one step in
that direction and return `(*cell & 0x3F0) >> 4` (identical masked read to the
matched sibling `sub_0800CD88`). `DIR_AUTO` reads `gIwram_3720._field_1A` (the
actor facing, 0..3) and recurses one step that way, bounds-checking two steps
out. Stride/row counts come from `sSpriteAssetIndexTable` at 0x08306444
(`entry[+4]` = stride, `entry[+5]` = rows). The dispatch is a dense
`switch(dir)` over cases 1,2,4,8,16 -> `mov pc,rN` + 16-word absolute jump
table at 0x0800c9a8 (everything else -> default `return 0`).

## STATUS: byte_diff 24, structurally CLEAN, PURE C (no pins/asm/symbols)

This is a **major advance** over the prior attempt (byte_diff 153/390). The
prior attempt's stated blocker — the agbcc cross-jump merge collapsing the

multiply. UP, DOWN, AUTO, the dispatch, and the shared read tail all match

## What was solved (the prior blocker) — TERM ORDER, not linker symbols

The prior note believed agbcc *dedups the 0x02030000 pool entry* and therefore
over-merges UP into DOWN, and that two distinct linker symbols at 0x02030000
were needed to force two pool slots. **That premise was wrong.** The over-merge
was a consequence of the wrong term order. With the right term order agbcc
emits two separate `0x02030000` pool slots for UP and DOWN *on its own* (one
per `b` to the shared read tail), exactly like baserom — even with a plain
`(u8 *)0x02030000` integer constant in BOTH cases. The differing
`ldr [pc,#N]` then stops the cross-jump merge precisely where the baserom does.

The load-bearing term orders (verified against baserom instruction-by-instruction):
- **DIR_UP / DIR_DOWN**: write `(2*(stride*ny) + 5*row*4096) + 2*tileX + base`
  with `2*tileX` **LAST** and the inner sum as `2*(stride*ny)` FIRST then
  `5*row*4096`. tileX-last keeps the offset accumulator in r1 with `2*tileX`
  added via a fresh r0 (matching baserom); tileX-FIRST instead makes r2 the
  accumulator and produces a second, divergent read tail (+12 bytes).
- **DIR_LEFT / DIR_RIGHT**: write `2*tileX + 5*row*4096 + 2*(...) + base` with
  `2*tileX` **FIRST**. Because these cases guard on tileX (so tileX is narrowed
  early into a callee-saved reg), tileX-first is what keeps the offset
  accumulator in r1 and yields the SINGLE shared read tail baserom uses.
  (Opposite of UP/DOWN — the guarded coordinate flips which position works.)
- The DIR_UP/DIR_DOWN inner `2*(stride*ny)`-first ordering moves the
  `5*row*4096` term into r0 as baserom does (vs accumulating into r2).

These four orderings take byte_diff from 390 -> 24, leaving only the multiply.

## The remaining wall — DIR_LEFT/DIR_RIGHT multiply dst register (global-alloc)

The only 14 mismatched instructions are the LEFT (+0x00f4) and RIGHT (+0x0126)
multiply cascades, which are IDENTICAL and all flow from one instruction:

```
baserom:  muls r0, r1     ; r0 = stride(r0) * tileY(r1)   dst = r0  (stride's reg)
built:    muls r1, r0     ; r1 = tileY(r1)  * stride(r0)  dst = r1  (tileY's reg)
```

Both have stride in r0 and tileY in r1 going INTO the mul (identical inputs).
The difference is purely which input register the result pseudo is colored to:
baserom r0, our agbcc r1. Everything downstream (which reg holds `5*row*4096`,
the accumulation order) cascades from that one choice. Fixing the mul dst alone
would close all 24 bytes.

This is `mulsi3` (`thumb.md`): `(mult (op1 "%l,*h,0") (op2 "l"))`. The `%`
makes it commutative and the `0` ties op1 to the output; reload picks the
2-byte tied form (`mul %0,%0,%2`) for both, but ties to a different operand.
The tie is decided in **global register allocation** (which hard reg the mul-
result pseudo gets), upstream of reload's commutative `try_swapped`. It is NOT
reachable from C-level operand order.

/* Neighbour-cell tile-class sampler on the per-room packed-halfword grid in

 * 8=right, 16=auto). Each directional case computes a (u16 *) cell address one

 * (2*(stride*ny) + 5*row*4096) + 2*tileX + base with tileX LAST so agbcc keeps

 * baserom) and only merges the shared masked-read tail; DIR_LEFT/DIR_RIGHT

 * shared read tail baserom uses. */

#define DIR_UP 1
#define DIR_DOWN 2
#define DIR_LEFT 4
#define DIR_RIGHT 8
#define DIR_AUTO 16

struct SpriteAssetIndexEntry {
    u32 dataPtr;
    u8 stride;
    u8 rows;
    u8 _field_6;
    u8 _field_7;
};

extern struct SpriteAssetIndexEntry sSpriteAssetIndexTable[];

u32 sub_0800C978(u8 col, u8 row, s16 tileX, s16 tileY, u8 dir)
{
    s32 ny;

    switch (dir) {
    case DIR_UP:
        ny = (s16)tileY - 1;
        if (ny < 0) {
            return 0;
        }
        return (*(u16 *)((2 * (sSpriteAssetIndexTable[(u8)col].stride * ny) + 5 * row * 4096) + 2 * (s16)tileX +
                         (u8 *)0x02030000) &
                0x3F0) >>

        ny = (s16)tileY + 1;
        if (ny >= sSpriteAssetIndexTable[(u8)col].rows) {
            return 0;
        }
        return (*(u16 *)((2 * (sSpriteAssetIndexTable[(u8)col].stride * ny) + 5 * row * 4096) + 2 * (s16)tileX +

                0x3F0) >>

    case DIR_LEFT:
        if ((s16)tileX - 1 < 0) {
            return 0;
        }
        return (*(u16 *)(2 * (s16)tileX + 5 * row * 4096 +
                         2 * ((s16)tileY * sSpriteAssetIndexTable[(u8)col].stride) + (u8 *)0x0202FFFE) &
                0x3F0) >>
               4;

    case DIR_RIGHT:
        if ((s16)tileX + 1 >= sSpriteAssetIndexTable[(u8)col].stride) {
            return 0;
        }
        return (*(u16 *)(2 * (s16)tileX + 5 * row * 4096 +
                         2 * ((s16)tileY * sSpriteAssetIndexTable[(u8)col].stride) + (u8 *)0x02030002) &
                0x3F0) >>
               4;

    case DIR_AUTO:
        switch (gIwram_3720._field_1A) {
        case 0:
            if ((s16)tileY - 2 < 0) {
                return 0;
            }
            return (u8)sub_0800C978(col, row, (s16)tileX, (s16)(tileY - 1), DIR_UP);
        case 1:
            if ((s16)tileY + 2 >= sSpriteAssetIndexTable[(u8)col].rows) {

            }

            }

        return 0;

## Corpus sweep (2026-06-03)

### Outcome: IMPROVED 390 -> 329; the deferred blocker (cross-jump merge) is SOLVED.

**The exact asm idiom that diverges.** Baserom's UP (0xc9f4) and DOWN (0xca22) cases have 13 byte-identical, register-identical address-compute instructions (`ldrb stride; adds r2,r0,#0; muls r2,r3; lsls r1,r5,#16; asrs r1,r1,#15; lsls r0,r7,#2; adds r0,r0,r7; lsls r0,r0,#12; lsls r2,r2,#1; adds r0,r0,r2; adds r1,r1,r0`) and both end `ldr r0,[pc,#N]; b.n 0xcab0`, loading 0x02030000. The two loads read **different, non-deduped constant-pool slots** (0xca18 vs 0xca50) — `ldr [pc,#4]` vs `ldr [pc,#8]`. That differing immediate is the ONLY difference and it stops gcc's backward cross-jump merge, so each case keeps its own full compute and they share only the 6-insn masked read at 0xcab0. agbcc instead DEDUPLICATES 0x02030000 into one pool slot, both cases emit the same `ldr`, and `jump.c`'s final `JUMP_CROSS_JUMP` pass merges UP's whole compute into DOWN's (byte_diff 390).

**Root-cause read of the agbcc pass.** `tools/agbcc-src/gcc_arm/jump.c` `find_cross_jump`/`do_cross_jump`, invoked at `toplev.c:4099` (`jump_optimize(insns, JUMP_CROSS_JUMP, …)`, gated ONLY by `optimize > 0` — there is NO `-fno-crossjumping` flag in this gcc 2.x). It walks two same-label simplejumps backward, merging insns while `rtx_renumbered_equal_p(p1,p2)` holds, stopping at the first non-equal insn or a CODE_LABEL. The Thumb constant pool is built later by MACHINE_DEPENDENT_REORG (after 4099), so at merge time both `ldr 0x02030000` are identical RTL and merge. KEY LEVER: `rtx_renumbered_equal_p` compares SYMBOL_REFs by identity — two DIFFERENT symbols at the same address are NOT equal, so the merge stops at the load, reproducing baserom's two-pool-slot shape.

**The trick that worked.** Declare two distinct absolute linker symbols at the same EWRAM address — `gRoomGridUp = 0x02030000; gRoomGridDown = 0x02030000;` (file-scope abs assignment in linker.ld, same syntax as the existing `gBlitSrcTable_08306b84 = …;`) — and have UP reference `&gRoomGridUp`, DOWN `&gRoomGridDown`. This is the GENERALIZATION of the cvaos linker-assigned-symbol CSE-defeat the doc already cites: the doc tried it with ONE symbol (dedups -> still merges, 370) and flagged "would need TWO distinct symbols, but `.` only moves forward". The fix is that ld permits repeated ABSOLUTE assignment (`sym = 0x…;`) outside any section, so two symbols CAN share an address. After the fix UP/DOWN compute is byte-identical to baserom (verified instruction-for-instruction, 0x7c..0x9a == 0xc9f4..0xca12) and the merge is gone. Reordering the offset sum to put `2*tileX` last and stride-term first in the inner paren (`(2*(ny*stride) + 5*row*4096) + 2*tileX + base`) matched baserom's exact term/register order: 411 -> 346 -> 328. Adding the same distinct-symbol treatment to LEFT (`gRoomGridLeft = 0x0202FFFE`) / RIGHT (`gRoomGridRight = 0x02030002`) trimmed size 536 -> 532 (329).
