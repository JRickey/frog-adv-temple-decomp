# sub_0800C978 — deferred (cross-jump merge of pool-deduped case tails)

Neighbour-cell tile-class sampler on the per-room packed-halfword grid at EWRAM
0x02030000. Switch on a direction mask (1=up, 2=down, 4=left, 8=right,
16=auto). The four directional cases each compute a `(u16 *)cell` address and
return `(*cell & 0x3F0) >> 4` (identical read tail to the matched sibling
`sub_0800CD88`). `DIR_AUTO` reads `gIwram_3720._field_1A` (the actor facing,
0..3) and recurses one step in that direction (bounds-checking two steps out).
Stride/row counts come from `sSpriteAssetIndexTable` at 0x08306444
(`entry[+4]` = stride/cols, `entry[+5]` = rows). The dispatch is a dense
`switch(dir)` over 1..16 → `mov pc, rN` + 16-word absolute jump table at
0x0800c9a8 (cases 3,5,6,7,9..15 and 0/>16 → default `return 0`).

## Drift

Best byte_diff 153 (diff_count 71) on a *deliberately mismatched* DOWN term
order; the structurally-correct form sits at byte_diff 390 (full tail merge).
The function is one structural blocker away from a byte match, and that blocker
is a backend constant-pool artifact, not a C-structure problem:

- **Narrowing of the stepped coordinate.** Baserom does `r0 = (s16)tileY`
  (lsls#16/asrs#16) THEN `subs r3, r0, #1` — i.e. sign-extend first, subtract
  second, result kept as a non-renarrowed int. An `s16 ny` local makes agbcc
  fold the `-1` BEFORE narrowing (`(tileY<<16) - (1<<16)` then asr → an
  `add 0xffff0000` pool load). FIX: declare the stepped coord as `s32`
  (`s32 ny = (s16)tileY - 1;`). With s32 the UP/DOWN guard prologue matches
  baserom exactly (lsls/asrs/subs/cmp/bge). This part is SOLVED.

- **Cross-jump merge of the UP and DOWN address tails (the real blocker).**
  In baserom UP (0xc9e8) and DOWN (0xca1c) have byte-identical address-compute
  tails — `ldrb stride; muls; 2*c; 5*b*4096; …; adds r1,r1,r0; ldr base;
  b 0xcab0` — and they share ONLY the final masked read at 0xcab0. The two
  `ldr r0,[pc,#N]` that load 0x02030000 reference DIFFERENT, non-deduped pool
  slots (0xca18 vs 0xca50), so the differing `ldr` immediate STOPS gcc's
  backward cross-jump merge right there — leaving each case its own multiply +
  address compute and merging only the 6-instruction read tail.

  This agbcc (old_agbcc, the default CC here, same as the matched siblings)
  DEDUPLICATES the 0x02030000 constant-pool entry, so both cases emit the
  SAME `ldr [pc, #slot]`, and the cross-jump merge extends backward through the
  WHOLE address tail (UP `b.n`s into DOWN's shared multiply). That is the 390.
  The cross-jump pass (gcc_arm/jump.c `jump_optimize(..., JUMP_CROSS_JUMP, …)`
  at toplev.c:4099) runs unconditionally for `optimize > 0`; the merge fires
  whenever the tails are bit-identical, which they are once the pool is shared.

## Levers already tried (all failed to break the merge — pick a DIFFERENT one)

- Per-case full `return` with `s16 ny` → 164 (wrong narrow + merge).
- Function-scope / block-scope `s32` stepped coord → 390 (right narrow, full
  merge). Block scoping does NOT stop agbcc CSE (it is whole-function).
- Shared `u16 *cell` + `break` then one post-switch return → 455.
- Shared `cell` + `goto read:` label after the switch → 459.
- Pointer-base arithmetic `(u8*)0x02030000 + …` (hoping for a distinct pool
  const) → 390 (agbcc folds it to the same const_int).
- `gRoomGrid` linker-assigned EWRAM symbol (the cvaos CSE-defeat trick) at
  0x02030000, referenced by UP/DOWN (LEFT=gRoomGrid-2, RIGHT=+2) → 370. A
  SINGLE symbol dedups to one `ldr =gRoomGrid` and still merges. Would need
  TWO distinct symbols at the same address to break it (hacky/wrong).
- `register u16 *cell asm("r1")` (UP) / `asm("r2")` (DOWN) to force
  register-distinct tails → 408 (pin ignored / cell recomputed).
- Reordering DOWN's terms so UP/DOWN tails differ DID break the merge → 153,
  but DOWN's instruction order then diverges from baserom (baserom UP and DOWN
  are term-IDENTICAL). Not a real match — trades one diff for another.
- Per-TU CFLAGS sweep — `-fno-thread-jumps`, `-fno-gcse`, `-fno-cse-follow-jumps`,
  `-fno-rerun-cse-after-loop`, `-fforce-addr`, `-fno-expensive-optimizations`,
  `-O0`, `-O1` — none change the merge (164 / 390 / 416). No flag disables the
  final cross-jump pass in agbcc 2.x.
- decomp-permuter (224 iters, base score 11345): score never dropped below
  base — statement/scope mutations don't reach the backend pool-dedup decision.

## Where to look next (NOT yet tried)

The blocker is purely "make agbcc emit TWO non-deduped pool entries for
0x02030000 (one per case), so the differing `ldr [pc,#slot]` stops the backward
cross-jump merge — exactly like baserom." Ideas a future agent could try:
- Find/inspect agbcc's constant-pool hashing (gcc_arm/varasm.c
  `mark_constant_pool` / `force_const_mem` / the const hash table) for a
  condition (mode, alignment, or a SYMBOL_REF+addend) that defeats dedup.
- Two distinct extern symbols aliased to 0x02030000 (e.g. `gRoomGridUp` and
  `gRoomGridDown` both `. = 0x00030000;` then advance) — but `.` only moves
  forward, so they cannot share an address via the dot trick; would need an
  ABSOLUTE `= 0x02030000` assignment for each, which ld permits outside a
  section. Worth testing whether two PROVIDE/abs symbols at the same address
  give two pool entries.
- Whether the matched siblings (sub_0800CB80/CD88) were built with a flag that
  happens to suppress pool dedup that we are not applying here.

## Best-effort C (structurally correct; narrowing solved; sits at byte_diff 390
## due to the cross-jump merge — promote once the pool-dedup is defeated)

```c
#include "game.h"
#include "iwram.h"
#include "macros.h"
#include "types.h"

#define DIR_UP 1
#define DIR_DOWN 2
#define DIR_LEFT 4
#define DIR_RIGHT 8
#define DIR_AUTO 16

struct SpriteAssetIndexEntry {
    u32 dataPtr;
    u8 stride;
    u8 rows;
    u8 _field_6;
    u8 _field_7;
};

extern struct SpriteAssetIndexEntry sSpriteAssetIndexTable[];

u32 sub_0800C978(u8 col, u8 row, s16 tileX, s16 tileY, u8 dir)
{
    s32 ny;
    s32 nx;

    switch (dir) {
    case DIR_UP:
        ny = (s16)tileY - 1;
        if (ny < 0) {
            return 0;
        }
        return (*(u16 *)(2 * tileX + (5 * row * 4096 + 2 * (ny * sSpriteAssetIndexTable[(u8)col].stride)) +
                         0x02030000) &
                0x3F0) >> 4;

    case DIR_DOWN:
        ny = (s16)tileY + 1;
        if (ny >= sSpriteAssetIndexTable[(u8)col].rows) {
            return 0;
        }
        return (*(u16 *)(2 * tileX + (5 * row * 4096 + 2 * (ny * sSpriteAssetIndexTable[(u8)col].stride)) +
                         0x02030000) &
                0x3F0) >> 4;

    case DIR_LEFT:
        nx = (s16)tileX;
        if (nx - 1 < 0) {
            return 0;
        }
        return (*(u16 *)(5 * row * 4096 + 2 * (sSpriteAssetIndexTable[(u8)col].stride * (s16)tileY) + 2 * nx +
                         0x0202FFFE) &
                0x3F0) >> 4;

    case DIR_RIGHT:
        nx = (s16)tileX;
        if (nx + 1 >= sSpriteAssetIndexTable[(u8)col].stride) {
            return 0;
        }
        return (*(u16 *)(5 * row * 4096 + 2 * (sSpriteAssetIndexTable[(u8)col].stride * (s16)tileY) + 2 * nx +
                         0x02030002) &
                0x3F0) >> 4;

    case DIR_AUTO:
        switch (gIwram_3720._field_1A) {
        case 0:
            if ((s16)tileY - 2 < 0) {
                return 0;
            }
            return (u8)sub_0800C978(col, row, (s16)tileX, (s16)(tileY - 1), DIR_UP);
        case 1:
            if ((s16)tileY + 2 >= sSpriteAssetIndexTable[(u8)col].rows) {
                return 0;
            }
            return (u8)sub_0800C978(col, row, (s16)tileX, (s16)(tileY + 1), DIR_DOWN);
        case 2:
            if ((s16)tileX - 2 < 0) {
                return 0;
            }
            return (u8)sub_0800C978(col, row, (s16)(tileX - 1), (s16)tileY, DIR_LEFT);
        case 3:
            if ((s16)tileX + 2 >= sSpriteAssetIndexTable[(u8)col].stride) {
                return 0;
            }
            return (u8)sub_0800C978(col, row, (s16)(tileX + 1), (s16)tileY, DIR_RIGHT);
        }
        return 0;
    }

    return 0;
}
```
