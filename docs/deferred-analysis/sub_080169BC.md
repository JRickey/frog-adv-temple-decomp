# sub_080169BC — deferred analysis

## Summary

Tilemap blit function: copies tile entries from `sFrogStatusBarFrames[24].tile_data`
into VRAM screenblock 31 (`0x0600f800`). Pure leaf function with no callees.

**Range:** `[0x080169bc, 0x08016a38)` — 124 bytes (116 code + 8 pool)  
**Pool:** `0x080e3628` (= `sFrogStatusBarFrames` base) and `0x0600f800` (VRAM screenblock 31)

## Algorithm

```
src = sFrogStatusBarFrames[24].tile_data
x   = sFrogStatusBarFrames[24].x        (row index, << 5 gives tile stride)
y   = sFrogStatusBarFrames[24].y        (column index)
dst = (u16*)0x0600f800 + (x*32 + y)    (tile destination in BG tilemap)
h   = sFrogStatusBarFrames[24].h
w   = sFrogStatusBarFrames[24].w

for row in 0..h:
    for col in 0..w:
        *dst++ = *src++
    dst += 32 - w                       // advance to next BG row
```

## Register map (baserom)

| Reg | Role |
|-----|------|
| r2  | `sFrogStatusBarFrames` base (0x080e3628); overwritten at outer loop entry |
| r4  | `src` (tile_data pointer, callee-saved) |
| r5  | dual-use: offset accumulator (0x120→0x124→0x126) during setup, then row counter |
| r6  | `&frame[24].w` (callee-saved) — used in row_end for `32 - *wp` |
| r7  | `h` (saved after loading, callee-saved) |
| r8  | `&frame[24].w` (copy of r6, callee-saved) — used in inner loop: `mov r0, r8; ldrh r3, [r0]` |
| ip  | `w` value (loaded before outer loop guard) |
| r1  | `dst` (scratch, preserved in leaf) |
| r2  | `col` counter (after base overwritten) |
| r3  | row counter (via zero-extend: `lsl r0, r5, #16; lsr r3, r0, #16`) |

r6 and r8 hold the SAME address (`&frame[24].w`) — r6 for direct ldrh in row_end,
r8 for indirect ldrh in inner loop (high regs need mov-to-low first).

## Drift

**Best byte_diff achieved: 104 / 124 bytes (120 bytes built vs 124 bytes target)**  
**Diff count: 42 instructions**

The function is 4 bytes shorter than target (112 code vs 116 code).

### Root cause: agbcc combine pass derives adjacent array offsets

The critical blocker is agbcc's **combine pass** (`gcc_arm/combine.c`) which always
fires for the setup phase:

Target generates (3 fresh instructions for x):
```asm
movs r3, #145    @ 0x91
lsls r3, r3, #1  @ r3 = 0x122
adds r0, r2, r3  @ x address
```

My code generates (2 derived instructions for x):
```asm
subs r1, r1, #6  @ r1 = 0x128 - 6 = 0x122 (derived from tile_data offset!)
adds r0, r2, r1  @ x address
```

Similarly, the y offset (0x120) is derived as `r1 - 8` instead of fresh
`movs r5, #0x90; lsls r5, r5, #1`.

The combine pass recognizes that `0x91*2 = 0x128 - 6` and `0x90*2 = 0x128 - 8`
(where 0x128 = tile_data offset still in r1) and emits `sub` instructions.

This saves 2 instructions = 4 bytes but produces WRONG register assignments:
- r1 (should be free for y addr) gets reused for x derivation  
- VRAM base ends up in r1 (not r3) → dst ends up in r2 (not r1)
- All subsequent register encodings cascade wrong → 42 diff instructions

### Levers tried (all failed to prevent the combine)

- Accessing x BEFORE tile_data, AFTER tile_data, before/after p init
- Explicit offset variable (`u32 x_off = 0x91; x_off <<= 1;`)  
- Separate pointer for x (`const u16 *x_ptr = base + 0x91;`)
- u8 byte-level casts (`*(u16*)((u8*)base + 0x122)`)
- `-fno-gcse` (old_agbcc doesn't support `-fno-schedule-insns`)
- `-ffixed-r1` (just moves derivation to r3)
- `-O1` (still uses combine, also emits pool in `.rodata` = wrong)
- Newer `agbcc` (identical behavior)
- All orderings of x, y, tile_data accesses

### Register pins tried

- `register const u16 *base asm("r2")` ✓ (correct, base in r2)
- `register const u16 *p asm("r5")` ✓ (walking pointer works)  
- `register const u16 *wp asm("r6")` ✓ (wp in r6 works)
- `register const u16 *wp8 asm("r8")` ✓ (wp8 in r8 works, correct prologue)
- `register u16 x asm("r3")` ✗ (breaks subsequent code, 124 bytes but more diff)
- `register const u16 *x_ptr asm("r3")` ✗ (x address in r3 but still sub-derives y)
- `register u32 x_off asm("r3")` ✗ (ignored by combine)

### What would make it match

The combine optimization must be defeated for the 3 adjacent accesses
(tile_data@0x128, x@0x122, y@0x120). This requires either:

1. An agbcc build flag that disables the combine pass for adjacent accesses
   (no known equivalent of `-fno-combine` in gcc 2.x)
2. An `asm("")` barrier between tile_data and x accesses to kill r1 liveness
   (would require the function to be clean from inline asm to stay "matched")
3. A fundamentally different struct access path that doesn't share the same
   base register for all three fields (e.g., three separate extern symbols
   pointing into sFrogStatusBarFrames at different offsets)

## Best-effort C

```c
#include "macros.h"
#include "types.h"

extern const u16 sFrogStatusBarFrames[];

void sub_080169BC(void)
{
    register const u16 *base asm("r2");  /* anchors base so outer loop can recompute &w */
    register const u16 *p asm("r5");     /* walking pointer: y(0x120)->h(0x124)->w(0x126); then row */
    register const u16 *wp asm("r6");    /* &frame[24].w, used in row_end for 32-w */
    register const u16 *wp8 asm("r8");   /* &frame[24].w, used in inner loop via mov r0, r8 */
    const u16 *src;
    u16 x;
    u16 y;
    u16 *dst;
    u16 h;
    u16 row;

    base = sFrogStatusBarFrames;
    src = (const u16 *)(*(const u32 *)(base + 0x94));
    x = base[0x91];
    p = base + 0x90;
    y = *p;
    dst = (u16 *)0x0600f800 + ((x << 5) + y);
    row = 0;
    p += 2;
    h = *p;
    if (row >= h)
        goto done;
    p++;
    wp = p;
    wp8 = wp;
    for (;;) {
        u16 w;
        u16 col = 0;
        if (col >= *wp)
            goto row_end;
        w = *wp8;
        do {
            *dst++ = *src++;
            col = (u16)(col + 1);
        } while (col < w);
    row_end:
        dst += 32 - *wp;
        row = (u16)(row + 1);
        if (row >= h)
            goto done;
    }
done:;
}
```

Byte_diff: 104 (120 bytes built vs 124 bytes target).
The loop body and register structure is correct.
The 4-byte discrepancy is entirely in the setup phase (x/y offset derivation).
