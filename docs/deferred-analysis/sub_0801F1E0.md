## The remaining 2 bytes (+0x16e/+0x170) — a sharp coupling, needs the permuter

baserom percent compute:
```
bl 0x1b188          ; r0 = sub_0801B188(slot._field0)
lsls r0,#24 ; lsrs r1,r0,#24   ; (u8)funcret -> r1
movs r0,#100        ; const 100 -> r0  (the multiply DEST)
muls r0,r1          ; r0 = 100 * funcret   (const-as-dest)
asrs r0,r0,#4       ; product >> 4 STAYS in r0
lsls r0,r0,#24 ; lsrs r1,r0,#24 ; (u8) -> r1 ; cmp r1,#100
```
Two facts baserom needs SIMULTANEOUSLY:
- (A) **const-as-dest multiply** (`movs r0,#100; muls r0,r1`, funcret in the source r1).
- (B) **asr stays in r0** (`asrs r0,r0,#4`, the product reg, no move to r1).

### What I proved about the coupling (do NOT re-test these — they are locked)
agbcc `expand_binop` (tools/agbcc-src/gcc_arm/optabs.c ~line 433) canonicalises a
commutative `(mult const reg)` by swapping the CONST to op1, so a plain
`100 * x` / `x * 100` ALWAYS makes the funcret the multiply dest (= built, fails A).
The ONLY source shape that yields (A) is the `target==op1` self-multiply:
```
s32 percent = sub_0801B188(slot._field0);
percent = (100 * percent) >> 4;        /* percent on BOTH sides */
```
BUT that exact shape makes the `>>4` result (percent) copy-suggest r1
(local-alloc.c `find_free_reg` copy-suggestion from the `(u8)percent` use), so the
asr lands in r1 — fails (B). Conversely, ANY form that splits the shift off the
multiply (`percent = 100*percent; percent >>= 4;`, a fresh result var
`s32 percent = (100*bitIdx)>>4;`, etc.) gives (B) asr-in-r0 but reverts to
funcret-dest mul (fails A). **A and B are mutually exclusive across every pure-C
source shape tried (~50 variants + ~15 minimal `old_agbcc` probes).**

A `volatile s32 t = funcret;` memory round-trip DOES give both A and B in a minimal
probe (optabs swap is bypassed because op0 stays const) — but in the full function
it allocates an EXTRA stack slot (`sub sp,#32` vs baserom's `#28`), shifting every
sp-relative offset → byte_diff 209. baserom uses NO extra slot and keeps funcret in
r1 purely in registers, so the volatile is not the baserom mechanism.
