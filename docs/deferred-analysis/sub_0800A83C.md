# sub_0800A83C — deferred analysis

`0x0800a83c .. 0x0800a910` (212 bytes), compiled with **old_agbcc**
(`src/engine/sub_0800a710.s: CC = $(OLD_AGBCC_BIN)`). Classifier verdict:
`ATTEMPT_MATCH` with advisory "3 high reg(s) (r8, r9, sl) pinned across a
`bl` — POSSIBLE Class-1".

## What it does

Near-twin of the already-NAKED `sub_0800BE18`. Iterates the hitbox-point
list of `sEntityHitboxTable[(s8)a]` (table at `0x080c0b00`, struct
`{u32 count; u32 points; u32 flags}`, 12 B/entry) and registers each
point via `sub_0800CB80`:

```
sub_0800CB80(b, c, points[i].x, points[i].y, flagByte)
```

- `a` (arg0, byte)  = signed table index (loop bound = `(s8)table[a].count`)
- `b` (arg1, byte)  = callee arg0  — pinned in **r9** across the bl
- `c` (arg2, byte)  = callee arg1  — pinned in **r8** across the bl
- `d` (arg3, byte)  = selects which flag byte: `d==0` → `(u8)table[a].flags`
                      (byte +8); `d!=0` → `(u8)(table[a].flags>>8)` (byte +9)
- `sl` holds `&sEntityHitboxTable[0].points` (= table_base+4) across the loop.

The `(x,y)` pair is `((s16*)table[a].points)[i]` (`j = i*4` byte offset,
`ldrsh +0`/`ldrsh +2`). The two `d` branches (blocks at `0xa888` and
`0xa8b8`) are DUPLICATED in the baserom, not factored — each recomputes
`sa*12`, the `points` deref, the `x/y` loads, and its own flag byte.

## Drift

Best result: **byte_diff 117, diff_count 74** (size 148 vs target 196) from
the simplest register-pinned factored version (the "Best-effort C" below).
Other structures tried, all WORSE in byte_diff:
- duplicated-branch (matches baserom's non-factored shape): size 176,
  byte_diff 151.
- `volatile u8 aStk/dStk` to force the stack spill: size 256, byte_diff 229
  (volatile reloads on EVERY access, far too many).
- loop counters pinned `i asm("r6"), j asm("r4"), sa asm("r5")`: size 184
  (closest to 196), byte_diff 162 — the explicit pins fight agbcc's natural
  choices and add moves.

The irreducible drift, present in EVERY variant:
1. The baserom **zero-extends `a` and `d` to bytes and SPILLS them to the
   stack** at entry (`lsls/lsrs #24; str r0,[sp,#8]` for `a`; `str r3,[sp,#4]`
   for `d`), then **reloads them once per loop iteration** (`ldr r1,[sp,#8]`
   at the loop bottom, `ldr r7,[sp,#4]` for the `d` test inside the body).
   old_agbcc instead keeps `a<<24` live in a register and never spills
   `a`/`d` to a stack slot — it has no reason to, given the register-pin
   structure leaves enough low registers free.
2. Because `d` is NOT spilled, old_agbcc treats the `d!=0` test as
   loop-invariant and **HOISTS it out of the loop**; the baserom keeps the
   test inside (`0xa884: ldr r7,[sp,#4]; cmp r7,#0; bne 0xa8b8`). The
   in-loop position is a consequence of the per-iteration stack reload.

This is the documented register-allocation / "two-stage loop with a value
re-read from a fixed location each iteration" unmatchable shape
(docs/codegen-notes.md). The DIRECT twin `sub_0800BE18` — same hitbox
iteration, same `sub_0800CB80` call, same r9/r8/sl pins — already ships
NAKED + NON_MATCHING for exactly this reason.

## Levers already tried (pick a DIFFERENT one next)

- `register u32 bReg asm("r9")=b; register u32 cReg asm("r8")=c;
  register const u32 *pointsBase asm("sl")` — pins ARE produced correctly
  (r9/r8/sl appear), but do not force the `a`/`d` stack spill.
- `volatile` on `a`/`d` — overshoots (per-access reload).
- counter register pins (r4/r5/r6) — size-converges, byte-diverges.
- Did NOT run the permuter: gap (117) is far beyond its useful range
  (~≤40) and the residual is a STACK-SPILL decision, not statement-ordering
  / register-coloring drift — permuter cannot invent a spill.

Next ideas NOT yet tried: a structure that genuinely forces `a`/`d` onto
the stack and reloaded per-iteration WITHOUT `volatile` (e.g. take the
address of `a`/`d`, or pass them through a tiny opaque `asm("")` barrier
keyed on a stack local so old_agbcc must materialize them in memory once
per iteration); or, if those fail, accept it as the same NAKED class as
`sub_0800BE18` (corpus-confirmed: the m4a/iteration-with-pinned-high-regs
idiom ships hand-asm).

## Best-effort C (byte_diff 117)

```c
extern int sub_0800CB80(int xTile, int unused, int x, int y, int flags);

void sub_0800A83C(u8 a, u8 b, u8 c, u8 d)
{
    register u32 bReg asm("r9") = b;
    register u32 cReg asm("r8") = c;
    register const u32 *pointsBase asm("sl");
    s32 i;
    s32 j;

    i = 0;
    if (i >= (s8)sEntityHitboxTable[(s8)a].count)
        return;

    pointsBase = &sEntityHitboxTable[0].points;
    j = 0;
    do {
        const s16 *pt;
        u8 flag;

        pt = (const s16 *)((u8 *)pointsBase[(s8)a * 3] + j);

        if (d != 0)
            flag = (u8)(sEntityHitboxTable[(s8)a].flags >> 8);
        else
            flag = (u8)sEntityHitboxTable[(s8)a].flags;

        sub_0800CB80(bReg, cReg, pt[0], pt[1], flag);

        j += 4;
        i++;
    } while (i < (s8)sEntityHitboxTable[(s8)a].count);
}
```
