### NEW (this session) — instrumentation PROOF + why every lever fails

ROOT CAUSE PROVEN by instrumenting a PRIVATE old_agbcc (copy `tools/agbcc-src/gcc`
to /tmp, `make old -j8 CC=cc` relinks fast using the prebuilt .o; byte-identical to
the installed compiler — verified). Added an fprintf in `equiv_constant()`
(`gcc/cse.c`, the `qty_const[reg_qty[REGNO(x)]]` substitution): pseudo 62 (`one`) is
folded reg→const **24 times**. The fold is UNCONDITIONAL for a `set reg, const_int 1`
whose register is later used (recorded at cse.c:1448-1453). At each use CSE's cost
model (`COST` macro, cse.c:479) treats `CONST_INT 1` as cheaper-or-equal to a
register and on a TIE prefers the constant (src_folded first, cse.c:6757-6765). So
the fold is structural in agbcc's CSE — no flag reaches it. (Note: Thumb-1 `ands` is
register-only, so the held register is strictly better, but agbcc's cost model is
mode-blind.)

CORPUS finding: `(mask >> i) & 1` loops in metroid/mf, mzm, etc. all DECOMP in pure
C with literal `1` and MATCH — because their original compiler ALSO rematerialized.
The corpus has NO example of a held-const-1-across-a-loop achieved in pure agbcc C.
This function's baserom HELD it — an original-compiler register-allocation choice
agbcc does not reproduce. (This is the same wall, now corpus-confirmed as a
divergence, not a missing idiom.)

THE WHACK-A-MOLE (key new finding): you CAN force `one` into r7 — pin
`register u32 one asm("r7")` + `register u32 i asm("r6")`. The masks then match
baserom EXACTLY (`asrs rX,r6; ands rX,r7`). BUT pinning frees a callee-saved
register, and `loop.c`'s invariant-motion (`move_movables`) immediately hoists ONE
of the loop-invariant ROM constants (the rec `&gBlitRecord_08306abc`, OR the table
base `gBlitInitTable_08306AD4`) into r7 in the preheader (`movs r7,#1; ldr r7,[pc]`),
CLOBBERING one. Verified via -dr relocations: f4=gBlitRecord (clean rec) or
f4=gBlitInitTable (entry-derived rec). The baserom hoists NOTHING — it reloads all
ROM consts each iteration. The clean (unpinned) 214 build also hoists nothing
(const-propagating `one` keeps register pressure high enough), but then `one` isn't
held. It's an inverse coupling: hold `one` ⇒ a reg frees ⇒ a ROM const hoists into
it. Could not find a source shape that holds `one` AND keeps all ROM consts reloaded.
