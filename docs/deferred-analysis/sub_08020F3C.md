# Deferred analysis: sub_08020F3C

Per-tick mover for the entity at index `arg` in the 0x38-stride entity array
at 0x03003720 (entity[0] doubles as the player header `gIwram_3720`).

## Semantics (confidently reconstructed)

```c
void sub_08020F3C(u8 arg)
{
    /* gate: sub_08006830 returns a u64; the caller ORs the halves and bails on 0 */
    if (sub_08006830(&gIwram_6110, arg, arg) == 0)
        return;

    e = &gEntities_03003720[arg];          /* base 0x03003720, stride 0x38 */

    /* rate-limit: skip until enough ticks have elapsed since field_2c was stamped */
    if ((u32)(gGameStuff._unk00 - e->_field_2c) < e->_field_32)
        return;

    dx = (s8)e->_field_30;                 /* signed per-tick X delta (ldrsb) */
    dy = (s8)e->_field_31;                 /* signed per-tick Y delta (ldrb + sxtb) */
    e->_field_2 += dx;                     /* advance entity sub-coords */
    e->_field_4 += dy;

    /* if this is the "controlled" entity (35E0.field_10 bit 1 set and
       35E0.field_D == arg), advance the player header (entity[0]) too */
    if ((gIwram_35E0._field_10 & 2) && gIwram_35E0._field_D == arg) {
        gIwram_3720._field_2 += dx;
        gIwram_3720._field_4 += dy;
    }

    e->_field_2c = gGameStuff._unk00;      /* restamp the rate-limit timestamp */
}
```

Field types nailed from the asm: field_2/field_4 = s16 (ldrh/strh), field_2c =
u32 (ldr/str), field_30 = s8 (read via `ldrsb`), field_31 = u8 read then
sign-extended (`lsl#24;asr#24`), field_32 = u8 (unsigned compare).
`gGameStuff._unk00` is the u32 at 0x03005330+0 (a tick/timestamp).
`sub_08006830(base6110, arg, arg)` returns a `long long`; gate is `== 0`.

## Drift

Best base: **byte_diff 105, diff_count 54** (size 168, exact). The C is
SEMANTICALLY correct and STRUCTURALLY very close; the residual is pure
agbcc register-coloring drift that pins could not pin down.

### What baserom does that we couldn't force

Baserom register map (THE TARGET):
- r6 = arg, r5 = arg<<3 (kept live; the final store **recomputes**
  `(r5-r6)<<3` rather than reusing the entity ptr)
- r3 = gIwram_3720 base (single base for entity[arg] AND player AND final store)
- r4 = gGameStuff at the gate, then `mov r8, r4` SPILLS it to r8 because r4 is
  reused as the zero index for `movs r4,#0; ldrsb r4,[r0,r4]` (field_30).
  Thumb-1 ldrsb has no immediate form, so it needs a register index — agbcc
  picks the now-free gGameStuff register r4 and spills the still-needed
  gGameStuff value to r8. This r4->r8 spill is the source of the
  `mov r7,r8; push{r7}` prologue + `pop{r3}; mov r8,r3` epilogue.
- ip = entity ptr, ALSO held in a low reg (r1) at the same time so the
  field accesses don't each need a `mov rX, ip`. Baserom forms
  `&field_2c = offset + (base+0x2c)` SEPARATELY from `ip = offset + base`
  (two address computations sharing the byte offset r1).

### Levers tried (all distinct structures)

1. Single-base via `(struct Entity*)&gIwram_3720` (defeats the 4-pool-literal
   CSE split that absolute-address casts cause). REQUIRED to get under ~110.
2. `register struct Entity *e asm("ip")` — REQUIRED to make agbcc use r8 at
   all. Without it agbcc puts gGameStuff in ip and never saves r8 (byte_diff
   jumps to ~148, prologue loses the r8 save). With it: 107/56.
3. `+ register base asm("r3")` -> 105/54 (pool literals + base now match).
4. `+ register arg asm("r6")` — REGRESSES to 148. The arg=r6 pin and the
   r8-spill are anti-correlated: pinning arg frees the allocator to resolve
   pressure without the r4->r8 spill, killing the r8 prologue. THIS IS THE
   WALL — arg lands in r5 (mine) vs r6 (baserom) and pinning it breaks r8.
5. `+ register gs asm("r4")` — also REGRESSES; locking gs in r4 PREVENTS the
   natural r4->r8 spill (agbcc can't reuse r4 for the ldrsb index), so dy
   ends up wrongly in r8 (`mov r8, r2`). The spill MUST be left natural.
6. field_2c via explicit byte-offset `*(u32*)(base+0x2c+offset)` to force the
   separate-address pattern: REGRESSES to 118-126 (dy lands in r8).
7. split `delta = gs->_unk00 - field_2c;` before forming e: 118.
8. Separate symbols (absolute-cast entity vs gIwram_3720 player): 139.
9. `-ffixed-r5` to push arg to r6: works for arg but rewrites the whole
   prologue to use r9 (wrong). Not a viable per-TU flag here.
10. old_agbcc: identical CSE/coloring to agbcc on every structure tried.

Permuter NOT attempted at byte_diff 105 (howto threshold is ~40; permuting a
base this far is wasted — the structure, not the schedule, is the gap... except
the structure IS right, so the gap is a single allocator decision the permuter
mutates poorly because the e=ip pin freezes most of the coloring).

## Next idea for the resumer (try a DIFFERENT lever than 1-10)

The whole wall is the r4->r8 spill being CONDITIONAL on arg NOT being pinned
to r6 while STILL needing arg in r6. Two untried angles:
- Get arg into r6 WITHOUT a `register asm("r6")` pin: e.g. make arg live
  across more of the body so the allocator prefers the highest callee-saved
  low reg (r6) for it — try referencing `arg` once more very late, or copy it
  into a second local used only at the `field_D == arg` compare, so the
  ORIGINAL arg coloring shifts to r6.
- Try `register dx asm("r1")` / `register dy asm("r1")`-style pins to keep the
  deltas in the low scratch reg baserom uses (r4 for dx, r1 for dy) so the
  spill register math falls out — but WITHOUT pinning arg/gs (leave those two
  to the allocator so the r4->r8 spill stays natural). The dx-in-r4 detail is
  notable: baserom's dx (field_30) lands in r4 AFTER the ldrsb, i.e. the same
  reg gGameStuff vacated — so dx reuses the freed register. Forcing dx=r4 may
  be the keystone that makes everything else fall into place.
- Permuter once a sub-40 base is reached via the above.
