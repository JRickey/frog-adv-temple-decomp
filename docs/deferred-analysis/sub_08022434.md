## Drift

Best (cleanest) result: **byte_diff 572, diff_count 182** with the plain C below
(no flags, no pins). The function structure is correct; the entire diff is one
preheader divergence cascading into branch-offset shifts.

ROOT CAUSE (confirmed by reading `tools/agbcc-src/gcc_arm/config/arm/arm.h`
`REG_ALLOC_ORDER` = `... 8, 10, 9 ...`, i.e. high-reg order r8 → sl(r10) → r9):

- Baserom keeps 3 callee-saved quantities: `i`→r8, `gEntities`→r9, `0x2ef`→sl,
  and recomputes `slot = i*56 + 0x03004638` (absolute &gEntities[69]) each
  iteration. It does NOT factor a `gEntities+0xf18` sub-base — each fixed-slot
  access does a full `ldr =offset; add r9` (and `gEntities[70].x` uses the
  absolute literal `0x03004672`).
- agbcc instead CSE-factors `gEntities + 0xf18` (= &gEntities[69]) as the
  TOP-priority quantity (most-used → allocated first → r8), which displaces
  `i` to r9 and keeps `gEntities` in sl. `0x2ef` is never promoted to a
  callee-saved reg (recomputed `0x26f + 0x80` inside case 2). So the quantity
  SET differs: baserom {i, gEntities, 0x2ef} vs agbcc {gEntities+0xf18,
  gEntities, i}. That single extra factored base is the whole divergence.
