# sub_0802EB34 — deferred analysis

`sub_0802EB34` ([0x0802eb34, 0x0802ebf8), 196 bytes) configures the
clamp-envelope (envelope-A, `SlotClampEnvelope` at +0x1c) of a sound channel
to reach a target value over a fixed number of frames.

Signature: `void sub_0802EB34(u8 absolute, u16 target, u16 frames, s32 mode)`
  - `mode` selects the channel bank: 0..2 = inline channels embedded in
    SoundSystem (slot-view at `ss + mode*36 + 0x20` = `&ss->inlineChannels[mode]`);
    `mode == 3` is a no-op; `mode >= 4` = software-slot bank
    (`SOUND_SYSTEM_SW_SLOT_FOR_CHANNEL`, `swSlots + mode*64 - 256`).
  - `absolute` (u8): nonzero = ABSOLUTE; zero = RELATIVE.
  - `target` (u16, used signed): target / delta value.
  - `frames` (u16): frame count → the `__divsi3` divisor.

For both banks, treating the channel as a `SoundSlot` view (acc0 at +0,
env at +0x1c):
  - absolute: `env->limit = (s16)target - acc0`,
              `dividend  = (s16)target - ((s16)acc0 + (s16)env->acc)`.
  - relative: `env->limit += (s16)target`,  `dividend = (s16)target`.
All paths converge on one shared `env->step = __divsi3(dividend, frames)` tail;
`mode == 3` returns before the div.

The semantics are fully reverse-engineered and the best-effort C below is
behaviourally correct — the blocker is purely register coloring / agbcc
cross-jump-vs-scheduling interaction.

## ROUND 5 (Opus escalation) — STRUCTURAL ADVANCE: 144 → 127, two new levers

### The core blocker: a cross-jump merge agbcc does but the baserom does NOT

The two ABSOLUTE branches (inline-abs at 0x2eb68 and swslot-abs at 0x2ebb4) end
in byte-IDENTICAL 6-instruction tails (`movs r5,#28; ldrsh r2,[r3,r5]; adds
r1,r1,r2; subs r0,r0,r1; adds r1,r6,#0; b 0x2ebe6`). old_agbcc's unconditional
jump2 cross-jump pass (toplev.c:3143, JUMP_CROSS_JUMP, runs at optimize>0, NO
flag disables it) merges these via `rtx_renumbered_equal_p` (post-reload hard-reg
compare). The BASEROM keeps them SEPARATE — i.e. the baserom build did NOT merge
identical post-reload tails. This is a genuine contradiction with the traced
cross-jump behaviour; no `-fXXX` flag (`-fno-thread-jumps`, `-O1`,
`-fno-defer-pop`, `-fno-caller-saves`, `-ffixed-rN`, …) changes it. The likely
true cause is still open (a register-liveness/death-note subtlety in
find_cross_jump that the C shape must trip, OR a build-config we haven't found).

### LEVER 1 (new): distinct `view` pointer breaks the merge

Reading the inline env->acc through a SEPARATE `u8 *view` local (`(s16)*(s16*)
((u8*)view + 0x1c)`) instead of reusing the `slot` variable makes the inline tail
NOT renumbered-equal to the swslot tail → **XJUMP=0, no merge** (matches the
baserom's separate-blocks shape, 180 B). Reusing `slot` for both → merge (152 B,
too small). This is the structural fix the rounds 8-15 plateau never found.

### LEVER 2 (new): `gpp = &gpSoundSystem` local forces the early-address-load

The baserom loads the gpSoundSystem POOL ADDRESS early (`ldr r0,[pc]` BEFORE the
`mode*36` math) and DEREFS late (`ldr r0,[r0,#0]` after), which keeps r0 busy and
makes `mode*36` land in r2 — this makes the ENTIRE offset-computation block
(0x2eb50-0x2eb62: the mul, the `+32`, the deref, view, env) byte-match the
baserom. Writing `SoundSystem **gpp = &gpSoundSystem; ss = *gpp;` (instead of the
`ss = gpSoundSystem` macro) induces exactly this schedule. WITHOUT gpp the address
loads late and the whole inline block is register-shifted by one.

### THE REMAINING TENSION (why 127 not 0)

Lever 1 (no-gpp, distinct view) and Lever 2 (gpp) are in OPPOSITION:
  - vF  = distinct-view, NO gpp  → XJUMP=0 (no merge, right SIZE) but late-addr
          (offset block register-shifted) → **byte_diff 138**.
  - vL  = gpp + distinct-view     → early-addr (offset block byte-MATCHES!) but the
          gpp allocation re-MERGES the absolute tails → **byte_diff 127** (BEST).
No combination found that gets BOTH no-merge AND early-addr. Every attempt to
break vL's merge (inline env->acc via cb+60, via env ptr, swslot `bw` local) keeps
XJUMP=2. New agbcc on vL = 128 (no better). Pins: pinning a→r7 spills `a` to the
stack; pinning b→r5 OR c→r6 RE-introduces the merge (over-constrains → tails
become renumbered-equal again); pinning all three = 150/merged. So pins are
self-defeating here, same as the prior rounds found.

The residual diff at byte_diff 127 is: (a) the persistent absolute-tail merge
(~16 B), and (b) a register shift in the inline block — a→r6 (want r7),
channelBase→r1 (want r2), (s16)b→r2 (want r0) — because b's backup grabbed r7
(baserom puts it in r8, freeing r7 for a). The shift root cause: b's
clobber-backup wants r8 but agbcc gives it r7.

### Levers tried (round 5), all > 0:
- vF (distinct view, no gpp, no pins): bd 138, XJUMP=0, size 180. CLEAN.
- vL (gpp local + distinct view, no pins): **bd 127, XJUMP=2, size 180. BEST, CLEAN.**
- vL + new agbcc: 128.  vF + new agbcc: 139.
- c→r6 pin (+vF): bd 153 dc 65 (a→r7 correct but a/b backups SWAP ip↔r8).
- a→r7 pin: spills a to stack (150-163).  all-three pins: 150, re-merged.
- `-ffixed-r2/r3/ip/r9`, `-fno-caller-saves`, `-fno-thread-jumps`, `-O1`: none help.
- decomp-permuter: UNUSABLE — both make_permuter_target.py AND setup_permuter.py
  emit a target.s with `.inst.n` for the literal pool and NO `$t`/`$d` mapping
  symbols, so the scorer reads the pool as garbage Thumb → base score 4059 for a

### NEXT ATTEMPT should try:
1. The crux is ONE of two things, pick one and drive it: (a) break vL's merge
   WITHOUT losing the early-addr — needs the inline env->acc read to use a
   different post-reload reg than swslot's while gpp is present (the gpp
   allocation currently colors them equal); or (b) keep vF's no-merge and induce
   the early-addr by a non-gpp mechanism (a different way to occupy r0 across the
   mode math).
2. Force b's clobber-backup to r8 (not r7) so r7 frees for a→r7 and the whole
   inline block un-shifts. A single high-reg `register u16 bbk asm("r8")` ALIAS
   over-spills (r8+r9, 200 B) — need the SAME value to have two homes (r5 working,
   r8 backup) with r5 clobbered between, which no single C local expresses. Maybe
   an `asm("")` mov-fence that copies b→r8 only on the swslot path.
3. Instrument find_cross_jump's register-death path (jump.c ~line 110-125,
   `last1 = afterlast1 … ++minimum`) to learn the EXACT condition under which the
   baserom's identical tails would NOT merge — that is the unsolved contradiction.

## Best-effort C — vL (byte_diff 127, size 180, XJUMP=2, BEST; PURE C, one gpp local)

```c
extern int __divsi3(int num, int den);

void sub_0802EB34(u8 absolute, u16 target, u16 frames, s32 mode)
{
    SoundSystem *ss;
    SoundSlot *slot;
    SlotClampEnvelope *env;
    s32 dividend;

    if (mode <= 2) {
        SoundSystem **gpp = &gpSoundSystem;            /* early pool-address load */
        s32 off = mode * SOUND_INLINE_CHANNEL_STRIDE;
        s32 viewOff = off + SOUND_INLINE_CHANNEL_BASE_OFFSET;
        u8 *view;
        ss = *gpp;
        view = (u8 *)ss + viewOff;                      /* ss + (off+32), NOT (ss+off)+32 */
        slot = (SoundSlot *)view;
        env = SOUND_SLOT_ENVELOPE_A(slot);
        if (absolute) {
            u8 *cb = (u8 *)ss + off;                    /* lazy channelBase */
            s32 bw = (s16)target;
            env->limit = bw - *(u16 *)(cb + SOUND_INLINE_CHANNEL_BASE_OFFSET);
            dividend = bw - ((s16) * (s16 *)(cb + SOUND_INLINE_CHANNEL_BASE_OFFSET) +
                             (s16) * (s16 *)((u8 *)view + SOUND_SLOT_ENVELOPE_A_OFFSET));
        } else {
            env->limit += (s16)target;
            dividend = (s16)target;
        }
    } else {
        if (mode == 3)
            return;
        ss = gpSoundSystem;
        slot = SOUND_SYSTEM_SW_SLOT_FOR_CHANNEL(ss, mode);
        env = SOUND_SLOT_ENVELOPE_A(slot);
        if (absolute) {
            env->limit = (s16)target - *(u16 *)slot;
            dividend = (s16)target - ((s16) * (s16 *)slot +
                                      (s16) * (s16 *)((u8 *)slot + SOUND_SLOT_ENVELOPE_A_OFFSET));
        } else {
            env->limit += (s16)target;
            dividend = (s16)target;
        }
    }

    env->step = __divsi3(dividend, frames);
}
```

## ROUND 6 (Opus escalation) — confirms the merge is unconditional; root-caused the register swap
----------------------------------------------------------------------

Re-derived from scratch (not extending vL). Reached **byte_diff 126, diff_count 59**
with PURE C (no asm, no pins; `-ffixed-r2` is moot — same number without it),
in a SEPARATE TU `src/system/sound_clamp_envelope.c` (not the EA80 file).

### Authoritative function model (re-disassembled, pool words separated)

Signature `void sub_0802EB34(u8 absolute, u16 target, u16 frames, s32 mode)`.
- Prologue zero-extends all three: absolute→{r7,ip}, target→{r5,**r8**}, frames→{r6,r2}.
- Inline (mode<=2): pool addr `gpSoundSystem` loaded EARLY (`ldr r0,[pc]` before the
  mode*36 math), deref LATE (`ldr r0,[r0,#0]`). `cb = ss+mode*36` (kept in r2),
  `view = ss+(mode*36+32)` (r3), `env = view+28` (r4). acc0 read via `cb[32]`
  (NOT via view[0]) — distinct-pointer fingerprint.
- swslot (mode>=4): `slot = swSlots + mode*64 - 256`, env=slot+28, acc0 via slot[0].
- mode==3 returns. All 4 paths: `dividend = ...; r1=frames; b 0x2ebe6` → one `bl __divsi3`.
- In the absolute branches `(s16)target` is computed ONCE (into r0) and reused for
  BOTH `env->limit = t - acc0` and `dividend = t - (acc0 + env->acc)`. (In C: a
  single `s32 t = (s16)target;` per abs branch — this is what gets size back to 180.)
- relative: `dividend = (s16)target; env->limit += dividend;` (dividend flows to limit).

The clean C below reproduces the offset block, both bank computations, mode==3
no-op, and the div tail EXACTLY. Three things remain wrong, ALL one root cause.

### ROOT CAUSE (new, definitive): the jump2 cross-jump merge demotes `frames`

agbcc 2.x runs `jump_optimize(insns, JUMP_CROSS_JUMP, ...)` UNCONDITIONALLY at
`optimize > 0` (toplev.c:4097-4101). There is **NO** `-fno-crossjumping` in agbcc
2.x (that flag is gcc-3.x; the `f_options[]` table has only `thread-jumps`,
`live-range` (rejected by old_agbcc), etc.). `find_cross_jump` (jump.c:2823)
merges any common suffix of two `b div` blocks when `rtx_renumbered_equal_p`
holds (the x87 death-note guard at :2896 is `#ifdef STACK_REGS` → never on ARM),
and `minimum` starts at 1 for simple jumps so a SINGLE matched insn triggers the
merge (:2998-3003).

Our 4 paths all end `…; r1=frames; b div` (identical) → agbcc factors the
`frames→r1; bl div` into ONE shared block → **`frames` is referenced ONCE** →
low allocation priority (`allocno_compare`, global.c:813 `floor_log2(n_refs)*n_refs
/live_length`) → `frames` loses the low callee-saved reg and lands in **r8**;
`target`'s backup grabs **r6**. The baserom is the MIRROR image: it did NOT merge,
so `frames` is loaded per-path (`adds r1,r6,#0` ×3, `adds r1,r2,#0` ×1) = 4 refs →
HIGH priority → `frames`→**r6**, freeing r8 for `target`'s backup.

**So the register swap (frames↔target home) and the tail-merge are the SAME bug.**
The 59 diffs are almost entirely the r6↔r8 / r2↔r3 rename cascade plus the merge.

### Why the baserom didn't merge is STILL the open contradiction

The baserom's three `b div` tails are byte-identical (`adds r1,r6,#0; b 2ebe6`) and
use identical hard regs, so `rtx_renumbered_equal_p` MUST hold and agbcc MUST merge
them — yet the baserom ships them un-merged. No reachable agbcc-2.x flag suppresses
jump2 cross-jump. The likely true cause is a build-config we cannot see (a compiler
variant where jump2 cross-jump is gated), NOT a C shape. This is consistent with
rounds 8-15 + round 5.

- `-ffixed-r2/-r3/-r6/-r7` (and pairs): 126/131/59 — change the rename but never the swap.
- jump/cse family: `-fno-thread-jumps -fno-defer-pop -fno-cse-follow-jumps
  -fno-cse-skip-blocks -fno-rerun-cse-after-loop -fno-expensive-optimizations -O1
  -fno-peephole -fcaller-saves -fno-force-mem -fno-function-cse -fno-inline
  -fno-delayed-branch -fno-combine-stack-adjustments -fno-schedule-insns2
  -frerun-loop-opt -funroll-loops -fno-pcc-struct-return`: ALL 126. None touch jump2.
- `-flive-range`: REJECTED by old_agbcc (the baserom's default CC) — yet the

  (`REG_N_RANGE_COPY_P`, global.c:804, the TOP allocno_compare key). Strong hint

- new agbcc (AGBCC_BIN) on this base: 127 (no better).
- pins: `target asm("r8")` (u16 or s16) forces ALL target uses to r8 → loses the
  per-branch `(s16)target` re-derivation → 158-164. `frames asm("r6")` over-spills

## Best-effort C — Round 6 (byte_diff 126, diff_count 59, size 180; PURE C, no asm, no pins)

```c
#include "sound.h"

void sub_0802EB34(u8 absolute, u16 target, u16 frames, s32 mode)
{
    SoundSystem *ss;
    SlotClampEnvelope *env;
    s32 dividend;

    if (mode <= 2) {
        SoundSystem **gpp = &gpSoundSystem;            /* early pool-address load */
        s32 viewOff = mode * SOUND_INLINE_CHANNEL_STRIDE + SOUND_INLINE_CHANNEL_BASE_OFFSET;
        u8 *view;
        ss = *gpp;
        view = (u8 *)ss + viewOff;                      /* ss + (mode*36+32), NOT (ss+..)+32 */
        env = SOUND_SLOT_ENVELOPE_A((SoundSlot *)view);
        if (absolute) {
            u8 *channelBase = (u8 *)ss + mode * SOUND_INLINE_CHANNEL_STRIDE;
            s32 t = (s16)target;                       /* computed once, reused */
            env->limit = t - *(u16 *)(channelBase + SOUND_INLINE_CHANNEL_BASE_OFFSET);
            dividend = t - ((s16)*(s16 *)(channelBase + SOUND_INLINE_CHANNEL_BASE_OFFSET) +
                            (s16)*(s16 *)(view + SOUND_SLOT_ENVELOPE_A_OFFSET));
        } else {
            dividend = (s16)target;
            env->limit += dividend;
        }
    } else {
        SoundSlot *slot;

        if (mode == 3)
            return;
        slot = SOUND_SYSTEM_SW_SLOT_FOR_CHANNEL(gpSoundSystem, mode);
        env = SOUND_SLOT_ENVELOPE_A(slot);
        if (absolute) {
            s32 t = (s16)target;
            env->limit = t - *(u16 *)slot;
            dividend = t - ((s16)*(s16 *)slot + (s16)env->acc);
        } else {
            dividend = (s16)target;
            env->limit += dividend;
        }
    }

    env->step = dividend / frames;
}
```
