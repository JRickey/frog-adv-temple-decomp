# sub_0802EB34 — deferred analysis

`sub_0802EB34` ([0x0802eb34, 0x0802ebf6), 194 bytes) configures the
clamp-envelope (envelope-A, `SlotClampEnvelope` at +0x1c) of a sound channel
to reach a target value over a fixed number of frames.

Signature: `void sub_0802EB34(u8 a, u16 b, u16 c, s32 mode)`
  - `mode` selects the channel bank: 0..2 = inline channels embedded in
    SoundSystem (`&ss->inlineChannels[mode]`, stride 36, base ss+0x20);
    `mode == 3` is a no-op; `mode >= 4` = software-slot bank (channel
    `mode-4` via `SOUND_SYSTEM_SW_SLOT_FOR_CHANNEL`).
  - `a` (u8 flag): nonzero = ABSOLUTE (drive from current acc toward `b`);
    zero = RELATIVE (bias the existing limit by `b`).
  - `b` (u16, used signed): target / delta value.
  - `c` (u16): frame count → the `__divsi3` divisor.

The channel's leading u16 (slot/inline-channel offset 0) is its current
accumulator (acc0). For both banks:
  - absolute: `env->limit = (s16)b - acc0`,
              `env->step  = ((s16)b - ((s16)acc0 + (s16)env->acc)) / c`.
  - relative: `env->limit += (s16)b`,  `env->step = (s16)b / c`.
All paths converge on one shared `env->step = dividend / c` store via
`__divsi3` (the only callee, the in-ROM libgcc signed-divide at 0x08033d14);
`mode == 3` returns before reaching the div.

The semantics are fully reverse-engineered and the best-effort C below is
believed behaviourally correct — the blocker is purely register coloring.

## Drift

Best result: **byte_diff 133, diff_count 78** (oracle:
`compile_and_view_assembly.py sub_0802EB34 --human`), from the v8 base in
"## Best-effort C" (shared `__divsi3` tail; params pinned `a`->ip, `b`->r5,
`c`->r6; inline path via typed `&ss->inlineChannels[mode]`).

diff_count stays ~78 across every variant tried — the macro STRUCTURE is
correct; ~78 instructions only have the wrong register operands. The whole
gap is a sharp register-coloring local minimum, not a structural error.

### Root cause (read the target asm)

The baserom DUPLICATES every parameter into two registers — a low working
copy consumed (clobbered) in the fall-through `mode <= 2` branch, plus a
preserved copy for the `mode >= 4` branch:
  - `a` -> r7 (working, the `cmp r7,#0`) AND ip (`mov ip,r7`, the branch-B `cmp`)
  - `b` -> r5 (working) AND r8 (`mov r8,r5`, branch B `mov r1,r8`)
  - `c` -> r6 (working, branch A divisor) AND r2 (branch B divisor)
That 5th callee-saved reg (r8) forces the wide prologue
`push {r4,r5,r6,r7,lr}; mov r7,r8; push {r7}` and epilogue
`pop {r3}; mov r8,r3; pop {r4-r7}; pop {r0}; bx r0`.

Why the duplication: in branch A the `ldrsh Rd,[Rn,Rm]` acc reads (Thumb-1
has no immediate-offset ldrsh) load their index into **r5** — i.e. they
reuse b's working register (`movs r5,#32` / `movs r5,#28`), which makes the
allocator keep a branch-B backup of b in r8. agbcc here instead loads the
ldrsh index into a caller-saved scratch (r3), so b survives in one register
and no r8 backup / no param duplication is emitted. Result: my object is
**140 bytes vs the target's 194** — the built code is genuinely *more
optimal*; the target carries ~54 bytes of redundant copies that only appear
under that specific allocator pressure. I cannot steer which register the
ldrsh index lands in from C (it is allocator-internal), so I cannot reproduce
the cascade.

A second, smaller divergence: the target reads the inline acc via
`[channelBase=ss+mode*36, #0x20]` (keeping `mode*36` materialized as its own
base) and the env via `view(=channelBase+0x20) + 0x1c`; agbcc folds these to
one base + offsets (`+0x3c`), which also lets cross-jumping MERGE the
inline-abs and swslot-abs blocks (target keeps them separate because their
addressing differs). Materializing `channelBase` explicitly only grew the
object (148).

### Levers tried (all leave the coloring intact)

- Structure: shared `__divsi3` tail (best) vs per-branch div + early return
  (162) vs `if/else if/else` (112 diff_count). Shared tail wins.
- Param pins, every combination: a->ip,b->r8,c->r6 (160); a->ip,b->r5,c->r6
  (**133, best**); a->ip,b->r8,c->r2 (136); b alone->r8 (172, size 192);
  none (174). Pinning b to r8 collapses the working+backup copies into one,
  defeating the duplication; pinning b to r5 (working) never spawns the r8

- Inline acc addressing: `&ss->inlineChannels[mode]` (best) vs explicit
  `channelBase=ss+mode*36` + `acc[+0x20]` (148) vs array-index form (148).

  tried (would be contorted "two locals per param" C — rejected on style).
- Compiler swap: NEW agbcc (`tools/agbcc/bin/agbcc`) — same batched-cast
  prologue, no r8, no help (and it breaks sibling sub_0802EA80 in this TU,

- Flags: `-fforce-addr -fno-expensive-optimizations` (no prologue change);
  old_agbcc REJECTS `-fno-schedule-insns(2)` and `-ffixed-rN`, so the
  all-`lsls`-then-`lsrs` cast batching (target interleaves per param) cannot

- Permuter: NOT run — byte_diff 133 is far above the ~40 productive
  threshold and the permuter only mutates statement order/scope/temps, which

  future attempt wants it: introducing redundant param-copy temps that the

## Best-effort C

```c
extern int __divsi3(int num, int den);

void sub_0802EB34(u8 a, u16 b, u16 c, s32 mode)
{
    register u8 aReg asm("ip");
    register u16 bReg asm("r5");
    register u16 cReg asm("r6");
    SoundSystem *ss;
    SoundInlineChannel *ch;
    SoundSlot *slot;
    SlotClampEnvelope *env;
    s32 dividend;

    aReg = a;
    bReg = b;
    cReg = c;

    if (mode <= 2) {
        ss = gpSoundSystem;
        ch = &ss->inlineChannels[mode];
        env = &ch->envelopeA;
        if (aReg != 0) {
            env->limit = (s16)bReg - *(u16 *)ch;
            dividend = (s16)bReg - ((s16) * (s16 *)ch + (s16)env->acc);
        } else {
            env->limit = env->limit + (s16)bReg;
            dividend = (s16)bReg;
        }
    } else {
        if (mode == 3)
            return;
        ss = gpSoundSystem;
        slot = SOUND_SYSTEM_SW_SLOT_FOR_CHANNEL(ss, mode);
        env = SOUND_SLOT_ENVELOPE_A(slot);
        if (aReg != 0) {
            env->limit = (s16)bReg - *(u16 *)slot;
            dividend = (s16)bReg - ((s16) * (s16 *)slot + (s16)env->acc);
        } else {
            env->limit = env->limit + (s16)bReg;
            dividend = (s16)bReg;
        }
    }

    env->step = __divsi3(dividend, cReg);
}
```

## Round 15 (Opus escalation) — re-derived from scratch, same plateau

Re-derived the C independently (not tweaking the prior near-match). Confirmed
the prior analysis and added a deeper root cause. Best results: clean unpinned
C = **byte_diff 142 / size 148**; pinned working copies a->r7,b->r5,c->r6 =
**byte_diff 132** (matches the prior plateau). Every fundamentally-different
structure tried landed >= 132.

### NOTE: the asm slice holds TWO functions

`asm/disasm_0x0802eb34.s` `.incbin`s `0x2eb34, 0x148` (328 bytes) but that
range is **two** functions: `sub_0802EB34` `[0x2eb34, 0x2ebf8)` (194 B, the
real target, wide r8 prologue, one `bl __divsi3`) and `sub_0802EBF8`
`[0x2ebf8, 0x2ec7c)` (132 B, `push {r4-r7,lr}` prologue, its own
`bl __divsi3`). `classify_unmatchable.py` sees the merged slice, counts 2 bl's
+ wide prologue, and FALSE-flags `STRONG_UNMATCHABLE [class3-libgcc]`. It is
NOT class3 — agbcc genuinely uses r4-r7 (env survives the div), so the wide
`push {r4-r7,lr}` is correct; the divergence is only the EXTRA r8 save.
A real decomp must first split the slice (peel `sub_0802EBF8` into
`asm/disasm_0x0802ebf8.s`, `.incbin 0x2ebf8, 0x84`, and point
`sound_envelope.o` at `0x0802ea80 - 0x0802ebf8`).

### Deeper root cause: agbcc pre-spills `mode` to r4

The clean build's FIRST instruction after the push is `adds r4, r3, #0` —
agbcc moves `mode` (arg r3) into callee-saved **r4** and keeps it there across
the whole branch. The baserom keeps `mode` in **r3** (caller-saved) because
`mode` dies before the `__divsi3` call (only used for the channel/slot address
math). This single pre-spill cascades the entire allocation: with `mode` in r4,
agbcc has r5,r6,r7 free for the three param working-copies AND r3/ip free for
their backups, so it never needs r8 -> narrow prologue, 148 bytes. The baserom,
keeping `mode` in r3, has its three working copies occupy r5,r6,r7 and r3 taken
by the channel/slot base, forcing one backup (b) to r8 -> wide prologue, 194
bytes. The baserom is ~54 bytes LESS optimal; agbcc's output is genuinely
better. Defeating the `mode->r4` pre-spill is the crux — a shadow-copy of
`mode` per branch (codegen-notes "Shadow-copy of a live value") was CSE'd away
(no effect); pinning a `mode` local to r3 did not help (145).

### Secondary divergence: cast batching

Baserom interleaves the param casts (`lsls r0,#24; lsrs r7,#24; mov ip,r7;
lsls r1,#16; ...` — one param fully processed before the next). agbcc batches
(`lsls r1,#16; lsls r2,#16; lsrs r5; lsrs r6; ...`). `old_agbcc` REJECTS
`-fno-schedule-insns`/`-fno-schedule-insns2` so the scheduler cannot be turned
off; reordering the source `xWork=..; xPres=..` per-param did not flip it.

### Corpus: the idiom IS reproducible (so NOT impossible)

`corpus_asm_search.py --asm 'mov +r8, *r[0-7]' --require-c` and
`'mov +ip, *r[0-7]'` both return matched pure-C functions (pret librfu,
metroidret mzm audio) — the param-backup-to-high-reg + wide r8 prologue idiom
is reproducible from plain C when the function carries the right pressure. So
this is a findable shape, not a true wall; the unfound piece is the C that
makes agbcc keep `mode` in r3 (caller-saved) instead of pre-spilling to r4.

### Levers tried this round (all >= 132, none reached 0)

- Clean unpinned shared-tail: 142 / 148 B (the readable reference, below).
- Pin working copies a->r7,b->r5,c->r6: 132 (best; agbcc then DROPS r7 and
  reads `absolute` from the stack — pins on derived/dead-early locals corrupt).
- Pin channel/slot bases to r3: 148/141 (no r8).
- Dual-locals (work + pres asm("ip"/"r8"/"r2")), per-branch div: 192 B but
