# sub_0802EB34 — deferred analysis

`sub_0802EB34` ([0x0802eb34, 0x0802ebf8), 196 bytes) configures the
clamp-envelope (envelope-A, `SlotClampEnvelope` at +0x1c) of a sound channel
to reach a target value over a fixed number of frames.

Signature: `void sub_0802EB34(u8 absolute, u16 target, u16 frames, s32 mode)`
  - `mode` selects the channel bank: 0..2 = inline channels embedded in
    SoundSystem (slot-view at `ss + mode*36 + 0x20` = `&ss->inlineChannels[mode]`);
    `mode == 3` is a no-op; `mode >= 4` = software-slot bank
    (`SOUND_SYSTEM_SW_SLOT_FOR_CHANNEL`, `swSlots + mode*64 - 256`).
  - `absolute` (u8): nonzero = ABSOLUTE; zero = RELATIVE.
  - `target` (u16, used signed): target / delta value.
  - `frames` (u16): frame count → the `__divsi3` divisor.

For both banks, treating the channel as a `SoundSlot` view (acc0 at +0,
env at +0x1c):
  - absolute: `env->limit = (s16)target - acc0`,
              `dividend  = (s16)target - ((s16)acc0 + (s16)env->acc)`.
  - relative: `env->limit += (s16)target`,  `dividend = (s16)target`.
All paths converge on one shared `env->step = __divsi3(dividend, frames)` tail;
`mode == 3` returns before the div.

The semantics are fully reverse-engineered and the best-effort C below is
believed behaviourally correct — the blocker is purely register coloring /
agbcc CSE-factoring.

### Two divergences vs the target, both proven allocator/CSE-internal

The target is GENUINELY LESS OPTIMAL than agbcc's natural output (196 vs the
124-byte clean build). Reproducing it = forcing agbcc to be wasteful in two
specific ways:

1. **r8 b-backup + wide prologue.** Target `push {r4,r5,r6,r7,lr}; mov r7,r8;
   push {r7}` (5 callee-saved). In branch A it CLOBBERS b's working reg r5 with
   the `ldrsh` acc index (`movs r5,#32`/`movs r5,#28`), so b is also held in r8
   for branch B (`mov r8,r5` at top; branch B `mov r1,r8`). Likewise a→r7+ip,
   c→r6+r2 (every param duplicated working+backup). agbcc-as-configured keeps
   each param in ONE register (no clobber → no backup → narrow prologue).
   ROOT CAUSE of the clobber: at the acc read in branch A the target has THREE
   pointers live — channelBase(r2), view(r3), env(r4) — so the lowest free reg
   for the `movs #idx` is r5 (b, already consumed into r0). My builds keep only
   two pointers, leaving r3 free for the index, so r5(b) survives.

2. **Eager-vs-lazy channelBase factoring.** Target keeps `mode*36` in r2 from
   the multiply and adds ss SEPARATELY for view (`ss + (mode*36+32)`) and
   channelBase (`adds r2,r0,r2` = ss+mode*36, ONLY inside the absolute branch).
   agbcc instead factors `ss + mode*36` out as a common base eagerly
   (`adds r2,r1,r0` at the top of branch A) and derives both view and env from
   it. This is a `cse.c`/`gcse.c` factoring decision — not steerable from C
   (the two addresses are provably equal, so agbcc CSEs them no matter where
   the source writes them).

### THE KEY NEW INSIGHT (escapes the prior cross-jump plateau)

Reading inline acc0 via a base of `ss + mode*36` at **offset 32** (`ldrsh
[channelBase, #32]`) instead of `*(u16*)view` (offset 0) PREVENTS agbcc from
cross-jumping (tail-merging) the inline-absolute and swslot-absolute blocks.
Cross-jumping is UNCONDITIONAL at `optimize>0` in agbcc (toplev.c:4097, no flag
to disable), so the only way to keep the two absolute blocks separate (as the
target does, ~half the 72-byte gap) is to make their instruction sequences
genuinely differ — which the offset-32 vs offset-0 acc read does. The clean v1
(`*(u16*)slot` both branches) merges them → byte_diff 122 but 124 B (too
small). The offset-32 form (best-effort C) keeps them separate → correct 152 B
shape. This is the structural advance over rounds 8-15.

### Why pure C can't close it (the contradiction)

The target needs, simultaneously: (a) b held in r5 in branch A but CLOBBERED
there (→ r8 backup), and (b) env in r4, mode in r3, channelBase factored
lazily. (a) requires b to have two homes (r5 working + r8 backup) — a single
`asm("r5")` pin gives it ONE home and kills the clobber; dual-locals give it
TWO distinct values and over-spill (r8+r9, 200 B). No single C shape expresses
"same value, two register homes, clobbered between." And (b)'s lazy factoring
is a CSE decision agbcc makes opposite to the target on provably-equal
addresses. The corpus confirms the `mov r8, rN`+wide-prologue idiom IS
reproducible elsewhere (pret librfu, metroidret mzm audio) — so it is NOT a
true wall — but no source shape on THIS function carries the exact pressure.

## Best-effort C (byte_diff 144, diff_count 74, size 152 — round 13)

```c
extern int __divsi3(int num, int den);

void sub_0802EB34(u8 absolute, u16 target, u16 frames, s32 mode)
{
    register u16 b asm("r5") = target;
    register u16 c asm("r6") = frames;
    SoundSystem *ss;
    SoundSlot *slot;
    SlotClampEnvelope *env;
    s32 dividend;

    if (mode <= 2) {
        u8 *channelBase;
        ss = gpSoundSystem;
        channelBase = (u8 *)ss + mode * SOUND_INLINE_CHANNEL_STRIDE;
        slot = (SoundSlot *)(channelBase + SOUND_INLINE_CHANNEL_BASE_OFFSET);
        env = SOUND_SLOT_ENVELOPE_A(slot);
        if (absolute) {
            env->limit = (s16)b - *(u16 *)(channelBase + SOUND_INLINE_CHANNEL_BASE_OFFSET);
            dividend = (s16)b - ((s16) * (s16 *)(channelBase + SOUND_INLINE_CHANNEL_BASE_OFFSET) +
                                 (s16) * (s16 *)((u8 *)slot + SOUND_SLOT_ENVELOPE_A_OFFSET));
        } else {
            env->limit += (s16)b;
            dividend = (s16)b;
        }
    } else {
        if (mode == 3)
            return;
        ss = gpSoundSystem;
        slot = SOUND_SYSTEM_SW_SLOT_FOR_CHANNEL(ss, mode);
        env = SOUND_SLOT_ENVELOPE_A(slot);
        if (absolute) {
            env->limit = (s16)b - *(u16 *)slot;
            dividend = (s16)b - ((s16) * (s16 *)slot +
                                 (s16) * (s16 *)((u8 *)slot + SOUND_SLOT_ENVELOPE_A_OFFSET));
        } else {
            env->limit += (s16)b;
            dividend = (s16)b;
        }
    }

    env->step = __divsi3(dividend, c);
}
```
