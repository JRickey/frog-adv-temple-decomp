# sub_0801F684 — deferred (byte_diff 9, diff_count 4)

Save-slot list renderer. Loops `i = 0..3` over `gSaveData.header.slotMask`
bits; for each populated slot draws the slot name + two counters + a
percentage, for each empty slot blits a placeholder sprite. Builds an
OAM-style attribute word on the stack and passes `&attr` to the sprite
helpers. Highlights the slot whose index equals `gIwram_3480._unk14`.

Range [0x0801f684, 0x0801f8bc), 568 bytes. Callees (all peeled):
sub_080196EC, sub_0801BE7C, sub_0801CF18, sub_0801C2B4, sub_0801B188,
sub_080184DC.

## Drift

both register-allocation / instruction-scheduling — NOT structure:

1. `+0x168` — the percentage `(u8)(sub_0801B188(...) * 100 >> 4)`:
   - target: `lsls r0,#24; lsrs r1,r0,#24` (the `(u8)n` truncation lands
     in **r1**), `movs r0,#100`, `muls r0,r1`  (100 in r0)
   - built:  `lsrs r0,r0,#24` (n stays in **r0**), `movs r1,#100`,
     `muls r0,r1`  (100 in r1)
   agbcc reuses the call-return register (r0) as the multiply accumulator;
   the baserom moves n to r1 to free r0 for the constant. Pure coloring.

2. `+0x1da/+0x1e0` — empty-slot branch, the `add r4, sp, #16` that
   materialises `&attr` for the byte-1 store + both call args:
   - target: `mov r1,sl; lsls r0,r1,#2; adds r0,#4` (value) THEN
     `add r4,sp,#16` THEN `strb r0,[r4,#1]`
   - built:  `add r4,sp,#16` (emitted ~2 instrs early by the asm anchor),
     then the value, then the store
   Net-zero size, pure scheduling of one instruction.

### Levers that WORKED (landed in the best-effort C, byte_diff 340 -> 9):
- `i = 0;` as an explicit statement BEFORE `attrp = &attr;` (the for-init
  emitted before attrp) — fixed the i/attrp init order.
- loop index `i` kept in `sl` WITHOUT a pin by deriving `y = i*4+4` (so it
  shares the `i*4` subexpr with the attr byte `i*4+3`); a plain or sl-pinned
  `i` made it WORSE.
- `vu16 fill;` (volatile) — the DMA fill local; collapsed the `&fill`
  recompute / value-vs-address store-operand ordering. Cast the DMA src as
  `(const void *)&fill` to keep -Werror green.
- `if (pct != 100) CF18 else C2B4` (NOT `== 100`) — matches the baserom's
  physical block order (`beq` to the later C2B4 body).
- empty branch: byte-0 via `attrp` ([sp+24]), byte-1 + BOTH calls via a
  held `u8 *ap = &attr` anchored with `asm("":"+r"(ap))` (the calls reuse
  r4=&attr; the populated branch uses attrp).
- empty branch table lookup: `u32 table = 0x08308ef4; asm("":"+r"(table));`
  before `((const u32*)table)[gIwram_34B0._data]` — orders the table-base
  load before the gIwram deref (sub_0801B374 idiom).
- in-loop first attr mask via a `u32 mask = 0xffffff00;` local (loads the
  const before attr — matches; without it agbcc loaded attr first).
- attr-byte: `register u32 m asm("r2");` for the byte temp + compute it
  between the two masks (`attr=(attr&mask)|3; m=(u8)(i*4+3)<<8;
  attr=(attr&0xffff00ff)|m;`) — pins attr accumulator to r1, byte to r2.

### Levers that did NOT work for the residual two:
- compiler swap OLD_AGBCC <-> AGBCC (both give 9).
- supported CFLAGS: -fno-strength-reduce, -fno-gcse, -fno-expensive-opt,
  -fno-thread-jumps, -fno-defer-pop, -fno-function-cse, -fno-caller-saves,
  -fno-cse-{follow-jumps,skip-blocks}, -fforce-addr — all 9 or worse.
  -O1/-fno-peephole/-fno-rerun-cse/-fno-rerun-loop-opt = much worse.
  (`-fno-schedule-insns` is REJECTED by old_agbcc; scheduling is already off.)
- `n*100` vs `100*n` vs `t=100;t*=n` vs `(u8)`/`(s32)`/`int`/`u16` n vs
  inlining the call — agbcc always keeps the call result as the r0
  accumulator. Pinning n to r1 / hundred to r0 forces moves (much worse).
- for #2 the truncation reg is decided by local-alloc qty preference

- for #3 the `add r4` position is fixed by where the asm anchor sits:

  folds to sp+17 + recompute (worse). A `b1`/`v` temp for the byte value
  breaks the i*4 share with the populated `y` (grows to 576).
