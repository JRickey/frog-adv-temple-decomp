# Deferred Analysis: sub_08006A0C

**Function**: sub_08006A0C (0x08006a0c, 104 bytes in ROM)  
**TU**: src/game/sub_08006948.c  
**Compiler**: OLD_AGBCC at -O2, plus `-fno-strength-reduce`

## Summary

A double-cmp pattern function (boolean materialization + fresh ldrh after alias-unsafe store).
The baserom was compiled by a version of old_agbcc with more conservative alias analysis
than the one in our toolchain. Two structural features can't be reproduced:

1. **Boolean materialization** (`cmp r0,#0; beq; movs r0,#1; b; movs r0,#0; cmp r0,#0; beq`)
   — old_agbcc at -O2 (our toolchain) merges the `flag = (expr); if (flag)` pattern into a
   single branch. `-fno-strength-reduce`, `-fno-gcse`, `asm("")` barriers, and ternary forms
   all fail to prevent the merge.

2. **Fresh ldrh after alias store** — `strh r5, [r4, #18]` (storing to _field_12 = key) should
   invalidate the cache of `r1 = [r4, #16]` (_field_10). The baserom old_agbcc does this;
   our old_agbcc keeps r1 cached (it knows offset 16 ≠ offset 18, so it doesn't invalidate).

## Drift

Best byte_diff: 73 (out of 92 baserom bytes compared; function is 104 bytes total in ROM).  
Expected: 100 bytes code+alignment (before pool word).  
Built best: 92 bytes code+alignment (12 bytes shorter).

The 12-byte gap comes from:
- Missing boolean materialization: +10 bytes (5 extra instructions: beq/movs/b/movs/cmp)
- Missing fresh ldrh in key==16 branch: +2 bytes (1 extra instruction)

## Levers tried

- `u16 field = p->_field_10; flag = field & 8` — gives correct `movs r0, #8; ldrh r1` order ✓
- `v = 9; p->_field_10 &= -v` — gives `movs r0, #9; negs r0, r0` (no pool literal) ✓

- `(field & 8) != 0` — same, triggers strength-reduction ✗

- `asm volatile("" : "=r"(field) : "0"(field))` — triggers bit-isolation form ✗
- `-O1` — gives materialization but uses r1 (not r0) for bool, different encoding ✗
- `-fgcse` enabled — no effect ✗
- `register u8 flag asm("r0")` pin — no effect ✗

## Root cause

The game's old_agbcc version has more conservative memory alias analysis:
after `strh r5, [r4, #18]`, it invalidates ALL cached loads through r4 regardless of
offset. Our old_agbcc's alias analysis is offset-aware: store to [r4+18] doesn't
invalidate [r4+16]. This is why the baserom gets the fresh ldrh and we don't.

The boolean materialization is a separate issue: our old_agbcc at -O2 always folds
`flag = (expr); if (flag)` into a single test. The original compiler apparently didn't.

u8 sub_08006A0C(struct StructA0C *p, u16 key)

        p->_field_14 = gGameStuff._unk00;

## Opus attempt (round 3) — narrowed to ONE CSE artifact, root-caused in agbcc source

Re-derived from scratch (did not extend the prior near-match). **Closed the function to
a single 2-instruction difference** that is a compiler-version CSE artifact, not a
C-structure problem. Verified the root cause by reading the agbcc source.

### What got SOLVED (vs the prior 73-byte_diff base)

The prior note's two blockers BOTH have a working lever now:

1. **Boolean materialization keeping mask 8 (no bit-isolation).**
   The trick is an `int val = field & 8;` *intermediate* feeding a ternary
   `int flag = val ? 1 : 0;`. The separate `val` blocks `fold`'s single-bit isolation
   (`(field>>3)&1`); writing `(field & 8) ? 1 : 0` or `(field & 8) != 0` directly always
   bit-isolates because `fold` sees a single-bit `?:`. With the `val` intermediate the
   materialization stays `movs r0,#8; ldrh r1; ands r0,r1; cmp r0,#0; ...; movs r0,#1`.

2. **Fresh `ldrh` after `strh r5,[r4,#18]` + `movs #9; negs` clear mask.**
   Solved at **-O1** (not -O2) PLUS an `asm volatile("" : "+r"(flag));` barrier right
   after the materialization. The barrier makes agbcc forget that `flag==1` inside the
   `if`, so (a) the clear mask is recomputed as `movs r0,#9; negs r0,r0` instead of being
   constant-folded from the live flag (`subs r0,#0xa`), and (b) `p->_field_10` is reloaded
   freshly (`ldrh r1,[r4,#16]`) in the key==16 clear branch. -O2 folds the materialization
   away entirely; -O1 keeps it. **This needs its own TU** (`src/game/sub_08006a0c.c` with
   `CFLAGS += -O1`) because the -O2 siblings in `sub_08006948.c` — especially the 64-bit
   shift `sub_0800696C` — regress at -O1 (verified: sub_0800696C → byte_diff 66 at -O1).

### The ONE remaining diff (the whole 76-byte_diff is this + branch-offset shift)

The built body is **byte-identical to baserom except a missing `movs r0,#0; b` pair** in
the false arm of the materialization:

```
baserom:                         built (-O1 + barrier):
  cmp  r0,#0                       cmp  r0,#0
  beq  .Lfalse  (-> movs #0)       beq  .Lcont   (-> skip)
  movs r0,#1                       movs r0,#1
  b    .Lcont                      .Lcont:
.Lfalse: movs r0,#0    <-- MISSING cmp  r0,#0
.Lcont:  cmp  r0,#0                beq  ...
  beq  ...
```

Everything after offset 0x16 matches **byte-for-byte** (strh/movs#9/negs/ldrh/ands/strh,
the timer branch, the OR-set branch, the epilogue). The 76 byte_diff is entirely the
4-byte (2-insn) shift cascading into every relative branch offset.

### ROOT CAUSE (read from agbcc source — not a guess)

The generic COND_EXPR expansion (`expr.c` ~line 7718, the final `else`) DOES emit both
arms: `jumpifnot op0; store 1; jump op1; op0: store 0; op1:` — i.e. an explicit
`movs r0,#0`. But agbcc's CSE then **deletes** that `movs r0,#0`: `cse.c:7844` calls
`record_jump_equiv(insn, 0)` *unconditionally* for every conditional `JUMP_INSN`, which
records that on the fall-through-to-op0 (branch-taken) path the compared register == 0.
CSE then sees `movs r0,#0` writing a value `r0` already provably holds, and removes it.
This fires precisely **because the ternary target `flag` coalesces into the same r0 that
holds `val = field & 8`** (the `cmp` operand).

`record_jump_equiv(insn,0)` is **not gated by any `-f` flag** (`-fno-cse-follow-jumps`,
`-fno-cse-skip-blocks`, `-fno-rerun-cse-after-loop`, `-fno-gcse`, `-fno-thread-jumps` all
verified ineffective — the `taken=0` recording is hardwired). So with our agbcc there are
only two reachable shapes:
  - **coalesced** (val & flag share r0) → the `movs #0` is CSE-deleted (built short form);
  - **un-coalesced** (force flag to a different reg, e.g. keep `val` live) → agbcc switches
    to the store_flag idiom `movs r1,#0; cmp r0,#0; beq; movs r1,#1` in r1 — ALSO not the
    baserom `cond-set-1 / b / set-0` branch-over.
The baserom keeps `movs r0,#0` despite val & flag both being r0, which means its older
agbcc's `record_jump_equiv` / coalescing simply did not perform this elimination. That is
a **toolchain-version difference**, the same conclusion the original note reached about the
alias analysis — both point at a more conservative older agbcc.

### Why this is DEFER, not NAKED, and not a pure-C match

- The closest build relies on `asm volatile("" : "+r"(flag))`, which is inline asm → by the
  workflow's definition it would be status="naked"/non-pure even if it matched. It does NOT
  match (off by the one CSE-deleted insn), so shipping it is pointless.
- The function is `ATTEMPT_MATCH` (no structural impossibility) and the corpus says game
  logic matches ~always, so NAKED would be a false "done". The blocker is a specific agbcc
  CSE/coalescing version difference, isolated to one instruction.

### Best-effort C (the new, much closer base — byte-identical except one CSE-deleted insn)

Built in its own TU `src/game/sub_08006a0c.c` with `CC = old_agbcc` and `CFLAGS += -O1`.
NOTE: uses an `asm volatile` barrier, so this is NOT a pure-C match even when it matches.

```c
#include "macros.h"
#include "types.h"
#include "game.h"

extern u32 sub_08000900(void);

struct StructA0C {
    u8 _pad00[16];
    u16 _field_10;
    u16 _field_12;
    u32 _field_14;
};

u8 sub_08006A0C(struct StructA0C *p, u16 key)
{
    int field = p->_field_10;
    int val = field & 8;
    int flag = val ? 1 : 0;
    int v;

    asm volatile("" : "+r"(flag));
    if (flag) {
        if (key == 16) {
            p->_field_12 = key;
            v = 9;
            p->_field_10 &= -v;   /* &= ~8 (clear bit 3) */
            return 1;
        }
        if (sub_08000900() - p->_field_14 > 30) {  /* 30-frame timeout */
            v = 9;
            p->_field_10 &= -v;
            return 0;
        }
    }
    if (key == 16) {
        p->_field_10 |= 8;
        p->_field_14 = gGameStuff._unk00;   /* save frame counter */
    }
    return 0;
}
```
