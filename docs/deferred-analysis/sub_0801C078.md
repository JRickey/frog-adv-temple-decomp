# sub_0801C078 — deferred analysis (round 16, Opus escalation)

## What the function is

A pipe(`|`)-terminated ASCII **text -> BG-tilemap renderer** (credits / menu /
save-dialog text). For each character it writes one or two 16-bit tilemap
entries into a BG screenblock chosen by param `sb` (0..3 ->
0x0600E000 / 0x0600E800 / 0x0600F000 / 0x0600F800, screenblocks 28..31).

Font layout (added to base tile id `sp8`, OR'd with palette field `palBits`):
  - `A`-`Z` -> sp8 + (c-'A')               (0..25)
  - `a`-`z` -> sp8 + (c-'a') + 26          (26..51)
  - `1`-`9` -> sp8 + (c-'1') + 0x3A        ; `0` -> sp8 + 9 + 0x3A
  - `' '`   -> 0 (blank tile)
  - `*`     -> two tiles: palBits+0x24 at row+1, palBits+0x09 at row+2
  - `?`     -> 0xE0D6
  - `~`     -> 0xE0EA + palBits
  - `\n`    -> newline (col=0, row++)
  - `|`     -> terminate
  - `[ddd]` -> 3-digit decimal escape (parsed by sub_0801CEC0). n = ddd - 0xC0;
              if n<=63, copy two halfwords from sCreditsTilemapEng (u16 stride 3:
              table[n*3+1] at addr, table[n*3+2] at addr+0x40). i += 4.

Address = base + colBase*2 + col*2 + ((row*2 + rowBase) << 6) [+ 0x40].
`palBits = (pal4 << 28) >> 16` = `(pal4 & 0xF) << 12`.

## BREAKTHROUGH this round — `-fno-caller-saves` spills `i` to memory (the prior agent missed this)

The single most important finding: **the baserom keeps `i` MEMORY-resident**
(`[sp,#12]`, reloaded into a scratch reg per use) — it never lives in a register.
The prior 344 base kept `i` in r3 (register-resident, spilled only around the BL).
That single difference cascades into ALL the per-case scratch-register picks.

`-fno-caller-saves` (per-TU CFLAGS) forces agbcc to NOT allocate `i` to a
caller-saved reg + save/restore around the call; instead `i` becomes a pure memory
pseudo, EXACTLY like the baserom. With it:
  - `i`-init -> `movs r3,#0; str r3,[sp,#12]`  (r3, matches baserom)
  - body str+i load -> `ldr r1,[sp,#0]; ldr r3,[sp,#12]; adds r2,r1,r3`  (r1/r3/r2 — byte-identical to baserom 0x1c0f6-fc)
  - r4 is then reserved-ish; 7 of the 8 address-formula cases get the CORRECT
    value/address register grouping (val=r0/addr=r1 for A-Z/a-z/*, val=r1/addr=r0
    for space/?/~).

Combined with `for (i = 0, base = (u16 *)(colBase * 2 + (u32)base); i < count; i++)`
(comma-init — see below) this reaches byte_diff 364 / diff_count 125, down from 344
documented but with a MUCH closer structure (the 344 had i-in-r3, wrong).

## The TWO remaining residuals (both isolated; next agent: attack THESE, not the rest)

### Residual 1 — `base += colBase*2` preheader placement (a ~2-instr cascade)
Baserom: guard FIRST, then base+= in the preheader:
```
movs r3,#0; str r3,[sp,#12]; ldr r0,[sp,#4]; cmp r3,r0; bcc .pre; b .exit
.pre: lsls r0,r2,#1; adds r6,r0,r6          <- base += colBase*2 (AFTER the guard)
.body: ldr r1,[sp,#0]; ldr r3,[sp,#12]; adds r2,r1,r3; ...
```
Ours (the 364 base): base+= is emitted BETWEEN `str i` and the guard (BEFORE it):
```
movs r3,#0; str r3,[sp,#12]; lsls r0,r2,#1; adds r6,r0,r6; ldr r0,[sp,#4]; cmp r3,r0; ...
```
The base+= operand order IS correct now (`adds r6,r0,r6`, via writing
`(u16 *)(colBase * 2 + (u32)base)` invariant-first). Only its POSITION (before vs
after the guard) differs. agbcc's loop optimizer places the one-time pre-loop
invariant BEFORE the entry guard; the baserom places it in the gcc loop PREHEADER
(after the guard). This resisted EVERY source phrasing tried (see "tried" below).
gcc creates the preheader block in `loop_optimize`; the loop-roll that produces the
top guard is `expand_end_loop`'s "meissner/loop test" rotation (stmt.c ~line 2023),
gated only by `optimize` (no -f flag). The original C apparently triggered preheader
insertion of the base+= that ours does not.

### Residual 2 — digit case value/address register tie (r0 vs r1)
Baserom digit (`1`-`9`,`0`) computes ADDRESS in r0, VALUE (`sp8 + (t+0x3A)`) in r1,
and CROSS-JUMP-MERGES its store tail with the `~` case (`b 0x1c264`: `add r1,sl;
strh r1,[r0]`). Ours computes ADDRESS in r1, VALUE in r0, and merges with the A-Z
tail instead. Root cause: the row-copy temp — baserom `mov r1,r9` (-> addr in r0),
ours `mov r0,r9` (-> addr in r1). This is a local-allocator scratch tie. It is also
linked to a reassociation: baserom keeps `(t + 0x3A)` adjacent (`adds r1,r2,#0;
adds r1,#0x3a; ldr r2,[sp,#8]; adds r1,r2,r1`), ours folds `(sp8 + 0x3A)` instead
(`ldr r0,[sp,#8]; adds r0,#0x3a; adds r0,r2,r0`). Every reassociation phrasing tried
keeps the value in r0.

NOTE: baking 0x3A into t (`t = c-'1' + 0x3A; store sp8 + t + palBits`) DROPS byte_diff
to **262** but is structurally WRONG (changes t's masking + the const) — a different,
lower-byte_diff local minimum, NOT closer to a real match. Do not pursue it.

## Best-effort C (byte_diff 364 / diff_count 125; per-TU `CFLAGS += -fno-caller-saves`)

```c
#include "types.h"

extern s32 sub_0801CEC0(const char *str, u8 len);

extern const u8 sCreditsTilemapEng[];

void sub_0801C078(const u8 *str, u8 count, u8 colBase, u8 rowBase, u16 sp8, s32 pal4, u8 sb)
{
    register s32 col asm("r8");
    register s32 row asm("r9");
    register u16 palBits asm("sl");
    register u16 *base asm("r6");
    u8 i;
    register int c asm("r5");
    u16 t;
    u16 *dst;
    register s32 n asm("r4");
    int d;

    palBits = (pal4 << 28) >> 16; /* (pal4 & 0xF) << 12 */
    col = 0;
    row = 0;

    switch (sb) { /* no default: base left unset for sb > 3 (matches baserom) */
    case 0:
        base = (u16 *)0x0600E000;
        break;
    case 1:
        base = (u16 *)0x0600E800;
        break;
    case 2:
        base = (u16 *)0x0600F000;
        break;
    case 3:
        base = (u16 *)0x0600F800;
        break;
    }

    /* comma-init: gets i-init into r3 and the str+i body load into r1/r3/r2,
       both byte-identical to the baserom. The base+= still lands BEFORE the
       guard (residual 1); writing colBase*2 first fixes the adds operand order. */
    for (i = 0, base = (u16 *)(colBase * 2 + (u32)base); i < count; i++) {
        c = str[i];
        if ((u8)(c - '0') <= 9) {
            if (c == '0') {
                t = 9;
            } else {
                t = c - '1';
            }
            *(u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2) + 0x40) = sp8 + t + 0x3A + palBits;
        } else if ((d = c - 'A'), (u8)d <= 25) {
            t = d;
            *(u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2) + 0x40) = sp8 + t + palBits;
        } else if ((d = c - 'a'), (u8)d <= 25) {
            t = d;
            *(u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2) + 0x40) = sp8 + t + 26 + palBits;
        } else if (c == '[' && str[i + 4] == ']') {
            n = sub_0801CEC0((const char *)(str + i + 1), 3) - 0xC0;
            if ((u32)n <= 63) {
                dst = (u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2));
                *dst = *(u16 *)(sCreditsTilemapEng + (n * 3 + 1) * 2);
                dst = (u16 *)((u8 *)dst + 0x40);
                *dst = *(u16 *)(sCreditsTilemapEng + (n * 3 + 2) * 2);
            }
            i += 4;
        } else if (c == ' ') {
            *(u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2) + 0x40) = 0;
        } else if (c == '*') {
            dst = (u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2) + 0x40);
            *dst = palBits + 0x24;
            dst = (u16 *)((u8 *)dst + 0x40);
            *dst = palBits + 0x24 - 0x1B;
        } else if (c == '?') {
            *(u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2) + 0x40) = 0xE0D6;
        } else if (c == '~') {
            *(u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2) + 0x40) = 0xE0EA + palBits;
        } else if (c == '|') {
            break;
        }

        col = (u8)(col + 1);
        if (c == '\n') {
            col = 0;
            row = (u8)(row + 1);
        }
    }
}
```
