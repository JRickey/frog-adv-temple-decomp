# sub_0801C078 — deferred analysis (round 36)

## What the function is

A pipe(`|`)-terminated ASCII **text → BG-tilemap renderer** (credits / menu /
save-dialog text). For each character it writes one or two 16-bit tilemap
entries into a BG screenblock chosen by param `sb` (0..3 →
0x0600E000 / 0x0600E800 / 0x0600F000 / 0x0600F800, screenblocks 28..31).

Font layout in the tile space (added to base tile id `sp8`, OR'd with the
palette field `palBits`):
  - `A`–`Z` → sp8 + (c-'A')               (0..25)
  - `a`–`z` → sp8 + (c-'a') + 26          (26..51)
  - `1`–`9` → sp8 + (c-'1') + 0x3A        ; `0` → sp8 + 9 + 0x3A   (digits at 58..)
  - `' '`   → 0 (blank tile)
  - `*`     → two tiles: palBits+0x24 at row+1, palBits+0x09 at row+2
  - `?`     → 0xE0D6
  - `~`     → 0xE0EA + palBits
  - `\n`    → newline: col=0, row++
  - `|`     → terminate
  - `[ddd]` → 3-digit decimal escape (parsed by sub_0801CEC0). n = ddd - 0xC0;
              if n<=63, copy two halfwords from the credits tilemap asset
              `sCreditsTilemapEng` (u16 stride 3: table[n*3+1] at addr,
              table[n*3+2] at addr+0x40 = next row). Advances i by 4 (+1 loop).

Address of a glyph cell (byte address):
  addr = base + colBase*2 + col*2 + ((row*2 + rowBase) << 6) [+ 0x40]
where `<<6` = *64 bytes = one tilemap row (32 entries), and +0x40 = +1 row.
Letters/digits/`?`/`~`/space draw at base-row+1; `[` draws its 2 tiles at
base-row and +1; `*` at +1 and +2. The glyph grid is 2 tiles per char column.

`palBits = (pal4 << 28) >> 16` = `(pal4 & 0xF) << 12` (the BG palette-bank field).

Helper sub_0801CEC0 (already peeled): parses `len` decimal digits of a string
into an int (`Σ digit_k * 10^(len-1-k)`), returns -1 on a non-digit.

## Drift (what the next agent must crack — try a DIFFERENT lever)

Two linked register-coloring artifacts account for ~all of the 344 bytes:

1. **Scratch-register off-by-one in the address-copy `mov`s, repeated in all 8
   cases.** Baserom uses `mov r2,r9 / mov r3,r8` (row/col copy temps = r2,r3);
   our build uses `mov r1,r9 / mov r2,r8` (temps = r1,r2). The shift *result*
   regs (r0,r1) match; only the intermediate `mov` temp is off by one. agbcc
   picks the lowest free scratch; in the baserom r1 is unavailable at that point
   (str/`i` pressure), in ours it's free. This is the dominant diff (each case
   contributes ~2 mismatched halfwords).

2. **Preheader placement of `base += colBase*2`.** Baserom emits it in the loop
   *preheader* (between the entry test `i<count` and the body, executed once via
   gcc loop-header-copy): `... cmp r3,r0; bcc .body_guard; b .end; .guard:
   lsls r0,r2,#1; adds r6,r0,r6; .body: ...`. Our `for` loop emits it *before*
   the entry test. Also operand order `adds r6,r0,r6` (baserom) vs `adds r6,r6,r0`
   (ours). ~3-instr cascade that shifts a few nearby branch targets.

`i` IS spilled to `[sp,#0xc]` in our build (the `n asm("r4")` pin below forced
the `sub sp,#16` 4-slot frame) — the only residual on `i` is that its =0 init
value lingers in r3 for the first iteration instead of being worked purely from
the stack, which feeds artifact (1).

## Levers already tried (do NOT repeat — pick something else)

- register pins that DID help and are in the best-effort C:
  `col asm("r8")`, `row asm("r9")`, `palBits asm("sl")`, `base asm("r6")`,
  `c asm("r5")` (int, NOT u8 — u8 added redundant `(c<<24)>>24` masks),
  and crucially **`n asm("r4")`** — pinning the `[ddd]` parse result to r4 is
  what forces `i` to spill and gives the correct `sub sp,#16` frame
  (no-pin → `sub sp,#12`, i in a reg). c→r5 alone (no n-pin) → 449.
- `t`/`d` as `u16`/`int` and the `(d=c-'A'),(u8)d<=25` comma form: makes agbcc
  reuse the range-check subtraction for the tile offset (matches baserom),
  preserves c in r5. (Comma-in-condition is a style violation; if this lands,
  split it and re-verify — splitting MAY perturb codegen.)
- formula written **rowpart-first**: `*(u16*)(((row*2+rowBase)<<6) +
  (u32)((u8*)base + col*2) + 0x40) = val;` — matches the baserom's
  rowpart-then-(col2+base) grouping. col-first → 386. Inlining the store
  (no `dst` temp) for single-store cases dropped diff_count 221→183.
- `sb`-switch with NO default (base intentionally unset for sb>3) — matches.
- i type sweep: u8 best (344); s32/int/u32/u16 → 437 (signed/`blt` compares).
- per-TU CFLAGS sweep (all measured, none spill i naturally / fix the off-by-one):
  `-ffixed-r4` (spills i but DROPS r4 from prologue → wrong push), `-ffixed-r3`,
  `-fno-strength-reduce`, `-fno-gcse`, `-fno-rerun-cse-after-loop`,
  `-fno-cse-follow-jumps`, `-fno-schedule-insns`, `-fno-schedule-insns2`,
  `-fcaller-saves`/`-fno-caller-saves`, `-fno-expensive-optimizations`,
  `-fforce-mem`, `-O1`, `-frerun-loop-opt`.
- guarded do-while rewrite (`i=0; if(i<count){ base+=..; do{...}while(i<count);}`)
  to force the preheader: it DOES move base+= into the preheader, but gcc then
  lays the do-while increment/continue at the TOP and the body after, inverting
  the layout → regresses to 428. The plain `for` (344) keeps the correct
  body/increment layout but base+= stays pre-loop.

## Best-effort C

```c
#include "types.h"

extern s32 sub_0801CEC0(const u8 *str, u8 len);

extern const u8 sCreditsTilemapEng[];

void sub_0801C078(const u8 *str, u8 count, u8 colBase, u8 rowBase, u16 sp8, s32 pal4, u8 sb)
{
    register s32 col asm("r8");
    register s32 row asm("r9");
    register u16 palBits asm("sl");
    register u16 *base asm("r6");
    u8 i;
    register int c asm("r5");
    u16 t;
    u16 *dst;
    register s32 n asm("r4");
    int d;

    palBits = (pal4 << 28) >> 16; /* (pal4 & 0xF) << 12 */
    col = 0;
    row = 0;

    switch (sb) {            /* no default: base left unset for sb > 3 (matches baserom) */
    case 0:
        base = (u16 *)0x0600E000;
        break;
    case 1:
        base = (u16 *)0x0600E800;
        break;
    case 2:
        base = (u16 *)0x0600F000;
        break;
    case 3:
        base = (u16 *)0x0600F800;
        break;
    }

    base = (u16 *)((u8 *)base + colBase * 2);

    for (i = 0; i < count; i++) {
        c = str[i];
        if ((u8)(c - '0') <= 9) {
            if (c == '0') {
                t = 9;
            } else {
                t = c - '1';
            }
            *(u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2) + 0x40) = sp8 + t + 0x3A + palBits;
        } else if ((d = c - 'A'), (u8)d <= 25) {
            t = d;
            *(u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2) + 0x40) = sp8 + t + palBits;
        } else if ((d = c - 'a'), (u8)d <= 25) {
            t = d;
            *(u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2) + 0x40) = sp8 + t + 26 + palBits;
        } else if (c == '[' && str[i + 4] == ']') {
            n = sub_0801CEC0(str + i + 1, 3) - 0xC0;
            if ((u32)n <= 63) {
                dst = (u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2));
                *dst = *(u16 *)(sCreditsTilemapEng + (n * 3 + 1) * 2);
                dst = (u16 *)((u8 *)dst + 0x40);
                *dst = *(u16 *)(sCreditsTilemapEng + (n * 3 + 2) * 2);
            }
            i += 4;
        } else if (c == ' ') {
            *(u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2) + 0x40) = 0;
        } else if (c == '*') {
            dst = (u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2) + 0x40);
            *dst = palBits + 0x24;
            dst = (u16 *)((u8 *)dst + 0x40);
            *dst = palBits + 0x24 - 0x1B;
        } else if (c == '?') {
            *(u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2) + 0x40) = 0xE0D6;
        } else if (c == '~') {
            *(u16 *)(((row * 2 + rowBase) << 6) + (u32)((u8 *)base + col * 2) + 0x40) = 0xE0EA + palBits;
        } else if (c == '|') {
            break;
        }

        col = (u8)(col + 1);
        if (c == '\n') {
            col = 0;
            row = (u8)(row + 1);
        }
    }
}
```
