# Deferred analysis: sub_0800088C (HBlank raster scroll handler)

## Function summary

HBlank IRQ handler at 0x0800088C. Per scanline (while VCOUNT <= 0xe3 = 227):
- Looks up per-scanline BG0 scroll delta from byte table at 0x030053a0[scanline]
- Adds to base BG0 scroll from 0x03003550[0] → writes to REG_BG0HOFS (0x04000010)
- Looks up per-scanline BG1 scroll delta from byte table at 0x03003610[scanline]
- Adds to base BG1 scroll from 0x03003550[2] → writes to REG_BG1HOFS (0x04000014)
- Always writes REG_IF = 2 (acknowledge HBlank IRQ)

Classic per-line parallax raster effect.

## Drift

**Best byte_diff: 6 / diff_count: 6 instructions**

Compiler: `old_agbcc` (Makefile: `src/game/sub_08000820.s: CC = $(OLD_AGBCC_BIN)`)
Permuter best score: 30 (base 40), did NOT reach 0 in ~800 iterations.

All 6 diffs are the SAME issue: the pool constant for the table base addresses
(0x030053a0 and 0x03003610) are loaded into **r4** (built) vs **r0** (target).

Target sequence (first block):
```asm
ldr r0, [pc, #48]    @ r0 = 0x030053a0 (pool constant into r0!)
adds r0, r3, r0      @ r0 = scanline(r3) + table_base(r0)
ldrh r4, [r2, #0]    @ r4 = bgScrollBase[0]
ldrb r0, [r0, #0]    @ r0 = delta
adds r0, r4, r0      @ r0 = base + delta
strh r0, [r1, #0]
adds r1, #4
ldr r0, [pc, #36]    @ r0 = 0x03003610 (pool constant into r0!)
adds r0, r3, r0      @ r0 = scanline + table_base
ldrh r2, [r2, #4]    @ r2 = bgScrollBase[2] (overwrites bgScrollBase ptr)
ldrb r0, [r0, #0]    @ r0 = delta
adds r0, r2, r0      @ r0 = base + delta (result in r0!)
strh r0, [r1, #0]
```

Built sequence (first block):
```asm
ldr r4, [pc, #48]    @ r4 = 0x030053a0 (pool constant into r4!)
adds r0, r3, r4      @ r0 = scanline(r3) + table_base(r4)
ldrh r4, [r2, #0]    @ r4 = bgScrollBase[0] (reuses r4)
ldrb r0, [r0, #0]    @ r0 = delta
adds r0, r4, r0      @ r0 = base + delta
strh r0, [r1, #0]
adds r1, #4
ldr r4, [pc, #36]    @ r4 = 0x03003610 (pool constant into r4!)
adds r0, r3, r4      @ r0 = scanline + table_base
ldrh r2, [r2, #4]    @ r2 = bgScrollBase[2]
ldrb r0, [r0, #0]    @ r0 = delta
adds r2, r2, r0      @ r2 = base + delta (result in r2, not r0!)
strh r2, [r1, #0]    @ uses r2
```

## Root cause

With `old_agbcc` and register pins `r1=dst, r2=bgScrollBase, r0=tbl (pinned result)`:
- r3 naturally gets `scanline` (the lsrs shift destination)
- r4 is the first available callee-saved register for pool constants

old_agbcc prefers r4 for pool constant loads when r0 is pinned as the "result"
register. For `ldr r0, pool; adds r0, r3, r0` (target), old_agbcc would need
to load the pool constant DIRECTLY into r0 (not via intermediate r4).

The issue: with `register u8 *tbl asm("r0")`, old_agbcc treats r0 as
reserved for the RESULT of the `tbl` assignment, but uses r4 as the
INTERMEDIATE for the pool constant. The target's code loaded the pool
constant into r0 and then updated it in-place.

## Levers tried (exhausted)

- `register vu16 *dst asm("r1")` — YES, fixes dst in r1
- `register u16 *bgScrollBase asm("r2")` — YES, fixes bgScrollBase in r2
- `register u8 *tbl asm("r0")` — YES, scanline goes to r3, but table base still goes to r4
- `register u8 scanline asm("r3")` (alone or combined) — creates push {r4,r5,lr} (worse)
- linker symbols for 0x030053a0 and 0x03003610 — scanline reverts to r4 (worse)
- Regular `agbcc` instead of `old_agbcc` — 13 diffs (much worse)
- Index-first pointer cast `(u8*)(scanline + (s32)0x030053a0)` — no change
- Two-step assignment `tbl = (u8*)0x030053a0; tbl += scanline;` — no change
- Explicit `base0 = bgScrollBase[0]` intermediate — reverses ldrh/ldrb order
- `*tbl + bgScrollBase[2]` (right operand last) — changed last diff from `adds r2, r0, r2` to `adds r2, r2, r0` but result still in r2 (1 diff changed but not fixed)
- Permuter with old_agbcc compile script: ~800 iters, best score 30 (base 40)

## Next lever to try

The fundamental issue: old_agbcc loads pool constants into r4 when r0 is reserved for the tbl pin result. To fix:

1. **Try WITHOUT any register pin on tbl** — just `register vu16 *dst asm("r1")` + `register u16 *bgScrollBase asm("r2")`, no r0 pin. This may put scanline in r3 naturally AND let old_agbcc use r0 for the pool constant. The risk: ldrh/ldrb order may be wrong.

2. **Try base0 intermediate with correct ordering** — explicit `base0 = bgScrollBase[0]` BEFORE `tbl = (u8*)0x030053a0 + scanline` (not after). This forces base0 to be loaded first, but may fix the ldrh/ldrb order.

3. **Two-file split** — sub_0800088C in its own .c file, try both agbcc and old_agbcc separately without `sub_08000820.c` affecting register coloring.

4. **Run longer permuter with seed from score-30 variant** — the score-30 variant from the permuter (no tbl pin but different structure) may be worth extending.

## Best-effort C

```c
/* HBlank IRQ handler — per-scanline parallax raster effect.
 * r1=dst, r2=bgScrollBase, r3=scanline (natural), r0=tbl (pinned). 
 * old_agbcc loads table constants into r4 instead of r0 — 6 byte drift. */
void sub_0800088C(void)
{
    u8 scanline;
    register vu16 *dst asm("r1");
    register u16 *bgScrollBase asm("r2");
    register u8 *tbl asm("r0");

    scanline = (u8)REG_VCOUNT;
    if (scanline > 0xe3) {
        REG_IF = IRQ_HBLANK;
        return;
    }
    dst = (vu16 *)0x04000010;
    bgScrollBase = (u16 *)0x03003550;
    tbl = (u8 *)0x030053a0 + scanline;
    *dst = bgScrollBase[0] + *tbl;
    dst += 2;
    tbl = (u8 *)0x03003610 + scanline;
    *dst = *tbl + bgScrollBase[2];
    REG_IF = IRQ_HBLANK;
}
```
