# sub_080135B8 deferred analysis

220-byte leaf, no `bl`. `classify_unmatchable.py` = `ATTEMPT_MATCH` (the
high-reg advisory is a false positive — there is no `bl`, so nothing crosses a
call). Do NOT ship NAKED. This IS matchable in pure C in principle; the wall is
a single sharp register-coloring coin-flip in agbcc global-alloc.

## What the function does (model is CORRECT and re-confirmed)

Per-frame scroll-axis updater. Two near-identical blocks over two IWRAM state
structs: X at `gIwram_6540` (pos @0x34, delta @0x2c) and Y at `gIwram_6480`
(pos @0x36, delta @0x2e). Each struct: `lastTick` u32 @0x04, `kind` u8 @0x09,
`interval` u8 @0x0b. `kind` semantics confirmed against `sub_0801377C` which
inits `gIwram_6540.field_9 = 0` (X) / `gIwram_6480.field_9 = 1` (Y):
  1 = Y_FORWARD, 2 = Y_BACKWARD, 3 = X_BACKWARD, 4 = X_FORWARD.
Gate per block: `if (kind && gGameStuff._unk00 - lastTick >= interval) { ... ;
lastTick = gGameStuff._unk00; }`. `gGameStuff` is the direct-address macro
`(*(GameStuff*)0x03005330)` — the pool loads `0x03005330` directly and derefs
(NOT a pointer-to-pointer like cvaos `gEwramData->`).

The "## Best-effort C" below compiles to **byte_diff 52 / diff_count 44**
(`compile_and_view_assembly.py`), size 220 — re-confirmed this pass. The single
carried `GameStuff *gs;` base pseudo is REQUIRED (direct `gGameStuff._unk00`
with no carried base → byte_diff 200; the baserom carries the *base* in r9 and
re-derefs `_unk00` at the lastTick store).

## The wall — ROOT CAUSE, found by instrumenting agbcc global.c (NEW)

The entire 52-byte diff is ONE register relabel that cascades:

| value            | baserom | our build |
|------------------|---------|-----------|
| maxX (u16 param) | **ip**  | **r9**    |
| gGameStuff base  | **r9**  | **ip**    |
| stepX/stepY/xKind shift down by one to compensate                |

Built instrumented `old_agbcc` (probes in `gcc/global.c`, NOT `gcc_arm/` —
`old_agbcc` is built from `gcc/` which uses `thumb.md`; `gcc_arm/` only builds
`agbcc_arm`/cc1, so a probe there never fires for thumb TUs). Traced
`reg_renumber` assignment, `regs_used_so_far`, `used1`, and the two-pass
`find_reg` scan. Findings:

- NO pseudo has any `hard_reg_preferences` / `copy_preferences` /
  `regs_someone_prefers` for r8/r9/r12 (all empty). So preference propagation
  is NOT the cause.
- The decider is the global-alloc **pass-0 "prefer an already-touched reg"**
  heuristic: `used_nopref = used1 | ~regs_used_so_far | someone`. In pass 0 a
  value can only land in a hard reg that is ALREADY in `regs_used_so_far`.
- In OUR build the prologue homes **maxX→r9 and maxY→r8** FIRST (these are the
  first high-reg touches). The single `gs` pseudo (nrefs=6, spans BOTH blocks)
  then CONFLICTS with both maxX(r9) and maxY(r8) → the only free high reg is
  r12 → `gs→ip`.
- In the BASEROM the prologue homes **maxX→ip, maxY→r8**, leaving r9 untouched;
  `gs` conflicts with ip+r8 and takes the free **r9**.
- WHY maxX→r9 in our build: maxX (allocno0) is first assigned **r7** (a low
  reg), then BUMPED by `retry_global_alloc` (r7 needed elsewhere) and
  re-assigned to **r9**. The baserom's maxX never takes r7 — it goes straight
  to ip. So the divergence originates in maxX's initial r7 grab + retry bounce,
  driven by low-reg pressure (stepX=r6, stepY=r7, xBase=r3, yBase=r4,
  xKind=r5).

So the fix the next agent must find: stop maxX from initially grabbing r7 and
bouncing to r9 (so r9 stays free and `gs` takes it, and maxX lands in ip). This
is a low-reg-pressure / allocation-order steer, NOT a control-flow or type bug.

## Levers tried this pass — ALL stuck at the 52 floor or worse

- `gs` split into per-block `gsx`/`gsy` (structurally MORE correct — baserom has
  two independent r9 ranges, one reloaded per block; the two `&gGameStuff` CSE
  to ONE pool literal, which is correct): still `gsx→ip`, byte_diff ~58/tool
  ~121. The conflict graph is right but `gsx` is processed first and still lands
  in r12 (r12 touched before r8/r9 at its turn under the split's order).
- `register GameStuff *gs asm("r9")`: byte_diff 59 — puts gs in r9 but ELIDES
  the load-to-r0-then-`mov r9,r0` (baserom loads to a temp, derefs, THEN homes
  to r9); pinning loads straight into r9. Wrong shape.
- `register u16 mx asm("ip")` + `my asm("r8")`: 158 (breaks param prologue).
- hoist single `gs` to top (carried across both blocks): 213 (forces one
  callee-saved range over the whole fn; baserom reloads per block).
- store `delta=0` via the `x`/`y` pointer instead of `gIwram_6540.delta=0`: 180
  (baserom loads the base fresh for the delta store, then `add r3,r0,#0` reuses
  it — the direct-store form is required).
- explicit `(u32)(... ) >= (u32)interval` gate cast: 52 (no change).
- CFLAGS: `-ffixed-r9` 60, `-ffixed-r8` 65, `-ffixed-ip`/`-ffixed-r12` 208
  (forces a 4th callee reg, size 224), `-ffixed-r10 -ffixed-r9` 58,
  `-fomit-frame-pointer` 58, `-fno-schedule-insns2` 58,
  `-fno-caller-saves`/`-fcaller-saves`/`-fno-cse-follow-jumps`/`-fno-defer-pop`
  all 58, `-fno-rerun-cse-after-loop` 70, `-fno-force-mem` 216. None reach 52→0.
- Compiler swap to newer `agbcc`: worse (size 224, byte_diff 183 — bad
  byte-param handling), confirmed again.
- decomp-permuter (corrected target via `make_permuter_target.py`, base score
  865, -j2 ~150 iters): plateaued at base (best 860 vs 865). The score
  landscape is flat noise — statement-reorder/scope mutations don't reach the
  allocation-order/retry-bounce decision. NOT a permuter-reachable tail.
- Corpus history (`corpus_asm_search.py --idiom highreg-spread`): the
  `mov rLO,r8; ldr [rLO]` base-in-callee-saved idiom IS pure-C-reachable
  (pret/pokeemerald librfu), but those are LONG-LIVED bases used many times so
  the allocator naturally homes them callee-saved. Our `gs` is used ~3× and the
  divergence is the retry bounce, not a missing idiom. cvaos uses `gEwramData->`
  (a real global POINTER) — does not transfer (our base is a direct cast).

## Best next step

Steer maxX off its initial r7 grab. Ideas NOT yet tried: (a) reduce live low-reg
pressure at the X-block so maxX stays where the baserom puts it — e.g. don't
carry `xKind` in a separate low reg (re-read `x->kind` instead of caching
`kind`), freeing r5; (b) instrument `retry_global_alloc` / the spill-cost in
`global.c` to see exactly which allocno bumps maxX out of r7 and why the baserom
doesn't bump it; (c) try the split-`gsx/gsy` form combined with re-reading
`x->kind`/`y->kind` to drop the `kind` cache. The instrumented-compiler recipe
(probe `gcc/global.c`, build only `old_agbcc`, run the
preproc|cpp-15|old_agbcc pipeline) is fast and is the right microscope here.

#include "macros.h"
#include "types.h"
#include "game.h"

enum ScrollAxisKind {
    SCROLL_AXIS_Y_FORWARD = 1,
    SCROLL_AXIS_Y_BACKWARD = 2,
    SCROLL_AXIS_X_BACKWARD = 3,
    SCROLL_AXIS_X_FORWARD = 4,
};

struct ScrollAxisX {
    u8 _pad00[4];
    u32 lastTick;
    u8 _pad08;
    u8 kind;
    u8 _pad0a;
    u8 interval;
    u8 _pad0c[0x20];
    s16 delta;
    u8 _pad2e[6];
    s16 pos;
};

struct ScrollAxisY {
    u8 _pad00[4];
    u32 lastTick;
    u8 _pad08;
    u8 kind;
    u8 _pad0a;
    u8 interval;
    u8 _pad0c[0x22];
    s16 delta;
    u8 _pad30[6];
    s16 pos;
};

extern struct ScrollAxisX gIwram_6540;
extern struct ScrollAxisY gIwram_6480;

void sub_080135B8(u16 maxX, u8 stepX, u16 maxY, u8 stepY)
{
    struct ScrollAxisX *x;
    struct ScrollAxisY *y;
    GameStuff *gs;
    u8 kind;

    gIwram_6540.delta = 0;
    gIwram_6480.delta = 0;

    x = &gIwram_6540;
    y = &gIwram_6480;

    kind = x->kind;
    if (kind != 0) {
        gs = &gGameStuff;
        if (gs->_unk00 - x->lastTick >= x->interval) {
            if (kind == SCROLL_AXIS_X_FORWARD) {
                if ((s32)x->pos <= (s32)(s16)maxX)
                    x->pos += stepX;
                x->delta = stepX;
            }
            if (x->kind == SCROLL_AXIS_X_BACKWARD) {
                if ((s32)x->pos >= (s32)(s16)maxX)
                    x->pos -= stepX;
                x->delta = -stepX;
            }
            x->lastTick = gs->_unk00;
        }
    }

    kind = y->kind;
    if (kind != 0) {
        gs = &gGameStuff;
        if (gs->_unk00 - y->lastTick >= y->interval) {
            if (kind == SCROLL_AXIS_Y_FORWARD) {
                if ((s32)y->pos <= (s32)(s16)maxY)
                    y->pos += stepY;
                y->delta = stepY;
            }
            if (y->kind == SCROLL_AXIS_Y_BACKWARD) {
                if ((s32)y->pos >= (s32)(s16)maxY)
                    y->pos -= stepY;
                y->delta = -stepY;
            }
            y->lastTick = gs->_unk00;
        }
    }
}
