## Root cause — REDUCED to a single reload decision (Opus round 6, re-confirmed)

The whole 44-insn cascade pivots on ONE thing: in the gate, does the deref
result (`now = gGameStuff._unk00`) reuse the base register (r0) or land in a
FRESH register (r1)?

- **Baserom** (deferred base-save):
  ```asm
  ldr  r0, [pc]      @ base addr -> r0
  ldr  r1, [r0]      @ now -> r1   (FRESH reg; base SURVIVES in r0)
  ldr  r2, [r3, #4]  @ lastTick -> r2   (uses r2 -> kind conflicts -> kind@r5)
  subs r1, r1, r2    @ elapsed
  mov  r9, r0        @ DEFERRED home-store (base was still live in r0)
  ldrb r0, [r3, #11] @ interval (r0 now free)
  cmp  r1, r0
  ```
- **old_agbcc** (eager base-save):
  ```asm
  ldr  r0, [pc]
  mov  ip, r0        @ EAGER home-store
  ldr  r0, [r0]      @ now REUSES r0 (base already saved to ip)
  ldr  r1, [r3, #4]  @ lastTick -> r1   (only r0,r1 used -> kind keeps r2)
  sub  r0, r0, r1
  ldrb r1, [r3, #11]
  cmp  r0, r1
  ```

Because baserom's gate uses r0,r1,**r2**, the `lastTick`@r2 hard-reg use
overlaps `kind`'s live range, so `kind` CONFLICTS with r2 and is pushed to r5.
That single change (kind: r2→r5) cascades: stepX r5→r6, stepY r6→r7,
maxX r7→ip, gGameStuff ip→r9, maxY stays r8. The prologue arg-register map and
the gate and both blocks all follow.

### Instrumented confirmation (private debug old_agbcc)

Built a private instrumented `old_agbcc` (fprintf at `gcc/global.c find_reg`'s
`reg_renumber[…] = best_reg` site). For the clean best-effort C:
```
ALLOC pseudo 45(kind)       -> r2   (target wants r5)  <- allocated FIRST, first-fit grabs r2
ALLOC pseudo 42(xAxis)      -> r3
ALLOC pseudo 43(yAxis)      -> r4
ALLOC pseudo 27(stepX)      -> r5   (target r6)
ALLOC pseudo 37(stepY)      -> r6   (target r7)
ALLOC pseudo 22(maxX)       -> r7→r9 (target ip)
ALLOC pseudo 44(gGameStuff) -> r12  (target r9)
ALLOC pseudo 32(maxY)       -> r8   (✓)
```
`kind` (pseudo 45) is allocated first (priority `floor_log2(6)*6/22 ≈ 0.545` >
xAxis `0.5` > yAxis `0.259`) and, since nothing is assigned yet, first-fit takes
the lowest free reg = r2. For kind to take r5, r2 must be in
`hard_reg_conflicts[kind]` at allocation — which only happens if a HARD-reg use
of r2 (the gate's `lastTick`@r2) overlaps kind's range. And the gate only uses
r2 when the base-save is deferred. So it is ALL downstream of the deferred save.

The dump'd RTL (`-dg` greg) shows the eager order is fixed at the position of
the original `gs = &gGameStuff` (`reg44 = const`) insn — reload realizes the
high-reg home-store THERE (`ip = r0`), then the later deref insn reuses r0
(`r0 = mem[r0]`). The deref result reusing r0 forces the eager save. This is a
`gcc/reload1.c` emit-ordering / equiv-materialization decision, NOT
allocation-time and NOT source-shape — no C reshaping moves it.

## Ruled out (Opus round 6, in addition to prior rounds; all measured)

byte_diff via the per-symbol harness (counts mismatched bytes over the 0xdc range;
~6 higher than `compile_and_view_assembly.py`'s 52 due to trailing-pool counting —
use it only for RELATIVE comparison):
- Clean re-derived C from scratch: 58 (harness) / 52 (compile_and_view). The floor.
- Explicit `u32 now` local (used at gate + tail re-read): 52 (compile_and_view) but
  PERTURBS the `(s16)` cast to `lsl;asr` — net worse. Do NOT add a `now` local.
- Explicit `now` cached for the tail (single read, no re-read): 163 — baserom
  RE-READS at the tail (`mov r1,r9; ldr r0,[r1]; str r0,[r3,#4]`), caching breaks it.
- Init writes THROUGH the xAxis/yAxis pointers (`xAxis->deltaX = 0`): 183 — the
  separate `gIwram_6540.deltaX = 0; xAxis = &gIwram_6540` form is BETTER (yields the
  pool-load + `adds r3,r0` copy pattern baserom uses).
- Direct `gGameStuff._unk00` (no `gs` local): 206/212-len — pool reloaded; `gs`
  local is required (base must span gate→tail in one pseudo).
- `asm volatile("" : "+r"(gs))` fence after `gs = &gGameStuff`: 149, len 220, but
  forces base into r6 (callee-saved, NO mov) — wrong direction; injects `.code 16`;
  is inline asm (would force status=naked). Rejected.
- PIN x-kind@r5 + y-kind@r3 (baserom's exact kind regs): aligns the prologue
  PERFECTLY through offset 0x14 (maxX@ip, stepX@r6, stepY@r7 all correct!) but then
  (a) maxY→r9 not r8, (b) xAxis→r2 not r3 (kind@r5 freed r5 so xAxis first-fits r2),
  so the `adds r3,r0` copy is dropped → 1 fewer insn → length 216 (4 short) →
  170 inflated. The pin fixes the prologue but NOT the eager save, and the freed-r5
  reshuffles xAxis/maxY. Adding xAxis@r3 + yAxis@r4 pins over-constrains (y-block
  re-reads yAxis@r4 for the ==2 check while y-kind@r3 wants the slot): 211 / len 208.
- PIN `gs asm("r9")` (target home): 65, len 220 — base→r9 (correct home!) but STILL
  EAGER (`mov r9,r0; ldr r0,[r0]`), and maxX→r8/maxY→ip swap. Proves the home reg is
  NOT the lever; the eager-vs-deferred ordering is independent of the home choice.
- `register` (no asm) on all params: 58 — no effect.
- decomp-permuter, CORRECT target (`make_permuter_target.py`, base score 865, not the
  old $t/$d-bugged ~100×): -j4, ~10000 iters / ~3.5 min, `--stop-on-zero --better-only`.
  Best 840 (from 865). Stuck at the coloring minimum — permuter mutates structure, not
  reload ordering, so it CANNOT reach this. (Confirms prior round's 840.)

```c
#include "macros.h"
#include "types.h"
#include "game.h"

struct IwramAt6540 {
    u8 _pad00[4];
    u32 lastTick;
    u8 _pad08;
    u8 kind;
    u8 _pad0a;
    u8 interval;
    u8 _pad0c[0x20];
    s16 deltaX;
    u8 _pad2e[6];
    s16 posX;
};

struct IwramAt6480 {
    u8 _pad00[4];
    u32 lastTick;
    u8 _pad08;
    u8 kind;
    u8 _pad0a;
    u8 interval;
    u8 _pad0c[0x22];
    s16 deltaY;
    u8 _pad30[6];
    s16 posY;
};

extern struct IwramAt6540 gIwram_6540;
extern struct IwramAt6480 gIwram_6480;

void sub_080135B8(u16 maxX, u8 stepX, u16 maxY, u8 stepY)
{
    struct IwramAt6540 *xAxis;
    struct IwramAt6480 *yAxis;
    GameStuff *gs;
    u8 kind;

    gIwram_6540.deltaX = 0;
    gIwram_6480.deltaY = 0;

    xAxis = &gIwram_6540;
    yAxis = &gIwram_6480;

    kind = xAxis->kind;
    if (kind != 0) {
        gs = &gGameStuff;
        if (gs->_unk00 - xAxis->lastTick >= xAxis->interval) {
            if (kind == 4) {
                if ((s32)xAxis->posX <= (s32)(s16)maxX)
                    xAxis->posX += stepX;
                xAxis->deltaX = stepX;
            }
            if (xAxis->kind == 3) {
                if ((s32)xAxis->posX >= (s32)(s16)maxX)
                    xAxis->posX -= stepX;
                xAxis->deltaX = -stepX;
            }
            xAxis->lastTick = gs->_unk00;
        }
    }

    kind = yAxis->kind;
    if (kind != 0) {
        gs = &gGameStuff;
        if (gs->_unk00 - yAxis->lastTick >= yAxis->interval) {
            if (kind == 1) {
                if ((s32)yAxis->posY <= (s32)(s16)maxY)
                    yAxis->posY += stepY;
                yAxis->deltaY = stepY;
            }
            if (yAxis->kind == 2) {
                if ((s32)yAxis->posY >= (s32)(s16)maxY)
                    yAxis->posY -= stepY;
                yAxis->deltaY = -stepY;
            }
            yAxis->lastTick = gs->_unk00;
        }
    }
}
```
