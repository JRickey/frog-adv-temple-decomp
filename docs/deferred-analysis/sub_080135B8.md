# sub_080135B8 — deferred analysis

220-byte leaf function (no callees), `asm/disasm_0x080135b8.s` →
`src/engine/sub_080135b8.c` at 0x080135B8.

## What it does (fully understood)

Per-axis auto-scroll/pan tick. Two independent scroll controllers live in
IWRAM, same struct type (`struct ScrollAxis` below):

- block A = gIwram_6540 (horizontal axis: kinds 4/3, fields posX@0x34 / deltaX@0x2c)
- block B = gIwram_6480 (vertical axis:   kinds 1/2, fields posY@0x36 / deltaY@0x2e)

Struct offsets (cross-checked against the project's own `struct IwramAt6480`
in src/engine/sub_08013694.c, which names +0x04 field_4 / +0x0b field_b):
- +0x04 u32 lastTick   — snapshot of gGameStuff._unk00 at last step
- +0x09 u8  kind       — direction/mode (A: 3 or 4; B: 1 or 2; 0 = idle)
- +0x0b u8  interval   — minimum gGameStuff._unk00 delta between steps
- +0x2c s16 deltaX / +0x2e s16 deltaY — per-step velocity reported each frame
- +0x34 s16 posX / +0x36 s16 posY     — accumulated position

Each frame the reported delta is cleared (unconditionally, at the top); a
block only steps once `gGameStuff._unk00 - lastTick >= interval`. kind 4 grows
posX toward maxX (arg0) by stepX (arg1) when posX <= maxX; kind 3 unwinds it
when posX >= maxX; kind 1/2 do the same on posY with maxY(arg2)/stepY(arg3).
Signature: `void sub_080135B8(u16 maxX, u8 stepX, u16 maxY, u8 stepY)`,
confirmed by the only caller sub_08013694 which calls `sub_080135B8(0,0,0xa0,1)`.
The signed clamp compiles via `lsl #16` on BOTH operands (compare
`(s32)(s16)posX` vs `(s32)(s16)maxX`). The `(s32)(s16)maxX` MUST stay inline at
each compare (re-`lsls` per compare); hoisting/caching the shift WORSENS.
gGameStuff._unk00 is re-read for the final lastTick store (NOT cached in a local
`now`; caching it jumps the diff to 116). The `gs = &gGameStuff` base pointer IS
a required local (without it agbcc reloads the pool at block end → 198).

## Round 3 (Opus, this run) — STRUCTURAL ADVANCE: base improved 59 → 43

Two source-shape changes lowered the clean (NO-PIN) base from the Round-2
plateau (byte_diff 180, diff_count 59) to **byte_diff 51, diff_count 43**:

1. **Do the `deltaX=0 / deltaY=0` stores via the linker symbols DIRECTLY
   (`gIwram_6540.deltaX = 0; gIwram_6480.deltaY = 0;`), THEN assign the `a`/`b`
   pointers AFTER the stores.** In Round 2 the stores went through `a`/`b`
   (`a->deltaX=0`), which made agbcc materialise A's base in its home reg up
   front and emit a different pointer-copy shape. Storing via the symbol first
   reproduces the target's `ldr r0,=A; strh; ldrb kind,[r0,#9]; adds r3,r0,#0`
   scratch-then-copy-to-home pattern. This alone took 59 → 44.
2. **Assign `b = &gIwram_6480;` BEFORE `a = &gIwram_6540;`** (B-pointer first).
   Took 44 → 43. (Equivalent: swap the two zero-stores; same result.)

The clean, NO-PIN, NO-FLAG version below is the new best base. RESUME FROM IT.

## Drift (diff_count 43 — 25 ARGUMENT_MISMATCH renames + 5 REPLACEMENT reorders)

EVERY remaining diff is downstream of ONE atomic register-allocation decision.
If it flips, all 30 diff lines resolve to 0 simultaneously. The register file,
value-by-value (verified via the agbcc `-dg` global-alloc dump):

| value (pseudo) | target | clean build (43) |
|----------------|--------|------------------|
| maxX  (22)     | ip     | r9               |  ← the SWAP
| gGameStuff(44) | r9     | ip               |  ← the SWAP
| kind  (45)     | r5     | r2 (scratch)     |
| stepX (27)     | r6     | r5               |  ← shifted (kind freed r5)
| stepY (37)     | r7     | r6               |  ← shifted
| maxY  (32)     | r8     | r8 (matches)     |
| A ptr (42)     | r3     | r3 (matches)     |
| B ptr (43)     | r4     | r4 (matches)     |

The 5 REPLACEMENT lines are pure REORDER artifacts of the same decision:
- target reads `ldrb r5,[r0,#9]` (kind via the scratch base r0) BEFORE the
  `adds r3,r0; adds r4,r2` home copies; the build copies to home first then
  reads kind via r3.
- target keeps gs-base in r0 through the subtraction (`ldr r1,[r0]; ldr
  r2,[r3,#4]; subs r1,r1,r2; mov r9,r0` — DEFERRED `mov r9`); the build caches
  gs to ip immediately (`mov ip,r0; ldr r0,[r0]`) so the subtract is r0,r1.

## ROOT CAUSE — fully traced to global.c find_reg (the agbcc CYGNUS 3-pass)

It ALL reduces to: does maxX's home reg become **ip** (target) or **r9**
(build)? Once maxX→ip, gs→r9 (next free), gs's `mov r9` defers (callee-saved
home keeps the value in the r0 scratch through the subtract → r2 is clobbered →
kind can't stay in r2 → kind→r5 → stepX→r6, stepY→r7). The whole 43-diff is
this one cascade.

agbcc gives maxX r9 (not ip) because of the CYGNUS "live range" 3-pass in
`global.c:find_reg` (symlinked at tools/agbcc-src/gcc_arm/global.c, ~line 1311):
- pass 1 uses `used_nopref` = used1 | ~regs_used_so_far | regs_someone_prefers,
  i.e. it ONLY allows registers that are ALREADY used-so-far AND not preferred
  by another pseudo. maxX (pseudo 22, allocated 10th of 12; order
  `45 42 43 63 91 124 152 27 37 22 44 32`) finds r9 already used-so-far and
  non-conflicting in pass 1, so it takes r9 and never reaches pass 2 (where
  first-fit in REG_ALLOC_ORDER `{3,2,1,0,12(ip),14,...,9,...}` would give it ip
  at position 4 before r9 at position 12). gs (44, lowest priority, allocated
  11th, ll=288) then takes the still-fresh ip in pass 2.
- To FLIP: make ip be `regs_used_so_far` (used by an earlier-allocated pseudo
  that dies before maxX's range) OR make maxX fail pass 1 entirely (no
  reusable non-conflicting reg) so it falls to pass-2 first-fit = ip. Neither
  was achievable by any pure-C shape, pin, or flag tried.

## Levers tried in Round 3 (ALL ≥ the clean 43 base, i.e. none better)

- `register GameStuff *gs asm("r9")` on the 43 base → 59/73. Forces `mov r9,r0`
  EARLY (right after the pool load) instead of deferred → wrong. Pins cannot
  reproduce the DEFERRED copy.
- `register u16 mx asm("ip") = maxX` (+ mx in the compares) → 160/66. The
  `= maxX` introduces an extra `mov r0,ip` copy for each `lsls`, and the
  cascade (kind→r5, stepX→r6) does NOT follow. Pinning maxX≠placing maxX's home.
- Two block-scoped `gs` locals → 121/106 (the shared gs pseudo is REQUIRED for
  the r9 reuse). Direct `gGameStuff._unk00` (no gs local) → 198/92.
- Reading kind via `gIwram_6540.kind` instead of `a->kind` → 211/74. Reading
  kind BEFORE the a/b assignment → 114/53. `a->kind`-after-assign is correct.
- Caching `s32 mx = (s32)(s16)maxX` (block-local or interval-block-local) →
  202/104. Caching `u32 now = gs->_unk00` → 141/116. The target re-does both.
- goto/early-skip flattened control flow → identical 51/43 (agbcc normalises).

## Why deferred (NOT NAKED)

Clean straight-line leaf game logic — NO computed jump, NO libgcc-helper
prologue, NO high-reg-across-bl. classify_unmatchable would return ATTEMPT_MATCH
(it could not run here only because .function_addresses.json isn't in the
worktree). The corpus says such functions match ~always; the right C shape that
nudges agbcc's pass-1 register reuse into maxX→ip EXISTS. Shipping NAKED would be
a false "done" and a permanent regression. The wall is the single atomic
maxX↔gGameStuff ip/r9 decision in global.c find_reg's CYGNUS 3-pass.

## Next ideas (try a lever DIFFERENT from every one above)

- The decisive move is to make **ip be `regs_used_so_far` when maxX (pseudo 22)
  is allocated** (so pass 1 can reuse it for maxX), OR make maxX fail pass 1 (no
  used-so-far non-conflicting reg → pass-2 first-fit = ip). Find a C shape that
  causes an EARLIER-allocated short-lived pseudo to occupy ip and die before
  maxX's live range — e.g. route one of the early posX/posY HI temps, or a
  throwaway value, through ip. (The temps are pseudos 63/91/124/152, allocated
  4th–7th, ll≈2.) This is the untried frontier.
- Instrumenting agbcc (fprintf in find_reg at the pass-1 vs pass-2 branch for
  pseudo 22) would pin the exact gate — but the private rebuild needs the FULL
  gcc source tree (../libiberty etc.); the symlinked tools/agbcc-src alone
  can't relink old_agbcc. A future agent with the gcc bootstrap deps could trace
  it directly. DO NOT rebuild the shared tools/agbcc{,-src}.
- Raising maxX's allocno priority so it's allocated EARLIER (before r9 becomes
  used-so-far) might let it grab fresh ip in pass 2: priority = refs²·log/
  live_length. maxX is refs=3, ll=45. An extra maxX reference that FOLDS AWAY
  (without changing the emitted compares) would bump refs without changing code
  — but every attempted extra-read either folded the compare's `lsls` away
  (worse) or didn't change refs. Needs a fold-resistant extra read.

## Best-effort C (clean, NO pins, NO flags — diff_count 43, the best base; resume from THIS)

```c
#include "game.h"
#include "macros.h"
#include "types.h"

struct ScrollAxis {
    u8 _pad00[4];
    u32 lastTick; /* +0x04 */
    u8 _pad08;
    u8 kind; /* +0x09 */
    u8 _pad0a;
    u8 interval; /* +0x0b */
    u8 _pad0c[0x20];
    s16 deltaX; /* +0x2c */
    s16 deltaY; /* +0x2e */
    u8 _pad30[4];
    s16 posX; /* +0x34 */
    s16 posY; /* +0x36 */
};

extern struct ScrollAxis gIwram_6540;
extern struct ScrollAxis gIwram_6480;

void sub_080135B8(u16 maxX, u8 stepX, u16 maxY, u8 stepY)
{
    struct ScrollAxis *a;
    struct ScrollAxis *b;
    GameStuff *gs;
    u8 kind;

    /* stores via the linker symbols FIRST, pointers assigned AFTER — reproduces
       the target's scratch-then-copy-to-home base-pointer shape (59 -> 44). */
    gIwram_6540.deltaX = 0;
    gIwram_6480.deltaY = 0;

    /* B-pointer assigned before A (44 -> 43). */
    b = &gIwram_6480;
    a = &gIwram_6540;

    kind = a->kind;
    if (kind != 0) {
        gs = &gGameStuff;
        if (gs->_unk00 - a->lastTick >= a->interval) {
            if (kind == 4) {
                if ((s32)(s16)a->posX <= (s32)(s16)maxX)
                    a->posX = a->posX + stepX;
                a->deltaX = stepX;
            }
            if (a->kind == 3) {
                if ((s32)(s16)a->posX >= (s32)(s16)maxX)
                    a->posX = a->posX - stepX;
                a->deltaX = -stepX;
            }
            a->lastTick = gs->_unk00;
        }
    }

    kind = b->kind;
    if (kind != 0) {
        gs = &gGameStuff;
        if (gs->_unk00 - b->lastTick >= b->interval) {
            if (kind == 1) {
                if ((s32)(s16)b->posY <= (s32)(s16)maxY)
                    b->posY = b->posY + stepY;
                b->deltaY = stepY;
            }
            if (b->kind == 2) {
                if ((s32)(s16)b->posY >= (s32)(s16)maxY)
                    b->posY = b->posY - stepY;
                b->deltaY = -stepY;
            }
            b->lastTick = gs->_unk00;
        }
    }
}
```
