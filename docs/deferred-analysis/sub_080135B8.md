## What the function does (model is CORRECT and re-confirmed twice)

Per-frame scroll-axis updater. Two near-identical blocks over two IWRAM state
structs: X at `gIwram_6540` (pos @0x34, delta @0x2c) and Y at `gIwram_6480`
(pos @0x36, delta @0x2e). Each struct: `lastTick` u32 @0x04, `kind` u8 @0x09,
`interval` u8 @0x0b. `kind` semantics confirmed against `sub_0801377C` which
inits `gIwram_6540.field_9 = 0` (X) / `gIwram_6480.field_9 = 1` (Y):
  1 = Y_FORWARD, 2 = Y_BACKWARD, 3 = X_BACKWARD, 4 = X_FORWARD.
Gate per block: `if (kind && gGameStuff._unk00 - lastTick >= interval) { ... ;
lastTick = gGameStuff._unk00; }`. `gGameStuff` is the direct-address macro
`(*(GameStuff*)0x03005330)` (pool loads `0x03005330` directly and derefs).
Both blocks cache `kind` for `==0` and the FORWARD compare, then RE-READS
`x->kind`/`y->kind` for the BACKWARD compare (the re-read IS required — caching
all three → 207). The `(s32)pos <= (s32)(s16)maxX` double-shift compare is
required (the `s16 mx` simplification → 69). The carried `GameStuff *gs;` base
re-deref of `_unk00` at the lastTick store is required (macro-direct, no carried
base → 200). The `## Best-effort C` below is byte_diff **52** / diff_count 44.

## THE WALL — ROOT CAUSE, now derived from the global.c PRIORITY FORMULA (NEW, definitive)

Built a private instrumented `old_agbcc` (probe at `find_reg`'s `best_reg`
assignment in `gcc/global.c`, env-gated `AGBCC_DUMP_ALLOC`) and traced every
allocno. The 52-byte diff is ONE swap: **maxX↔gs (r9↔ip)**.

agbcc `allocno_compare` priority = `floor_log2(refs)*refs/live_length * 10000`
(higher = allocated FIRST). For this function:
  - maxX  pseudo: refs=3, len=45  → pri = 1*3/45  *1e4 = **666**
  - gs    pseudo: refs=6, len=288 → pri = 2*6/288 *1e4 = **416**
  - maxY  pseudo: refs=3, len=81  → pri = 1*3/81  *1e4 = 370
`find_reg` scans hard regs LOWEST-FIRST (no REG_ALLOC_ORDER in thumb.h, so
0,1,2,…). With NO `bl`, `used1 = fixed_reg_set` (caller-saved r0-r3 + ip are all
candidates).

OUR build: maxX (pri 666) is allocated FIRST. Low regs r3,r4 (xBase,yBase),
r5,r6 (stepX,stepY) are taken; r7 is the lowest free → maxX grabs **r7**, then
`retry_global_alloc` (reload needs r7) bumps it to **r9** (lowest free HIGH reg,
since r8=maxY). gs (pri 416) is allocated LATER → only **ip** (r12) is left.
Result: maxX→r9, gs→ip, maxY→r8 (maxY is ALREADY CORRECT in the default build).

BASEROM: maxX→**ip**, gs→**r9**, maxY→r8. For that, gs must be allocated BEFORE
maxX so gs takes r9 (lowest free high) and maxX, finding r9 taken, takes ip.

THE FLIP CONDITION (provably source-unreachable): gs.pri > maxX.pri requires
`2*6/len_gs > 1*3/45` → `len_gs < 180`. gs spans BOTH blocks (reloaded per
block but the pool literal CSEs to one `.word`, so the pseudo is live across the
inter-block gap) → len = 288, immovable. The gsx/gsy split makes two pseudos of
len 72 each, but each is refs=3 → pri `1*3/72*1e4 = 416`, STILL < maxX's 666 →
maxX is processed first and still grabs r9. No source SHAPE shrinks gs's range
below maxX's nor split-refs above maxX's priority. This is the local minimum.

## `-fno-rerun-cse-after-loop` — the near-miss that swaps the bug to the Y side (NEW)

This flag (already an established lever for `sub_0801a894`) makes maxX→ip and
the stepX→r6/stepY→r7 cascade PERFECT — it stops maxX's r7-grab+bounce. BUT it
symmetrically breaks the Y side: now **gs→r8, maxY→r9** (baserom: gs→r9,
maxY→r8). byte_diff **64** (worse total, but structurally one clean swap). With
the flag the allocno order is gs (pri 416) then maxY (pri 370): gs grabs r8,
maxY r9. Flipping needs maxY.pri > gs.pri → same unreachable len/refs wall as
above (maxY len 81 must drop < ~72; it's a param homed in the prologue).

So: default = maxX wrong (52). flag = maxY/gs wrong (64). The bug is conserved —
no flag fixes BOTH high-reg pairs at once.

## Levers tried — ALL stuck (this pass + prior)

This pass (re-derived from scratch, NOT tweaking the prior near-match):
- `-fno-rerun-cse-after-loop`: 64 (fixes X cascade, breaks Y — see above).
- `-fno-rerun-cse-after-loop` + {`-fno-gcse` (gs→ip), `-ffixed-r8` (maxY→sl
  spill), `-ffixed-r9` (maxX→sl), `-fno-cse-follow-jumps`, `-fno-schedule-insns`,
  …}: all 56-121, each trades one wrong reg for a worse one or an sl spill.
- `register u16 mx asm("ip")` / `my asm("r8")` raw pins (with the s16 compare
  kept): 160/56 — the explicit `mov` copy disrupts the prologue param-home
  scheduling (baserom homes inside the lsls/lsrs sequence; the pin homes after).
- `register u8 kind asm("r5")`: 195 — forces ONE persistent kind range over both
  blocks; baserom has TWO independent kind ranges (X-kind=r5, Y-kind=r3).
- cache `now=gs->_unk00` / `tick=x->lastTick` temps: 52 (CSE'd away).
- cache raw maxX/maxY in u16 locals (keep s16 cast): 79.
- s16 mx/my (simplify compare): 69. re-read kind (no cache): 181. cache all 3
  kind checks: 207. macro-direct gs (no carried base): 200. gsx/gsy split: 121
  (+flag: 121). reverse gate compare operand order: 53. swap delta-store order:
  55. kind as s32: 52. block reorder: just swaps which param gets ip.
- WHY kind lands in r2 (ours) vs r5 (baserom): kind is live across the gate; in
  the baserom the gate uses r2 as scratch for `x->lastTick` (because gs→r9
  forces an extra temp), so kind conflicts with r2 → r5. In ours the gate uses
  r0/r1 only, so r2 is free for kind. This is DOWNSTREAM of the gs→r9 coloring —
  circular, cannot be steered from source.

Prior pass (re-confirmed): `gs` split, `gs asm("r9")` (59, elides the
load-temp), hoist gs to top (213), `-ffixed-r9` 60/`-ffixed-r8` 65, newer agbcc

(a) accept this as a true local minimum (the formula proves no source shape

    formula, re-probe with the instrumented compiler:
    `cp -RL tools/agbcc-src/gcc /tmp/sb && make -C /tmp/sb old` (the probe is

    pipe `preproc|cpp-15 -P|/tmp/sb/old_agbcc -O2 -mthumb-interwork -fhex-asm`
    and read the ASSIGN trace. The target order is: maxY→r8, then gs→r9, then
    maxX→ip — i.e. gs must beat maxX on priority. Watch for any flag that drops

#include "macros.h"
#include "types.h"
#include "game.h"

enum ScrollAxisKind {
    SCROLL_AXIS_Y_FORWARD = 1,
    SCROLL_AXIS_Y_BACKWARD = 2,
    SCROLL_AXIS_X_BACKWARD = 3,
    SCROLL_AXIS_X_FORWARD = 4,
};

struct ScrollAxisX {
    u8 _pad00[4];
    u32 lastTick;
    u8 _pad08;
    u8 kind;
    u8 _pad0a;
    u8 interval;
    u8 _pad0c[0x20];
    s16 delta;
    u8 _pad2e[6];
    s16 pos;
};

struct ScrollAxisY {
    u8 _pad00[4];
    u32 lastTick;
    u8 _pad08;
    u8 kind;
    u8 _pad0a;
    u8 interval;
    u8 _pad0c[0x22];
    s16 delta;
    u8 _pad30[6];
    s16 pos;
};

extern struct ScrollAxisX gIwram_6540;
extern struct ScrollAxisY gIwram_6480;

void sub_080135B8(u16 maxX, u8 stepX, u16 maxY, u8 stepY)
{
    struct ScrollAxisX *x;
    struct ScrollAxisY *y;
    GameStuff *gs;
    u8 kind;

    gIwram_6540.delta = 0;
    gIwram_6480.delta = 0;

    x = &gIwram_6540;
    y = &gIwram_6480;

    kind = x->kind;
    if (kind != 0) {
        gs = &gGameStuff;
        if (gs->_unk00 - x->lastTick >= x->interval) {
            if (kind == SCROLL_AXIS_X_FORWARD) {
                if ((s32)x->pos <= (s32)(s16)maxX)
                    x->pos += stepX;
                x->delta = stepX;
            }
            if (x->kind == SCROLL_AXIS_X_BACKWARD) {
                if ((s32)x->pos >= (s32)(s16)maxX)
                    x->pos -= stepX;
                x->delta = -stepX;
            }
            x->lastTick = gs->_unk00;
        }
    }

    kind = y->kind;
    if (kind != 0) {
        gs = &gGameStuff;
        if (gs->_unk00 - y->lastTick >= y->interval) {
            if (kind == SCROLL_AXIS_Y_FORWARD) {
                if ((s32)y->pos <= (s32)(s16)maxY)
                    y->pos += stepY;
                y->delta = stepY;
            }
            if (y->kind == SCROLL_AXIS_Y_BACKWARD) {
                if ((s32)y->pos >= (s32)(s16)maxY)
                    y->pos -= stepY;
                y->delta = -stepY;
            }
            y->lastTick = gs->_unk00;
        }
    }
}
