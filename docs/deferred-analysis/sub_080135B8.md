# sub_080135B8 — deferred analysis

220-byte leaf function (no callees), `asm/disasm_0x080135b8.s` →
`src/engine/sub_080135b8.c` at 0x080135B8.

## What it does (fully understood)

Per-axis auto-scroll/pan tick. Two independent scroll controllers live in
IWRAM, same struct type (`struct ScrollAxis` below):

- block A = gIwram_6540 (horizontal axis: kinds 4/3, fields posX@0x34 / deltaX@0x2c)
- block B = gIwram_6480 (vertical axis:   kinds 1/2, fields posY@0x36 / deltaY@0x2e)

Struct offsets (cross-checked against the project's own `struct IwramAt6480`
in src/engine/sub_08013694.c, which names +0x04 field_4 / +0x0b field_b):
- +0x04 u32 lastTick   — snapshot of gGameStuff._unk00 at last step
- +0x09 u8  kind       — direction/mode (A: 3 or 4; B: 1 or 2; 0 = idle)
- +0x0b u8  interval   — minimum gGameStuff._unk00 delta between steps
- +0x2c s16 deltaX / +0x2e s16 deltaY — per-step velocity reported each frame
- +0x34 s16 posX / +0x36 s16 posY     — accumulated position

Each frame the reported delta is cleared (unconditionally, at the top); a
block only steps once `gGameStuff._unk00 - lastTick >= interval`. kind 4 grows
posX toward maxX (arg0) by stepX (arg1) when posX <= maxX; kind 3 unwinds it
when posX >= maxX; kind 1/2 do the same on posY with maxY(arg2)/stepY(arg3).
Signature: `void sub_080135B8(u16 maxX, u8 stepX, u16 maxY, u8 stepY)`,
confirmed by the only caller sub_08013694 which calls `sub_080135B8(0,0,0xa0,1)`.
The signed clamp compiles via `lsl #16` on BOTH operands (compare
`(s32)(s16)posX` vs `(s32)(s16)maxX` — shift both by 16, compare the shifted
values, the `asr` back is elided). The `(s32)(s16)maxX` MUST stay inline at
each compare (hoisting it to an `s32 mx` local pre-computes the shift once →
WORSE, diff jumps to 199).

## Drift (diff_count 59, all register renames — structure is 100% correct)

The clean build's register file vs the target's, value-by-value:

| value      | target | clean build |
|------------|--------|-------------|
| maxX       | ip     | r9          |
| gGameStuff | r9     | ip          |  ← a clean SWAP with maxX
| kind       | r5     | r2 (scratch)|
| stepX      | r6     | r5          |  ← shifted down because kind freed r5
| stepY      | r7     | r6          |
| maxY       | r8     | r8 (matches)|
| a (ptr)    | r3     | r3 (matches)|
| b (ptr)    | r4     | r4 (matches)|

Three coupled differences, ALL pure register-allocation (the *instructions* and
control flow match exactly — every diff line is an ARGUMENT_MISMATCH rename):

1. **maxX↔gGameStuff ip/r9 swap.** REG_ALLOC_ORDER is
   `{3,2,1,0,12,14,4,5,6,7,8,10,9,...}` (ip=pos4, r9=pos12). For a LEAF the
   allocator can use caller-saved freely; whichever of {maxX, gGameStuff-base}
   has higher allocno priority (`refs²·log/live_length`, SHORTER life = higher)
   grabs ip first. gGameStuff-base has a shorter live range (block-A-local) so
   it wins ip in the clean build, pushing maxX to r9. The target is reversed.
2. **kind → r5 (callee-saved) vs r2 (scratch).** In the target kind is given a
   pushed callee-saved reg r5; the clean build keeps it in r2 (cheaper, no
   push) because r2 survives the block-A scratch usage in a leaf. kind in r5 is
   what FREES r5 and shifts stepX→r6, stepY→r7 in the target.
3. **Pointer-copy `adds r3,r0,#0; adds r4,r2,#0`.** Target materialises &A/&B
   into scratch r0/r2 (the bases for the deltaX/deltaY=0 stores + the first
   kind read), then copies to the home regs r3/r4. The clean build loads the
   pool literals straight into r3/r4. This is a reload-move, not live-range
   split (flag_live_range defaults 0 in this agbcc).

## Levers tried in Round 2 (ALL strictly worse than the clean 59 base)

- `register u8 kind asm("r5")` ALONE → 123/192. Frees r5 but reshuffles the
  whole file (a→r2, b→r3, maxX→r7); prologue still keeps push {r6,r7}.
- `kind r5 + my r8 + gs r9` (Round-1's "winning" combo) → 75 (matches Round-1).
- Full pin set `mx ip + sx r6 + my r8 + sy r7 + kind r5` → 236 bytes, 200 diff.
  Pinning sx→r6 / sy→r7 POISONS the prologue (drops r9 from the push, only
  `mov r7,r8; push {r7}`).
- `kind r5 + sx r6 + sy r7` → 224 bytes, 203 (same prologue poison).
- `gs asm("r9")` alone → 86. Forces the cache but too early.
- `mx asm("ip")` alone → 182/67. The `lsls r0,#16` floats up, `lsrs r0,#16`
  sinks; stepX still r5 (kind not freed).
- Accessing `gGameStuff._unk00` directly (no `gs` local) → 92/198. WITHOUT the
  `gs` local agbcc reloads the pool at block end instead of caching to r9 — the
  `gs = &gGameStuff` local IS required for the r9 cache.
- Two separate kind variables (kindA/kindB) → 76. Single shared `kind` (one
  variable reassigned) is better.
- `s32 mx = (s32)(s16)maxX;` block-local → 199 (pre-computes the shift).
- newer agbcc (AGBCC_BIN) → only pushes r8 (one high reg), further off.

## Why deferred (not NAKED)

This is clean game logic; the corpus says such functions match ~always, so the
right C structure that nudges agbcc's allocno priorities into the target file
EXISTS — neither Round 1 (Sonnet) nor Round 2 (Opus) found it, and the permuter
provably can't reach it by mutation. Shipping NAKED would be a false "done".
The wall is a single coupled allocation decision (kind's reg class + the
maxX/gGameStuff ip↔r9 swap) that agbcc derives from `refs²·log/live_length`
allocno priorities (global.c `allocno_compare`, find_reg walking REG_ALLOC_ORDER
in a leaf where r0-r3/ip/lr are all freely usable).

## Next ideas (NOT yet tried — try a DIFFERENT lever than every one above)

- The decisive lever is almost certainly raising maxX's allocno priority above
  gGameStuff-base's (to win ip) AND making kind land in r5 *without* a hard pin.
  Priority = refs²·log(refs)/live_length. Find a C shape where maxX is referenced
  one more time / has a shorter live range than gGameStuff-base, WITHOUT changing
  the emitted instructions. E.g. a no-op self-assign or an extra read folded away.
- Read global.c `find_reg` + `prune_preferences` + the `hard_reg_copy_preferences`
  path: the pointer-copy `adds r3,r0,#0` is a copy-preference artifact. Forcing
  &A's FIRST use to be in r0 (a scratch) while its home is r3 might be reproduced
  by reading the kind through a SEPARATE scratch pointer `p=&gIwram_6540; ...;
  a=p;` and arranging p to die into r0 — but agbcc coalesced p/a in a quick try;
  needs a use pattern that defeats coalescing (cast p to an index then back?).
- Dump the .greg/.lreg from `old_agbcc -dg /tmp/pp.c` (writes /tmp/pp.c.greg) and
  read the "sorted order" priorities for the maxX vs gGameStuff-base pseudos to
  see the exact priority gap to close, then engineer the ref-count/live-length
  delta in C to flip it.

## Best-effort C (clean, NO pins — diff_count 59, the best base; resume from THIS)

```c
#include "game.h"
#include "macros.h"
#include "types.h"

struct ScrollAxis {
    u8 _pad00[4];
    u32 lastTick; /* +0x04 */
    u8 _pad08;
    u8 kind; /* +0x09 */
    u8 _pad0a;
    u8 interval; /* +0x0b */
    u8 _pad0c[0x20];
    s16 deltaX; /* +0x2c */
    s16 deltaY; /* +0x2e */
    u8 _pad30[4];
    s16 posX; /* +0x34 */
    s16 posY; /* +0x36 */
};

extern struct ScrollAxis gIwram_6540;
extern struct ScrollAxis gIwram_6480;

void sub_080135B8(u16 maxX, u8 stepX, u16 maxY, u8 stepY)
{
    struct ScrollAxis *a = &gIwram_6540;
    struct ScrollAxis *b = &gIwram_6480;
    GameStuff *gs;
    u8 kind;

    a->deltaX = 0;
    b->deltaY = 0;

    kind = a->kind;
    if (kind != 0) {
        gs = &gGameStuff;
        if (gs->_unk00 - a->lastTick >= a->interval) {
            if (kind == 4) {
                if ((s32)(s16)a->posX <= (s32)(s16)maxX)
                    a->posX = a->posX + stepX;
                a->deltaX = stepX;
            }
            if (a->kind == 3) {
                if ((s32)(s16)a->posX >= (s32)(s16)maxX)
                    a->posX = a->posX - stepX;
                a->deltaX = -stepX;
            }
            a->lastTick = gs->_unk00;
        }
    }

    kind = b->kind;
    if (kind != 0) {
        gs = &gGameStuff;
        if (gs->_unk00 - b->lastTick >= b->interval) {
            if (kind == 1) {
                if ((s32)(s16)b->posY <= (s32)(s16)maxY)
                    b->posY = b->posY + stepY;
                b->deltaY = stepY;
            }
            if (b->kind == 2) {
                if ((s32)(s16)b->posY >= (s32)(s16)maxY)
                    b->posY = b->posY - stepY;
                b->deltaY = -stepY;
            }
            b->lastTick = gs->_unk00;
        }
    }
}
```
