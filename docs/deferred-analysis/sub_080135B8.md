# sub_080135B8 — deferred analysis

220-byte leaf function (no callees), `asm/disasm_0x080135b8.s` →
`src/engine/sub_080135b8.c` at 0x080135B8.

## What it does (fully understood)

Per-axis auto-scroll/pan tick. Two independent scroll controllers live in
IWRAM, same struct type (`struct ScrollAxis` below):

- block A = 0x03006540 (horizontal axis: kinds 4/3, fields posX@0x34 / deltaX@0x2c)
- block B = 0x03006480 (vertical axis:   kinds 1/2, fields posY@0x36 / deltaY@0x2e)

Struct offsets (from struct_xref of both bases + this function's own r/w):
- +0x04 u32 lastTick   — snapshot of gGameStuff._unk00 at last step
- +0x09 u8  kind       — direction/mode (A: 3 or 4; B: 1 or 2; 0 = idle)
- +0x0b u8  interval   — minimum gGameStuff._unk00 delta between steps
- +0x2c s16 deltaX / +0x2e s16 deltaY — per-step velocity reported each frame
- +0x34 s16 posX / +0x36 s16 posY     — accumulated position

Each frame the reported delta is cleared; a block only steps once
`gGameStuff._unk00 - lastTick >= interval`. kind 4 grows posX toward maxX
(arg0) by stepX (arg1); kind 3 unwinds it; kind 1/2 do the same on posY with
maxY (arg2)/stepY (arg3). Args: `(u16 maxX, u8 stepX, u16 maxY, u8 stepY)`.
The signed clamp compiles via `lsl #16` on both operands ((s32)(s16) casts).

## Drift

Best reached: **byte_diff 178, diff_count 75** (default agbcc) with the
register file FULLY matched to the target:
maxX→ip, stepX→r6, maxY→r8, stepY→r7, kind→r5, &A→r3, &B→r4, &gGameStuff→r9.
Prologue (`mov r7,r9; mov r6,r8; push {r6,r7}`), all four arg extends, the
`mov ip,r0` (maxX), `mov r8,r2` (maxY), and the whole comparison/clamp body
match register-for-register. The residual 75 is purely agbcc reload /
local-alloc micro-scheduling that C structure could not force and the
permuter could not mutate into:

1. **Pointer-copy pattern.** Target materialises &A/&B into scratch r0/r2
   (used as the base for the `deltaX/deltaY=0` stores and the first kind
   read, with the zero parked in r1), THEN copies to r3/r4 via
   `adds r3,r0,#0; adds r4,r2,#0`. My build loads the pool literals directly
   into r3/r4 and parks the zero in r0 — no copy. Pinning a→r3/b→r4 with
   `register asm(...)` did NOT produce the copy (it just loads straight into
   r3/r4); it lowered byte_diff to 164 but raised diff_count to 84.

2. **Late gGameStuff cache.** Target keeps the gGameStuff pointer in r0 across
   the value load (`ldr r1,[r0]`, value in r1), does the subtraction, THEN
   `mov r9,r0`. My build emits `mov r9,r0` BEFORE the value load, so the value
   lands in r0 (`ldr r0,[r0]`) and the interval compare flips operand order.
   The `gs = &gGameStuff` local correctly forces the r9 cache but not its late
   placement.

3. **Extend interleave.** Target emits the full maxY extend
   (`lsls r2,#16; lsrs r2,#16; mov r8,r2`) before the stepY extend; my build
   splits it (the `lsls r2,#16` floats up and `lsrs r2,#16; mov r8,r2` sinks
   below the stepY extend). agbcc has no `-fno-schedule-insns` here (rejected).

## Levers already tried (try a DIFFERENT one)

- Register pins: `my asm("r8")`, `gs asm("r9")`, `kind asm("r5")`, `mx asm("ip")`,
  `sx asm("r6")`, `sy asm("r7")`, `a asm("r3")`, `b asm("r4")` — in many
  combinations. The winning set is `my→r8 + gs→r9 + kind→r5` (the kind→r5 pin
  is what frees r6/r7 for the steps and pushes maxX to ip — the breakthrough
  from diff 108 to 75). Pinning sy→r7 directly POISONS the prologue (drops r7
  from the push, cascades to 236 bytes). Pinning mx→ip explicitly also works
  but drops r7 from the push unless steps are already in r6/r7.
- Comparison operand order: writing the clamp as `cap >= pos` / `cap <= pos`
  (cap syntactically first) dropped diff 89→84 on the clean base and is part
  of the 75-diff base. Keep this.
- Compilers: default agbcc and OLD_AGBCC_BIN give IDENTICAL results once the
  pins are in (pins override the allocator difference). Clean (no-pin) base is
  diff 84 under OLD_AGBCC vs 89 under default — but pins win regardless.
- `+=` vs explicit `x = x + s`: identical. `(u32)interval` cast: no-op.
- Reordering pointer assignments interleaved with the init stores: WORSE (119).
- decomp-permuter: base score 2025 on the 75-diff base (down from 2645 on an
  earlier base), -j4 ~50s, --better-only --stop-on-zero. NO improvement below
  base, no score 0. The mutations cannot invent the pointer-copy / late-cache.
- `register s16 z asm("r1") = 0; a->deltaX = z; b->deltaY = z;` — forces the
  zero into r1 (matching target's `movs r1,#0`), dropping byte_diff 185→178.
  But agbcc still loads &A/&B directly into r3/r4 (no `adds r3,r0,#0` copy) and
  inserts a spurious `adds r0,r1,#0` instead. Did NOT trigger the pointer-copy.
  This z→r1 pin is in the best-effort C below.

#include "game.h"
#include "types.h"

struct ScrollAxis {
    u8 _pad00[4];
    u32 lastTick;
    u8 _pad08;
    u8 kind;
    u8 _pad0a;
    u8 interval;
    u8 _pad0c[0x20];
    s16 deltaX;
    s16 deltaY;
    u8 _pad30[4];
    s16 posX;
    s16 posY;
};

void sub_080135B8(u16 maxX, u8 stepX, u16 maxY, u8 stepY)
{
    struct ScrollAxis *a = (struct ScrollAxis *)0x03006540;
    struct ScrollAxis *b = (struct ScrollAxis *)0x03006480;
    register u16 my asm("r8") = maxY;
    register GameStuff *gs asm("r9");
    register u8 kind asm("r5");
    register s16 z asm("r1") = 0;

    a->deltaX = z;
    b->deltaY = z;

    kind = a->kind;
    if (kind != 0) {
        gs = &gGameStuff;
        if (gs->_unk00 - a->lastTick >= a->interval) {
            if (kind == 4) {
                if ((s32)(s16)maxX >= (s32)(s16)a->posX)
                    a->posX = a->posX + stepX;
                a->deltaX = stepX;
            }
            if (a->kind == 3) {
                if ((s32)(s16)maxX <= (s32)(s16)a->posX)
                    a->posX = a->posX - stepX;
                a->deltaX = -stepX;
            }
            a->lastTick = gs->_unk00;
        }
    }

    kind = b->kind;
    if (kind != 0) {
        gs = &gGameStuff;
        if (gs->_unk00 - b->lastTick >= b->interval) {
            if (kind == 1) {
                if ((s32)(s16)my >= (s32)(s16)b->posY)
                    b->posY = b->posY + stepY;
                b->deltaY = stepY;
            }
            if (b->kind == 2) {
                if ((s32)(s16)my <= (s32)(s16)b->posY)
                    b->posY = b->posY - stepY;
                b->deltaY = -stepY;
            }
            b->lastTick = gs->_unk00;
        }
    }
}
