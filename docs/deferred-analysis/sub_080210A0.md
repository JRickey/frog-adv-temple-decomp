# Deferred analysis: sub_080210A0

## Function info

- Address: 0x080210a0, size 160 bytes
- File: src/engine/sub_080210a0.c
- Asm: asm/disasm_0x080210a0.s
- Callers: sub_0802ab64, sub_0802205c, sub_080220c4
- Callees: sub_08021F1C (peeled), sub_0800A580 (peeled)

## Summary

Entity-slot initializer. Takes an entity index + spawn-record pointer + 6 init
fields and writes them into the entity at gEntities_03003720[idx]. Converts a
direction byte from the spawn record to delta-X/Y via sub_08021F1C. Passes the
entity + deltas to sub_0800A580 for further setup.

## Drift

Best byte_diff: **72** (size=164, target=160 — 4 bytes extra due to extra pool word).
diff_count: 41 instructions.

### Root cause

The target prologue saves **three** high registers (r8, r9, sl):
```
push {r4, r5, r6, r7, lr}
mov  r7, sl
mov  r6, r9
mov  r5, r8
push {r5, r6, r7}
sub  sp, #4
mov  sl, r1        ; sl = a1 = rec ptr  (FIRST operation after sub sp)
ldr  r6, [sp, #36] ; r6 = a4 (u16, goes to low reg for strh compatibility)
ldr  r1, [sp, #40] ; → r8 = a5
mov  r8, r1
ldr  r1, [sp, #44] ; → r9 = a6
mov  r9, r1
ldr  r5, [sp, #48] ; r5 = a7
```

With `register rec asm("sl")` pin only (best attempt), the prologue saves the
3 high regs correctly, but the register assignment is shifted by one:
- Built: a4→r8, a5→r9, a6→r5, a7→r6  (WRONG)
- Target: a4→r6, a5→r8, a6→r9, a7→r5 (correct)

The `mov sl, r1` is deferred to offset 0x46 in the built version (after all entity
stores). In the target it's the FIRST instruction after `sub sp, #4`.

Consequence: the built version generates TWO pool constants (0x03003720 and
0x03003753 = 0x03003720+0x33) making it 164 bytes instead of 160.

### Instruction-level diffs (beyond prologue)

The direction byte extraction:
- Target: `ldrh r2, [r2, #0]; lsls r0, r2, #16; asrs r0, r0, #24` (sign-extend high byte)
- Built: `ldrh r0, [r1, #0]; lsrs r0, r0, #8; lsls r0, r0, #24; cmp r0, #0` (zero-extend)

entity[0x33] store:
- Target: `adds r0, r7, #0; adds r0, #51; strb r1, [r0, #0]` (reuses entity ptr in r7)
- Built: `ldr r2, [pc]; adds r0, r4, r2; strb r1, [r0, #0]` (uses pool constant)

### Levers already tried

1. **No pins, plain C** — byte_diff 119-121, same size (160), but uses only 2 high regs.
2. **`register rec asm("sl")`** — byte_diff 72, size 164 (extra pool word). Prologue
   saves 3 high regs but wrong register assignment (a4→r8 instead of r6).
3. **`register rec asm("sl")` + `register a4 asm("r6")`** — byte_diff 146, size 168.
   Worse; extra zero-extension added.
4. **`register rec asm("sl")` + `register a5 asm("r8")` + `register a6 asm("r9")`** —
   byte_diff 148, size 168. Even worse.
5. **OLD_AGBCC per-TU** — no improvement over regular agbcc for this function.
6. **`u16` cast for direction extraction** — no change in prologue issues.

### What's still needed

The fundamental issue: need agbcc to generate `mov sl, r1` as the VERY FIRST
instruction after `sub sp, #4`, before any stack-arg loads. This would free r1
as the intermediary for r8/r9 loads, causing a4 to go into r6 (directly loadable
via `ldr r6, [sp, #36]`) instead of r8 (which requires `ldr r4; mov r8, r4`).

Possible approach: find a C structure where the FIRST use of rec (= a1 = r1) is
something that forces `mov sl, r1` immediately (not deferred). This might be
achieved by having an expression that NEEDS rec AND a4 simultaneously before
any other computation.

An `asm volatile("" : "+r"(rec))` barrier immediately after the pin declaration
WOULD work but agbcc 2.x rejects the `+r` constraint with a pointer type (syntax
error: "before `*'"). Some other barrier form might work.
