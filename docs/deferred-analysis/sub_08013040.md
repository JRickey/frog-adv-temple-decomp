## Drift (best-effort C, byte_diff 139)

PROLOGUE MATCHES exactly: `ldr r4,=gGameStuff; ldr r2,=base720; movs #0xd3;
lsls #5; adds r3,r2,r0; ldr r0,[r4]; …`. Achieved by (a) using link symbols
`gIwram_3720`/`gIwram_3610`/`gGameStuff` (NOT absolute casts) so agbcc can't
constant-fold `base + 0x1a60`, and (b) a `GameStuff *gs = &gGameStuff;` local
referenced first so gGameStuff loads into r4 before base720 into r2.

Four compounding loop-body drifts remain (all cost-model / CSE decisions):

1. **Mask `1` hoisted out of the loop.** baserom re-materialises `movs r1,#1`
   at the top of every iteration and reuses r1 for both the `(flags>>i)&1`
   test and the `nib&1` test. agbcc instead promotes the loop-invariant
   constant `1` into callee-saved **r7** before the loop (one `movs r7,#1`,
   then `ands r0,r7` twice). This is loop.c move_movables: with
   `threshold = (loop_has_call?1:2)*(1+n_non_fixed_regs)`, the product
   `threshold*savings*lifetime >= insn_count` passes because the constant's
   lifetime spans both `& 1` sites. Costs 1 insn + occupies r7.

2. **base610 `+0xd4` folded into the pool constant.** baserom does
   `ldr r0,=0x03003610; adds r0,#0xd4; ldrb` (re-loaded each iteration).
   agbcc folds `&gIwram_3610 + 0xd4` (or `(u8*)0x03003610 + 0xd4`) into a
   single relocated pool word `0x030036e4` → `ldr; ldrb` (one insn shorter).
   With an absolute/link base used only once, agbcc always folds the const
   offset. Making base610 a multi-use local instead hoisted it into a 3rd
   high reg (sl) — strictly worse.

3. **`_frames` read via `[r3,#16]` instead of recompute.** baserom keeps
   `i*24` in r2 and `table` in r5 and recomputes `&entry._frames` as
   `r5 + 0x10 + r2`. agbcc forms a single entry pointer `r3 = &table[i]` and
   reads `ldr [r3,#16]`. Re-indexing (`sScaleAnimDescriptors2[i]._frames`,
   link symbol) DID produce the table+i*24 separation but cost a 3rd high reg
   (sl) and clobbered the loop counter → byte_diff 159.

4. **`dst = 0x0600e000` emitted BEFORE the `nib&1` test.** baserom order is
   test → `mov r9,=e000` → conditional `mov r9,=e800`. agbcc schedules the
   unconditional e000 store ahead of the test. A ternary
   `dst = (nib&1) ? e800 : e000` reorders to test-first but creates a
   branch-merge form (byte_diff 143). `dst = e000; if (nib&1) dst = e800;`
   still gets the e000 store reordered before the `ands`.

## Next-agent suggestions (try DIFFERENT levers)

- The mask hoist (drift 1) is the root that adds register pressure and
  cascades the pool offsets (the function ends up 4 bytes short, so EVERY
  `ldr [pc,#N]` mismatches on offset). Find a way to keep the constant `1`
  with a short enough lifetime that loop.c won't promote it — e.g. structure
  the two `& 1` tests so they don't share an RTL constant whose lifetime
  spans the descriptor block, or read the agbcc local-alloc/loop passes to
  see exactly which value's lifetime triggers the move.
- The frames-recompute (drift 3) and base610-fold (drift 2) both stem from
  agbcc reusing a single pointer where the baserom keeps base+offset
  separate. The original C likely computes the descriptor address as a raw
  `u8 *` base + a manual `i*24` offset (not a `struct[]` index) so that
  `table` and `i*24` stay separate registers, with `_frames` read as
  `*(u32**)(p + 0x10)`. A `u8 *p = (u8*)table; … *(u16*)(p + i*24 + 0)` style
  that the compiler can't collapse to one entry pointer may reproduce both
  the entry-ptr-for-fields AND the table+i*24 recompute for frames.
- Permuter was NOT run: 139 is far above the ≤40 near-match threshold and the
  base has 4 structural drifts (permuting a wrong base is wasted). Re-run it
  only after the mask hoist + frames recompute are fixed structurally.
