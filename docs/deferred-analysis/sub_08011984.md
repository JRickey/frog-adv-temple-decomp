### THE residual wall (one root cause, cascades to ~all 71 remaining diffs)

The target keeps the strength-reduce **partial `idx<<3`** live across the whole
loop, **spilled to `[sp,#12]`**, and re-derives `&elems[idx]` at the tail via
`ldr r5,[sp,#12]; mov r6,ip; subs r4,r5,r6; lsls #2; add r4,r9`. agbcc (mine)
instead keeps only `idx` (in ip) and **recomputes** `idx<<3` at the tail
(`mov r5,ip; lsls r4,r5,#3; subs ...`). Confirmed `[sp,#12] == idx<<3` (set at
prologue `lsls r0,#3; mov r8,r0`, spilled at loop entry `mov r5,r8; str r5,[sp,#12]`,
reloaded at tail).

Why the target spills it: the inner loop needs **8 low regs** (dst,width,height,
y+1,src,temp,x×2) so the loop-invariant `gIwram_60A0` base must live in a HIGH reg
→ r8; r8 already holds `idx<<3` → forced spill (not optional). Mine's loop uses
FEWER low regs (it **spills `height` instead**), so the 60A0 base fits in r9/ip and
`idx<<3` is never forced out → agbcc recomputes it (cheaper: 1 `lsls` vs spill+load).

Cascade from the un-kept `idx<<3`: elems lands in **r8** (mine) instead of **r9**
(target, where idx<<3 took r8 first); the 60A0 loop base lands in r9/ip instead of
r8; the 6540 base stays **persistent in r4** (mine) instead of being **reloaded**
at the tail (target reuses r4 for `height` in the loop).

So it is ONE allocator decision: *keep+spill `idx<<3`* (PRE/GCSE on the
strength-reduce partial) vs *recompute it*. The cost model picks recompute unless
the loop FORCES `height` to stay in a low reg (raising loop low-reg pressure to 8),
which evicts the 60A0 base to r8 and forces the `idx<<3` spill.
