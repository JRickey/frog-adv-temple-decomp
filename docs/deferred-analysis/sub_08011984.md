## Function summary

`sub_08011984(struct Elem *arg0, u8 idx)` — copies a rectangular halfword block into
EWRAM and primes two IWRAM control blocks (gIwram_6540 at 0x03006540, gIwram_6480 at
0x03006480) from element `arg0[idx]` (28-byte stride) and its successor `arg0[idx+1]`,
then tail-calls sub_0801025C. `gIwram_60A0.field_1a` (0x030060a0 + 0x1a) is the source
row stride (width). Single callee sub_0801025C is already peeled.

Element struct (28 bytes): u16 field_0/2/4/6, u8 field_c @0xc, u32 field_10 @0x10.
The fixed read at `arg0+0x22` is `elems[1].field_6` (28+6=34=0x22), independent of idx.

## Drift

- **best byte_diff: 180, diff_count 79** (was 187/92 before the loop restructure).
- The FIRST 15 instructions match exactly. Divergence is ONE instruction:
  - **Target** materializes `idx*8` into r8 (`mov r0,ip; lsls r0,#3; mov r8,r0; subs r2,r0,r1; lsls r2,#2; add r2,r9`),
    SPILLS it to `[sp+12]` at loop entry (`mov r5,r8; str r5,[sp,#12]`), and at the call
    reloads it (`ldr r5,[sp,#12]; mov r6,ip; subs r4,r5,r6; lsls r4,#2; add r4,r9`) to
    re-derive `&elems[idx]` for the final `elems[idx].field_10` arg. Stack frame
    `sub sp,#16`.
  - **Built** never keeps idx*8; it RECOMPUTES it from ip at the call site
    (`mov r5,ip; lsls r4,r5,#3; subs; lsls; add`) and instead stashes `&gIwram_6540`
    in `sl`. Stack frame `sub sp,#12` (one fewer slot — no [sp+12]).
  - This single spill-vs-recompute choice shifts the element pointer from r2 (target) to
    r3 (built) and the constant `1` from r3 to r2, cascading into ~79 "different"
    instructions that are nearly all semantically identical, register-renamed.
- A secondary symptom: target CSEs `elem->field_4`/`field_6` into one register each for
  the duplicated field_30/2c and field_32/2e stores; built re-loads. This is downstream
  of the same allocation (target had r1/r0 free because idx*8 lived in r8).

### The exact asm idiom that diverges
The baserom strength-reduces `idx*28` (the `Elem` stride is 28) to `(idx<<3 - idx)<<2`, and keeps the partial product `idx*8` live in the HIGH callee-saved reg **r8** from the prologue:
```
mov r0,ip ; lsls r0,#3 ; mov r8,r0     @ r8 = idx*8 (kept)
subs r2,r0,r1 ; lsls r2,#2 ; add r2,r9 @ r2 = &elems[idx]
```
At loop entry it **spills idx*8 to the stack** because r8 is reused as an inner-loop scratch:
```
mov r5,r8 ; str r5,[sp,#12]            @ spill idx*8 ; sub sp,#16 (extra slot)
... mov r8,r1 (loop body uses r8 to cache &gIwram_60A0 for the per-iter stride re-read) ...
```
and at the tail **reloads** it to re-derive `&elems[idx]` for the final `elems[idx].field_10`:
```
ldr r5,[sp,#12] ; mov r6,ip ; subs r4,r5,r6 ; lsls r4,#2 ; add r4,r9 ; ldr r4,[r4,#16]
```
agbcc instead keeps `elem` (the full `&elems[idx]` pointer) in a LOW reg (r6) across the loop, never needs r8 in the loop, and so emits `sub sp,#12` (no spill slot) with no reload. This single spill-vs-keep-in-low-reg choice is the entire residual.

### The two divergences (clean-build verified)

1. **`field_18 = 0x02020000` dead-store elimination (FIXED, 241->234).** The baserom
   stores `gIwram_6480.field_18 = (u16*)0x02020000` (0x119de) then later overwrites it
   with `dst` (0x1a0c) — TWO `str [x,#24]`. agbcc (old_agbcc) DSE-removes the first
   (provably-dead) store, leaving ONE. **Fix that works:** declare the struct field as
   `u16 *volatile field_18;` — forces both stores. This is the ONLY lever that moved the
   no-pin baseline. (A plain `u16 *base` local does NOT help — agbcc constant-propagates
   it and DSE still fires.) Whether the original is truly volatile or just structured so
   DSE can't fire is unknown; volatile is the cheapest reproduction.

2. **`idx*8` spill-vs-recompute (THE residual, unsolved).** Identical to the Round 19 /
   corpus-sweep finding. Element stride is 28; `idx*28` strength-reduces to
   `((idx<<3)-idx)<<2`. **Target:** materializes `idx*8` into callee-saved **r8**
   (`mov r0,ip; lsls r0,#3; mov r8,r0`), keeps it until loop entry, then **spills to
   [sp,#12]** (sub sp,#16) because the inner loop reuses r8 to cache `&gIwram_60A0` for
   the per-iteration `dst += width-cx` stride read; reloads at the tail to re-derive
   `&elems[idx]` for the final `field_10` arg. **agbcc (mine):** CSE fuses `idx*8` inline
   into the pointer computation (`lsls r2,r1,#3; subs r2,r2,r1`), never materializes it
   as a separate pseudo, so at the tail it RECOMPUTES the whole chain from `idx` (in ip)
   — `sub sp,#12`, no spill slot. Everything else (the gIwram_60A0/gIwram_6480 hoist
   shuffle at diff +0x70..+0x88) cascades from this one r8 contention.

### Why no clean C shape flips it (root cause, agbcc source read)
- gcc-2.x `reload1.c` only rematerializes `reg_equiv_constant`/`reg_equiv_mem` — NOT
  recomputable arithmetic. So `idx*8` is either KEPT-IN-REG (and spilled across the loop)
  or RECOMPUTED inline; there is no third option. Which one happens is decided upstream
  by whether `cse.c` materializes `idx*8` as its own pseudo. `cse.c rtx_cost`/`COST`
  keeps the HIGHER-cost common subexpression — it prefers to CSE the full `&elems[idx]`
  (mult+add) over the cheap `idx*8` (a shift). The full pointer then dies in the loop
  (`cse_around_loop` invalidates it) and gets recomputed at the tail. The target instead
  kept the cheap partial — an allocation-order artifact, not reachable by source shape.
- A `register u32 n8 asm("r8")` PIN cannot help: a pinned hard reg CANNOT be spilled, but
  the target SPILLS idx*8. Pinning keeps it in r8 forever (variant F: tail does
