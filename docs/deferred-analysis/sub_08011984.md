# Deferred: sub_08011984

## Drift

`classify_unmatchable.py sub_08011984` returns `ATTEMPT_MATCH`; this is not a
class3-libgcc strong-unmatchable case, so I did not ship NAKED or inline asm.
The only callee, `sub_0801025C`, is already peeled.

Semantics are straightforward: `sub_08011984(struct Unk11984Elem *elems, u8 idx)`
copies a `width x height` halfword rectangle from `elems[idx + 1].field_10` into
EWRAM `0x02020000`, initializes the IWRAM control blocks at `0x03006540` and
`0x03006480`, then calls `sub_0801025C`. The element stride is 28 bytes.

Best result in this worktree: **byte_diff 236 / diff_count 62 / size 280** from
the readable C below, with `field_18` volatile to preserve the target's first
store to `gIwram_6480.field_18`. Without that volatile store-preserving lever,
the first clean pass was `byte_diff 237 / diff_count 58 / size 276`; agbcc DSEs
the initial `field_18 = 0x02020000` store.

Residual root cause remains the cross-loop `idx * 8` lifetime:

- Target computes `idx << 3` into `r8`, derives `&elems[idx]` with
  `((idx << 3) - idx) << 2`, then spills `r8` to `[sp, #12]` at loop entry
  because the loop reuses `r8` for the `gIwram_60A0` base. The epilogue reloads
  `[sp, #12]` to re-derive `elems[idx].field_10`. Stack frame is `sub sp, #16`.
- agbcc recomputes the multiply at the tail or spills the full element pointer
  too early. Stack frame stays `sub sp, #12` unless a wrong value is spilled.

New attempts ruled out in this pass:

- Clean C, no pins/volatile: `237/58`, size 276. Correct semantics, but DSEs
  the first `field_18` store and recomputes `idx * 8`.
- Source-level `elem`/`next` pointer rewrite with a visible `dst` base:
  `247/117`, size 252. This worsens register choice and shrinks the function.
- Pure-C high-register base pins (`r9` for element base, `sl` for
  `gIwram_6480`) plus volatile `field_18`: `222/106`, size 288. This gets the
  size right but forces the `gIwram_6480` base load too early and still does not
  produce the target `idx * 8` spill.
- `r9` element-base pin only: `257/98`, size 284. It spills the full element
  pointer early instead of spilling `idx * 8` at loop entry.
- Shared-TU `-fno-rerun-cse-after-loop`: `240/71`, size 284. It changes the
  high-register base allocation but still does not preserve the desired
  `idx * 8` value.
- Explicit `idx8 = n << 3` with pointer derivation from `((idx8 - n) << 2)`:
  `248/177`, size 268. The partial product becomes source-visible too early and
  agbcc schedules/register-colors the whole head differently.
- Corpus checks found no direct asm-to-C history pairing for the spill idiom:
  `corpus_asm_search.py search --asm 'str\s+r[0-7],\s*\[sp,\s*#[0-9]+\]' --require-c`
  returned no usable hits; C grep for `*dst++ = *src++` only found generic copy
  loops, not this indexed-element spill pattern.

The implicated passes are still `gcse.c`/PRE for deciding to recompute the
cross-loop shift instead of preserving it, then `local-alloc.c`/`global.c` for
the resulting high-register and spill choices. I read those pass sections this
round; the relevant behavior is that GCSE creates/keeps only the expressions it
judges worth carrying across blocks, while local allocation can only spill an
existing pseudo. Source-visible `idx8` creates the pseudo, but at the wrong
lifetime and cost.

## Best-effort C

Struct growth used by the best-effort body:

- `IwramAt60A0_sub1190C`: add `u16 field_1a` at offset `0x1a`.
- `IwramAt6480_sub1190C`: grow fields through `0x36`; `field_18` is
  `u16 *volatile` to preserve the target's otherwise-dead first store.
- `IwramAt6540_sub1190C`: grow fields through `0x34`; `field_30` and
  `field_32` are unsigned so the loop bounds compile to `ldrh`.
- `Unk11984Elem`: 28-byte stride, `u16` fields at `0/2/4/6`, `u8 field_c`,
  and `u32 field_10`.

    u16 *dst;

    u32 height;

    gIwram_6540.field_a = 0;

    gIwram_6540.field_32 = elems[n].field_6;

    gIwram_6540.field_2e = elems[n].field_6;
    gIwram_6540.field_b = elems[n].field_c;
    gIwram_6540.field_10 = elems[n].field_10;

    gIwram_6480.field_0 = 1;
    gIwram_6480.field_9 = 1;
    gIwram_6480.field_36 = elems[n + 1].field_2;
    gIwram_6480.field_34 = elems[n + 1].field_0;
    src = (u16 *)elems[n + 1].field_10;
    gIwram_6480.field_10 = (u32)src;

    gIwram_6480.field_32 = elems[1].field_6;
    gIwram_6480.field_2c = elems[n + 1].field_4;

                 gIwram_6480.field_36, 2, elems[n].field_10, 0x0600f000);
}
