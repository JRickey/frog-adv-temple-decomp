# sub_0802C200 — deferred (Opus round 25)

Entity-pool spawn/dispatch sweep over slots 8..21 (loop var `j` = 0..13).
Iterates `gEntities[j+8]`, and for each slot dispatches between a "pending
spawn" branch (`status & 0x08`) and a per-state dispatch branch. Semantics are
confirmed-correct against the disassembly.

## What this round FIXED vs the prior note (escape the old plateau)

The prior attempt (byte_diff 360, diff_count 207) had the **control flow
WRONG**. This round re-derived it from the asm and dropped diff_count to
**152** (byte_diff 394). The corrections — re-apply these, they are solved:

1. **Shared-tail, NOT `continue`, after `sub_0800679C`.** At 0x2c250 the target
   does `bne 0x2c2fc` — when `sub_0800679C != 0` it FALLS THROUGH to the else
   block (the per-state dispatch at 2c2fc), it does NOT `continue` the loop. So
   the spawn branch guard is:
   ```c
   if ((e->status & 0x08) && !sub_0800679C(&gIwram_6110, 3, 6)) { ...spawn... }
   /* else (or && false): fall through to the dispatch block */
   ```
   The `&&` short-circuit reproduces the two `b 0x2c2fc` edges (from
   `!(status&8)` at 2c23a and from `sub_0800679C!=0` at 2c250) exactly.

2. **Fire path joins the dispatch tail.** After firing (`sub_0802C3E4`) the
   spawn branch does `e->status &= 0xFF7F` then `goto call_59c4` — the SAME
   `sub_080059C4(&base8[j])` the field_1A>5 dispatch path uses (target
   `b 0x2c38c`). Use a shared `call_59c4:` label.

3. **spawnMask block ordering.** Test `spawnMask == 0` FIRST so the
   `spawnMask != 0` case falls through to the shared fire (target puts the
   nonzero-fire block at 2c2d0, AFTER the coin-flip block at 2c2c0):
   ```c
   if (gIwram_6110.spawnMask == 0) {
       if (!(u8)sub_08000764(3)) goto clear_pending;
       sub_0802C3E4(actor, 8, j);
       goto clear_pending;
   }
   sub_0802C3E4(actor, 8, j);
   clear_pending:
       e->status &= 0xFF7F;
       goto call_59c4;
   ```

4. **Callee return types.** `sub_0802C5E0`/`sub_0802C640` return **s32**
   (target tests with a bare `cmp r0,#0`, NO `lsls #24` truncation — they
   return 0/1 already). `sub_08000764` declared **u32** with an explicit
   `(u8)` cast at each use — this makes the coin-flip emit the target's
   `lsls r0,#24; cmp r0,#0` truncation. (With u8 the coin-flip mis-handled.)

5. **High-reg pins + base8.** `actor` (r9) = owner, `pool` (r8) = gEntities,
   `base8` (sl) = `&pool[8]`, all assigned INSIDE the loop so LICM hoists them
   into the preheader AFTER `movs r2,#0` (j=0). This matches the target's
   `mov r9 ; movs r2,#0 ; ldr=gEntities ; mov r8 ; …+0x1c0… ; mov sl` order and
   the `add r1,r8 ; mov sl,r1` (sl derived from r8, not a separate literal).
   OLD_AGBCC (the Makefile default) is as good as AGBCC here (both 152); no
   per-TU override needed.

## The IRREDUCIBLE divergence (the whole remaining 152)

**agbcc ALWAYS distributes `(j+8)*0x38` → `j*0x38 + 0x1c0`.** The target keeps
`r5 = (j+8)*0x38` undistributed and reuses it for `e = pool + r5`, the
`field_2C` store (`pool + 0x2c + r5`), the `field_2C` read, and the fire-path
`e->status &= 0xFF7F` recompute. My build computes `r5 = j*0x38` (the offset
shared with the `&base8[j]` calls, `sl + j*0x38`) and adds the `0x1c0`
constant (`movs r0,#0xe0; lsls #1; adds`) at every slot site — ~3 extra insns ×
4 sites + the register-name cascade = the entire 152.

This was probed exhaustively and is a HARD agbcc codegen invariant, NOT a
source-shape or coloring choice:
- Tried: `&pool[j+8]`, `&base8[j]` (single base), index-first byte cast
  `(u8*)pool + ((s8)j+8)*sizeof + 0x2c`, explicit `s32 slot=j+8`,
  `register s32 idx asm("r1")` pin, `e->field_2C` vs `pool[j+8].field_2C` —
  ALL produce `j*0x38 + 0x1c0` (or worse). agbcc distributes the constant out
  of `(j+8)*size` during address expansion, after any source rewrite.
- Tried compilers: OLD_AGBCC (152) and AGBCC (154) — both distribute.
- Tried flags (all neutral on the distribution): `-fno-strength-reduce`,
  `-fno-gcse`, `-fno-cse-follow-jumps`, `-fno-cse-skip-blocks`,
  `-fno-expensive-optimizations`, `-fforce-addr`, `-fno-schedule-insns`,
  `-ffixed-r4/r5/r6`, `-fno-thread-jumps`, `-O1`.
- Removing `base8` (so no `pool+0x1c0` value exists) did NOT help — agbcc
  re-materialises `0x1c0` inline anyway.

The target keeps `(j+8)*0x38` only because it carries that byte-offset live in
a callee-saved reg across the whole loop body under HIGHER register pressure
than agbcc generates from this C. The prior note diagnosed the same root
(spill of `&gIwram_6110`, packed-j, reusable r5). **This is the textbook
decomp-permuter case** (statement-order / temp-scope mutation to coax the
extra spill that raises pressure) — but the permuter `.venv` is BROKEN in this
environment (the `vendor/decomp-permuter` symlink on main is a self-referential
loop — `Too many levels of symbolic links`; a real checkout exists at
`/Users/jackrickey/decomp-permuter/` but the project import flow needs a
healthy `vendor/decomp-permuter`). And byte_diff 394 is FAR above the
permuter's ≤~40 near-match window anyway, so it is unlikely to help until the
pressure issue is closer.

## Best-effort C (diff_count 152, byte_diff 394 — control flow MATCHES)

Built with default OLD_AGBCC (no per-TU Makefile override). Entity struct needs
`u32 field_2C;` at +0x2C (split out of `field_2B[5]` → `u8 field_2B; u32 field_2C;`).

```c
#include "game.h"
#include "iwram.h"
#include "types.h"

extern u32 sub_08000764(u8 range);
extern u8 sub_0800679C(void *base, u32 selector, u32 bit);
extern void sub_0800696C(void *p, s32 idx);
extern void sub_080059C4(struct Entity *p);
extern void sub_08020F3C(u8 idx);

extern void sub_0802C3E4(u8 owner, u8 group, u8 idx);
extern s32 sub_0802C5E0(u8 group, u8 idx);
extern s32 sub_0802C640(u8 group, u8 idx);

void sub_0802C200(u8 owner)
{
    register u8 actor asm("r9") = owner;
    register struct Entity *pool asm("r8");
    register struct Entity *base8 asm("sl");
    s8 j;
    struct Entity *e;

    for (j = 0; j <= 13; j++) {
        pool = gEntities;
        base8 = &pool[8];
        e = &pool[j + 8];

        if ((e->status & 0x08) && !sub_0800679C(&gIwram_6110, 3, 6)) {
            if (!(e->status & 0x80)) {
                e->field_32 = (u8)sub_08000764(0xC8) + 0x32;
                e->status |= 0x80;
                pool[j + 8].field_2C = gGameStuff._unk00;
                continue;
            }

            if (gGameStuff._unk00 - pool[j + 8].field_2C <= e->field_32)
                continue;

            if (gIwram_6110.spawnMask == 0) {
                if (!(u8)sub_08000764(3))
                    goto clear_pending;
                sub_0802C3E4(actor, 8, j);
                goto clear_pending;
            }
            sub_0802C3E4(actor, 8, j);

        clear_pending:
            e->status &= 0xFF7F;
            goto call_59c4;
        }

        sub_0800696C(&gIwram_6110, j + 8);

        if (sub_0802C5E0(8, j)) {
            if (sub_0802C640(8, j))
                return;
            continue;
        }

        e = &gEntities[j + 8];
        if (e->field_1A > 5) {
            if (e->status & 0x8000) {
                e->status &= 0x7FFF;
                switch (e->field_1A) {
                case 6:
                    e->field_1A = 0;
                    break;
                case 7:
                    e->field_1A = 2;
                    break;
                case 8:
                    e->field_1A = 4;
                    break;
                default:
                    goto call_59c4;
                }
                e->status |= 2;
            }
        call_59c4:
            sub_080059C4(&base8[j]);
            continue;
        }

        if (e->status & 0x8000)
            e->status = (e->status & 0x7FFF) | 2;
        sub_08020F3C(j + 8);
        sub_080059C4(&base8[j]);
    }
}
```
