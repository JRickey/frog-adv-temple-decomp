# sub_0802C200 — deferred

Entity-pool spawn/dispatch sweep over slots 8..21 (loop var `j` = 0..13).
Iterates `gEntities[j+8]`, and for each slot:

- If `status & 0x08` ("pending spawn"): query `sub_0800679C(&gIwram_6110, 3, 6)`
  (a flag gate); if clear and `status & 0x80` not yet set, seed a cooldown byte
  at `field_32 = sub_08000764(0xC8) + 0x32`, set `status |= 0x80`, snapshot
  `gGameStuff._unk00` into the slot's `field_2C` (a u32 added to the Entity
  struct at +0x2C). On a later pass, once `gGameStuff._unk00 - field_2C >
  field_32`, fire `sub_0802C3E4(owner, 8, j)` (gated by `gIwram_6110.spawnMask`
  or an `sub_08000764(3)` coin-flip), clear `status & 0x80`, and call
  `sub_080059C4(&gEntities[8+j])`.
- Else (`status & 0x08` clear): `sub_0800696C(&gIwram_6110, j+8)`; if
  `sub_0802C5E0(8, j)` is false, normalise the slot's `status` flag-15/flag-1
  bits keyed on the dispatch state `field_1A` (the same idiom as
  sub_08009140), then `sub_08020F3C(j+8)` / `sub_080059C4`. If
  `sub_0802C5E0` true, call `sub_0802C640(8, j)` and `return` early when it is
  nonzero.

Semantics are confirmed-correct (control flow + every field access verified
against the disassembly). The PEEL of the two embedded callees sub_0802C5E0 /
sub_0802C640 out of the sub_0802C3E4 incbin slice is a standalone good change
and is kept (see commit "Peel sub_0802C5E0 and sub_0802C640"). The Entity
struct gained `u32 field_2C` at +0x2C (was inside `field_2B[5]`) — but that
header change was reverted with the rest of the defer; re-apply it when
resuming.

## Drift

Best result: **byte_diff 360, diff_count 207** (of ~250 Thumb insns), built
with the NEWER agbcc (`CC = $(AGBCC_BIN)`) + `CFLAGS += -fforce-addr
-fno-expensive-optimizations` and high-register pins
`r8`=gEntities, `sl`=&gEntities[8], `r9`=owner.

What MATCHES already (do not re-derive these — they are solved):
- High-reg pins r8/r9/sl exactly match the target's allocation.
- Loop var lives in **r2** (matched) by declaring `actor` (r9) first, then
  assigning `pool`/`base8` *inside* the loop body so loop-invariant motion
  hoists their loads into the preheader AFTER the `j=0` init (matches the
  target's `mov r9,r0 ; movs r2,#0 ; ldr =gEntities ; mov r8 ; … mov sl`
  order). Eager decl-initializers put the r8/sl loads BEFORE `j=0` (wrong).
- Slot computation `(s8)j` → `+8` → `*0x38` shape matches when `e` is the
  cached pointer `e = (struct Entity *)((j+8)*sizeof(Entity) + (u32)pool)`
  (index-first cast, per the sub_080184dc precedent). A best-of run used
  `e = &base8[j]` (single base) which dropped diff_count to 207 but loses
  the target's reusable byte-offset `r5`.
- Newer agbcc beats OLD_AGBCC here by ~6 bytes and gives the r2 loop var.

The IRREDUCIBLE divergence (where every approach stalled):
1. **Stack spill of `&gIwram_6110`.** The target reserves `sub sp,#4` and
   spills `&gIwram_6110` (r3) across the `bl sub_0800679C` call, reloading it
   (`str r3,[sp] … ldr r3,[sp]`) and reusing the SAME pointer for the
   `spawnMask` read at `r3+0x33` later in the `status&8` block. agbcc (mine)
   keeps it in a register without spilling and re-loads the literal for the
   spawnMask read — because the surrounding register pressure is LOWER than
   the target's. A `struct IwramAt6110 *ctrl = &gIwram_6110;` anchor reused
   for both the call and `ctrl->spawnMask` did NOT force the spill (tried).
2. **`(s8)j` cached vs re-derived.** The target keeps the loop var PACKED
   (`r7 = j<<24`, via `adds r7,r2,#0`) and re-derives `(s8)j` (`asrs r1,r2,#24`
   / the callee args via `lsrs r2,r7,#24`) at each use. My build sign-extends
   `(s8)j` once into a callee-saved reg and reuses it, so r7 is occupied and
   the loop-var save spills to `[sp]` instead of `adds r7,r2,#0`.
3. **Reusable byte-offset `r5`.** The target keeps `r5 = (j+8)*0x38` live and
   reuses it for the `field_2C` store (`pool + 0x2c + r5`) and the `&gEntities`
   slot. The cached-`e`-pointer form loses this; the pure-array-index form
   (`gEntities[j+8].field` everywhere) recomputes the slot at every access
   (byte_diff 548) — worse.

These three are all the SAME root: the target carries more simultaneously-live
subexpressions (e in r4, offset r5, packed-j r7, the 0x80 const in r6, AND the
spilled `&gIwram_6110`), which the compiler only emits under exactly the right
register pressure. This is a sharp register-coloring / liveness local minimum
on a 250-insn function — the textbook permuter case.

Levers tried (all kept the structure correct):
- compilers: OLD_AGBCC (377) vs AGBCC (371→360 best). AGBCC wins.
- flags: `-fforce-addr -fno-expensive-optimizations` (best); also tried
  `-fno-strength-reduce`, `-fno-gcse`, `-fno-schedule-insns`, `-ffixed-r1`
  (all neutral or worse).
- structures: cached `e` ptr (dual base, 371) / `e=&base8[j]` (single base,
  360) / pure `gEntities[j+8]` indexing (548) / `s32 slot` var (worse) /
  index-first cast `(j+8)*sizeof+(u32)pool`.
- pins: r8/r9/sl (kept); pinning loop var `j` to r2 explicitly was WORSE
  (431) — the natural flow already puts it in r2.
- anchor: `ctrl = &gIwram_6110` reused for call + spawnMask (no spill forced).

## Best-effort C

Built with (Makefile):
```
src/game/sub_0802c200.s: CC = $(AGBCC_BIN)
src/game/sub_0802c200.s: CFLAGS += -fforce-addr -fno-expensive-optimizations
```
Entity struct needs `u32 field_2C;` at +0x2C (split out of `field_2B[5]`).

```c
#include "game.h"
#include "iwram.h"
#include "types.h"

extern u8 sub_08000764(u8 range);
extern u32 sub_0800679C(void *base, u32 selector, u32 bit);
extern void sub_0800696C(void *p, s32 bits);
extern void sub_080059C4(struct Entity *p);
extern void sub_08020F3C(u8 idx);

extern void sub_0802C3E4(u8 a, u8 b, u8 c);
extern u8 sub_0802C5E0(u8 a, u8 b);
extern u8 sub_0802C640(u8 a, u8 b);

void sub_0802C200(u8 owner)
{
    register u8 actor asm("r9") = owner;
    register struct Entity *pool asm("r8");
    register struct Entity *base8 asm("sl");
    s8 j;
    struct Entity *e;

    for (j = 0; j <= 13; j++) {
        pool = gEntities;
        base8 = &gEntities[8];
        e = &base8[j];

        if (e->status & 0x08) {
            if ((u8)sub_0800679C(&gIwram_6110, 3, 6))
                continue;

            if (!(e->status & 0x80)) {
                e->field_32 = sub_08000764(0xC8) + 0x32;
                e->status |= 0x80;
                e->field_2C = gGameStuff._unk00;
                continue;
            }

            if (gGameStuff._unk00 - e->field_2C <= e->field_32)
                continue;

            if (gIwram_6110.spawnMask != 0)
                sub_0802C3E4(actor, 8, j);
            else if ((u8)sub_08000764(3))
                sub_0802C3E4(actor, 8, j);

            e->status &= 0xFF7F;
            sub_080059C4(e);
            continue;
        }

        sub_0800696C(&gIwram_6110, j + 8);

        if (!sub_0802C5E0(8, j)) {
            e = &base8[j];
            if (e->field_1A > 5) {
                if (e->status & 0x8000) {
                    e->status &= 0x7FFF;
                    switch (e->field_1A) {
                    case 6:
                        e->field_1A = 0;
                        break;
                    case 7:
                        e->field_1A = 2;
                        break;
                    case 8:
                        e->field_1A = 4;
                        break;
                    default:
                        goto do_call;
                    }
                    e->status |= 2;
                }
            do_call:
                sub_080059C4(e);
                continue;
            }

            if (e->status & 0x8000)
                e->status = (e->status & 0x7FFF) | 2;
            sub_08020F3C(j + 8);
            sub_080059C4(e);
            continue;
        }

        if (sub_0802C640(8, j))
            return;
    }
}
```

(The dual-base variant — `e = (struct Entity *)((j+8)*sizeof(struct Entity) +
(u32)pool)` with `sub_080059C4(&base8[j])` — gives byte_diff 371 but is
structurally closer to the target's two-base form; resume from whichever the
permuter prefers.)
