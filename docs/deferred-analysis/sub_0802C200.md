## Round 38 BREAKTHROUGH (escape the prior plateau — re-apply these)

The round-25 note called the `(j+8)*0x38 -> j*0x38 + 0x1c0` distribution "the
IRREDUCIBLE divergence" and "a HARD agbcc codegen invariant". **It is NOT.**
Round 38 cracked it and drove byte_diff 394 -> **322** with **exact size (484)**
and the target's exact register layout. Re-apply, do not re-derive from cold:

1. **The distribution is `expand_expr`, not fold/CSE.** It is the
   "Apply distributive law if OP0 is x+c" branch in
   `tools/agbcc-src/gcc_arm/expr.c` line ~7093 (case `MULT_EXPR`,
   `modifier == EXPAND_SUM`): when an ARRAY_REF index expands to a
   `PLUS(reg, const)` rtx, `(j+8)*0x38` is rewritten to `j*0x38 + 0x1c0`.
   `fold-const.c`'s `associate`/`split_tree` does NOT do it (split_tree
   returns 0 for code==MULT over a PLUS), and `reduce_expression_tree_depth`
   only explodes same-CODE operands — so all the round-25 flag sweeps were
   neutral *for the right reason*: the distribution is in expand, gated on
   nothing tunable.

2. **DEFEAT it by materialising the index in a register BEFORE the multiply.**
   A named local `s32 off = (j + 8) * 0x38;` (or `s32 k = j + 8;`) forces
   agbcc to compute `j+8` into a register first, so `op0` at the expand site
   is a REG, not `PLUS(reg,const)`, and the distributive branch does not fire.
   Loop top then emits the target's `asr; adds #8; lsl #3; sub; lsl #3` and
   keeps `(j+8)*0x38` undistributed. (Inline `pool[j+8]` always distributes.)

3. **`off` (NOT `k`) is the right named value** — it makes agbcc keep the
   OFFSET `(j+8)*0x38` live across the loop body (target's `r5`), recomputing
   `j+8` at the call sites, exactly like the target. A named `k = j+8` instead
   keeps the INDEX live (agbcc's cheaper choice) and recomputes the offset →
   wrong (byte_diff 406, diff_count 178). Access the pool fields as
   `*(u32 *)((char *)pool + off + 0x2c)` / `*(u16 *)(... + 0x34)`.
   NOTE: a bare `s32 off` formed a strength-reduced IV (size 440) UNTIL the
   high-reg pins (next item) were added — with the pins, no IV forms even
   without `-fno-strength-reduce`.

4. **Pin `pool=r8`, `base8=sl`, `owner->actor=r9`** (`register T x asm("rN")`,
   pure C). Leave `off` UNPINNED (pinning `off=r5` gives an awkward
   `subs r5,r5,r0` multiply; unpinned, agbcc places the offset in r5 itself).
   These three pins lock the target's high-reg layout, stabilise the offset
   into r5, and bring size to EXACT 484. byte_diff 322, diff_count 126.

5. **`(u8)sub_08000764` truncation.** Use a `u8 r` temp:
   `r = sub_08000764(0xC8); e->field_32 = r + 0x32;` — this emits the target's
   `lsls #24; lsrs #24` truncation of the return that a one-liner drops.
   Coin-flip keeps `(u8)sub_08000764(3)`.

6. Entity struct needs `u32 field_2C;` at +0x2C — split `field_2B[5]` into
   `u8 field_2B; u32 field_2C;` in include/iwram.h (the +0x2C field is a u32
   spawn-timestamp snapshot of `gGameStuff._unk00`). RE-APPLY this split; this
   deferral is docs-only so iwram.h is left pristine. It is a correct,
   independently-useful struct fix once the decomp lands.
