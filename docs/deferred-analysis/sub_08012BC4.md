# Deferred analysis: sub_08012BC4

Tilemap blit helper at 0x08012BC4 (232 bytes). Copies a `width x srcRows`
block of u16 tiles from `srcTable[srcIndex]` into one of two EWRAM tilemap
buffers (0x02000000 or 0x02010000, selected by flag bit 4 of `flags`),
then calls sub_080100E4 to flush it to VRAM screenblock 28/29, clears a
sentinel byte at 0x030064CA, and (when srcIndex==0) sets the
BG2-active byte at 0x03003610.

`state` = 0x030060A0; `state[13]` (offset 0x1A, u16) is the destination row
stride. The dst pointer advances `state[13] - width` halfwords after each
copied row.

## Parameters / register homes (from the baserom prologue)
- p0 `flags`  -> `ip` as `flags << 24`; the flag is `(ip>>28)&1` = bit 4.
  Computed twice (once before the loop, once via `r5 = ip>>28; r5 & 1`
  at the tail for the sub_080100E4 base selection).
- p1 `dstX`   -> r9  (u16)
- p2 `dstY`   -> r2  (u16)
- p3 `width`  -> **r6** (u8)   <-- key: baserom MOVES width to callee-saved r6
- p4 `srcRows`-> sl  (u8)   [sp,#32]
- p5 `srcTable` (const u16 **) [sp,#36]
- p6 `srcIndex` -> r8 (u8)  [sp,#40]

## Resolution

Matched as pure C in `src/engine/sub_08012bc4.c`. Verified with
`compile_and_view_assembly.py sub_08012BC4 --human` (`byte_diff 0`) and
`make check`.

The final lever was reusing an ordinary `scratch` pseudo, not a hard `r7`
register variable, for both the table index and the row-stride reload:
`scratch = loopState; scratch = ((struct BlitState *)scratch)->stride;`.
That lets agbcc allocate the pseudo to `r7` naturally and emit the target
`mov r7, ip; ldrh r7, [r7, #26]` pair. After that allocator shape is in
place, `dstY`, `srcRows`, and `src` no longer need hard register homes, and
the final BG2-active byte can be written as a direct `*(u8 *)0x03003610 = 1`.

## Historical drift notes

Earlier plateaus were pure register-coloring + prologue-promotion-order drift:

1. Baserom prologue promotes params in PARAMETER order, fully extending each
   (`lsls;lsrs;mov` per param). agbcc instead BATCHES all the `lsls #N`
   first, then the `lsrs/mov`, so `mov ip,r0` / `mov r9,r1` land late.
2. Baserom allocates **width -> r6** (callee-saved), freeing r3 for the dst
   base (`movs r3,#0x80; lsls r3,#18` = 0x02000000 built directly in r3),
   state ptr -> r4, and saves state across the inner loop via `mov ip,r4`.
   My builds keep width in r3 (where p3 arrives) and put dst in r5, state
   in r1, re-loading state from the pool at the bottom of the outer loop.

This is a 4-way SIMULTANEOUS coloring (width=r6, flag-nibble=r5, dst=r3,
state=r4). agbcc's local-alloc priority `QTY_CMP_PRI = floor_log2(n_refs)*
n_refs*size/live_len` (tools/agbcc-src/gcc_arm/local-alloc.c:1488) picks the
lowest free register per quantity in priority order, and my C structures all
land on a *different but valid* coloring.

## Early levers tried
- `register u32 f asm("ip") = flags<<24`  -> 153 (best; needed, else flags
  lands in r6 and width can't reach it).
- `register asm("r9"/"r8")` pins for dstX/srcIndex are still required in the
  final source. The `srcRows` value naturally lands in `sl` after the final
  lifetime cleanup.
- u8 loop counters (row/col) -> 186 -> 153 (helped; matches the `(u8)i+1`
  truncations).
- Pinning `width` to r6 (with or without the ip pin) -> ALWAYS spills
  (`sub sp, #4`): the flag-nibble also wants a callee-saved reg and there
  isn't a free one, so forcing width->r6 overflows. byte_diff 202-214.
- Pinning `dst` to r3 -> 208 (fights p3 arriving in r3).
- Local-declaration reordering (dst before state) -> no change (153).
- Caching `nibble = f>>28` in a variable for the 2nd flag test -> 197 (worse,
  extra reg).
- `-fno-schedule-insns` per-TU -> agbcc rejects the flag (scheduling is
  already off: flag_schedule_insns=0 default), so NOT a scheduler artifact.
- decomp-permuter: base score 3320, ~1200 iters over two runs, crawled to
  best 2730 — never near 0. The drift is global register assignment the
  randomizer's statement/scope mutations don't reach.

### 2026-05 continuation findings

- Delaying `rows/width/index` assignment until after the EWRAM base branch is
  what lets `dst` stay in `r3`. Moving `rows`/`index` earlier improves the
  apparent prologue order but regresses the body and grows to 240 bytes.
- `register const u16 *src asm("r2")`, `register u32 bank asm("r5")`, and
  tail temporaries pinned to `r2`/`r3` reduce the best diff from 153 to 117
  without changing size. The tail then matches the target's single-call shape
  much more closely.
- `s32 row` is the surprising allocator lever that keeps `width` in `r6`.
  Unsigned row types fix branch condition flavor but move row/width into the
  wrong registers. Casted unsigned comparisons also lose the `width -> r6`
  allocation.
- Hard-pinning `width`, `dst`, or `state` still spills/splits the pool. A
  scoped `ip` state alias also collides with the flag lifetime and regresses.
- The remaining body mismatch is row/state lifetime: target starts with row in
  `r0`, computes `nextRow` into `r4`, then time-shares `ip` for the
  `0x030060A0` state pointer. The best C keeps row/nextRow in `r4` and
  rematerializes the state pointer from the pool at the row advance.
- A later row-shaped variant (`row asm("r0")`, explicit `row = 0` before
  `bank = f >> 28`, scoped `nextRow asm("r4")`) reached the same **117**
  byte_diff with fewer instruction mismatches (**38**). It gets the loop
  entrance and `movs r1,#0; adds r4,r0,#1` order, but still keeps the state
  pointer in `r9` or rematerializes it; forcing `loopState asm("ip")` spills
  `dst` out of `r3` and grows the function. Treat this as a promising
  lifetime clue, not a shippable replacement.
- `-O1` plus the row-shaped loop can naturally produce the desired
  `state -> ip` handoff, and an explicit `rowState asm("r7")` produces
  `mov r7, ip` at the row advance. It is still not viable: the `-O1` prologue
  does not save `r7` like the target, and attempts to force `r7`/`r4` under
  `-O2` either move `dst` out of `r3` or split the literal pool. Keeping `x`
  (`r9`) artificially live after the loop did not stop `loopState` from being
  allocated to `r9`.

### Later 2026-05 plateau breaks

- Best reached in this pass: **byte_diff 95, diff_count 46**, size still 232.
  The two useful changes were:
  - Write the dirty-byte clear as a base plus offset:
    `u8 *sentinel = (u8 *)0x030064C0; sentinel[10] = 0;`. This matches the
    target's `ldr 0x030064C0; strb #10` tail and drops 117 -> 114.
  - Do **not** pin the shifted flag to `ip`; use `u32 f = flags << 24`, test
    the first buffer branch from `(flags >> 4) & 1`, and keep `bank = f >> 28`
    for the tail. This lets agbcc put the `0x030060A0` state pointer in `ip`
    across the row loop and drops 114 -> 96.
  - Split the initial stride load into `register u16 stride asm("r1")` before
    the destination offset calculation. This reproduces the target's
    `ldrh r1, [state,#0x1a]; mov/add r0, r1; muls ...` setup shape and drops
    96 -> 95. With the shifted flag pinned, the same `r1` stride split grows
    to 236 bytes, so this is only useful in the ordinary-`f` family.
- This is progress but not the match. It swaps the remaining allocator problem:
  the target uses `ip` for the shifted flag first, holds the state pointer in
  `r4`, computes `bank` from `ip`, then time-shares `ip` with `mov ip, r4`.
  The 95-byte C instead holds the shifted flag in `r7` and the state pointer
  in `ip` from setup onward.
- Scoped `register u32 f asm("ip")`, hard-pinning state/stateAddr to `r4`,
  two-pointer aliases, struct aliases, linker-pinned `gIwram_60A0` /
  `gIwram_64C0`, `-ffixed-r7`, `-ffixed-r9`, and formal-parameter type sweeps
  all regressed. `old_agbcc` is identical for the 96-byte shape.
- A structurally interesting alternate reached **byte_diff 113, diff_count 38**:
  pin the shifted flag in `ip`, split stride into `r1`, use a row-in-`r0`
  precheck, and introduce a plain `loopState = state` inside the non-empty
  row block. That version gets `state` into `r4`, keeps `width` in `r6`, and
  keeps `dst` in `r3`, but agbcc assigns `loopState` to `r9` and emits
  `mov r9, r4` instead of target `mov ip, r4`. Naming `loopState asm("ip")`
  produces the desired hard register but pushes `dst`/`width` into the wrong
  registers and grows the function.
- Follow-up targeted tests did not find a clean way out:
  - C89/K&R parameter declarations compile identically to the prototype form;
    they do not change the parameter-promotion ordering.
  - Removing the standalone `dstY = (u16)dstY` and casting only in the offset
    expression also compiles identically; the prologue drift is not caused by
    that source statement.
  - A global `nextRow asm("r4")` plus explicit `col = 0; nextRow = row + 1`
    matches the target loop-top order (`movs r1,#0` before `adds r4,r0,#1`)
    and gives **byte_diff 115, diff_count 36**. It still leaves the same
    `loopState -> r9` handoff and adds a tail constant-coloring drift.
  - A small per-TU flag sweep did not beat the 95-byte family:
    `-fno-cse-follow-jumps`, `-fno-cse-skip-blocks`, `-fno-peephole`,
    `-fno-strength-reduce`, `-fcaller-saves`, and `-fno-caller-saves` are
    unchanged from the row-shaped source; `-fno-gcse` (228 bytes),
    `-fno-rerun-cse-after-loop` (236 bytes), `-ffixed-r3`, `-ffixed-r5`,
    `-ffixed-r8`, `-ffixed-r9`, `-ffixed-r10`, `-fcall-used-r8/r9/r10`,
    and `-fcall-saved-r12/r3` all regress.
  - `-ffixed-r7` is a clue only: it naturally produces `mov ip, r4`, but the
    prologue stops saving r7 (`push {r4,r5,r6,lr}`), so it cannot match the
    target as a TU flag.
  - A statement-expression `stateReg asm("ip")` around the row-advance load
    emits `mov ip, r9` inside the loop and grows to 236 bytes. A goto-shaped
    explicit loop likewise regresses.

### 2026-05 isolated worktree continuation

- Best honest shape in this continuation: **byte_diff 90, diff_count 31**,
  size 232. The useful combination is:
  - `rows` and `index` as `register u32` pinned to `sl` / `r8` (using `u8`
    for either one spills/grows).
  - `width` as `register u32 width asm("r6")` (using `u8` for the pinned
    width spills).
  - `f` pinned to `ip`, `row` pinned to `r0`, `nextRow` pinned to `r4`, and
    a scoped `loopState asm("ip") = state`.
  - The explicit `col = 0; nextRow = row + 1; if (col < width) do { ... }`
    loop shape matches the target loop top.
- Remaining 90-byte deltas:
  - Parameter normalization is still batched by agbcc: it emits the `lsl`s
    for `dstX`, `dstY`, `width`, `rows`, `srcIndex`, then shifts/moves
    `flags` into `ip`. The target interleaves each promoted value in
    parameter order (`flags -> ip`, `dstX -> r9`, `dstY`, `width -> r6`,
    `rows -> sl`, `srcIndex -> r8`).
  - Source-table indexing still uses `r1` as the temporary
    (`mov r1,r8; lsls r0,r1,#2`), while the target uses `r7`
    (`mov r7,r8; lsls r0,r7,#2`).
  - The row advance with `u16 *state` preserves the target save set but
    precomputes the address before the inner copy:
    `mov r7,ip; adds r7,#0x1a; ...; ldrh r7,[r7]`. Target delays it:
    `mov r7,ip; ldrh r7,[r7,#0x1a]`.
- Typed `struct BlitState { u8 pad[26]; u16 stride; }` is a strong clue but
  not shippable yet. It gets the offset load form and reaches
  **byte_diff 68**, but the compiler no longer preserves `r7`:
  `push {r4,r5,r6,lr}` instead of target `push {r4,r5,r6,r7,lr}`. Variants
  with a plain `rowStride`, top-level `rowStride`, a table-index local, or
  `row` moved before the stride load did not restore the save set.
- Extra levers tried in this worktree:
  - Raw byte pointer (`*(u16 *)(state + 0x1a)`) collapses to the same
    precomputed-address form as `u16 *state`.
  - `srcTable += index; src = *srcTable` loads `srcTable` into `r7` too early
    and shifts the pool; address-integer indexing uses `r0/r1`, not target
    `r7/r1`.
  - `register` parameters, split `f = flags; f <<= 24`, and moving the first
    bank branch before `rows/index` do not fix the prologue order.
  - A direct goto spelling compiles back to the same 90-byte loop, confirming
    the row-address hoist is optimizer/allocator driven rather than a
    structured-loop artifact.
  - `-O1` and `-fno-gcse -fno-regmove` can reduce raw byte diff to 76, but
    only by dropping the required `r7` save; this is a false lead.
  - Keeping both `row` and `col` live across the stride load forced more
  pressure, but agbcc put the destination pointer in `r7` instead of the
  stride temporary.

### 2026-05 v2 final breakthrough

- Final result: **byte_diff 0, diff_count 0**, size exact at 232.
- The big unlock was widening the ABI-facing parameters and doing explicit
  casts in source order:
  `flags/dstX/dstY/widthArg/srcRowsArg/srcIndex` as `u32`. Earlier variants
  pinned `y` to `r2`, but the final source leaves `y` ordinary and still gets
  the byte-exact prologue through the `r8` index setup.
- A delayed `u32 scratch = index` used for the table lookup, plus a harmless
  `bank = (bank & one) + scratch - scratch`, forces the source-table scratch
  to `r7` without losing the final `r8` compare.
- Declaring `sub_080100E4` with a word-sized first argument (`u32`) is required
  for agbcc to keep the target call sequence:
  `mov r0,#1; ands r5,r0; adds r0,r5,#0`.
- The final-byte store originally needed pointer/constant shaping while the
  surrounding tail was still drifting. In the final allocator shape, the plain
  direct store `*(u8 *)0x03003610 = 1` matches.
- The last 2 bytes closed when the same `scratch` pseudo first held the
  `loopState` base and was then overwritten by the stride load. Hard-pinning
  a separate stride local to `r7` kept producing
  `mov r0, ip; ldrh r7, [r0, #26]`; the ordinary pseudo gives the desired
  `mov r7, ip; ldrh r7, [r7, #26]`.
- Row-stride attempts that did **not** close:
  hard `rowBase asm("r7")` plus `rowStride`, integer-address casts, volatile
  struct fields, split `dst += rowStride; dst -= width;`, moving the row update
  before the stride advance, and freeing the `loopState` pin. Freeing
  `loopState` reaches **byte_diff 5** but chooses `r9` instead of `ip`.

## Obsolete early best-effort C (byte_diff 153, size exact)
```c
#include "macros.h"
#include "types.h"

extern void sub_080100E4(u8, void *, void *);

void sub_08012BC4(u8 flags, u16 dstX, u16 dstY, u8 width, u8 srcRows, const u16 **srcTable,
                  u8 srcIndex)
{
    register u32 f asm("ip") = flags << 24;
    register u16 x asm("r9") = dstX;
    register u8 rows asm("sl") = srcRows;
    register u8 index asm("r8") = srcIndex;
    u16 *dst;
    u16 *state;
    const u16 *src;
    u8 row;
    u8 col;

    if ((f >> 28) & 1) {
        dst = (u16 *)0x02010000;
    } else {
        dst = (u16 *)0x02000000;
    }

    state = (u16 *)0x030060A0;
    dst += state[13] * dstY + x;
    src = srcTable[index];

    for (row = 0; row < rows; row++) {
        for (col = 0; col < width; col++) {
            *dst++ = *src++;
        }
        dst += state[13] - width;
    }

    if ((f >> 28) & 1) {
        sub_080100E4(1, (void *)0x02010000, (void *)0x0600E800);
    } else {
        sub_080100E4(0, (void *)0x02000000, (void *)0x0600E000);
    }

    *(u8 *)0x030064CA = 0;
    if (index == 0) {
        *(u8 *)0x03003610 = 1;
    }
}
```
