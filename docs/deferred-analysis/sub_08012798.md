# sub_08012798 — deferred analysis

Parameterless tilemap blit. Same idiom as the matched sibling **sub_08012BC4**
but with all blit parameters computed inline from a ROM descriptor and entity
slot 30 coords, and `srcIndex` fixed at 0.

Semantics:
- descriptor at ROM `0x08306E64`: `+4` = width, `+6` = rows, `+8` = flags
  (`>> 4 & 1` selects EWRAM/VRAM bank 1), `+16` = source-row table.
- destination coords are `(u16)(entity[30].x * 3)` and
  `(u16)(entity[30].y * 3)`, read as signed halfwords from
  `0x03003720 + 0x692 / + 0x694`.
- blits `srcTable[0]` into EWRAM bank `0x02000000`/`0x02010000` at
  `dstY * *(u16 *)(0x030060A0 + 0x1A) + dstX`, then flushes via
  `sub_080100E4(flags & 1, ewramBank, vramBank)`.
- clears `0x030064C0[10]` and sets `*(u8 *)0x03003610 = 1`.

## Drift

Classifier: `ATTEMPT_MATCH`. Callees `sub_0801185C` and `sub_080100E4` are
already peeled.

Best reached this pass: **diff_count 50 / byte_diff 109**, size-correct
244 bytes, pure C with register declarations only. The remaining drift is
still a coupled register-allocation plateau:

1. Target loads descriptor into `r3`; agbcc allocates descriptor to `r7`.
   Pinning `desc asm("r3")` fixes those descriptor loads but breaks the
   prologue (`push {r4,r5,r6,lr}` instead of `{r4,r5,r6,r7,lr}`) and moves the
   bank value into `r5`, yielding **diff_count 52 / byte_diff 118**.
2. Target uses `movs r7, #0; ldrsh ..., [ptr, r7]` for both signed coord reads.
   A scoped `register zero asm("r7")` probe emitted an extra `movs r7,#0` but
   reload still chose `r2`/`r0` for the actual `ldrsh` index, so it did not help.
3. Target time-shares `r6`: first `srcTable`, then `flags` after
   `src = srcTable[0]`. Whole-function `srcTable asm("r6")` reaches the best
   plateau, but keeps `r6` unavailable for the later flags copy, so built code
   uses `ldr r6, [r6]` for `src` and never emits target `ldr r1, [r6]; adds r6, r3, #0`.
   Narrowing the `srcTable` pin to a scope ending after `srcTable[0]` made the
   function shorter and worse (**diff_count 61 / byte_diff 182**); agbcc still
   kept the loaded source in `r6`.
4. A scoped `stride asm("r1")` did not solve the source-pointer/flags time-share
   when combined with the narrowed `srcTable` scope.
5. Newer `AGBCC_BIN` for this TU was identical to default `OLD_AGBCC_BIN` at the
   best plateau (**diff_count 50 / byte_diff 109**). No compiler-version lever.
6. Current-tree corpus search finds many `ldrsh ..., [*, r7]` asm hits but no
   current C pattern for forcing this exact zero-index idiom. History
   `corpus_asm_search.py --require-c` could not be run because
   `tools/agent/corpus-mirrors/` is not populated in this worktree.

The next useful attempt should instrument a private copy of
`tools/agbcc-src/gcc_arm/{local-alloc,regclass,reload,reload1}.c` around the
hard-register choice for the descriptor pseudo, signed-halfword zero index, and
post-`srcTable[0]` `r6` reuse. The source shape needed is likely a small change
that flips one allocator decision; local pinning one variable at a time only
moves the plateau.

#define SPAWN_ENTITY_X_OFFSET (SPAWN_ENTITY_SLOT * sizeof(struct Entity) + 2)
#define SPAWN_ENTITY_Y_OFFSET (SPAWN_ENTITY_SLOT * sizeof(struct Entity) + 4)

#define BLIT_VRAM_BANK0 ((void *)0x0600E000)
#define BLIT_VRAM_BANK1 ((void *)0x0600E800)

struct TilemapDescriptor {
    u32 _field_00;
    u8 width;
    u8 _field_05;
    u8 rows;
    u8 _field_07;
    u8 flags;
    u8 _field_09[7];
    const u16 **srcTable;
};

struct BlitState {
    u8 _pad00[26];
    u16 stride;
};

void sub_08012798(void)
{

    register u32 rows asm("r9");
    register u32 dstY asm("ip");

    u32 width;

    u32 nextRow;
    u16 stride;

    entities = (u8 *)0x03003720;

    rows = desc->rows;
    srcTable = desc->srcTable;

                do {

                    col++;

        flushDst = BLIT_VRAM_BANK0;

        sentinel[10] = 0;
    }

}
