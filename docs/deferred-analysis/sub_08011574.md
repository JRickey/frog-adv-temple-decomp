Prologue, epilogue, control flow, the `ip` field_a-copy/compare, the field_b read
(into r1), and the gGameStuff post-BL reload all MATCH. Three register-coloring /
fold diffs remain:

1. **field_a in r2 (caller-saved), target wants r7 (callee-saved).** Root cause:
   in the target, `field_a + 1` is emitted PRE-call but its live range crosses the
   r0-r4-clobbering field-arg reads, forcing callee-saved r7. In every C structure
   tried, agbcc emits the `+1` right after the timer-check (field_a range is SHORT,
   ends before the field reads), so field_a gets a caller-saved reg (r2).

   ldr [r4,#16]` (i.e. `(base+stride)`, +16 as ldr offset). agbcc reassociates
   `base+16+stride` → `(base+stride)+16` and folds. `(base+16)+stride`, a block-scoped

### The exact asm idiom that diverges
The baserom keeps `fieldA` (`s->field_a`) live **redundantly in BOTH r7 and ip** for the entire function body, and uses **fresh caller-saved scratch registers (r0, r1, r4)** for three short-lived temps:
- gGameStuff materialization: baserom `ldr r0,[pc]; mov r9,r0; ldr r0,[r0,#0]` — pool addr in **r0**, dereferenced through r0.
- field_b reload for the timer compare: baserom `ldrb r1,[r5,#11]` — into **r1**.
- srcTable base recompute: baserom `mov r4,r8; adds r4,#16; adds r4,r6,r4; ldr r4,[r4,#0]` — copy tableBase to **r4**, +16 as a *separate* `adds`, then +stride, then `ldr [.,#0]`.

agbcc instead observes that after `mov ip, r7` the value of fieldA is duplicated, declares **r7 dead**, and **reuses r7** as the scratch for all three temps: `ldr r7,[pc]; mov r9,r7` (gGameStuff), `ldrb r7,[r5,#11]` (field_b reload), `mov r7,r8` (srcTable base) — and folds the srcTable +16 into the load offset (`ldr r4,[r4,#16]`). ## Round 2 (Opus escalation) — re-derived from scratch; byte-30 base is a MISCOMPILE

Confirmed by reading the emitted asm (not just byte_diff): the documented
"byte_diff 30" base (full pins incl. `register u32 fieldA asm("r7")`, comma-arg
`(s->field_a = fieldA+1, ipVal)`) is **semantically WRONG**. agbcc reload reuses
the pinned r7 as the srcTable base scratch:

    mov r7, r8        ; r7 := base   (CLOBBERS pinned fieldA)
    add r4, r6, r7    ; srcTable addr
    ldr r4, [r4,#0x10]
    add r4, r7, #1    ; r4 := base+1  -> s->field_a = base+1  (WRONG)
    strb r4, [r5, #0xa]

So `s->field_a` is stamped with `base+1`, not `fieldA+1`. The byte-30 distance is
illusory — DO NOT ship or permute from it. Every `fieldA asm("r7")` variant
miscompiles this way (reload ignores the pin for the high->low srcTable copy).

### The genuine barrier (a reload coloring fixed-point)

The target keeps `fieldA` in r7 (callee-saved low) for the WHOLE body, so the
`+1` reads it at the end. For that, r7 must never be a scratch. The target funnels
every scratch through r4/r0/r1:
  - base initial load  -> r4   (`ldr r4,=tbl; mov r8,r4; adds r4,r6,r4`)
  - gGameStuff temp    -> r0   (`ldr r0,=gs; mov r9,r0; ldr r0,[r0]`)
  - field_b reload     -> r1   (`ldrb r1,[r5,#0xb]`)
  - srcTable base copy -> r4   (`mov r4,r8; adds r4,#16; adds r4,r6,r4; ldr [r4]`)
  - post-BL gs reload  -> r1   (`mov r1,r9; ldr r0,[r1]`)

From correct C, agbcc instead claims a callee-saved reg (r7) for the base-load or
srcTable copy, which evicts fieldA to **sl** (a 3rd high-reg save → +`push {r5,r6,r7}`
cascade) or to a stack slot. That single eviction accounts for the bulk of the diff.
