### Exact residual diffs (byte_diff 88 version) vs target

Prologue, epilogue, control flow, the `ip` field_a-copy/compare, the field_b read
(into r1), and the gGameStuff post-BL reload all MATCH. Three register-coloring /
fold diffs remain:

1. **field_a in r2 (caller-saved), target wants r7 (callee-saved).** Root cause:
   in the target, `field_a + 1` is emitted PRE-call but its live range crosses the
   r0-r4-clobbering field-arg reads, forcing callee-saved r7. In every C structure
   tried, agbcc emits the `+1` right after the timer-check (field_a range is SHORT,
   ends before the field reads), so field_a gets a caller-saved reg (r2).
   `-fno-schedule-insns{,2}` do NOT move it (verified — it's local-alloc/RTL emission
   order, not the scheduler). Moving the `+1` statement AFTER the call makes agbcc
   spill field_a to `sl`/r10 (a 3rd high-reg save — worse).

2. **srcTable `+16` folds into the ldr offset.** Target: `mov r4,r8; adds r4,#16;
   adds r4,r6,r4; ldr [r4]` (i.e. `(base+16)+stride`). Mine: `add r4,r6,r7(base);
   ldr [r4,#16]` (i.e. `(base+stride)`, +16 as ldr offset). agbcc reassociates
   `base+16+stride` → `(base+stride)+16` and folds. `(base+16)+stride`, a block-scoped
   `u8 *p=base+16`, etc. all either still fold or precompute base+16 into a low reg
   (r5, clobbering gIwram) — neither is the target's "recompute from r8 each time".

3. **base-pin entry-mov.** With `register u8 *base asm("r8")`, the FIRST entry
   computation needs `mov r1,r8; adds r4,r6,r1` (extra mov) because r8 can't feed a
   3-op `adds`. Target loads base into r4 first (`ldr r4,=base; mov r8,r4; adds
   r4,r6,r4`) — base lives in BOTH r4 (immediate use) and r8 (later srcTable). The
   pin forces base ONLY into r8. WITHOUT the base pin, base is not kept across the
   field reads (the srcTable folds to entry+16), so it's never promoted to r8 — the
   chicken-and-egg: base-alive ⟺ srcTable-not-folded ⟺ entry-dead.

All three are the SAME knot: the target keeps {gIwram r5, stride r6, field_a r7,
base r8, gGameStuff r9} all live simultaneously + an ip copy of field_a, which
forces entry to share r4 with the `rows` arg (so entry dies → srcTable recomputes
from base, base stays in r8). I could not get the allocator into that exact 5-callee-
saved + ip pressure state from pure C: pinning base+gs+ip gets gIwram→r5, stride→r6,
gGameStuff→r9 correct, but field_a lands in r2 (not r7) so the pressure is one reg
short and the fold/entry-mov appear.
