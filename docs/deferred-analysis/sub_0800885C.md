# sub_0800885C — deferred analysis

ATTEMPT_MATCH (classifier: no structural-impossibility signature). Function is
clean game logic and almost certainly matchable; the residual is pure agbcc
register-coloring around one un-folded constant that no lever tried so far
reproduces. Deferred, not NAKED — DO NOT ship NAKED.

## What the function is

Directional area attack. Range [0x0800885c, 0x080089a4), 328 bytes, one callee
(`sub_080089A4`, already peeled at 0x080089a4).

- Args: `(u8 arg0, u8 arg1)`; both sign-extended to s8 (`a`, `b`).
- Switches on `gIwram_3720._field_1A` (offset 0x1A), cases 12..15. Each case calls
  `sub_080089A4(sel, d1, d2, d3, &xLo, &xHi, &yLo, &yHi)` to fill a box:
    - case 12: sel=0, (b, a, b)
    - case 13: sel=1, (b, a, b)
    - case 14: sel=2, (a, a, b)
    - case 15: sel=3, (a, a, b)
  The four out-params are FOUR SEPARATE s16 locals (NOT an array — arrays change
  the stack-pointer setup; separate locals reproduce `add r0,sp,#16; adds r0,#2;
  add r0,sp,#20; adds r0,#2`). Stack frame: xLo=sp+16, xHi=sp+18, yLo=sp+20,
  yHi=sp+22.
- Loops i over `gIwram_6110.liveCount` (offset 0x31), reading the index table
  `gEntityIndex_03006160[i].id` (u8, stride 8). For each non-zero id, the 56-byte
  entity record is `gEntities_03003720[id]` (stride 0x38). Skip unless: `_h34 & 4`
  clear, `gEntities[0]._b6 == e->_b6`, and `e->_h2` strictly in (yLo, yHi) and
  `e->_h4` strictly in (xLo, xHi). The first record with `_b0 == 11` is latched
  (`e->_h34 = 0x80 | flags | 4`) and returns 1. Else returns 0.

`sub_080089A4` signature derived from its asm:
`void sub_080089A4(u8 sel, s8 d1, s8 d2, s8 d3, s16 *x0, s16 *x1, s16 *y0, s16 *y1)`
(r1→d1 used as primary delta, r2/ip→d2, r3→d3; writes x0=ctr-d/2, x1=ctr+d/2 for
each pair).

## Drift

Best clean PURE-C result: **byte_diff 144, size 328** (correct size) with
`register u16 flags asm("r5")` pinning the cached `_h34` and four separate s16
locals (in src/game/sub_080087b4.c, appended after sub_080087B4). The loop body
is byte-for-byte identical to the target EXCEPT register numbers.

Two coupled, unresolved divergences:

1. **Held `4` in r7 + the latch fold.** The baserom latch is THREE ORs with `4`
   held in a callee-saved register across the loop body:
       movs r7, #4            (set at loop top, 0x893c, alongside ldrh r5=flags)
       ...
       movs r0, #0x80 ; orrs r0, r5(flags) ; orrs r0, r7(4)   (the hit, 0x88ea)
   Any literal source `0x80 | flags | 4` (or `(flags|0x80)|4`, or two `|=`
   statements) is constant-folded by agbcc's tree `fold()`/`associate` to
   `flags | 0x84` (`movs r0,#0x84; orrs`), which is UNCONDITIONAL — no `-fXXX`
   flag controls it (`-fno-expensive-optimizations` does not stop it). The fold
   collapses the second `4`, so `-frerun-cse-after-loop` never gets two `4`s to
   CSE into r7, so r7 is never reserved → prologue stays `push {r4,r5,r6,lr}`
   (missing r7) and the whole loop allocation shifts down by one register
   (i=r3, bound=r4, temp=r6 instead of the target i=r4, bound=r6, temp=r3).

2. **Box-pointer setup in the last switch case (15).** Cases 12/13/14 emit the
   clean `add r0,sp,#16; str; adds r0,#2; ...`; case 15 (falls through to the
   loop, box still live) instead holds `&xLo` in callee-saved r6
   (`add r6,sp,#16; str r6; mov r0,sp; adds r0,#18`). ~6 mismatch entries.
   `-fforce-addr` fixes the recompute style but breaks the sibling sub_080087B4
   in the same TU (BL-to-__divsi3 offset).

## Levers already tried (all FAILED — pick a DIFFERENT one)

- Four separate s16 locals (vs `s16 box[4]` / `s16 xb[2],yb[2]`): separate locals
  give size 328 and the closest result; arrays diverge the pointer setup. KEEP
  separate locals.
- `register u16 flags asm("r5")`: helps (144), keeps flags in r5. KEEP.
- `register ... latch asm("r7") = 4` (loop scope): produces the 3-OR form but
  corrupts the box reads (`movs r0,#8; ldrsh r0,[r0,r6]` garbage) — r7 was the
  box scratch.
- `register ... latch asm("r7") = 4` (function scope): emits `movs r7,#4` at
  function entry but does NOT add r7 to the push list (uses r7 unsaved) and
  mis-places the materialization.
- `u16 mask = 4` loop-local used in BOTH test+OR: `mask` in the test changes the
  `ands` source (target test uses a fresh literal `movs r0,#4`); and `mask`
  hoists to a redundant pre-loop `movs` (+4 bytes → size 332).
- `u16 mask = 4` used ONLY in the OR + `-fno-gcse`: gives the CORRECT prologue
  `push {r4,r5,r6,r7,lr}` AND the correct 3-OR `orrs r3,r0; orrs r3,r5`, but a
  redundant hoisted `movs r5,#4` before the loop keeps size at 332/byte_diff 238.
  Could NOT kill the hoist with `-fno-rerun-loop-opt`, `-fno-rerun-cse-after-loop`,
  or `-fno-move-all-movables` (all still 332).
- Two-statement `flags |= 0x80; flags |= 4;`: re-reads/writes `_h34`, size 332.
- CFLAGS combos on a SEPARATE file src/game/sub_0800885c.c (to isolate from
  sub_080087B4): `-fno-gcse`, `-fno-expensive-optimizations`, `-fforce-addr`, and
  pairs. None reached 328 with the right coloring; `-fforce-addr`/`-fno-exp-opt`
  shift the temp register r3→r7.

## What the NEXT attempt should try (DIFFERENT levers)

- The crux is making the latch's `4` a NON-foldable runtime value so
  `-frerun-cse-after-loop` reserves r7 for it. Ideas not yet tried:
  - An `asm("")` optimization barrier on the mask between its definition and the
    latch use, to defeat the tree-level fold without disabling a whole pass.
  - Read the inactive-mask bit from a tiny `static const u16` (forces a load, not
    a literal — then CSE the load value into r7). Check whether the resulting
    extra `ldr` matches or breaks.
  - Compute the latch from the SIGN/zero of a loop value so the `4` is data-
    dependent (e.g. derive from `flags` after the `&4`-clear test) — risky.
  - Read agbcc-src `gcc_arm/fold-const.c` `associate`/`fold` for BIT_IOR to find
    the exact tree shape that escapes constant combination, and the
    `gcc_arm/cse.c` `cse_around_loop` / `loop.c` invariant-motion to understand
    why a loop-local `4` is both hoisted AND CSE'd in-loop (the double
    materialization). The right C is the one that yields a SINGLE in-loop
    `movs r7,#4`.
- Separately, the case-15 box-base-in-r6 needs the per-case setup to match
  cases 12-14. Reordering the switch arms or a shared post-call `goto` may
  equalize the codegen without `-fforce-addr`.
- Permuter not yet run (scratch setup was blocked: extract-function-bytes --asm
  emits objdump style with baked-in pool/BL data, not a clean `glabel` target.s;
  build_expected.py needs the symbol already in a built .o). Build target.o by
  compiling a near-match and objcopy'ing, or hand-write target.s with the pool

    u8 _pad[7];

{

        break;

        break;

        break;

}
