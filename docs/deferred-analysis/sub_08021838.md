# sub_08021838 — deferred analysis

A 388-byte engine helper at 0x08021838 (asm/disasm_0x08021838.s). Functionally
fully understood and decompiled; the C is byte-divergent only on agbcc 2.x
register allocation / coalescing in the prologue + the first switch, which has
resisted every lever tried so far.

## What the function does (confirmed against the disassembly)

Signature (5 params, ABI: r0..r3 + one stack arg at [sp,#36]):

    void sub_08021838(u8 *src, u8 dstIdx, u8 selector, u8 idx, u8 cmpVal)

- `src`  (r0 → pinned r8): pointer to an array of 8-byte source records
  (x@+0 u16, y@+2 u16, field@+4 s8).
- `dstIdx` (r1 → r7): index into the entity array `gEntities_03003720`
  (stride 56 = 0x38). Entity addr = base + dstIdx*56, which agbcc strength-
  reduces to `(dstIdx*8 - dstIdx) << 3` and CSEs the `dstIdx*8` partial in r4.
- `selector` (r2 → r4 copy): first switch selector (0/1/2/3).
- `idx` (r3 → r5): index passed to sub_080217D4; also reassigned to 2 in one
  case-1 branch.
- `cmpVal` (stack → r3): compared as `idx == cmpVal + 1` in every case.

Two switches:
1. `switch (selector)` decides how `result` (r6) and `idxReg` (r9) are set,
   mostly via `result = sub_080217D4(src, idx, idxReg)`. Case 1 has an
   `if (idx==2) { result = src[2]; idxReg = 3; }` fast path. Case 3 pokes
   bit 0x800 in `gEntities[dstIdx].flags` based on idx==cmpVal+1 / idx==2,
   then picks idxReg = idx±1 from whether bit 0x800 is set.
   In the `default`/selector==0 path, `result` (r6) is left UNINITIALIZED —
   the baserom does not set r6 on that path (do NOT initialize result=0).
2. `switch (result)` writes a 2-byte stack scratch `buf[2]` (buf[0]=dx,
   buf[1]=dy): result 1→buf[1]=-1, 2→buf[1]=1, 3→buf[0]=-1, 4→buf[0]=1.
   `bufHi` (= &buf[1]) is pinned to `sl`.

Tail: recompute `entity = &gEntities[dstIdx]`; `srcRecord = &src[idx*8]`;
`sub_0800A580(entity, srcRecord[4], buf[0], buf[1])`; then
`entity->x = srcRecord.x; entity->y = srcRecord.y; entity->_field_1A = result;
entity->flags |= 2; entity->_field_33 = idxReg;`.

Callees (both already peeled): sub_080217D4 @0x217d4, sub_0800A580 @0xa580.

## Drift

Best results by structure (all PURE C, no NAKED):
- Clean readable version (gEntities[dstIdx] inline, no register pins beyond
  r8/r9/sl): byte_diff 352, diff_count 130, size 396.
- BEST so far — pin `register s32 selector asm("r4")` + assign `(u8)selectorArg`:
  byte_diff 345, diff_count 147, size 396. THIS cracked the first switch:
  signed `s32` selector makes the dispatch use `cmp r4,#2 / bgt` (signed,
  matches the baserom) instead of `bhi` (unsigned), AND places selector in r4
  and cmpVal in r3 — both correct registers.

Remaining divergence in the r4-pinned version is concentrated in the PROLOGUE:
- baserom keeps selector in BOTH r2 (for the first three `cmp r2,#N` compares)
  and r4 (`adds r4,r2,#0`, used only for the `selector>2 → cmp r4,#3` branch).
  The r4 pin forces selector into r4 ONLY (all compares use r4), losing the
  r2 copy → the `adds r4,r2,#0` instruction never appears.
- baserom does `mov r8,r0` FIRST, then `ldr r0,[sp,#36]` (loads the stack arg
  into r0, z-exts to r3). Our build loads the stack arg into r4 as scratch
  (`ldr r4,[sp,#36]`), then z-exts to r3 — a scratch-register-choice diff that
  shifts the whole prologue.
- The explicit `selector = (u8)selectorArg;` copy is itself an artifact (the
  baserom has no separate copy instruction for it).

Net: the switch + case bodies + the entire tail (0x2196c onward) MATCH well;
the ~147 instruction diffs are dominated by prologue byte-shift, not logic.

## Next ideas (untried)

1. The crux is reproducing the baserom's selector dual-home: selector live in
   r2 for the main switch AND a callee-saved r4 copy for the deferred
   `cmp #3`. This is agbcc making selector callee-saved because `dstIdx*8`
   (which shares r4) crosses the case-3 call, and selector coalesces into it.
   Try: do NOT pin selector; instead force `dstIdx*8` to cross the case-3 call
   as a shared value with the tail (so r4 becomes callee-saved for the entity
   partial), then let the unpinned `int selector` naturally coalesce into r4.
   The blocker was that cmpVal grabbed r4 first — combine with cmpVal asm("r3")
   so r4 is free for the dstIdx*8/selector coalesce.
2. Try declaring the params as `int`/`s32` (not u8) and casting at use, so the
   switch is naturally signed (matching `bgt`) WITHOUT a register pin, removing
   the `(u8)selectorArg` copy artifact.
3. Read agbcc local-alloc.c qty_n_calls_crossed / CALLER_SAVE_PROFITABLE
   (lines ~1946, ~2062) to determine why cmpVal is flagged call-crossing in our
   C but not the baserom's; the answer dictates how to shorten its live range.

## Best-effort C (clean, readable — the 352/130 version; no register pins
beyond r8/r9/sl. The 345 version is this plus `register s32 selector asm("r4")`
and `selector = (u8)selectorArg;`.)

```c
#include "types.h"

typedef struct {
    u16 a;
    u16 b;
    u16 c;
    u16 d;
} Entry;

typedef struct {
    u8 _pad00[2];
    u16 x;        /* +2 */
    u16 y;        /* +4 */
    u8 _pad06[0x14];
    u8 _field_1A; /* +0x1A */
    u8 _pad1B[0x18];
    u8 _field_33; /* +0x33 */
    u16 flags;    /* +0x34 */
    u8 _pad36[2];
} Entity;

extern u8 sub_080217D4(Entry *base, u8 idxA, u8 idxB);
extern void sub_0800A580(Entity *e, s8 param, s8 deltaX, s8 deltaY);

extern Entity gEntities_03003720[];

void sub_08021838(u8 *src, u8 dstIdx, u8 selector, u8 idx, u8 cmpVal)
{
    register u8 *srcReg asm("r8");
    register u32 idxReg asm("r9");
    u8 result;
    s8 buf[2];
    register s8 *bufHi asm("sl");
    Entity *entity;
    s8 *srcRecord;

    srcReg = src;
    buf[0] = 0;
    bufHi = &buf[1];
    *bufHi = 0;

    switch (selector) {
    case 1:
        if (idx == 2) {
            result = srcReg[2];
            idxReg = 3;
            break;
        }
        if (idx == cmpVal + 1) {
            idx = 2;
            idxReg = 3;
            result = sub_080217D4((Entry *)srcReg, 2, idxReg);
            break;
        }
        idxReg = (u8)(idx + 1);
        result = sub_080217D4((Entry *)srcReg, idx, idxReg);
        break;
    case 2:
        if (idx == cmpVal + 1)
            idxReg = 2;
        else
            idxReg = (u8)(idx + 1);
        result = sub_080217D4((Entry *)srcReg, idx, idxReg);
        break;
    case 3: {
        Entity *e3 = &gEntities_03003720[dstIdx];
        if (idx == cmpVal + 1)
            e3->flags |= 0x800;
        if (idx == 2)
            e3->flags &= 0xf7ff;
        if (e3->flags & 0x800)
            idxReg = (u8)(idx - 1);
        else
            idxReg = (u8)(idx + 1);
        result = sub_080217D4((Entry *)srcReg, idx, idxReg);
        break;
    }
    default:
        break;
    }

    buf[0] = 0;
    *bufHi = 0;
    switch (result) {
    case 1:
        *bufHi = -1;
        break;
    case 2:
        *bufHi = 1;
        break;
    case 3:
        buf[0] = -1;
        break;
    case 4:
        buf[0] = 1;
        break;
    default:
        break;
    }

    entity = &gEntities_03003720[dstIdx];
    srcRecord = (s8 *)&srcReg[idx * 8];
    sub_0800A580(entity, srcRecord[4], buf[0], *bufHi);
    entity->x = *(u16 *)&srcRecord[0];
    entity->y = *(u16 *)&srcRecord[2];
    entity->_field_1A = result;
    entity->flags |= 2;
    entity->_field_33 = idxReg;
}
```

## UPDATE — int-param version is the cleanest switch match (348/145)

Declaring the four small params as `int` (and casting `(u8)` into locals
`dstIdx/selector/idx/cmpVal`) makes the first switch dispatch use
`cmp r2,#2 / beq / cmp r2,#2 / bgt / cmp r2,#1 / beq / cmp r2,#3` — selector
stays in r2 for ALL compares, EXACTLY matching the baserom's first three
compares (signed `bgt`, no register pin needed). The ONLY switch-dispatch
difference left: the baserom copies selector to a callee-saved r4
(`adds r4,r2,#0`) and uses `cmp r4,#3` for the `>2` branch; our build uses
`cmp r2,#3` directly (no copy).

Root cause (confirmed): the baserom's `adds r4,r2,#0` exists ONLY because
`dstIdx*8` lives in callee-saved r4 (it crosses the case-3 call: computed for
the entity flag-poke BEFORE the call, reused in the tail AFTER), and selector
COALESCES into that same r4 during its dead window. Our C never makes
`dstIdx*8` cross a call (entity is recomputed in case 3 and again in the tail
as separate expressions), so r4 is not callee-saved, so selector has no reason
to take an r4 copy. Trying to force it (single shared `entity` var across case 3
and the tail) makes agbcc spill the FULL pointer (sub sp,#8) instead of keeping
just the `dstIdx*8` partial — the baserom keeps ONLY the shift result in r4 and
finishes `(x - dstIdx) << 3 + base` at each site, which plain C can't express
(you can't tell agbcc "CSE only the partial product, recompute the rest").

NEXT AGENT: start from the int-param version below (cleanest switch). The whole
game is getting `dstIdx*8` to cross the case-3 call as a callee-saved partial
WITHOUT spilling the full entity pointer. Promising untried angles:
- A custom strength-reduction expression that yields the bare `dstIdx<<3` as a
  named local used in case 3 AND tail, e.g. `u32 p8 = dstIdx << 3;` then
  `*(Entity*)((char*)base + ((p8 - dstIdx) << 3))` at BOTH sites — but make
  `p8` (not the finished pointer) the value that lives across the call. The
  earlier `ent8` attempt did this but ALSO precomputed it before the switch,
  which swapped dstIdx↔idx into r5/r7; try computing `p8` lazily (first in
  case 3, GCSE hoists it) instead of before the switch.
- Per-TU `CFLAGS += -fgcse` variants / read agbcc gcse.c to see whether partial-
  redundancy elimination across a call is even enabled at -O2 for this shape.

    switch (selector) {

        break;
