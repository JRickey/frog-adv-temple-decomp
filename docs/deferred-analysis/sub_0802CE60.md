## Drift (what does NOT work — try a DIFFERENT lever)
Best byte_diff 440 / diff_count 226.

1. **buf word-RMW keep-live — SOLVED.** The baserom keeps the packed word in
   callee-saved r4 across the y-divsi3 and writes it via two masked stores
   (`(buf & 0xffff0000)|tx`, then `(…&0xffff)|(ty<<16)` reusing r4). The match
   needs: `register s32 packed asm("r4");` + a single-expr first AND
   (`packed = buf & 0xFFFF0000; packed |= tx; buf = packed;`) then two-step
   `packed &= 0x0000FFFF; packed |= ty<<16; buf = packed;`. Plain `buf =
   (buf&mask)|x` reloads buf into a caller-saved reg after the call (529);
   the r4 pin + two-step makes this region BYTE-EXACT. (responsible pass:
   local-alloc/reload spilling a value live across a call to a caller-saved reg.)

2. **`do_store_flag` boolean materialization — UNSOLVED, the real blocker.**
   The baserom's 4 table checks emit `ldrb; cmp #0; bne L1; movs r0,#1; b L2;
   L1: movs r0,#0; L2: cmp r0,#0; beq xy` — i.e. it MATERIALIZES `(table==0)`
   into r0 (full two-arm, no setcc on Thumb-1) then re-tests. Every plain-C form
   I tried compiles to a direct `cmp; beq` (no materialize) OR an r3 SINGLE-arm
   optimized form (`bne; movs r3,#1; cmp r3,#0; bne`, because the jump-optimizer
   knows r3 is pre-zero). Tried: `if(table==0)goto despawn`; `if(table!=0){xy}
   else goto despawn`; `u8 b=(table==0); if(b)`; `u8 b=!table; if(b!=0)`;
   `u8 occ=table; if(occ==0)`; `(…==0)?1:0`; `((…==0)!=0)`. None gives the full
   two-arm r0 form. Compiler swap (AGBCC vs OLD_AGBCC) and flags
   (-O1,-fno-gcse,-fno-schedule-insns{,2},-fno-strength-reduce,-fforce-addr,
   -fno-expensive-optimizations,-ffixed-r1,-fno-thread-jumps,-fno-cse-follow-jumps)
   ALL → 440 (no effect). do_store_flag (gcc_arm/expr.c:197) fires only when the
   comparison is an RVALUE the jump-optimizer can't collapse; the exact source
   shape that produces the un-collapsed two-arm r0 form is the missing piece.
   This idiom ×4 ≈ 24 bytes of the 56-byte size gap and breaks diff alignment at
   ~0x126, inflating diff_count downstream.

3. **table-index `&buf` re-derivation + base-load timing — UNSOLVED.** Baserom
   re-derives `add rN, sp, #16` for EACH of buf.h[1] and buf.h[0] (Thumb ldrsh =
   reg-offset only) and loads `gIwram_3610` base EARLY (2nd). My build CSE's the
   single `((s16*)&buf)` and loads the base LAST. Tried `s16 *bp=(s16*)&buf;

4. Directional-check register coloring (r0 vs r2 on `ldrh [r5,#2]`, r2 vs r3 on
