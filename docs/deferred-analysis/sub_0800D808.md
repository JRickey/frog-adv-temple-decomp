# Deferred analysis: sub_0800D808

## Function Summary
- Address: 0x0800d808, 152 bytes
- Algorithm: builds an active-slot index array from gIwram_53A0[0..63], then
  randomly removes `n` entries from gIwram_53A0, rebuilding the index after each removal.
- Calls: sub_08000764 (RNG, returns u8 in [0, range))

## Drift

byte_diff: 54, diff_count: 31

Root cause: **pure register allocation swap** — n_byte (u8) lands in r2 and the inline
pool address for &gIwram_3610 lands in r3, but target has them SWAPPED (n_byte→r3,
indices→r2).

All 31 instruction-level diffs cascade from this single r2/r3 swap:
- `lsrs r2` vs `lsrs r3` for n_byte extraction
- `ldr r3` vs `ldr r2` for indices pool load  
- Downstream: operand order `adds r0, r5, r4` vs `adds r0, r4, r5`
- Between-loops: `lsls r6, r2, #24` vs `lsls r0, r3, #24; adds r6, r0, #0` (two-step)
- After BL: `ldrb r0; mov r2, r8; adds r1, r2, r0` vs `ldrb r1; add r1, r8` (3 vs 2 instrs)
- Inner loop setup order: `adds r2, r4, #1; movs r4, #0` vs `movs r2, #0; adds r3, r4, #1`

## Mechanism (from agbcc local-alloc.c analysis)

QTY_CMP_PRI = floor_log2(n_refs) * n_refs * size / lifetime.
SHORTER lifetime → HIGHER priority → LOWER register number.

In my 54-diff C: n_byte has lifetime spanning the entire outer do-while loop
(because `while (i < (s8)n_byte)` uses n_byte in the loop condition). This makes
n_byte's lifetime longer than indices (first loop only) → n_byte gets LOWER register r2.

In the TARGET: n_byte has SHORT lifetime (only used for n_enc computation, NOT in loop
condition). The loop condition uses n_enc (`asrs r0, r6, #24; cmp r4, r0`). With short
lifetime, n_byte gets LOWER priority → r3. Indices has longer lifetime (spans first loop
body iterations) → gets r2.

## Key structural fix needed

Replace `while (i < (s8)n_byte)` with `while (i < ...)` using n_enc, so n_byte has
SHORT lifetime (not in loop condition). BUT when tried, ibuf went to r6 and n_enc→r7
instead of target's n_enc→r6, ibuf→r7.

The chain for target's n_enc→r6 assignment:
1. n_byte→r3 (not r2) forces `ldr r0, [pc]; mov r8, r0` pattern for slots pool load
2. `ldr r0` (slots pool load) CLOBBERS r0 after n_enc was computed in r0
3. n_enc MUST be stored to callee-saved r6 before r0 is clobbered
4. ibuf gets r7 (next callee-saved)

In my attempt with n_enc in condition: slots pool load used r2 (NOT r0), so r0 was NOT
clobbered, and agbcc optimized away n_enc's storage to r6.

## Best-effort C (54 byte_diff, do-while with n_byte in condition)

```c
#include "game.h"
#include "iwram.h"
#include "macros.h"
#include "types.h"

extern u8 sub_08000764(s16 range);
extern u8 gIwram_53A0;
extern u8 gIwram_3610;

void sub_0800D808(u32 a)
{
    register u8 *slots asm("r8");
    s32 i;
    u8 *s;
    u16 count;
    s32 n_enc;
    u8 *ibuf;
    volatile u8 rnd;
    u8 n_byte;

    n_byte = (u8)a;
    count = 0;
    i = 0;
    s = &gIwram_53A0;

    for (; i <= 63; i++) {
        if (s[i] != 0) {
            (&gIwram_3610)[(s16)count] = i;
            count++;
        }
    }

    n_enc = (s32)((u32)n_byte << 24);
    if (n_enc <= 0)
        return;

    slots = &gIwram_53A0;
    ibuf = &gIwram_3610;
    i = 0;
    do {
        s32 next;
        rnd = sub_08000764(count);
        slots[ibuf[rnd]] = 0;

        count = 0;
        next = i + 1;
        for (i = 0; i <= 63; i++) {
            if (slots[i] != 0) {
                ibuf[(s16)count] = i;
                count++;
            }
        }
        i = next;
    } while (i < (s8)n_byte);
}
```

## Levers tried

1. `register u8 n_byte asm("r3")` — forces n_byte to r3 BUT generates `adds r3, r0, #0`
   instead of the `lsls r0, r0, #24; lsrs r3, r0, #24` pattern. Also ibuf→r6 (not r7).
2. `-ffixed-r2` — makes r2 unavailable, but causes r9 to be used and breaks everything.
3. `volatile u8 n_byte` — no effect on register allocation.
4. Declaring `u8 *buf = &gIwram_3610` before n_byte — buf goes to r7 (CSE with ibuf).
5. Separate `j` variable for inner loop — changes count register (r1→r2) and breaks more.
6. `while (i < (s32)(n_enc >> 24))` instead of n_byte condition — correct n_byte→r3
   assignment but ibuf→r6 and n_enc→r7 (reversed from target).
7. Permuter: base 1505, best found 1080 after 1000+ iterations. Plateau.

## What a future agent should try

The circular dependency:
- Use n_byte in do-while condition → n_byte has long lifetime → n_byte→r2 (wrong)
- Use n_enc in do-while condition → n_byte short lifetime → n_byte→r3 (right for n_byte
  but ibuf/n_enc allocation reverses)

Breaking the circle requires ONE of:
A. Force the slots pool load to use r0 (not r2) even when n_byte is in r2. Then r0 gets
   clobbered → n_enc must be stored to r6 → ibuf→r7. Attempt: declare `slots` before
   `ibuf` in the second phase differently, or use `register u8 *slots_tmp asm("r0");`.
B. Find a C expression that makes n_byte have the SAME pool-load-birth-order as in
   the target (indices allocated to RTL BEFORE n_byte, despite indices being referenced
   later in C source order).
C. Two-pass approach: find a C expression for `(u8)a` that naturally uses r3 without
   the `lsls r0, r0, #24; lsrs r?, r0, #24` pattern — e.g., some cast that forces r3
   directly. Maybe `register u8 n_byte asm("r3"); asm("lsls %0, %0, #24" : "+r"(a)); n_byte = a >> 24;`
   but that's NAKED territory.
