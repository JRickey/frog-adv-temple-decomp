# Deferred analysis: sub_0800D808

## Function Summary
- Address: 0x0800d808, 152 bytes. Compiles ONLY under OLD_AGBCC (per-TU
  `src/engine/sub_0800d808.s: CC = $(OLD_AGBCC_BIN)` in the Makefile).
- Algorithm: HBlank raster-scroll buffer compaction. `gIwram_53A0` (0x030053a0)
  is BG0's 64-entry raster-scroll byte array, `gIwram_3610` (0x03003610) is BG1's
  (see src/game/sub_0800088c.c for the HBlank ISR that reads them). The function:
    1. Builds an index of nonzero slots in gIwram_53A0 into gIwram_3610[0..count).
    2. For `(s8)a` iterations: picks a random active slot (sub_08000764(count)),
       zeroes gIwram_53A0[gIwram_3610[rnd]], then REBUILDS the index from scratch.
- Calls: sub_08000764(u8 range) — LCG RNG, returns u8 in [0,range). Already
  decompiled in src/system/init.c.

## Progress: 54 -> 30 byte_diff (this Opus round)

The Sonnet attempt plateaued at byte_diff 54 / diff_count 31 (root-caused as an
n_byte/indices r2/r3 swap). This round re-derived from scratch and reached
**byte_diff 30 / diff_count 25** with a clean PURE-C structure (no NAKED, no
inline asm). Three structural keys the prior attempt missed:

1. **`s16 count` (signed), NOT `u16`.** The permuter found this; it changes the
   index codegen and is closer to the baserom. (Both produce the `lsls#16;asrs#16`
   sign-extend at the index sites, but signed `count` matches the rest.)
2. **`s8 m = (s8)n;` held as the loop bound, recomputed via `>>24` each iter.**
   This DEFEATS the `n_enc >> 24` loop-invariant HOIST that the prior `s32 n_enc`
   form suffered (agbcc would hoist `asrs` before the loop into a spare reg; the
   baserom recomputes `asrs r0,r6,#24` at the bottom each iteration). Holding the
   bound as a narrow signed `s8` makes agbcc keep its `<<24` canonical form in a
   callee-saved reg and re-extract — exactly the baserom shape. THIS WAS THE KEY
   UNLOCK (drops ~10 cascading diffs vs the `n_enc>>24` form).
3. **`base = slots;` copy inside the do-loop before the inner rebuild.** Mirrors
   the baserom's `mov r4,r8` (copy the r8-pinned slots base to a low reg for the
   inner loop's `ldrb` addressing). Drops 1-2 diffs and reads cleanly.

Register pins that ARE load-bearing and correct: `slots asm("r8")`,
`idx1 asm("r2")` (loop-1 index buffer), `slots1 asm("r5")` (loop-1 slots base).
With `idx1=r2`, loop 1 matches the baserom EXACTLY (n_byte lands in r3, indices
in r2 — the prior attempt's r2/r3 swap is fully resolved here).

## Remaining drift (byte_diff 30) — THREE coupled register-coloring clusters

A. **m / ibuf callee-saved swap (~10 diffs, the dominant cluster).**
   Baserom: phase-2 `m` (the `<<24` bound) -> **r6**, `ibuf` (gIwram_3610 reload)
   -> **r7**, and the slots pool-load uses **r0** (`ldr r0; mov r8,r0`), which
   forces `m` to be saved to r6 (`adds r6,r0,#0`) BEFORE the load and tested there
   (`cmp r6,#0; ble`).
   Mine: `m` -> **r7**, `ibuf` -> **r6**, slots pool-load uses **r2** (idx1's
   freed reg), so r0 (holding `(s8)n`) survives and the early-test is `cmp r0,#0`.
   ROOT CAUSE (local-alloc.c QTY_CMP_PRI = floor_log2(refs)*refs*size/lifetime;
   SHORTER lifetime -> HIGHER priority -> LOWER reg number): `m` is born right
   after loop 1 (long lifetime) -> LOW priority -> r7. `ibuf` born later (short
   lifetime) -> HIGH priority -> r6. The baserom has them reversed, i.e. in the
   baserom `m` outranks `ibuf`. Could not flip via source order or pins:
     - `register s8 m asm("r6")` -> COALESCES `n` into r6 (n no longer in r3;
       `lsls r6,r6,#24` instead of the separate `lsls r0,r3,#24; adds r6,r0,#0`).
       Re-introduces a loop-1 diff. (Same coalescing trap the prior note hit with
       n_enc=r6.)
     - `register u8 *ibuf asm("r7")` -> BREAKS THE PROLOGUE: agbcc then emits
       `push {r4,r5,r6,lr}; mov r6,r8` (drops r7 from the save list, spills r8 via
       r6) instead of the baserom `push {r4,r5,r6,r7,lr}; mov r7,r8`. Net +5 diffs.
     - Reordering ibuf-before-m moves the ibuf pool load up into loop 1 (worse).
     - `ibuf = idx1` (keep r2 live to force slots->r0) -> slots picks r3, not r0.
   The circular dependency: getting `m` into r6 by a pin pulls `n` in with it;
   getting `ibuf` out of r6 by a pin breaks the high-reg prologue save. The right
   answer is a C shape that makes local-alloc rank `m` above `ibuf` WITHOUT a pin.

B. **Loop-operand order (~3 diffs).** Baserom computes the element address
   INDEX-FIRST: loop1 `adds r0, r4, r5` (i + slots1), store `adds r1, r0, r2`
   ((s16)count + idx1); inner loop `adds r0, r2, r4` (inner_i + base). Mine emits
   BASE-FIRST: `adds r0, r5, r4`, `adds r1, r2, r0`. agbcc's combine.c
   canonicalization (line ~3354: "put a complex expression first") leaves two REG
   operands in source/RTL-birth order; I could not get the index to sort first.
   Tried: `slots1[i]`, `i[slots1]`, `*(i+slots1)`, `*(u8*)(i+(s32)slots1)` — all
   canonicalize identically to base-first. Likely needs the index to be the
   lower-numbered pseudo at combine time (born before the base pseudo) in a way
   source reordering didn't achieve, OR is a giv/strength-reduction artifact.

C. **Inner-loop counter register (~5 diffs).** Baserom inner counter -> **r2**,
   `next` (outer_i+1) -> **r3**, and reuses **r4** (outer_i's reg, now dead/saved
   in r3) for the `base` copy. Mine: `next` -> r2, inner counter -> r4, `base`
   copy -> r3. The `base = slots` copy got the reuse-idiom closer but the inner
   counter still lands in r4 (it reuses loop-1's `i` register) instead of r2.
   A separate inner variable `k` pushes `count` off r1 and is worse.

## What a future agent should try (DIFFERENT from the above)
- The crux is cluster A: make local-alloc rank `m` ABOVE `ibuf` (so m->r6,
  ibuf->r7) WITHOUT a register pin (pins coalesce n or break the prologue).
  Idea: increase `m`'s reference count or shorten its live range so QTY_CMP_PRI
  favors it — e.g. find a C form where `m` is referenced a third time cheaply, or
  where `ibuf`'s first reference is delayed past `m`'s death. Read local-alloc.c
  `qty_compare`/`update_qty_class` for the exact tiebreak when two callee-saved
  pointer/int qtys collide.
- Alternatively, force the slots pool-load to r0 WITHOUT keeping r0 live: the
  baserom spills `m` to r6 to free r0 for the load. A C form that makes `m` HAVE
  to be in a callee-saved reg at the point of the slots load (so reload spills it
  and reuses r0) would cascade-fix A. The `m=r6` pin does this but coalesces n —
  need the spill WITHOUT the coalesce (maybe n and m as genuinely independent
  webs: compute `m` from `a` again rather than from `n`?).
- Operand order (B): try making `i` the basic induction variable that strength
  reduction turns into the address giv with index-first form.

## Best-effort C (byte_diff 30, diff_count 25, PURE C, OLD_AGBCC)

```c
#include "game.h"
#include "iwram.h"
#include "macros.h"
#include "types.h"

extern u8 sub_08000764(u8 range);
extern u8 gIwram_53A0;
extern u8 gIwram_3610;

void sub_0800D808(u32 a)
{
    register u8 *slots asm("r8");
    register u8 *idx1 asm("r2");
    register u8 *slots1 asm("r5");
    u8 *ibuf;
    u8 *base;
    s16 count;
    s32 i;
    s8 m;
    volatile u8 rnd;
    u8 n;

    n = (u8)a;
    count = 0;
    i = 0;
    slots1 = &gIwram_53A0;
    idx1 = &gIwram_3610;
    for (; i <= 63; i++) {
        if (slots1[i] != 0) {
            idx1[count] = i;
            count++;
        }
    }

    if ((s8)n <= 0)
        return;

    ibuf = &gIwram_3610;
    slots = &gIwram_53A0;
    m = (s8)n;
    i = 0;
    do {
        s32 next;
        rnd = sub_08000764(count);
        slots[ibuf[rnd]] = 0;
        base = slots;
        count = 0;
        next = i + 1;
        for (i = 0; i <= 63; i++) {
            if (base[i] != 0) {
                ibuf[count] = i;
                count++;
            }
        }
        i = next;
    } while (i < m);
}
```

Note: also requires the per-TU OLD_AGBCC line in the Makefile
(`src/engine/sub_0800d808.s: CC = $(OLD_AGBCC_BIN)`).
