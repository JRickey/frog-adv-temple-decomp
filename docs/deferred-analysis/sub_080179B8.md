## THE remaining blocker — Drift G: the second `(u8)cursor` index mask

Target (op==0 block at 0x17a26):
```
ldrb r0,[r6,#0]     ; X = s->cursor  (UNSIGNED ldrb -> nonzero_bits 0xFF)
adds r1,r0,#1       ; c1 = X+1
strb r1,[r6,#0]
lsls r0,r0,#24      ; \  (u8)X << 1   <-- MASK on a clean unsigned-ldrb value
lsrs r0,r0,#23      ; /
adds r0,r0,r5
ldrh r4,[r0]        ; op = script[(u8)X]
```
My build emits `lsls r0,r0,#1` (the mask ELIDED). The op==0 branch's SECOND index
`(u8)c1` DOES mask in both (c1 = X+1 has nonzero_bits 0x1FF), so the asymmetry is
purely the FIRST index `(u8)X`.

ROOT CAUSE (read tools/agbcc-src/gcc/combine.c `reg_nonzero_bits` setup, ~line
740-805, and thumb.md `zero_extendqisi2` expand line 370): `(u8)X << 1` is generated
as `(X<<24)>>24<<1` = `(X<<24)>>23`, but combine ELIMINATES the `<<24;>>24` when
`nonzero_bits(X) <= 0xFF`. For a single-set pseudo fed by an UNSIGNED ldrb,
nonzero_bits = 0xFF, so it's always narrowed to `lsls #1`. The TARGET keeps the mask,
which means the original's X pseudo had WIDE nonzero_bits despite the unsigned ldrb.

### Exhaustively tried (ALL narrow to `lsls #1` — do NOT repeat):
- `(u8)cursor`, `cursor & 0xFF`, `(u8)(cursor + 0x100)`  (combine knows low byte)
- `(u8)(c1 - 1)`, `(u8)(s->cursor - 1)` re-read  (folds (x+1)-1 -> x, narrows; or
  KEEPS the mask but ADDS `adds;subs` the target doesn't have)
- index BEFORE the store / AFTER the store / increment via field re-read
- cursor as `u8`, `char`, multi-set (shared with the first-block index), hard-reg
  pinned (`register int cursor asm("r0")` — pin is post-combine, no effect)
- `*(volatile u8*)&s->cursor`
- per-TU flags: `-fno-strength-reduce -fno-gcse -fno-expensive-optimizations
  -fforce-mem -fcaller-saves -fno-peephole -fno-cse-follow-jumps
  -fno-rerun-cse-after-loop`  (direct agbcc compile: ALL give exactly 1 lsl#24, the
  c1-branch only; NONE flip the first-index narrowing)
- OLD_AGBCC: WRONG — it drops the target's `pop {r1}; bx r1` epilogue.
