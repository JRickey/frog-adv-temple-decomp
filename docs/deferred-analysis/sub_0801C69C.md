# Deferred analysis: sub_0801C69C

Range: [0x0801c69c, 0x0801c6e4) — 72 bytes, Thumb. Dest: src/engine/sub_0801c464.c.

## Function semantics

Clears DISPCNT.WIN0_ON (bit 13), zeros WIN0H (0x04000040) + WIN0V (0x04000044),
zeros palette[0] (0x05000000), then DMA3-fills BG screenblock 31 (0x0600f800,
0x400 halfwords = 2048 bytes) with 0 from a stack local (DMA_SRC_FIXED), reading
DMA3.cnt back once, and finally clears DISPCNT.BG3_ON (bit 11).

Takes a `u8 a` parameter (callers at ROM 0x1a416/0x1a488/0x1a4aa/0x1a5ba pass
`adds r0, r5, #0`, r5 = a state value, can be non-zero e.g. 14). The sibling
`sub_0801C6FC` at 0x1c6fc has the SAME prologue but narrows `a` into r3 and
`switch`es on it (`cmp r3,#15; ... mov pc,r0`). In 0801C69C, `a` is narrowed
into r0 and then **never read** — the body fills with 0, not `a`.

## ROOT CAUSE — why this is NOT matchable in clean pure C (NEW, agbcc-source proof)

This is the same byte_diff-34 plateau the first attempt hit, but here is the
mechanism, derived from the agbcc 2.x source (tools/agbcc-src), not guessed:

The target's prologue is `sub sp,#4; lsls r0,#24; lsrs r0,#24` — the standard
`u8`-param narrow into r0. Empirically (probed both old_agbcc AND agbcc):

  **agbcc NEVER emits this narrow for a fully-dead `u8` param.** A dead param's
  use is eliminated and the narrow with it. So `a` MUST be referenced.

The ONLY reference that produces exactly `lsls#24;lsrs#24` + the observed shape
is `local = a` (store the narrowed param to the u16 stack slot). But the baserom
stores **0** to local (`movs r0,#0; strh r0,[sp]`), not `a`. So the source must
be `local = a; local = 0;` — and the first (dead) store must vanish, leaving the
narrow.

  **agbcc structurally REFUSES to dead-store-eliminate a STACK-SLOT store.**
  flow.c `mark_set_1` (~line 2393):

      if (GET_CODE (reg) == MEM && ! side_effects_p (reg)
          && ! reg_mentioned_p (stack_pointer_rtx, reg))   /* <-- */
        mem_set_list = gen_rtx_EXPR_LIST (VOIDmode, reg, mem_set_list);

  A MEM store is added to the dead-store tracking list (`mem_set_list`) ONLY if
  its address does NOT mention the stack pointer. `local` is `[sp]`, so `local=0`
  is never tracked, so the earlier `local=a` can never be marked dead
  (insn_dead_p, ~line 2057, only fires on an identical *tracked* later store).
  The flow.c comment is explicit: "don't eliminate any stores through SP."

Consequence: `local=a; local=0` ALWAYS emits BOTH `strh`s (byte_diff 34 floor),
while the target has ONE store of 0 + a DISPCNT-base reload. No clean C, register
pin, per-TU flag, or compiler swap bridges this — confirmed exhaustively below.

## Drift: byte_diff 34, diff_count 11 (floor; same as prior attempt)

The two residual differences vs target, after `local=a;local=0`:
1. EXTRA `strh r0,[r1]` (the dead `local=a` store agbcc can't DSE — see root cause).
2. The 2nd DISPCNT base CSEs (`ldrh r1,[r3]`) where target RELOADS
   (`movs r2,#128; lsls r2,#19; ldrh r1,[r2]`). The reload only appears when `a`
   genuinely occupies r0 DEAD across the body (never read); when `a` is read by a
   store, agbcc keeps r3 live and CSEs. `0x04000000` is a `thumb_shiftable_const`
   (config/arm/thumb.c) so agbcc rematerializes it cheaply — but only under the
   exact live-range profile of a dead-in-r0 param, which can't be produced cleanly.

`local = a` alone (fill with `a`) is byte_diff 48 — closer on instruction count
(only 3 extra), but it's the WRONG semantic (fills with `a`, not 0) and stores
`a` where target stores 0, so it is not a real base either.

## Levers tried this pass (all fail — do NOT re-try these)

- `local = a; local = 0;` (both orders): byte_diff 34. Two stores (root cause).
- `local = a` (single, fill=a): byte_diff 48. Wrong value + CSE, no reload.
- `local = 0` (a unused): byte_diff 79. Drops narrow, whole alloc shifts (r2first).
- palette = a / WIN = a / DISPCNT-mask |= a : narrow appears but stores `a` to the
  wrong MMIO reg (wrong bytes); none give the reload.
- `a << 8 << 8` in the FINAL DISPCNT mask: DOES reproduce narrow + reload(!), but
  agbcc emits the runtime `lsr r0,#8; orr; bic` shift code (a<<16) instead of the
  plain `ands 0xf7ff` — byte_diff 59. This is the only construct that triggers the
  reload, and it always emits extra `a` instructions the target lacks.
- `(u16)(a<<8<<8)` / `a&0x10000` / `a<<8<<8<<8` : all const-fold to 0 → no narrow.
- `a ? 0 : 0`, `(a,0)`, `a==a?0:0`, `if(a){}`, `(void)a`, `a=a`, dead `fill=a`:
  all eliminated → no narrow.
- `{volatile u8 z=a;}` : narrow survives but adds a 2nd stack slot + strb/ldrb.
- `asm("" :: "r"(a))` barrier (various placements): keeps narrow but swaps the
  local-store register order, emits `.code 16` debt, and never produces the reload.
- per-TU flags swept on the `local=a` base for the reload: -fno-gcse, -fforce-addr,
  -fno-expensive-optimizations, -fno-cse-follow-jumps, -fno-cse-skip-blocks,
  -fno-function-cse, -fno-strength-reduce, -O1, -fno-schedule-insns,
  -fno-rerun-cse-after-loop, -fno-caller-saves — NONE produce base-synth=2 (reload).
- Newer `agbcc` (vs default old_agbcc): identical (no dead-param narrow, CSEs).

## Conclusion / next attempt

This is a genuine clean-C impossibility under agbcc (dead-narrowed stack param +
SP-store DSE refusal). It is NOT STRONG_UNMATCHABLE (no libgcc class), so it stays
an honest asm slice rather than a fake NAKED ship.

Only remaining theoretical paths for a future attempt (all unlikely / not clean):
- A NAKED + NON_MATCHING ship (hand-asm) IF policy ever allows it for this class.
- A future agbcc-flag discovery that narrows a dead `u8` param (none found in the
  whole `-fXXX` surface) — would let `local = 0; (void)a;` keep the narrow.
- A source form that puts `a` dead-in-r0 with zero emitted code AND triggers the
  shiftable-const reload — none exists in the agbcc cost model as analyzed.

## Best-effort C (byte_diff 34 floor — readable, two-store)

```c
void sub_0801C69C(u8 a)
{
    u16 local;

    REG_DISPCNT &= ~DISPCNT_WIN0_ON;
    *(vu16 *)0x04000040 = 0;
    *(vu16 *)0x04000044 = 0;
    *(vu16 *)0x05000000 = 0;
    local = a; /* dead store agbcc cannot DSE (SP-slot); see root cause */
    local = 0;
    REG_DMA3.src = &local;
    REG_DMA3.dst = (void *)0x0600f800;
    REG_DMA3.cnt = DMA_ENABLE | DMA_SRC_FIXED | 0x400;
    (void)REG_DMA3.cnt;
    REG_DISPCNT &= ~DISPCNT_BG3_ON;
}
```
