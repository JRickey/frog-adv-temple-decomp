# sub_08022360 — deferred analysis

Level/screen entity-init for entity slots 69 and 70 (stride 0x38) in the entity
array based at `gIwram_3720` (= `&gEntities[0]`). Loops over slots 69,70 setting
five fields to constants, then writes per-slot x/y/_field_14/flags, then calls
`sub_0800A580(&slot, 4, 0, 1)` for each.

- Range: [0x08022360, 0x08022434) (212 bytes, thumb). Callee `sub_0800A580` peeled.
- Slot 69 = base+0xf18, slot 70 = base+0xf50.  EntitySlot field map (from sibling
  `src/engine/sub_080210a0.c`): _field_00@0, x@2, y@4, _field_06@6, _field_14@0x14,
  _field_16@0x16, _field_17@0x17, _field_1A@0x1A, flags@0x34.
- **This file must use OLD_AGBCC** (Makefile: `src/engine/sub_08022360.s: CC =
  $(OLD_AGBCC_BIN)`). Under NEW agbcc base lands in r5; the closest structure
  (below) needs base in r4. The standard `compile_and_view_assembly.py` /
  `build_expected.py` tools IGNORE the per-file CC override and use NEW agbcc — so
  they MISREPORT this function (they show base=r5). Verify with the real `make`
  build + objdump on `src/engine/sub_08022360.o`, NOT the tools.

## CORRECTED semantics (the prior note's offset map was WRONG)

The prior deferred note mis-assigned several stores. The ground-truth baserom
register trace gives these EXACT stores in source order (r2 = offset accumulator,
r0 = value, r4 = base):

  s69._field_14 = 0x175    (off 0xf2c)
  s70._field_14 = 0x185    (off 0xf64)
  s69.x         = 0x143    (off 0xf1a = 0xf2c-18 ; val 0x143 = 0x185-66)   <- s69.x NOT s70.x
  s69.y         = 0x2F4    (off 0xf1c ; 0xbd<<2)
  s70.x         = 0x15B    (off 0xf52 = 0xf1a+56)
  s70.y         = 0x33A    (off 0xf54)
  s69._field_1A = 0        (off 0xf32, strb, value in r3)
  s69.flags    |= 2        (off 0xf4c ; mask in r1, address in r2)
  s70._field_1A = 0        (off 0xf6a, strb, value in r3)
  s70.flags    |= 2        (off 0xf84 = 0xf6a+26 ; CHAINED via r2)
  sub_0800A580(base+0xf18, 4, 0, 1);   /* &s69 */
  sub_0800A580(base+0xf50, 4, 0, 1);   /* &s70 */

Baserom register lifetimes (the target coloring to reproduce):
- r4 = base (whole function).
- r3 = loop const 3 (_field_17), REUSED as the post-loop zero (the two
  `_field_1A = 0` byte stores both `strb r3`).  `movs r3,#0` is hoisted at the
  loop exit (0x2238a).
- r2 = loop const 2 in loop; post-loop OFFSET accumulator, then the flags
  address.
- r1 = loop counter; post-loop the store address (first 6 stores) and the
  flag mask (#2) on the flags stores.
- r0 = loop pointer in loop; post-loop the store VALUE / fresh-offset temp.

Baserom offset chains (only these three; everything else is a fresh `ldr` pool
load — agbcc's cost model chose fresh for 0xf4c and 0xf6a):
  r2 chain:  0xf2c -18-> 0xf1a +56-> 0xf52   (s69._f14, s69.x, s70.x)
  val chain: 0x185 -66-> 0x143               (s70._f14 value -> s69.x value)
  r2 chain:  0xf6a +26-> 0xf84               (s70._f1A -> s70.flags)

## Drift (BEST: 9 instruction-level mismatches, ~41 register-aware; OLD_AGBCC -fno-gcse)

Hugely better than the prior note's 142 byte_diff (which had the WRONG offsets and
no working r3-hoist). The loop + all 6 main stores match byte-for-byte. The
residual ~9 instr / ~41 register-aware mismatches are concentrated in TWO spots:

1. **Prologue scheduling.** Baserom emits the first two loop constants
   (`movs r7,#16; movs r6,#15`) BEFORE the loop-pointer setup
   (`ldr r1,=0xf18; adds r0,r4,r1`), then `r5,r3,r2`, and the counter `r1=1`
   LAST.  The best C emits base, [counter r1=1], [p-setup], then ALL five consts.
   The `do { } while(--i>=0)` form (vs `for(i=1;i>=0;i--)`) moved the counter
   closer but did NOT split the consts around the p-setup. No -fschedule-insns[/2]
   toggle (on/off) reproduces the split (it makes things much worse, ~75).
   Pinning the consts to r7/r6 via `register asm("r7")` DID emit them before p,
   but agbcc then DROPS them from the push list (`push {r4,r5,r6,lr}` — r7 not
   saved) which is wrong codegen. So const-pinning is a dead end.

2. **Tail flags-store coloring.** Baserom: flags `|=2` with mask in r1, address in
   r2 (off accumulator), and 0xf4c/0xf6a fresh + 0xf6a->0xf84 chained. The best C
   uses `q` pinned to r1 for the store address of the first 6 stores — which then
   forces the flags address into r1 too, colliding with the baserom's r1=mask.
   Pinning `zero asm("r3")` correctly puts the byte-store zero in r3 (matches), but
   the flag MASK then lands in r5 (baserom: r1) and the flag ADDRESS in r1
   (baserom: r2). Routing the flags address through `off` (r2) instead of `q`
   did not fix the mask register either (still 42).
   The `|= 2` read-modify-write inherently needs the address held across
   ldrh+orr+strh; agbcc colors that holder differently than baserom whenever the
   q/off pins are present, and removing the pins regresses the first 6 stores.

## Levers already tried (try a DIFFERENT one next)

- struct-array `gEntities[N].field` (base-CSE `[slot,#imm]`, 63 — WRONG addressing
  shape; baserom uses full-offset `r4+0xNNN; [r,#0]`).  DON'T go back to this.
- u8* + pure-constant offsets `*(u16*)(base+CONST)` (228 bytes, 170+ — every offset
  a fresh pool load, no chain; too big).
- u8* + explicit off/val accumulator chains, no pins (163, base in r5 under the
  TOOL's new-agbcc; under real old_agbcc this is ~10 with value-copies).
- **q-pointer (addr) + v-value(r0) + off(r2) pins + `zero` local after the loop**:
  this is the BREAKTHROUGH that got the loop + 6 main stores byte-matching and the
  r3=0 hoist working. `do/while(--i>=0)` loop form → 9 instr-level. THE BEST BASE.
- base `register asm("r4")` pin: NEEDED once q/v/off are pinned (otherwise the
  pins displace base to r5). With it, base stays r4. (Note: contradicts the prior
  note's "old_agbcc gives r4 for free" — that's only true with NO pins.)
- `zero asm("r3")` pin: puts byte-store zero in r3 (matches baserom) but pushes the
  flag mask to r5 — net same mismatch (41 vs 41).
- const pins r7/r6/r5/r3/r2: emit consts before p (good) but corrupt the push list
  (r7 not saved) — INVALID. Dead end.
- Flag sweep (OLD agbcc, on best base): -fno-gcse (best/needed), -fno-cse-follow-jumps,
  -fno-rerun-cse-after-loop, -fno-cse-skip-blocks, -fno-schedule-insns[/2] (much
  worse, ~75), -fcaller-saves, -ffixed-r5 (worse), -O1/-O3, -fno-strength-reduce,
  -fno-expensive-optimizations — none beat 9/41.
- Permuter (OLD_AGBCC via `tools/permuter_compile_old.sh`, ~480 iters): base score
  12055 → best 6510, NO score-0. Its "improvements" were trivial reorders
  (`i=1` into the loop, `field=(i=3)` hacks) — it cannot invent the prologue split
  or the tail coloring. Permuter is exhausted for this base.

## Next ideas (untried)

- The prologue split (r7,r6 BEFORE p) is the highest-value remaining fix. It likely
  comes from agbcc NOT loop-hoisting r7/r6 but computing them in the preheader as
  part of the first store's combine, while r5/r3/r2 ARE loop-hoisted. Try a source
  shape where the first two field writes' constants are "more tied" to the pointer
  init — e.g. write the first iteration's flags/_field_00 stores OUTSIDE the loop
  (peel one iteration) and loop only once, or restructure so r7/r6 are used in an
  expression that forces preheader materialization before the IV.
- The tail mask-register (r1) collides with q's r1 pin. Try: do NOT pin q; instead
  pin the flag MASK to r1 (`register s32 mask asm("r1") = 2;`) and let the address
  float — may free agbcc to put the flags address in r2 like baserom while keeping
  the first-6-stores address wherever it lands. Combine with zero=r3.
- Try expressing the two flags stores as a single helper-free `s->flags |= 2` on an
  EntitySlot* whose base is `base` (full offset) — but the 0x34 field offset (52)
  fits the thumb strh immediate, so agbcc would use `[slot,#52]` (base-CSE). To
  force full-offset, the flags address must be a runtime offset > 62. Dead-ish.

## Best-effort C (BEST base, 9 instr-level mismatches, OLD_AGBCC -fno-gcse; NOT committed)

Requires Makefile lines:
  `src/engine/sub_08022360.s: CC = $(OLD_AGBCC_BIN)`
  `src/engine/sub_08022360.s: CFLAGS += -fno-gcse`

```c
#include "iwram.h"
#include "types.h"

typedef struct EntitySlot {
    u8 _field_00;
    u8 _field_01;
    u16 x;
    u16 y;
    u8 _field_06;
    u8 _pad07[13];
    u16 _field_14;
    u8 _field_16;
    u8 _field_17;
    u8 _pad18[2];
    u8 _field_1A;
    u8 _pad1B[0x19];
    u16 flags;
    u8 _pad36[2];
} EntitySlot;

extern void sub_0800A580(EntitySlot *e, s8 param, s8 deltaX, s8 deltaY);

void sub_08022360(void)
{
    register u8 *base asm("r4") = (u8 *)&gIwram_3720;
    EntitySlot *p;
    register s32 off asm("r2");
    register u8 *q asm("r1");
    register s32 v asm("r0");
    s32 zero;
    s32 i;

    i = 1;
    p = (EntitySlot *)(base + 0xf18);
    do {
        p->flags = 16;
        p->_field_00 = 15;
        p->_field_16 = 12;
        p->_field_17 = 3;
        p->_field_06 = 2;
        p++;
    } while (--i >= 0);

    zero = 0;

    off = 0xf2c;
    q = base + off;
    v = 0x175;
    *(u16 *)q = v;

    q = base + 0xf64;
    v = 0x185;
    *(u16 *)q = v;

    off -= 18;
    q = base + off;
    v -= 66;
    *(u16 *)q = v;

    q = base + 0xf1c;
    v = 0x2F4;
    *(u16 *)q = v;

    off += 56;
    q = base + off;
    v = 0x15B;
    *(u16 *)q = v;

    q = base + 0xf54;
    v = 0x33A;
    *(u16 *)q = v;

    q = base + 0xf32;
    *q = zero;

    q = base + 0xf4c;
    *(u16 *)q |= 2;

    off = 0xf6a;
    q = base + off;
    *q = zero;

    off += 26;
    q = base + off;
    *(u16 *)q |= 2;

    sub_0800A580((EntitySlot *)(base + 0xf18), 4, 0, 1);
    sub_0800A580((EntitySlot *)(base + 0xf50), 4, 0, 1);
}
```
