# sub_08022360 — deferred analysis

Level/screen entity-init: writes EntitySlot records 69, 70 (and one field of 71)
in the 56-byte entity array based at `gIwram_3720` (= `&gEntities[0]`), then calls
`sub_0800A580(&slot, 4, 0, 1)` for slots 69 and 70.

- Range: [0x08022360, 0x08022434) (212 bytes, thumb). Callee `sub_0800A580` is peeled.
- Entity stride is 0x38; slot 69 = offset 0xf18, slot 70 = 0xf50, slot 71 = 0xf88.
- Sibling `src/engine/sub_080222bc.c` is the prev neighbour (same level-init cluster);
  it calls `sub_080210A0` instead. `src/engine/sub_080210a0.c` has the EntitySlot
  field map (x@2, y@4, _field_06@6, _field_14@0x14, matchKey/_field_16@0x16,
  _field_17@0x17, dispatchState/_field_1A@0x1A, flags@0x34, _field_00@0).

## Semantics (verified against baserom)

Loop over slots 69, 70 (counter `i=1..0`, pointer increments by 0x38):
  flags(0x34)=16, _field_00=15, _field_16=12, _field_17=3, _field_06=2.

Then individual writes (exact baserom store order):
  s69._field_14 = 0x175      (off 0xf2c)
  s70._field_14 = 0x185      (off 0xf64)
  s70.x         = 0x143      (off 0xf52 = 0xf64-18 ; val 0x143 = 0x185-66)
  s69.y         = 0x2F4      (off 0xf1c ; val 0xbd<<2)
  s71.x         = 0x15B      (off 0xf8a = 0xf52+56)
  s70.y         = 0x33A      (off 0xf54)
  s69._field_1A = 0          (off 0xf32, strb)
  s69.flags    |= 2          (off 0xf4c)
  s70._field_1A = 0          (off 0xf6a, strb)
  s70.flags    |= 2          (off 0xf84 = 0xf6a+26)
  sub_0800A580(base+0xf18, 4, 0, 1);  /* &s69 */
  sub_0800A580(base+0xf50, 4, 0, 1);  /* &s70 */

## Drift (best byte_diff 142, len 212==212; compiled with OLD_AGBCC)

The structure that gets the RIGHT shape is the "Best-effort C" below: a `u8 *base`
plus *byte-offset pointer stores* `*(u16*)(base + OFF) = V`. This is required because
the baserom uses the FULL-OFFSET addressing form everywhere post-loop:
`adds r1, r4, <fulloffset>; strh r0, [r1, #0]` (offset materialised in a register,
store at `[r,#0]`). Struct-array indexing `e[70].field` instead makes agbcc keep a
per-slot base and use `[slot, #fieldimm]` (base-CSE) — a structurally different shape
that plateaus at byte_diff 131 and will NOT converge.

WHAT IS RIGHT in the best version:
- Addressing form: full-offset `[r,#0]` matches.
- Base register: r4 — ONLY with OLD_AGBCC (new agbcc colours base into r5; the file was
  set to `OLD_AGBCC_BIN` in the Makefile to fix this). The loop body matches byte-for-byte.
- Offset chains: explicit `off`/`val` locals (`off=0xf64; off-=18; off+=56;` and
  `val=0x185; val-=66;`) DO reproduce the baserom's offset chain
  `0xf64 -18-> 0xf52 +56-> 0xf8a` and value chain `0x185 -66-> 0x143` (no copy on those).

WHAT STILL DRIFTS (the 142, concentrated in the post-loop — 125 of the 142 is at
offset >= 0x26, only ~17 in the prologue):
1. Prologue scheduling: baserom interleaves the first two loop constants
   (`movs r7,#16; movs r6,#15`) BEFORE the loop-pointer setup (`ldr r1,off; adds r0,r4,r1`),
   then emits the remaining consts. The best C emits base, then p-setup, then ALL consts.
   No `-fschedule-insns[/2]` toggle (on/off, OLD+NEW agbcc) changes this.
2. Two residual value-copies (`adds r0, rN, #0`) on the STANDALONE stores (0xf2c=0x175 is
   one). The baserom has ZERO copies — it loads each standalone value straight into r0.
   Root cause: the baserom hoists `movs r3, #0` (the byte-store zero) EARLY, occupying r3,
   which forces value loads into r0; the best C frees r3 so agbcc routes the value through
   r3 then copies to r0. A `s32 zero = 0;` local did NOT trigger the hoist (made it 157).
3. agbcc's GCSE re-derives offset chains by numeric proximity and partially overrides the
   source `off` threading (e.g. NEW agbcc chains 0xf2c->0xf64 (+0x38), which the baserom
   does NOT; baserom loads 0xf2c fresh). OLD_AGBCC respects the explicit chain better but
   still differs on the standalone stores.

## Levers already tried (try a DIFFERENT one next)

- struct-array `e[N].field` (base-CSE, 131, WRONG shape — don't go back to this).
- u8* + pure constants `*(u16*)(base+CONST)` (NEW 172 / OLD 153, value-chain + copies, 228 len).
- u16-array `((u16*)base)[OFF/2]` (185).
- explicit off/val chain locals (142, OLD_AGBCC) — BEST, structure correct.
- `register u8 *base asm("r4")` pin (164 — pin shuffling made it worse; OLD_AGBCC already
  gives r4 for free, so do NOT pin).
- `s32 zero=0;` local to force the r3 hoist (157, did not hoist).
- Flag sweep OLD+NEW agbcc: -fno-gcse, -fno-cse-follow-jumps, -fno-expensive-optimizations,
  -fno-schedule-insns[/2], -fno-force-mem, -fno-strength-reduce, -frerun-cse-after-loop,
  -fno-thread-jumps, -fcaller-saves, -fno-peephole, -fno-defer-pop, -fno-cse-skip-blocks,
  -O1/-O3 — none beat 142.
- Permuter NOT run: scratch venv (vendor/decomp-permuter) is an empty dir in the worktree,
  and 142 >> the ~40 threshold anyway. NEXT agent: fix the venv and try permuter ONLY after
  a structural change drops byte_diff under ~40 (the residual is scheduling + 2 copies, which
  permuter statement-reorder could plausibly close from a closer base).

## Next ideas (untried)

- Find the source shape that makes agbcc hoist `movs r3,#0` early (kills both copies). The
  baserom does this — likely the two `_field_1A = 0` byte stores share a hoisted zero pseudo
  that local-alloc places in r3 BEFORE the standalone halfword stores. Try writing the two
  `=0` byte stores FIRST (before the halfword stores) so the zero is live across them and
  gets a callee-ish reg early; or reorder the whole post-loop to the baserom's chain-implied
  pointer form: `q=&e[70]; q->_field_14=0x185; q->x=0x143; (q+1)->x=0x15b;` etc., which is
  what the 0xf64/0xf52/0xf8a (=s70.f14,s70.x,s71.x) chain implies — but that gave base-CSE
  before; combine with the u8* full-offset trick somehow.
- The prologue interleave may come from a different loop FORM (e.g. count-up `for(i=0;i<2;i++)`
  with the pointer derived inside, or the loop consts declared as locals initialised before p).

## Best-effort C (byte_diff 142, OLD_AGBCC, structure correct; NOT committed)

```c
#include "iwram.h"
#include "types.h"

extern void sub_0800A580(void *e, s8 param, s8 deltaX, s8 deltaY);

struct Entity {
    u8 _field_00;
    u8 _pad01;
    u16 x;
    u16 y;
    u8 _field_06;
    u8 _pad07[13];
    u16 _field_14;
    u8 _field_16;
    u8 _field_17;
    u8 _pad18[2];
    u8 _field_1A;
    u8 _pad1B[0x19];
    u16 flags;
    u8 _pad36[2];
};

void sub_08022360(void)
{
    u8 *base = (u8 *)&gIwram_3720;
    struct Entity *p = (struct Entity *)(base + 0xf18);
    s32 off;
    s32 val;
    s32 i;

    for (i = 1; i >= 0; i--) {
        p->flags = 16;
        p->_field_00 = 15;
        p->_field_16 = 12;
        p->_field_17 = 3;
        p->_field_06 = 2;
        p++;
    }

    *(u16 *)(base + 0xf2c) = 0x175;

    off = 0xf64;
    val = 0x185;
    *(u16 *)(base + off) = val;
    off -= 18;
    val -= 66;
    *(u16 *)(base + off) = val;

    *(u16 *)(base + 0xf1c) = 0x2F4;

    off += 56;
    *(u16 *)(base + off) = 0x15B;

    *(u16 *)(base + 0xf54) = 0x33A;
    *(base + 0xf32) = 0;
    *(u16 *)(base + 0xf4c) |= 2;

    off = 0xf6a;
    *(base + off) = 0;
    off += 26;
    *(u16 *)(base + off) |= 2;

    sub_0800A580(base + 0xf18, 4, 0, 1);
    sub_0800A580(base + 0xf50, 4, 0, 1);
}
```

NOTE: shipping this requires the Makefile line `src/engine/sub_08022360.s: CC = $(OLD_AGBCC_BIN)`
(base lands in r4 only under OLD_AGBCC).
