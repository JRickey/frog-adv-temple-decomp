# sub_08032148 — deferred (register-coloring local minimum)

Sound-engine "is anything still busy?" predicate at 0x08032148 (184 bytes,
src/system/sub_08032148.c). Reached entirely through `*gpSoundSystem`
(0x030065e0). Returns 1 while pending work remains, 0 once drained.

Semantics are FULLY decoded and the C below is structurally correct (control
flow + struct field types verified against agbcc offsets, not host gcc — host
gcc sizes `SoundRequestTimer`/`SoundChannelSeq` differently). All offsets in
the C resolve to the exact baserom offsets:

- `gpSoundSystem->slot`           -> [sys+0x118]  (SoundRequestSlot*)
- `slot->flags`                   -> (u8)[slot+0x151]
- `slot->timers[i].cursor`        -> [slot + i*8]      (i 0..15)
- `slot->streams[i].cursor`       -> [slot+0x88 + i*8] (i 0..15)
- `gpSoundSystem->count`          -> (u8)[sys+0]
- `slot->nextRegion`              -> [slot+0x110] (SoundDrainEntry*, 12-byte stride)
- `drain[i].live`                 -> (u8)[base + i*12 + 4]
- `gpSoundSystem->channelSeqs[i].opPtr` -> [ [sys+0x114] + i*16 ]
- `gpSoundSystem->chanAcc[i]` (i<=3)    -> (u16)[sys+0xac + i*2]
- `SOUND_SYSTEM_SW_SLOT(sys,i-4)->accA` (i>3) -> (u16)[ [sys+0xc8] + (i-4)*64 + 0x34 ]

Busy condition per channel j (after `channelSeqs[j].opPtr != 0`): the
accumulator (chanAcc[j] for j<=3, swSlots[j-4].accA for j>3) being `<= 0xff`
(signed ble in baserom; the ldrh keeps r0 in 0..0xffff so it is effectively
unsigned `<= 0xff`).

## Drift

Best result: **byte_diff 156, diff_count 47 (Thumb)** — but the diff is almost
entirely a register-NAME cascade. The whole INNER LOOP matches the baserom
register-for-register (r5=drain base, r7=&gp, r6=limit, r2=reloaded sys,
r3=j, r4=j<<1). Control flow and instruction *shapes* match.

The genuine divergence is ~5 instructions: the baserom keeps `&gpSoundSystem`
in a LOW callee-saved reg (r5) materialised first in r0 then copied
(`adds r5, r0, #0` at 0x32160), and in the L_184 loop preamble it COPIES the
live ranges out (`adds r7, r5, #0` = save &gp; `adds r6, r1, #0` = save
limit). Our build allocates `&gp` straight to r7 and `limit` straight to r6
with NO copies — fewer instructions, but a different (mirror) coloring that
cascades r5<->r7 across every subsequent instruction.

This is a GLOBAL register-allocator live-range-splitting decision
(global.c / reload.c), not local-alloc. The baserom splits the long-lived
`&gp` value across two hard regs (r5 early, r7 in the loop) with explicit
reg-reg copies; agbcc here coalesces them into a single hard reg (r7).

### Levers tried (all stay at diff_count 46-47, none reach the split)
- `-fno-gcse` is REQUIRED and correct: without it agbcc hoists `*gpSoundSystem`
  out of the loop (caches sys in a callee reg) instead of reloading `[&gp]`
  each iteration; WITH it the inner loop reloads `r2 = [r7]` exactly like the
  baserom. Keep this flag for any future attempt.
- `-fno-schedule-insns{,2}`, `-fno-strength-reduce`, `-fforce-addr`: no change
  (force-addr made it worse, 167).
- Newer agbcc (`AGBCC_BIN`): WRONG compiler here — it folds `0x151` as
  `0x118 + 0x39` (`adds r1,#57`) instead of loading the `0x00000151` pool
  literal the baserom uses. old_agbcc is correct.
- `register SoundSystem **gpsp asm("r5")`: forces `ldr r5,[pc]` direct, drops
  r7 entirely (`push {r4,r5,r6,lr}`), 4-reg frame — diverges worse (67).
- `-ffixed-r7`: spills to `ip`/`fp` high regs, breaks the 5-reg push — worse.
- Source-shape variants (sys=*gpsp cached vs re-deref; drain inside vs outside
  loop; limit computed early vs at L_184; macro-direct vs gpsp-var; two-pointer
  alias gp5+gpsp): all land 46-47. The two-pointer alias (gp5 used early,
  gpsp=gp5 for the loop) coaxed ONE of the three copies (46) but at the cost of
  a meaningless second pointer variable — rejected as unreadable.
- **decomp-permuter**: 1531 iterations from the byte_diff-156 base. base score
  2150; best score 1850 (just inlined `limit` and added a dead `new_var=NULL`).
  Never approached 0. Confirms statement-reorder / scope / temp mutations
  cannot escape this coloring minimum — consistent with the CLAUDE.md caveat
  ("a near-match can still be a sharp register-coloring local minimum no single
  source shape escapes").

### Next attempt should try

in the first half and split it to r7 across the second loop. Likely needs

## Best-effort C

```c
#include "sound.h"

/* Compile with: src/system/sub_08032148.s: CFLAGS += -fno-gcse */
u8 sub_08032148(void)
{
    SoundSystem **gpsp = &gpSoundSystem;
    SoundRequestSlot *slot = (*gpsp)->slot;
    SoundDrainEntry *drain;
    s32 i;
    s32 limit;

    if (slot->flags & 2) {
        for (i = 0; i <= 15; i++) {
            if (slot->timers[i].cursor != NULL)
                return 1;
            if (slot->streams[i].cursor != NULL)
                return 1;
        }
    }

    limit = (s32)(*gpsp)->count + 4;
    for (i = 0; i < limit; i++) {
        drain = (SoundDrainEntry *)slot->nextRegion;
        if (drain[i].live != 0)
            return 1;
        if ((*gpsp)->channelSeqs[i].opPtr != NULL) {
            if (i <= 3) {
                if ((s32)(*gpsp)->chanAcc[i] <= 0xff)
                    return 1;
            } else {
                if ((s32)SOUND_SYSTEM_SW_SLOT(*gpsp, i - 4)->accA > 0xff)
                    continue;
                return 1;
            }
        }
    }

    return 0;
}
```
