# Deferred analysis: sub_0801C464

Range: 0x0801c464..0x0801c4f8 (148 bytes, Thumb)

## Function summary

Fills two 3×3 tile blocks in VRAM (screenblock 31 at 0x0600f800) with
sequential tile indices. Block 1 starts at row 16 col 1 (offset 0x402) with
tile base 0xB100; block 2 at row 16 col 20 (offset 0x428) with tile base
0xA109. No function calls — pure register arithmetic loops.

## Status

ATTEMPT_MATCH (classifier). Pure loop arithmetic — no BL calls, no high-reg
cross-BL issue. Reached **byte_diff 21 / diff_count 12** with the C below.

## Drift

**Best byte_diff: 21, diff_count: 12**

Two systematic differences remain:

### 1. Loop 1 (and similarly loop 2): row*64 register choice

Target: `lsls r1, r3, #6` (row*64 → r1), then `lsls r0, r3, #1` (row*2 →
r0) **before** either is consumed. This interleaved-dual-shift scheduling
puts row*64 in r1.

Built (both agbcc and old_agbcc): `lsls r0, r3, #6` (row*64 → r0), used
immediately in `adds r5, r0, r7`, THEN `lsls r0, r3, #1` reusing r0.

The target computes BOTH shifts before using either (interleaved); mine
schedules sequentially (compute-use-compute-use). This is a register
scheduling difference in agbcc's expression evaluation order.

### 2. Loop 2 structural asymmetry

Target outer loop body:
```
movs r2, #0       ; col = 0
lsls r1, r3, #6  ; row*64 → r1
lsls r0, r3, #1  ; row*2 → r0
adds r5, r3, #1  ; r5 = row + 1  ← EARLY counter backup
adds r4, r1, r7  ; r4 = vramRow  (in r4, not r5 like loop1!)
adds r0, r0, r3  ; r0 = row*3
mov r1, r9        ; r1 = tileBase2
adds r3, r1, r0  ; r3 = tileBase2+row*3  ← OVERWRITES row counter!
```
Then inner loop uses r4 (vramRow) and r3 (tileRow). Loop tail recovers r3
from r5 via `lsls r0, r5, #24; lsrs r3, r0, #24`.

My built loop2 (both loops symmetric): r5=vramRow, r4=tileRow, r3 stays as
the outer loop counter throughout.

The asymmetry arises because loop2's r3-reuse frees r5 for the counter
backup, then uses r4 for vramRow. Getting agbcc to produce this specific
shape requires the outer loop counter (`row`, r3) to be overwritten
mid-body with the tileRow 32-bit value.

Attempted C structures that trigger this pattern (with row as u8):
```c
row = tileBase2 + (u32)row * 3;  // truncates to u8 → adds lsls/lsrs mask (2 extra bytes)
```
Using u32 for row produces the `adds r3, r1, r0` without mask but changes
register assignments elsewhere (r5 used for row instead of r3).

## Levers tried

- `register u32 vramBase asm("r6")` — fixes r6/r7 swap for VRAM vs rowOff
- `register u32 ipBase asm("ip")` — enables ip-retained-across-loops
- `asm volatile("" : "+r"(ipBase))` — prevents ip+0x28 hoisting into loop1
- old_agbcc per-TU override — produces identical output to new agbcc
- Permuter 2000 iters (-j4, 45s): base score 1015, best 855 (no score 0)
- Multiple C structure rewrites for loop2 (u8 row, u32 row, separate
  row2/row3 variables, explicit row-overwrite, nextRow backup)

## Next lever to try

The `lsls r1` vs `lsls r0` issue: try writing `vramRow = row*64 + rowOff`
and `tileRow = tileBase1 + row*2 + row` with EXPLICIT interleaving in a
single compound statement, or try a macro that forces `row*64` to be
evaluated into r1 by making r0 busy first. The key: if r0 can be "occupied"
right before the `row*64` computation, agbcc will use r1 for the shift.

For loop2 structural match: the outer loop counter r3 needs to be
OVERWRITTEN with a 32-bit value without masking. This requires row to be
declared as u32 (or an explicit intermediate u32 variable to receive the
tile base value without mask). The challenge: making r3 be the same
register for both the row counter and the tileRow intermediate while also
getting r5 = row+1 early in the body.

Possible approach: try `register u32 row asm("r3")` pin together with
explicit intermediate `register u32 tileRow asm("r3")` in loop2 scope.

```c
#include "macros.h"
#include "types.h"

void sub_0801C464(void)
{
    register u32 tileBase1 asm("r8") = (u32)0xb1 << 8;
    register u32 tileBase2 asm("r9") = 0x0000a109;
    register u32 ipBase asm("ip");
    register u32 vramBase asm("r6");
    u8 row;
    u8 col;
    u32 rowOff;
    u32 vramRow;
    u32 tileRow;

    row = 0;
    ipBase = (u32)0x80 << 3;
    rowOff = ipBase + 2;
    vramBase = 0x0600f800;
    do {
        col = 0;
        vramRow = (u32)row * 64 + rowOff;
        tileRow = tileBase1 + (u32)row * 3;
        do {
            *(vu16 *)((u32)col * 2 + vramRow + vramBase) = (u16)(tileRow + col);
            col++;
        } while (col <= 2);
        row++;
    } while (row <= 2);

    row = 0;
    asm volatile("" : "+r"(ipBase));
    rowOff = ipBase + 0x28;
    vramBase = 0x0600f800;
    do {
        col = 0;
        vramRow = (u32)row * 64 + rowOff;
        tileRow = tileBase2 + (u32)row * 3;
        do {
            *(vu16 *)((u32)col * 2 + vramRow + vramBase) = (u16)(tileRow + col);
            col++;
        } while (col <= 2);
        row++;
    } while (row <= 2);
}
```
