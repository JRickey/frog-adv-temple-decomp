## Semantics (fully reverse-engineered, believed correct)

The blitter streams the animated status-bar widget into VRAM 0x0600F800 via
the `sFrogStatusBarFrames` descriptor table @ 0x080e3628 (already a typed array
in src/data/ui_status_bar.c, `const u32 sFrogStatusBarFrames[25*3]`; I extern it
as `struct StatusBarFrame { u16 xpad, yskip, rows, width; const u16 *tiles; }`).

Two cursors drive two phases:
* **phase 1** — cursor `gIwram_6100` (NEW symbol; same `{u8 byte0; u32 field4}`
  shape as `gIwram_5320`), guard `gGameStuff[0] - gIwram_6100.field4 > 7`,
  frames `[byte0+1]` (byte0 wraps at >6).
* **phase 2** — cursor `gIwram_5320`, guard `gGameStuff[0] - gIwram_5320.field4 > 13`,
  frames `[byte0+9]` (byte0 wraps at >4), iterated `(s8)gIwram_35E0._data[4]`
  times, accumulating `sl` (a u8 column accumulator init 1, += frame.xpad and
  += *(u8*)0x080E369A per iteration); VRAM dst = 0x0600F800 + sl*2.
* between the phases: `if ((s8)gIwram_35E0._data[4] >= gIwram_6110.threshold ||
  gGameStuff.pendingMode==15) goto phase2; else { sub_08016928(); return; }`.

Inner blit per descriptor row: skip `yskip` rows (dst += 0x20 each), then for
`rows` rows: dst += xpad, copy `width` halfwords from `tiles`, dst += 32-xpad-width.

Established idioms confirmed from already-matched neighbours:
* `(s8)gIwram_35E0._data[4]` (NOT `((s8*)&gIwram_35E0)[4]`) — the bare-cast form
  emits the register-offset `ldrsb` the baserom uses; the pointer-cast folds a
  spurious `00000004` pool word. Confirmed against matched src/engine/sub_08009884.c:29.
* `sub_080172B6` / `sub_08017290` mirror the first half of the matched
  `sub_08016928` in src/engine/sub_08016824.c (reuse `struct DmaDesc2Entry`).

## Drift

Best reached: **byte_diff 425, diff_count 165** (of ~294 insns; built 292 insns).
The STRUCTURE is correct — instruction *count and ordering* line up across both
phases after these two source-shape wins:
1. **Access `gIwram_6100`/`gIwram_5320` as globals, not through a cached local
   pointer.** The pointer form makes agbcc strength-reduce `(byte0+1)*12` into
   `byte0*12 + 12` (spurious `0000000c` pool) and over-CSE the descriptor index;
   direct global access makes agbcc recompute `&frames[byte0+1]` per field exactly
   like the baserom, and spills the cursor base to `ip` (`mov ip, r2`) as the
   baserom does. This dropped 543 -> 428.
2. `(s8)gIwram_35E0._data[4]` + `*(u8*)0x080E369A` (unsigned) idioms: 428 -> 425.

What REMAINS is pure register-colouring divergence, NOT structure:
* **phase 1**: baserom RELOADS `&gGameStuff` (into r3) for the frame-word read
  because `ldrb r1,[r1,#10]` (pendingMode) consumed the base register; agbcc here
  reads pendingMode into r0, keeps `&gGameStuff` live in r1, and reuses it (so
  built is 1 insn shorter and the downstream regs shift). Could not coerce
  pendingMode into the base register by any source shape tried.
* **phase 2**: baserom keeps `&sFrogStatusBarFrames` in `ip` and re-loads
  `&gIwram_5320` from the pool each byte0 read, keeping `&gIwram_5320` in r9 only
  for the writes; the loop counter `idx` lives in r3 and is stashed to r8 across
  the inner loops. agbcc inverts this (cursor->r8/r9, table uncached->r0). The
  `register cur5320 asm("r9")` pin made it WORSE (572) because then the table
  doesn't reach ip. A mixed "global byte0 reads + r9-pinned cursor for writes"
  is the shape to try next.
* `row` loop counter is r4 in baserom, r5 in built (consistent swap).

Responsible agbcc pass: `gcc_arm/local-alloc.c` / `reload.c` register colouring
under the high-register pressure of {sl=acc, r8=idx-save, r9=cursor, ip=table}.
This is a textbook "sharp register-colouring local minimum" — the brief's
designated escape is `vendor/decomp-permuter`, which is **NOT installed** in this
environment (no `.venv` in main or the worktree), so it could not be run.

#include "macros.h"
#include "types.h"

/* Status-bar tile-stream blitter.
 *
 * sub_08017000 streams the animated status-bar widget into VRAM at
 * 0x0600F800, one descriptor row at a time. Two independent cursors drive
 * it: gIwram_6100 advances once every 8 frames through the 7-frame loop at
 * sFrogStatusBarFrames[1..7], and gIwram_5320 advances once every 14 frames
 * through the 5-frame loop at sFrogStatusBarFrames[9..13]. Both cursors record
 * the frame timestamp (gGameStuff._unk00) of their last step in their
 * `field4` so the rate is wall-clock, not call-count.
 *
 * Each descriptor is a 12-byte record { u16 xpad, u16 yskip, u16 rows,
 * u16 width, const u16 *tiles }; the blit pads `xpad` cells on the left of
 * each of `rows` rows, copies `width` halfwords from `tiles`, then pads the
 * remaining (32 - xpad - width) cells to reach the next 32-cell VRAM row. */

struct StatusBarFrame {
    u16 xpad;
    u16 yskip;
    u16 rows;
    u16 width;
    const u16 *tiles;
};

extern const struct StatusBarFrame sFrogStatusBarFrames[];

/* DMA descriptor table at 0x08306888 (see sub_08016824.c). */
struct DmaDesc2Entry {
    u16 maxCount;
    u8 threshold;
    u8 _pad3;
    u32 *srcPtrTable;
    u32 destAddr;
    u16 count;
    u16 _pad0e;
};

extern u32 gDmaDescTable_08306888[];
