# sub_080132E8 — deferred analysis (round 40)

Panel-border corner-segment renderer. Loops modes 4..7; for each mode that is
*requested* (bit set in `gIwram_6110.byteFlags8` @ +0x2a) but not yet *drawn*
(`gIwram_6110.gateByte` @ +0x2b), it issues 4 `sub_08012BC4(...)` blits (a
diagonal pair from each of two scene tables) and clears that mode's two status
bits in the byte at `0x030036e4`, then marks the mode done in `gateByte`.

Classifier: ATTEMPT_MATCH (advisory: 3 high regs r8/r9/sl held across the `bl`).
NOT corpus-confirmed unmatchable. The structure is fully understood and the C is
correct; this is a sharp **register-coloring / instruction-scheduling** local
minimum, not a structural wall.

## Layout / data model (verified against baserom)

- `gIwram_6110` (`struct IwramAt6110`, iwram.h): `byteFlags8` @ +0x2a (requested
  bits 4-7), `gateByte` @ +0x2b (done bits 4-7). Entry guard:
  `if ((byteFlags8 & 0xf0) == (gateByte & 0xf0)) return;`.
- Two `const` scene tables of 24-byte records (`struct TilemapTableEntry`, same
  layout as sub_080139BC/sub_08013AAC siblings): sceneA @ 0x0830702c (pinned r6),
  sceneB @ 0x083070ec (pinned r5). 8 records each at +0x00/0x18/0x30/0x48/0x60/
  0x78/0x90/0xa8; fields u16 unk00/02/04/06, u8 unk08 @+8, `void *tiles` @+0x10.
- Status flag byte @ 0x030036e4 (pinned r8). srcIndex args: indexA=2 (sl),
  indexB=3 (r9).
- Per-mode record indices and clear masks:
  - mode4: recs {0,5}; clears 0x01,0x20 (masks 0xfe,0xdf); own store.
  - mode5: recs {1,4}; clears 0x02,0x10 (masks 0xfd,0xef); shared tail.
  - mode6: recs {7,2}; clears 0x04,0x80 (masks 0xfb,0x7f); shared tail.
  - mode7: recs {6,3}; clears 0x08,0x40 (masks 0xf7,0xbf); shared tail.
- The clear is `*status = (*status & maskA) & maskB` — ONE load, ONE store, two
  ANDs (NOT two `*status &= x`). Modes 5/6/7 jump to a SHARED epilogue (0x1357e)
  that does the second AND + store, carrying maskB in a reg; mode 4 stores alone.
- Secondary-call tiles addressing depends on the tiles field's offset from r6:
  off ≤0x7c → `[r6,#off]`; rec5 (off 0x88) → ABSOLUTE pool `*(0x083070b4)`;
  rec6/rec7 (off 0xa0/0xb8) → recompute `adds r4,r6,#off; ldr[r4,#0]`.

## Drift (best byte_diff 539, diff_count 92 — ~23 real diffs, rest is branch cascade)

Best base = `docs/deferred-analysis` "Best-effort C" below. Function SIZE matches
(708 bytes); the byte_diff is dominated by the branch-target cascade from a
handful of register-scheduling diffs. Permuter (proper $t/$d target, base score
17490) ran ~6000 iters and bottomed out at **8540, never approaching 0** — this is
NOT a permuter-reachable near-match; the differences are systematic agbcc
allocation choices, not mutateable statement order.

Remaining real diffs (all register-scheduling micro-choices):
1. **Secondary-call idx temp reg = r3 (baserom) vs r4 (mine).** Baserom moves the
   pinned `sl`/`r9` (idx) into **r3** for the `str rX,[sp,#8]`, which forces it to
   first spill the width arg (`str r3,[sp,#12]` ... `ldr r3,[sp,#12]`) and bumps
   the frame to `sub sp,#16`. Mine grabs the now-free **r4** (after tiles loaded
   into r4 then stored), so no width spill and `sub sp,#12`. Both are valid; agbcc
   picks r4 because r4 is free after the absolute/recompute tiles load. This is the
   dominant cluster (the width save/restore + sp size + cascade). Driven by
   local-alloc/reload reg preference, NOT source-controllable by any shape tried.
2. **Init scratch-temp regs**: baserom `movs r1,#3; mov r9,r1; ldr r3; mov r8,r3`
   (temps r1 then r3) vs mine `movs r3,#3; mov r9,r3; ldr r4; mov r8,r4` (r3 then
   r4). Cosmetic temp selection for the high-reg pin init.
3. **case4 clear & first-AND operand reg** — minor.

## Levers tried (none reached byte_diff 0)

- **mode pinned to r7** → agbcc constant-folds the pinned r7=4 and PEELS the whole
  first iteration (`asrs r0,r0,#4`, `cmp r0,#5` with literal 4 everywhere). This is
  hard-register value-tracking; happens with ANY literal init while pinned, and
  with mode=3+increment-first too. `-fno-rerun-cse-after-loop` removes the fold but
  spills mode. An `asm("":"=r"(mode):"0"(mode))` fence removes the fold but spills.
- **THE KEY MOVE that avoids the fold AND gets mode into r7 unpinned**: pin
  `desc` to **r4** (`register ... desc asm("r4")`) and leave `mode` UNPINNED. Then
  desc's many short scratch live-ranges no longer steal r7, agbcc naturally colours
  mode into r7, and because mode is a plain pseudo (not a hard reg) there is NO
  constant-fold → variable `asrs r0,r7`. This single change took diff_count from
  226 → 149.
- **Secondary tiles via `sceneX[N].tiles`** (r6-relative, NOT `desc->tiles`):
  matches the baserom's r6-based tiles addressing for off ≤0x7c and the
  recompute for rec6/rec7 → diff_count 149 → 92.
- **rec5 tiles forced absolute** via `((const struct TilemapTableEntry *)0x0830702c)[5].tiles`
  (literal base folds to `*(0x083070b4)`) — needed because rec5's tiles off 0x88
  exceeds the `[r6,#imm]` range and the baserom uses an absolute pool there.
- Compiler swaps: AGBCC (newer) made it worse (622) and still folded. OLD_AGBCC is
  correct. Per-TU CFLAGS sweep (`-fno-gcse`, `-fno-cse-follow-jumps`,
  `-fforce-addr -fno-expensive-optimizations -fno-gcse`, `-fno-schedule-insns[2]`,
  `-fcaller-saves`, `-fno-peephole`, `-fno-thread-jumps`, `-fno-rerun-loop-opt`)
  — none fixed the width-spill / idx-temp-reg or improved on 539.
