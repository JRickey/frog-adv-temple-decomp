# Deferred analysis: sub_0800803C

Range [0x0800803c, 0x08008174) (312 bytes), thumb. Dest:
`src/game/sub_08007dd0.c` (append at tail, after sub_08007F88). Pure leaf,
no callees. Operates on `gIwram_3720` (pool literal 0x03003720, loaded

## What the function does (semantics fully reversed — this part is solid)

`u8 sub_0800803C(s16 x, s16 y, s16 targetX, s16 targetY)` — steps
`gIwram_3720._field_2` (X sub-coord) and `._field_4` (Y sub-coord) toward
(targetX, targetY), at most 4 units per axis per call (clamped to the
remaining distance: 1, 2, 3, else 4). Returns 1 iff BOTH axes equal the
target after this call (compared as 16-bit), else 0.

Four independent `if` blocks in order:
  block1  if (x > targetX): switch((s16)(x-targetX)) { 1: f2-=1; 2: f2-=2;
          3: f2-=3; default: reload &gIwram_3720; f2-=4; }
  block2  if (x < targetX): switch((s16)(targetX-x)) { ... f2+=1..4 }
  block3  if (y > targetY): switch((s16)(y-targetY)) { ... f4-=1..4 }
  block4  if (y < targetY): switch((s16)(targetY-y)) { ... f4+=1..4 }
  tail    dy=f4; dx=f2; if (dx != targetX) return 0; if (dy == targetY) return 1; return 0;

The structure (block-by-block) MATCHES the baserom exactly. This is NOT a
structural problem.

## Drift (best byte_diff 249, diff_count 73 — all cascade from 2 root causes)

ROOT CAUSE 1 — 3-way callee-saved register ROTATION of the precomputed
zero-extended args. agbcc precomputes zext(arg1=y), zext(arg3=targetY),
zext(arg0=x) into callee-saved regs at the prologue (kept alive because the
arg regs r0-r3 get reused as scratch). The coloring differs:
    TARGET:  zext(y)->r4,  zext(targetY)->r7, zext(x)->r6
    BUILT:   zext(y)->r7,  zext(targetY)->r6, zext(x)->r4   (cyclic r7->r4->r6->r7)
This single rotation shifts every subsequent compare/branch, producing the
73-instruction cascade. The pointer pin (r5) is correct in both.

ROOT CAUSE 2 — final-compare representation. TARGET keeps `ip=targetX<<16`,
`r6=targetY<<16` and compares `field<<16` against them (`lsls r0,dx,#16; cmp r0,ip`).
BUILT instead extracts u16 (`lsrs r0,ip,#16; cmp dx,r0`). Both correct, 1 insn
each, but agbcc picks the lsr direction. Plain `dx != targetX` (s16) got
byte_diff from 253->249 vs the `(u16)` cast; neither flips the lsls form.

 * target (targetX, targetY), at most 4 units per axis per call (clamped to
 * the remaining distance: 1, 2, 3, else 4). Returns 1 once both axes have
 * reached the target this call, else 0. */
u8 sub_0800803C(s16 x, s16 y, s16 targetX, s16 targetY)
{
    register struct IwramAt3720 *p asm("r5") = &gIwram_3720;
    s16 dx;
    s16 dy;

    if (x > targetX) {
        switch ((s16)(x - targetX)) {
        case 1: p->_field_2 -= 1; break;
        case 2: p->_field_2 -= 2; break;
        case 3: p->_field_2 -= 3; break;
        default: p = &gIwram_3720; p->_field_2 -= 4; break;
        }
    }
    if (x < targetX) {
        switch ((s16)(targetX - x)) {
        case 1: p->_field_2 += 1; break;
        case 2: p->_field_2 += 2; break;
        case 3: p->_field_2 += 3; break;
        default: p->_field_2 += 4; break;
        }
    }
    if (y > targetY) {
        switch ((s16)(y - targetY)) {
        case 1: p->_field_4 -= 1; break;
        case 2: p->_field_4 -= 2; break;
        case 3: p->_field_4 -= 3; break;
        default: p->_field_4 -= 4; break;
        }
    }
    if (y < targetY) {
        switch ((s16)(targetY - y)) {
        case 1: p->_field_4 += 1; break;
        case 2: p->_field_4 += 2; break;
        case 3: p->_field_4 += 3; break;

        }
    }

    dy = p->_field_4;
    dx = p->_field_2;
    if (dx != targetX) {
        return 0;
    }
    if (dy == targetY) {
        return 1;
    }
    return 0;
}

## Corpus sweep (2026-06-03)

**Outcome: DEFERRED.** A genuine 7-query corpus sweep across all 23 mirrors plus several agbcc-source-grounded structural attempts confirm the existing doc's diagnosis: this is a 3-way **suggested-register coloring drift** of three zero-extended `s16` arguments kept in callee-saved registers, NOT a missing C-shape idiom that another decomp solved. Tree restored pristine (0 commits, `make check` exits 0, asm slice intact).

### The exact asm idiom that diverges
The prologue zero-extends three of the four `s16` args into callee-saved regs and keeps them alive across the whole body (arg regs r0-r3 get reused as scratch):
- **TARGET** (baserom 0x803e..0x804c): `lsrs r4,r1,#16` = zext(y)→**r4**; `lsrs r7,r3,#16` = zext(targetY)→**r7**; `lsrs r6,r0,#16` = zext(x)→**r6**; then `ldr r5,[pc]` (pointer load LAST, after all three zexts).
- **BUILT** (best-effort C, byte_diff 249): `lsrs r7,r1,#16` = zext(y)→**r7**; `lsrs r6,r3,#16` = zext(targetY)→**r6**; `ldr r5,[pc]` scheduled EARLY (before the third zext); `lsrs r4,r0,#16` = zext(x)→**r4**.

So the built version rotates the trio (y: r4→r7, targetY: r7→r6, x: r6→r4) AND schedules the r5 pointer-load early. This single rotation cascades into a 73-instruction diff (every subsequent cmp/branch target shifts). A secondary divergence (ROOT CAUSE 2 in the doc): the tail final-compare — target keeps `ip=targetX<<16`/`r6=targetY<<16` and compares `field<<16` against them; agbcc instead extracts u16 and compares the low halves.

Note: I corrected the doc's per-register labelling by tracing live ranges directly. The three callee-saved zexts and their last-use sites are: zext(x)→r6 (born 0x804a, dies 0x8098 in block2 — SHORTEST live range), zext(y)→r4 (born 0x8042, dies 0x80de — LONGEST), zext(targetY)→r7 (born 0x8048, dies 0x80e2). targetX's zext is the one NOT kept callee-saved (it's the scratch r3, recomputed) because it dies after block2.

### Why the trick did not transfer
The divergence is decided inside agbcc's **suggested-register** machinery, not by any C-expressible idiom. The zext quantities tie on `size` (1) and ~`n_refs`, so `QTY_CMP_PRI = floor_log2(n_refs)*n_refs*size/(death-birth)` would order them by live range (shorter=higher priority → earlier reg in REG_ALLOC_ORDER `{3,2,1,0,12,14,4,5,6,7,...}`). But the OBSERVED target assignment is the *opposite* of pure-priority (shortest-lived zext(x) gets r6, longest-lived zext(y) gets r4), which means `qty_sugg_compare` (copy-preferences carried from the arg regs r0/r1/r3) runs FIRST and dominates. That preference structure is a function of how the m2c/agbcc internal RTL forms the copies — it is not steerable from C statement structure without changing the function's semantics. This is why every C-shape attempt left byte_diff pinned.
