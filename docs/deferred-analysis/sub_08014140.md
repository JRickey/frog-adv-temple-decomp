## MAJOR ADVANCES this round (use these; they are confirmed)

1. **`p` lands in r4 (was r3) via pinning `oldField2c asm("r3")`.** ROOT CAUSE proven by
   instrumenting a PRIVATE debug old_agbcc (probe at `reg_renumber[...] = best_reg` in
   gcc/global.c): `REG_ALLOC_ORDER` is `{3,2,1,0,12,14,4,...}` (r3 FIRST), and `p` is the
   single highest-priority pseudo (nrefs=34, livelen=158, priority `floor_log2(34)*34/158`),
   so it deterministically grabs r3. The baserom has p in r4. `-ffixed-r3` flips p→r4 AND
   gives the 2-slot frame, but bans r3 from the loop (src) → bloat. The FIX that keeps r3
   available later: pin the value the baserom actually keeps in r3 — `oldField2c` — to r3.
   That occupies r3 during the gate (p→r4) and frees it for `src` in the loop. **This is
   the keystone the prior note missed.** Cost: see cluster A-of2c below.

2. **`counter asm("r2")` is load-bearing (byte_diff 308→209).** Without it agbcc detours
   counter through r8 (`mov r8,r0; mov r2,r8`) because r2 is contended; pinning it keeps
   `ldr r2,[gGameStuff]` direct AND lets `oldField2e`/`oldField36` spill to the stack
   (the 2-slot frame `sub sp,#8`).

3. **The f9 load must use a scratch THEN move to r9** — split as `t9 = p->field_09;
   mode = t9 & 0xF; f9 = t9;` with `f9 asm("r9")`, `t9` a plain local (byte_diff 314→146).
   Writing `f9 = p->field_09; mode = f9 & 0xF;` directly forces a `ldrb r2; mov r9,r2` +
   mode re-fetch. Baserom: `ldrb r0,[r4,#9]; movs r2,#15; ands r2,r0; mov r9,r0`.

4. **Nibble unfold (cluster A) is reproducible** — `register u32 tt asm("r2")=f9;
   asm("":"=r"(tt):"0"(tt));` fence keeps f9 untraceable so combine emits `lsls#24;lsrs#28`
   not `lsr#4`. To also force the `<<24` into r0 (scratch) and `>>28` into r2 (hi): add
   `register u32 sh asm("r0"); asm("":"=r"(sh):"0"(tt<<24)); hi=(u8)(sh>>28);` with
   `hi asm("r2")`. Gets `lsls r0,r2,#24; lsrs r2,r0,#28` — MATCHES the nibble (byte_diff
   135→113). The leftover A residual is now tiny.

5. **`v34 asm("r0")` removes the v34 stack spill (cluster B, SOLVED).** Baserom keeps
   v34 in r0 across the hi-switch; agbcc otherwise spills it `mov r8,r0`. With v34=r0 the
   spill is gone.

  / `subs r0,r3,r1`, preserving r3); ours clobbers r3 in-place (`lsls r3,r3,#24` /
  `subs r3,r3,r1`). CAUSE: the `oldField2c asm("r3")` PIN makes reload treat r3 as free

  preserved (its live range spans all switch cases). Tension: the pin is REQUIRED for
  p→r4, but it costs these 4 insns. Tried: temp var for the subtraction (folded back),
  `&0xFF` vs `(u8)` (identical). UNSOLVED — needs a way to give of2c r3 as a normal
  pseudo (e.g. boost its allocno priority above p so it naturally wins r3) instead of a

- **Cluster B (v34/v36 lsl/asr ordering, 0xfc/0x100, 2 lines only).** Baserom does BOTH

- **Cluster C (dst-calc iw r1-staging, ~5 insns, 0x12e-0x142, the BIGGEST cascade).**
