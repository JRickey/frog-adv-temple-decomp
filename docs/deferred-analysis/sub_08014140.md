# sub_08014140 — deferred analysis

2D tilemap-blit / scroll-step on the `struct AnimState` shared with
`sub_080140A0` (sub_08014078.c). Pure-C structure is **fully solved** — every
instruction is the correct opcode; the only residual is one agbcc spill-mode
artifact plus the register-coloring cascade it causes.

## What it does
`u8 sub_08014140(struct AnimState *p, u8 step)`:
1. Frame gate: `if (gGameStuff._unk00 - p->field_04 < p->field_0b) return 0;`
2. Save `oldField2e = p->field_2e`; `if (field_2e == 0 || field_2c == 0) return 1;`
   (each compared via signed `ldrsh`, the save via unsigned `ldrh`).
3. Commit: `field_04 = counter`, snapshot `field_34/36/10`, `field_0c = field_10`.
4. `switch (field_09 & 0xF)` (scroll mode 1..4): updates field_34/36/2c/2e and
   recomputes `field_10` (dest offset) by ± `step*field_30*2` or ± `step*2`.
   Also sets `cols`/`rows` (the blit extents) and `*(u8*)0x03003611 = 1`.
5. `switch ((field_09 >> 4) & 0xF)` (dest bank 0/1/2) selects EWRAM base
   0x02000000 / 0x02010000 / 0x02020000.
6. `dst = base + (field_34_signed + gIwram_60A0.stride*field_36_signed)*2`,
   `src = field_0c`. Then a `rows × cols` u16 2D copy with src row-stride
   `field_30` and dest row-stride `gIwram_60A0.stride` (gIwram_60A0 + 0x1a).
7. `return 0;`

## Drift (best pure-C: byte_diff 260, diff_count 95; size 404 = correct)
The function is structurally exact. The blocker is a single agbcc spill-mode
decision that cascades into register coloring:

- **`oldField2e` is spilled as SImode (word) instead of HImode (halfword).**

  barrier — see below), **every remaining diff is pure register coloring**

  oldField2e/oldField36). With the barrier the readable C reaches **byte_diff
  183, ALL `ARGUMENT_MISMATCH`** (no insertion/deletion/replacement).

### The exact asm idiom that diverges
The documented crux: `oldField2e` (a `u16` saved before the switch mutates `p->field_2e`) is spilled by the baserom as a **HImode** stack slot — `ldrh r0,[r4,#46]; mov r7,sp; strh r0,[r7,#4]` at the save, and reloaded fresh per switch-case via `mov r5,sp; ldrh r5,[r5,#4]`. Our agbcc instead allocated `oldField2e` as a **SImode** pseudo, CSE-cached the zero-extended value, and reload-spilled it as a WORD (`str r7,[sp,#4]` / `ldr r7,[sp,#4]`). `oldField36` is correctly a word spill in both. So the two stack slots differed ONLY in spill *mode* for oldField2e.

### Root cause (agbcc pass implicated)
NOT register-coloring for the crux — it is `tools/agbcc-src/gcc_arm/config/arm/thumb_020428.h` **PROMOTE_MODE** (lines 402-413): every `MODE_INT` local with size < 4 is forced to `SImode` (and `UNSIGNEDP=1`). So *every* scalar `u8/u16/s16` local becomes an SImode pseudo and spills as a word (the spill slot mode is `GET_MODE(regno_reg_rtx[i])` in `reload1.c:alter_reg`, ~line 2356/2389). The baserom's HImode spill therefore cannot come from a scalar local. **The fix: aggregate members escape PROMOTE_MODE.** Declaring `oldField2e` as `u16 oldField2e_a[1]` (a 1-element array) makes it a genuine HImode memory object — agbcc emits `mov rX,sp; strh` on save and `mov rX,sp; ldrh` per use, byte-matching the baserom. This was the documented "next idea" the prior agent could only reach with an `asm volatile("":"+m")` barrier; the array-member form achieves it in pure C.
