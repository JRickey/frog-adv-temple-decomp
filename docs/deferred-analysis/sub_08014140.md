## Drift

`classify_unmatchable.py sub_08014140` reports `ATTEMPT_MATCH`, not
`STRONG_UNMATCHABLE`; do not ship NAKED. The function is a leaf:
`u8 sub_08014140(struct AnimState *p, u8 step)`. It rate-limits on
`gGameStuff._unk00`, updates the source rectangle according to the low nibble of
`field_09`, selects an EWRAM tile bank from the high nibble, then copies a
`rows x cols` halfword rectangle using the stride at `0x030060A0 + 0x1a`.

Best result this round: `byte_diff 96`, `diff_count 24`, size 404. This improves
the previous `byte_diff 104` plateau. The improvement is from removing the
`oldField2c asm("r3")` pin: agbcc still keeps the required early allocation
shape, and the case-3/case-4 `field_2c` updates now use target `r0` scratch
instead of clobbering `r3` in place. The earlier note's `oldField2c` pin is not
load-bearing and should not be restored.

Remaining drift at the 96-byte plateau:

- Early return branch offsets differ by 2 because later code still has a small
  schedule/layout skew.
- Signed-cast cluster around old fields `0x34`/`0x36`: target emits both
  `lsls #16` before both `asrs #16`; agbcc emits one `lsls/asrs` pair together.
  This is combine/local-alloc ordering.
- Blit-state address calculation: target copies `v34` to `r2`, loads
  `0x030060A0` into `r1`, reads `stride` into `r7`, multiplies in `r0`, then
  caches `r1` into `r7` for the row loop. The best C still loads the state base
  directly into `r7` and uses `r1` as the stride temporary.
- Inner-loop guard: target keeps the zero counter in `r2` and emits
  `cmp r2, r5; bcs`; agbcc folds the known zero to `cmp r5, #0; beq`. This is
  a constant/copy propagation fold; manual `c = 0; if (c < cols) do ...` compiles
  identically.
- Loop epilogue: target reads `ldrh r2, [r7, #26]`; best C emits
  `adds r0, r7, #0; ldrh r0, [r0, #26]`.
