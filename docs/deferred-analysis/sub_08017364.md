# Deferred analysis: sub_08017364

EEPROM/save-restore routine. `[0x08017364, 0x0801756c)` = 520 bytes, called
once from Init1 (sub_08000430). VERDICT from classify_unmatchable.py:
ATTEMPT_MATCH (3 high regs r8/r9/sl pinned across `bl` — advisory, NOT a
structural-impossibility signature; NAKED is forbidden here).

The asm slice `asm/disasm_0x08017364.s` also holds two SIBLING functions
(`sub_0801756C` and the one at 0x17710); only the first block is this target.
All callees are peeled (sub_08020C3C / sub_08020C58 peeled this round).

## What the function does (confirmed by trace)
1. Save `REG_IE` to a stack u16, call sub_0802D99C(savedIeValue), then mask
   IE: `&= 0xfffe; &= 0xfffd; |= 0x40` (serial IRQ dance).
2. Init the IWRAM block at 0x03003500: `[0x3c]=0; [0x38]=0; [0x0e]=0;
   [0x0d]=5; [0x0c]=0; *(u32*)[8]=0xff; [0x0f]|=0xff; [0x13]=0xff|[0x13];
   [1]=0; [0]=0`.
3. `if (sub_080172F4() == 0) { block[0x3c]=0; goto restore; }`  (read whole save)
4. **Reads `ok` (r7) UNINITIALIZED**: `cmp r7,#0; beq cont; b restore` at
   0x173dc, where r7 is later the validation flag set to 1 at 0x173f6 — so on
   this path it is the caller's leftover `sl`. Modeled as `register u8 ok
   asm("r7"); if (ok != 0) goto restore;` placed between the sub_172F4 and
   sub_177A0 calls. This DOES reproduce `cmp r7,#0` (good).
5. `sub_080177A0(header /* sp+52, u32[2] */)` — fills 8-byte header; on 0 goto
   restore.
6. `block[0x3c]=1; ok=1;` then validate header bytes:
   `if (header[0]>15) ok=0; if (header[3]!=0) ok=0; if (header[1]>4) ok=0;
    if ((u8)(header[6]-3)>6) ok=0; if ((u8)(header[7]-3)>6) ok=0;`
7. `if (!ok) { header[0]=header[2]=header[3]=header[1]=0;
    *(u32*)(header+4)=*(u32*)0x030034b4; if (!sub_080177D8(header)) goto restore; }`
8. Copy header u64 into block[0],[4]. Then loop i=0..3: if `(header[0]>>i)&1`
   call `sub_08017814(slots+i*12, i)` else init slots+i*12 in this exact store
   order: [5]=0,[6]=0,[8]=0x41,[9]=0x41,[10]=0x41,[4]=0,*(u32*)[0]=0,[7]=0,[11]=0.
   Then copy: `*(u32*)(blk+i*12+8)=src[0..3]; +12=src[4..7]; +16=src[8..11];`
   then bytes `blk[i*12+16..18]=src[8..10]` (overlapping the prior u32 store —
   the baserom's `ldmia {r4,r6,r7}/stmia` + 3 strb).
9. Tail: 0x030034b4[3]=5,[2]=5,[0]=1,[1]=1; *(u32*)0x030034b0=header[1];
   *(0x03003500+0x38)=0; sub_08020388(); if(!flags[0]) sub_08020BF0();
   if(flags[1]) sub_08020C58() else sub_08020C3C(); REG_IE=*savedIe; return 1;
10. restore: sub_08020388(); same flags dispatch; REG_IE=*savedIe; return 0;

## Drift (best: byte_diff 399, diff_count 159 Thumb instructions)
The PROLOGUE, savedIe save/restore, and the entire INIT block (steps 1-2) MATCH
byte-for-byte after these levers:
  - savedIe: store value to a temp `ie`, store to local, pass `ie` (not a reload)
    to sub_0802D99C. (fixes the reload).
  - stack layout: declare `u32 header_buf[2]` (NOT u8[8]) so agbcc places savedIe
    @sp+48 and header @sp+52 like the baserom. u8[8] put them reversed.
  - `register u32 zero asm("r2")`, `register u32 fullByte asm("r0")` — reuse the
    0 / 0xff constants in the baserom's registers; write `block[0x0f] |= fullByte`
    (result in load reg) but `block[0x13] = fullByte | block[0x13]` (result back
    in fullByte/r0) — the baserom uses `orr r1,r0` then `orr r0,r1` respectively.
  - `register u8 *block asm("r6")`, `header asm("r8")`, `savedIe asm("r9")`.

The RESIDUAL 159-instruction drift is in the VALIDATION block + the two COPY
LOOPS and is pervasive **instruction-scheduling + register-coloring**:
  - agbcc HOISTS the validation/loop address setup (`mov r1,sp; lsls ...`) ABOVE
    the `bl sub_177A0`, while the baserom keeps strict order
    `cmp r7,#0 / beq / b restore / add r4,sp,#52 / bl 177a0`. Cannot block this:
    **agbcc rejects `-fno-schedule-insns` / `-fno-schedule-insns2`** ("Invalid
    option"). OLD_AGBCC_BIN gives the identical 399/159.
  - field reads: baserom does a fresh `mov rN,r8; ldrb [rN,#off]` per header
    field; agbcc CSEs `mov r0,r8` once then `adds r0,#off; ldrb [r0]`.

## Levers already tried (pick a DIFFERENT one next)
  - Local reorder (savedIeBuf before/after header_buf): no effect on layout once
    header_buf is u32[2].
  - Per-TU CFLAGS sweep (all clean-built, stale-.o artifacts excluded):
    -fno-gcse, -fforce-addr, -fno-expensive-optimizations, -fno-cse-follow-jumps,
    -O1, CC=OLD_AGBCC_BIN → all 399/159 or WORSE (-fforce-addr = 492/214).
    The schedule-disabling flags that would actually help are NOT in agbcc.
  - Split `headerAddr` (r4, &header_buf) for the first field read vs `header`(r8)
    for the rest: no effect (160) — agbcc won't keep r4 live.
  - Moving `header = (u8*)header_buf` before the ok-check: 399→399, 161→159.
  - permuter NOT attempted: byte_diff 399 is far outside its ~≤40 useful range.

## Next ideas (untried)
  - The scheduler hoist is the dominant blocker. Try an `asm("")` barrier or a
    volatile read on the header to create a fake data-dep that pins sub_177A0
    before the validation/loop setup (sub_0800A104-style barrier).
  - Model the validation as reads through a SEPARATE non-pinned u8* that agbcc
    is forced to re-materialize from r8 each field (maybe via `(*(volatile u8*)
    (header+N))`), to defeat the `mov r0,r8` CSE into per-field `mov rN,r8`.
  - Re-derive the copy loop with the exact `ldmia/stmia {r4,r6,r7}` triple via a
    struct-typed 12-byte memcpy + 3 trailing strb, checking the loop index reg
    (baserom uses r5, count-up `cmp r5,#3; bls`).
