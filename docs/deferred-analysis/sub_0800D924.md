## Drift — three structural artifacts, in priority order

1. **else-branch `0xfffdfffd` is built by register RMW, not a constant load.**
   Baserom: `r4 &= 0xffff0000; r4 |= 0xfffd; r0 = 0xfffd+2 (=0xffff);
   r4 &= r0; r4 |= 0xfffd0000`. i.e. `result=(result&0xffff0000)|(u16)-3;
   result=(result&0xffff)|((u16)-3<<16);` on an r4-held `u32 result`, and the
   `0xffff` mask is materialized as `0xfffd+2` (constant reuse). agbcc in our
   build FOLDS this back to a single `ldr 0xfffdfffd` because `result` is a
   dead-initialized local. The baserom kept `result` genuinely live in r4 — so
   `result` is probably NOT a fresh local but shares storage with the
   then-branch value. KEY UNTRIED IDEA: make `result` and the then-branch's
   value the SAME live r4 variable that the compiler can't prove dead (e.g.
   read it once before the if, or `asm("":"=r"(result))` barrier), so the two
   `&=`/`|=` are not folded. ~20 bytes of the 97 live here.

2. **(s8)limit precompute into ip keeps CSE-folding with (u8)limit (r8).**
   Baserom precomputes `(s8)limit` ONCE into ip (used only in the loop `<`)
   and re-sign-extends r8=(u8)limit AFTER the loop for the `==`. Our agbcc
   folds `slimit=(s8)limit` and `(s8)ulimit` into one value and re-asr's r8
   every iteration. Pinning slimit to ip via `register asm("ip")` makes it
   WORSE (agbcc adds moves around its scratch reg). UNTRIED: a barrier between
   the two so CSE can't merge them, or compute the `==`'s limit through a
   different expression path.

3. **A dead-in-loop `lsls r0,(u8)limit,#24` is PRE-hoisted INTO the loop**
   (baserom 0xd974) but only USED after the loop (0xd982 asr). Pure
   partial-redundancy-elimination scheduling — hard to force from C; likely
   falls out for free once #1/#2 are right.
