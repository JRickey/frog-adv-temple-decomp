# sub_08020FE4 — deferred (pure-C plateau at byte_diff 15)

Range `[0x08020fe4, 0x080210a0)`, 188 bytes. Destination remains
`src/engine/sub_08020f3c.c` (the loop-twin of the matching `sub_08020F3C`
directly above it); the asm slice remains linked from
`asm/disasm_0x08020fe4.s`.

Classifier verdict: `ATTEMPT_MATCH` (no `mov pc`, no libgcc-only prologue;
advisory: r9 pinned across the gate `bl` — benign). **Do NOT ship NAKED.**

## What this round ACHIEVED over the prior (byte_diff 20 -> 15)

Two structural wins, both kept in the Best-effort C below:

1. **Fixed the loop-pointer / off-CSE that the prior round left as "off -> r7"
   (its offsets 0x26..0x52).** Root cause: the elapsed pre-check stamp address
   `(base+0x2c)+off` is arithmetically EQUAL to the first loop `stampPtr`
   `(off+0x2c)+mover` (mover==base), so agbcc CSE-folds them and keeps the
   elapsed address ALIVE in a callee-saved reg (r7) to seed the loop, instead
   of recomputing `stampPtr` fresh from `off` (r3) like the baserom. This was
   the DOMINANT cost (~92 bytes of branch-offset cascade), NOT the high-reg
   swap.
   **The fix is a SOURCE-level CSE break, no pin/flag:** compute the elapsed
   stamp address by INCREMENTAL pointer staging so agbcc forms a distinct
   value-number from the loop expression:
   ```c
   { u8 *p = (u8 *)base; p += 0x2c; p += off; elapsed = gsLo->_unk00 - *(u32 *)p; }
   ```
   (A single `*(u32 *)(off + (u32)(base+0x2c))` expression folds; the staged
   `p += ; p +=` does not.) This alone drops byte_diff 107 -> a low value once
   `idx` is also pinned.
2. **`register s32 idx asm("r4")`** — the staged elapsed shifts idx off r4 to
   r5 without it; pinning idx back to r4 takes byte_diff 32 -> 15.

So the plateau is now ONLY the high-reg swap (13 diffs, all one cause), not
the off/CSE the prior round was stuck on.

## ROOT CAUSE of the residual byte_diff 15 — STALE INSTALLED COMPILER

The entire residual is a SINGLE global-allocation decision: which of two
loop-invariant addresses gets `ip` (r12) vs `r8`.

- Target: `gsHi`(=&gGameStuff) -> r8, `flags`(=&gIwram_35E0) -> ip.
- Built (installed old_agbcc): `gsHi` -> ip, `flags` -> r8 (SWAPPED).

All 13 residual diffs cascade from this swap (the `mov rX, ip` / `mov rX, r8`
field reloads at 0x6e/0x78/0x8c and the `(r3+const)+r6` vs `(r6+const)+r3`
loop-setup operand order at 0x4a-0x52 follow the swapped registers).

`global.c:allocno_compare` sorts allocnos by density
`floor_log2(n_refs)*n_refs / live_length`, descending; whoever is allocated
first gets `ip` (first high reg in REG_ALLOC_ORDER {3,2,1,0,12,...,8,10,9}).
`flags` has MORE refs (2 reads/iter) and a SHORTER live range than `gsHi`
(assigned early at `gsHi = gsLo`), so by that formula `flags` SHOULD win `ip`
— and the baserom agrees.

**INSTRUMENTATION PROOF (the new, load-bearing finding):** I built a private
debug `old_agbcc` from the SAME `tools/agbcc-src` (per codegen-notes
"Instrumenting agbcc itself") and probed `global.c:find_reg`. The fresh build
allocates `gsHi -> r8, flags -> ip` (CORRECT) for the EXACT Best-effort C
below. The INSTALLED `tools/agbcc/bin/old_agbcc` (dated May 24) allocates the
SWAP. **The installed binary is a different/older build than the current
`tools/agbcc-src` and diverges on this function's allocno ordering.** This is
NOT a C-shape problem solvable against the installed binary — it is a
toolchain-version artifact. (A fresh build is ALSO not a drop-in: it saves
only r8/r9 in the prologue, not r8/r9/sl, so it doesn't reproduce the baserom
byte-for-byte either. The baserom was built with a SPECIFIC agbcc version that
neither the installed binary nor a current-source rebuild matches here.)

## Two mutually-exclusive bases (the catch-22, now precisely characterised)

- **bd15** (Best-effort C below): off-CSE FIXED, byte_diff 15 / diff_count 13,
  residual = the swap. The staged-elapsed `p` pseudo is what shifts allocno
  ordering so the installed compiler picks the swap.
- **d24** (bd15 WITHOUT the staged elapsed, i.e. plain
  `*(u32 *)(off + (u32)stampBase)`): high regs CORRECT (flags->ip, gsHi->r8)
  via the same flags-as-variable-loaded-after-mover trick, BUT off-CSE present
  -> byte_diff 107 / diff_count 24. Adding the staged `p` to fix off-CSE
  re-breaks the swap; they cannot both hold against the installed binary.

## Levers RULED OUT this round (pick a DIFFERENT one next)

- `register gsHi asm("r8")` (bd15): byte_diff 27 — reshapes, flags lands wrong.
- `register flags asm("ip")` (bd15): byte_diff 168 — the classic ip-pin
  round-robin DESYNC (codegen-notes sub_08032094); makes `mov rX,ip` an
  allocator copy not a reload.
- BOTH `gsHi asm("r8")` + `flags asm("ip")`: byte_diff 168.
- making `flags` a copy from an early `flagsLo` (so it gets a suggested reg
  first): 64 — early load forces a register early (baserom loads flags right
  before the loop).
- moving `gsHi = gsLo` early (longer range, lower priority) OR after `flags`
  (lower allocno for flags): 135 / 47 — both move the `mov r8,r2` out of its
  baserom position (gsHi is set up DURING the elapsed calc).
- single `gs` instead of gsLo/gsHi split: 135/142 — split is required (matches
  the baserom r2->r8 copy; the sibling F3C also splits).
- `gIwram_5330` linker-symbol for gGameStuff instead of the `0x03005330`
  `#define`: NO swap change AND adds a stray pool word (worse).
- per-TU CFLAGS sweep on bd15/d24: `-fno-gcse`, `-fno-cse-follow-jumps`,
  `-fno-rerun-cse-after-loop`, `-fno-cse-skip-blocks`, `-fno-thread-jumps`,
  `-fno-expensive-optimizations`, `-fforce-addr`, `-fno-strength-reduce`,
  `-fno-schedule-insns[2]`, `-fno-function-cse`, `-fcaller-saves` — NONE change
  diff_count (the swap is in global.c allocno ordering, unreachable by these).
- permuter from bd15 (`--better-only`, ~3-4 min, -j4): floors at score 55
  (~byte_diff 11), only finds a trivial `new_var = dy` temp; CANNOT flip the
  global allocation swap (it mutates statement order/scope, not allocno
  priority).

## Best-effort C (byte_diff 15, PURE C, no inline asm; the `s32` gate decl is REQUIRED)

```c
extern long long sub_08006830(struct IwramAt6110 *p, s32 a, s32 b);

void sub_08020FE4(s32 start, s32 end)
{
    EntityMover *base;
    GameStuff *gsLo;
    GameStuff *gsHi;
    register s32 idx asm("r4");
    register s32 last asm("r9");
    u32 off;
    u32 arg8;
    u32 elapsed;
    u8 interval;
    struct IwramAt35E0 *flags;

    idx = start;
    last = end;
    if (sub_08006830(&gIwram_6110, idx, last) == 0)
        return;

    gsLo = &gGameStuff;
    base = (EntityMover *)gEntities;
    arg8 = idx << 3;
    off = (arg8 - idx) << 3;

    {
        u8 *p = (u8 *)base;
        p += 0x2c;
        p += off;
        elapsed = gsLo->_unk00 - *(u32 *)p;
    }

    interval = *(u8 *)((off + (u32)base) + 0x32);
    gsHi = gsLo;
    if (elapsed < interval)
        return;
    if (idx > last)
        return;

    {
        EntityMover *mover = base;
        u32 *stampPtr;
        u16 *xyPtr;

        flags = &gIwram_35E0;
        stampPtr = (u32 *)((off + 0x2c) + (u32)mover);
        xyPtr = (u16 *)((off + 2) + (u32)mover);

        do {
            s32 dx;
            register s32 dy asm("r1");

            dy = ((u8 *)stampPtr)[5];
            dx = ((s8 *)stampPtr)[4];
            xyPtr[0] += dx;
            dy = (dy << 24) >> 24;
            xyPtr[1] += dy;

            if ((flags->_field_10 & 2) != 0 && idx == flags->_field_D) {
                mover->x += dx;
                mover->y += dy;
            }

            *stampPtr = gsHi->_unk00;
            stampPtr = (u32 *)((u32)stampPtr + 0x38);
            xyPtr = (u16 *)((u32)xyPtr + 0x38);
            idx++;
        } while (idx <= last);
    }
}
```
