# sub_08020FE4 — deferred (matchable-in-principle, register-coloring blocker)

Range `[0x08020fe4, 0x080210a0)`, 188 bytes. Lives in `asm/disasm_0x08020fe4.s`,
destination `src/engine/sub_08020f3c.c` (appended after the matching neighbour
`sub_08020F3C`). This is the **range/loop** sibling of `sub_08020F3C` (which is
the single-element version and already matches in pure C): it advances every
EntityMover in `[start, end]` by its `(dx, dy)` velocity once enough ticks have
elapsed, and mirrors the moving entity's delta onto `gIwram_3720[0]` when the
active-entity flag (`gIwram_35E0._field_10 & 2`) is set and `idx == _field_D`.

The structure is **correct** — best base reaches **byte_diff 18 / 14 Thumb diffs**,
all of which are register-naming, not control flow or operations.

## Drift

Two mirror-image register-allocation states, neither closes:

- **Base A (off unpinned → r7): byte_diff 18, diff_count 14** (the stashed C below).
  Prologue/epilogue MATCH (`push {r4,r5,r6,r7,lr}` + r8/r9/sl). Residual:
  - `off` (= idx*56) lands in **r7**; target keeps it in **r3**
    (`lsls r3,r0,#3` vs built `lsls r7,r0,#3`; +0x26/+0x2c/+0x34/+0x4a-0x52).
  - the loop's high-reg→low-reg address copies use **r0**; target uses **r7**
    (`mov r7,ip`/`mov r7,r8` vs built `mov r0,ip`/`mov r0,r8`; +0x78/+0x8c).
  - one off-by-one schedule of `mov r5,ip` (+0x6c/+0x6e).

- **Base B (off pinned r3 + r0-temp for the shift): byte_diff 21-24.**
  `off` now correctly in r3 AND the `lsls r0,r4,#3 / subs / lsls r3,r0,#3`
  intermediate matches. BUT the prologue then drops r7 (`push {r4,r5,r6,lr}`):
  freeing r3 lets agbcc use r0 for the loop scratch, so r7 is never a
  callee-saved reg and isn't pushed → epilogue `pop` also diverges.

### Root cause (read from agbcc source)
`tools/agbcc-src/gcc_arm/global.c` ~L375-395: global alloc seeds
`regs_used_so_far` with all `call_used_regs` because caller-saved regs are
"free" (no save cost). So agbcc PREFERS **r0/r3** (caller-saved) for any global
qty that doesn't cross a call — which is exactly the loop's `mov rN,ip` /
`mov rN,r8` address copies. The baserom instead spends **r7** (callee-saved) on
those copies and r3 on `off`. This is a global-vs-local split the baserom makes
that agbcc reverses, and the two functions co-habit one TU
(`src/engine/sub_08020f3c.c`), so a per-TU `-ffixed-r0` / `-ffixed-r7` lever is
unusable: it would break the already-matching `sub_08020F3C` (which uses r7).

## Levers already tried (pick a DIFFERENT one next)
- `register asm("rN")` pins in every combination: off→r3 (breaks prologue),
  off unpinned→r7 (base A), scratch var `r7 asm("r7")` for y-read+field_D
  (helped, got to 18), gs-deref result into r7 (no improvement).
- `coord`/`sum` temp idiom copied from the matching neighbour (helped: 32→27→18).
- r0-pinned temp for the `idx*56` shift chain (fixes the off-compute mnemonics
  but only in the off=r3 base, which breaks the prologue).
- cast-through-`(u32)` to force a high-reg deref into r7 → **spills to stack**
  (`ldr r0,[sp,#0]`), worse (65). Do NOT recast pinned high regs.
- pointer-arithmetic / struct-field rewrite (`e = base + idx; e->x; e++`) →
  agbcc multiplies / increments differently, byte_diff 138. The raw-offset form
  is much closer; keep it.
- unpin xPtr so it coalesces with off=r3 → whole loop drifts (34).
- decomp-permuter (`-j4 --stop-on-zero`, ~250 iters): base score 180, best 175.
  It only inserted a throwaway `new_var = off + 0x2c`; cannot flip the
  global r3↔r7 allocation with statement mutation. Permuter is NOT the tool here.

## Opus attempt (round 3) — confirmed the blocker is agbcc reload + global-alloc, not C shape

Independently re-derived the function from scratch (did NOT extend base A) and
reproduced base A at **byte_diff 18**. Mapped the full target loop register usage
and confirmed the two callee-saved scratch registers the baserom spends:

- **r5** = the "compute then consume" scratch: dx-index (`movs r5,#4; ldrsb r5,[r2,r5]`),
  flags->_field_10 low-copy (`mov r5,ip; ldrh r5,[r5,#16]`), cur->y read (`ldrh r5,[r6,#4]`).
- **r7** = the "load into low reg" scratch: xPtr[1]/y read, field_D materialize+result
  (`mov r7,ip; ldrb r7,[r7,#13]`), gs materialize (`mov r7,r8; ldr r0,[r7]`).
- **r0** = pure arithmetic accumulator (NOT reused as a materialize scratch).
- **r3** = xPtr (coalesced from off). off and xPtr share r3 the whole time.

### Two irreducible attractors (neither reaches the target)
1. **xPtr pinned r3** → off is forced to **r7** (base A, byte_diff 18). Mechanism
   confirmed from `global.c` find_reg pass-1: `used_nopref |= regs_someone_prefers`.
   xPtr's r3 pin marks r3 "preferred by someone", so off AVOIDS r3 in pass 1 and takes r7.
2. **off in r3** (pinned, or off-as-loop-pointer with no separate xPtr) → the prologue
   DROPS r7 (`push {r4,r5,r6,lr}`), materializes go to **r0**, plateau byte_diff 21-24.
   Freeing r3 lets agbcc use r0 as the loop scratch, so r7 is never a callee-saved qty.

The target needs BOTH off=r3 AND r7-pushed AND materialize=r7 simultaneously. agbcc
will not produce all three because its allocator prefers caller-saved r0/r3 for
loop scratch (`global.c` ~L394: `regs_used_so_far` seeded with all `call_used_regs`
as "free"), and its reload picks the **lowest-numbered** free low reg (r0) for the
`mov lowreg, highreg; ldr ...` high-base materialization — independent of the result
register's pin.

### NEW things tried this round that FAILED (don't repeat)
- off-as-the-loop-pointer (no separate xPtr, off pinned r3, casts in loop): **24**.
  Closest off=r3 variant but r7 never pushed → prologue/epilogue diverge.
- merge off+xPtr into one C variable (pinned r3 and unpinned): **34-37**. The loop
  `xPtr` is a distinct pseudo from the merged var; no coalesce.
- pin the loop scratch to r5 AND/OR materialize-holder to r7 with `register asm()`

- single r7 pointer var for field_D (`fp asm("r7"); fp=flags; idx==fp->_field_D`):

  fp live, won't overwrite r7 with the load).
- `t=(u32)flags; t=((u8*)t)[13]` cast idiom: **82-87** (cast spills the high-reg deref).
- direct `idx == flags->_field_D` compare (no var): **19** — DOES reuse one reg for
  materialize+result, but picks **r0** not r7. Confirms the reload-scratch = r0 root.
- forcing the off-compute intermediate to r0 (`register u32 prod asm("r0")`): -2 bytes

- `-fcall-saved-r0` (probe, breaks ABI/neighbor): r0 becomes pushed but the
  materialize STILL uses r0 (`mov r0,ip`). Reload picks lowest reg regardless of
  call-saved status → this lever cannot move the materialize to r7. So the

## Corpus sweep (2026-06-03)

### The exact asm idiom that diverges
All 14 diffs are register-naming in three clusters, with control-flow / operations / prologue / epilogue byte-identical:
1. **`off` (idx*56) lands in r7; baserom keeps it in r3** (+0x26 `lsls r3,r0,#3` vs built `lsls r7,...`; +0x2c/+0x34/+0x4a-0x52). Driver: base A pins `xPtr` to r3, and `global.c find_reg` pass-1 does `used_nopref |= regs_someone_prefers`, so off avoids r3 and takes r7.
2. **The HI->LO base materialize scratch is r0; baserom uses r7** — `mov r7,ip; ldrb r7,[r7,#13]` (field_D, +0x78/+0x7a) and `mov r7,r8; ldr r0,[r7]` (gs deref, +0x8c/+0x8e) become `mov r0,ip; ldrb r7,[r0,#13]` and `mov r0,r8; ldr r0,[r0]`. This is the heart of the blocker.
3. **One `-fschedule-insns2` swap of `mov r5,ip` vs `movs r0,#2`** (+0x6c/+0x6e).

### Every regex searched + hit count
- `mov r7, (r8|r9|sl|ip)` via the tool default (`\s`-regex): **0 hits** — root cause found: `git log -G` uses POSIX ERE where `\s` is NOT whitespace, so the tool's default `\s+` patterns silently match nothing. Future agents MUST pass literal spaces / `[ ]+` to `--asm`.
- `mov r[0-7], (r8|r9|sl|ip)` (`\s`): **0 hits** (same bug).
- `mov r[0-7], (r8|r9|sl|ip)` POSIX literal-space + `--require-c`: many hits (pokeemerald dodrio_berry_picking, pokenav_unk_10) — all the generic funnel/spread idiom, no clean pairing for the r0-vs-r7 choice.
- `mov r7, (ip|r8|r9|sl)` + `--require-c --clean`: pokeemerald 3f858c1c26 (sub_8022F04/berry_crush), a08cbaee0a (pokenav_unk_2), 4ae8a52473 (contest_painting_effects) — single-fn commits but the `mov r7,*` lines were prologue high-reg saves (`mov r7,r10`), not the deref-materialize.

All are the **spread** case (one high reg fanned to *distinct* low regs for field-by-field access) — the opposite of my **funnel** (everything to ONE low reg, and the question is *which*).

### Why the trick did not transfer
My blocker is the **funnel** tie-break (which single low reg holds a repeatedly-materialized high-reg base inside a loop), NOT the **spread** shape the corpus presets target. I verified at the agbcc source why no C-shape can fix it: `tools/agbcc-src/gcc_arm/config/arm/thumb.h` defines **`SECONDARY_RELOAD_CLASS`** = `LO_REGS` for a high-reg (regnum>7) base (L601-606), and crucially **there is NO `REG_ALLOC_ORDER` defined** in thumb.h — so reload allocates the *lowest-numbered free LO_REG* (r0) for that secondary-reload scratch, unconditionally, independent of any pin on the load's result register. This is exactly the prior rounds' finding, now confirmed in the machine description: there is no flag and no C statement that biases the secondary-reload scratch toward r7 when r0 is free.

### agbcc pass implicated
Register-coloring. Two passes: (a) `tools/agbcc-src/gcc_arm/global.c` `find_reg` / `prune_preferences` (~L375-395, `regs_used_so_far` seeded with all `call_used_regs` as "free", and pass-1 `used_nopref |= regs_someone_prefers`) — decides off=r3-vs-r7. (b) `tools/agbcc-src/gcc_arm/reload1.c` allocate-reload-reg + `config/arm/thumb.h` `SECONDARY_RELOAD_CLASS` (L601) with **no `REG_ALLOC_ORDER`** — decides the HI->LO materialize scratch = lowest-free = r0. The two are coupled: every C-shape that forces off=r3 (pin, or off-as-loop-pointer) frees r3, which lets agbcc use r0 as the loop scratch so r7 is never callee-saved → prologue drops `push {...,r7}` (byte_diff 24). The target needs off=r3 AND r7-pushed AND materialize=r7 simultaneously; agbcc cannot produce all three.

        interval = *intervalAddr;
    }

        return;
    if (idx > last)

        register u32 *stampPtr asm("r2");
        register u16 *xPtr asm("r3");

        flags = &gIwram_35E0;

            register s32 dy asm("r1");

                    coord = cur->y;

            }

            *stampPtr = gs->_unk00;
            stampPtr = (u32 *)((u32)stampPtr + 0x38);
            xPtr = (u16 *)((u32)xPtr + 0x38);
            idx++;
        } while (idx <= last);
    }
