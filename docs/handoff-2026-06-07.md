## Next: #14 — pin / register-coloring reaping (the original goal)

**Premise (proven this campaign):** data-model unification is byte-neutral and does NOT
reap pins — pins are genuine agbcc register-coloring divergences (see memory
[[pin-forest-not-data-model]]). The plan: remove `register T x asm("rN")` pins and recover
the match via `vendor/decomp-permuter`, per function.

**START HERE:** read **`docs/depin-worklist.md`** (landed this session, commit `fcfab18e`) —
53 functions ranked by ACTUAL clean-rebuild byte_diff after pin removal. Key findings:

- **The tractability signal is `nonARG == 0`** (every diff is pure register coloring = the
  permuter's exact domain). Only 6 of 53 have any structural (`nonARG>0`) delta.
- **Free wins first — byte_diff 0 means the pin is already REDUNDANT** (remove it, no permuter,
  byte-neutral): `Display_ResetLayers`, `Entity_MoveToEntry`, `Tilemap_DispatchPendingBlits`.
  Then low-diff pure-coloring: `Scene_EntityTick`(2), `EntityDispatch_RunFrame`(11),
  `Blend_StepFade`(11), `sub_0800D9C8`(16), `Mode4_BlitRect`(22), `TileBlit_DrawEntry`(22),
  `Credits_InitStateA/B`(24).
- **Struct-high-reg priority class = 5 LIVE functions**: `Tilemap_DispatchPendingBlits`
  (sl, diff 0 — free), `Entity_UpdateHitboxSlots` (r8=EntityHitbox*, diff 65, pure coloring),
  `Blit_ApplyFlaggedRecords` (r9, 114), `BlitSpriteRect` (r8+r9, 158), `sub_080210A0`
  (sl, 136 — documented resistant). ~13 other struct-high-reg pins are DEAD inside
  `#ifdef NON_MATCHING` (already NAKED) → those belong to the reclaim-naked track, not #14.
- **Measurement nuance on `Entity_UpdateHitboxSlots`:** the worklist's 65 is from stripping
  ALL pins; the owner-remembered "~10" was from removing only the two high-reg base-pointer
  pins. Both are pure coloring (permuter-tractable) — try the minimal removal first.
- **Gotcha the agent re-confirmed:** incremental builds FALSE-GREEN after a pin strip (stale
  `.o` reuse) — `CollisionTable_ScanForPlayer` and several blit fns showed `byte_diff=0`
  incrementally but 53/158/200 on a clean rebuild. Only trust `make tidy && make -j8`.

Known resistant: `sub_080210A0` (byte_diff ~136, structural; a prior 17-pin removal failed).

**How to run #14 (per function, easiest byte_diff first):**
1. Remove the `asm("rN")` pins (plain locals).
2. `python3 tools/agent/make_permuter_target.py <fn>` — **regenerate target.o**; without
   `$t/$d` symbols the permuter scores ~100x too high (memory [[permuter_target_bug]]).
   Confirm `vendor/decomp-permuter` venv exists (`scripts/setup-*.sh`; memory
   [[permuter_venv_broken]] — it was once a broken self-symlink, now restored).
3. Run the permuter from the near-matching base; also try the corpus-history idiom search
   (CLAUDE.md "Stuck on a fold? Search the corpus FIRST").
4. **Match** ⇒ drop the pins, `make tidy && make -j8 && make check`, commit, decrement count.
   **Genuine residue** (one of the 4 hard classes in docs/codegen-notes.md AND 0% permuter
   improvement) ⇒ restore pins, keep NON_MATCHING, document the class.
5. These functions touch shared files (Entity / the IWRAM structs above) — run them
   **serially or in non-overlapping worktrees**; do NOT run a pin-edit and another agent's
   `git checkout` on the same file concurrently (that hazard cost a restart this session).

**Discipline (non-negotiable):**
- The ONLY matching oracle is `make tidy && make -j8 && make check` (exit 0). Incremental
  `make check` **false-greens on header changes**, and a failed build leaves stale `.o`s that
  **false-RED** an incremental check — always `make tidy` after any failure.
- clangd "no member / undeclared" diagnostics in this repo are **stale-index phantoms** —
  trust only `make check`.
- Subagents have false-greened here before — **independently re-verify** any agent's "green"
  with your own clean build.
- Field renames don't change bytes, so `make check` can't catch a field renamed on the wrong
  struct — scope by fully-qualified expression, not bare `_field_NN` tokens.
